# 过程级案例：workflow-pb SKILL.md 优化（2026-09-03）

**归属类型**：过程级案例（主 agent 在会话中的设计/执行行为）
**迭代范围**：workflow-pb SKILL.md v1.1.0 + v1.2.0 两轮优化（消除内联漂移、补角色路径解析）

---

### 案例 1：中途误加未获批的改动，事后自查撤销

**现象**：用户就三个边界问题给出确认后，改动范围已明确（移除内联速查表、加角色映射表）。但在改写 Workflow 章节时，顺手在阶段2→3之间加了一个新 Gate——理由是协议里有"步骤数≥5时中间应设Gate"的一般性建议。后续自查发现这条超出用户确认的范围，主动撤销。

**根因**：把协议的"一般性最佳实践建议"和"用户本次具体确认的改动清单"混为一谈。长文档改写任务里，保持结构完整性的惯性会驱使顺手补全协议提到的其他条目，即使那不在本次授权范围内。

**候选原则**（记案例，暂不升级）：遇到"参照协议做定向修改"的任务，先把用户确认的改动点列成清单，写完后逐项核对 diff 只覆盖清单内容，协议里其他"建议性"条目不夹带进来。

---

### 案例 2：长文件 Write 被工具截断，靠事后 Edit 补救而非提前分段

**现象**：一次性 Write 245 行内容，实际只落地到约 50 行处（Success criteria 之前），是工具的分块限制起了作用，之后靠多次 Edit 补全剩余内容。

**根因**：系统提示已明确"超过150行必须主动分50行写入"，规划 content 时没有主动分段，让工具截断后才补救——规则已存在，是执行纪律没跟上，不是缺规则。

**候选原则**：无需新增，记案例即可——已有规则本身足够，问题在执行遵守。

---

### 案例 3：首轮修改漏了部署场景，被用户第二轮指出才补

**现象**：v1.1.0 优化 SKILL.md 时只验证了"agents 项目自身开发"场景下角色路径的正确性，没有检查这些路径引用在"copy 到 `.pb-agents/`"业务部署场景下是否仍成立，直到用户第二轮明确指出才补上（v1.2.0）。

**根因**：项目里已有明确协议记录了双环境路径差异（`README.md` §使用方法、`docs/memory-system.md` §六、`principles/meta/agent-design-protocol.md` §路径约定），但这些既有规则覆盖的是"角色文件自身的 data/ 路径"，没显式覆盖"Skill 文件里对角色文件路径的引用"这个场景。做边界问题澄清时，问题聚焦在 SKILL.md 内容缺口本身，没有主动检索项目里已有的部署协议文档来核对本次改动是否会踩到环境差异。

**候选原则**（**升级为原则候选**，三问过滤：①三个月后仍成立 ✓ ②换场景适用 ✓ ③一句话可执行 ✓）：修改会被 copy 到 `.pb-agents/` 部署的文件（Skill/角色文件）时，先搜索项目里"部署"/`.pb-agents` 相关的既有协议文档，确认改动涉及的路径引用在两种运行场景下是否都成立，不能只验证当前所在的开发环境。**用户本次选择先记案例，未升级，留待后续再次出现时评估。**

---

### 好做法：方案空间大时先提边界问题再设计（第 4 次独立出现）

**做了什么**：接到"分析并给优化方案"的请求后，没有直接产出方案，先读完 SKILL.md/workflow-pb.md/相关角色文件确认现状，再提三个具体边界问题（整体处理路线、角色映射粒度、内联速查表处理方式），等用户逐一确认后才动笔。

**为什么有效**：三个答案精确圈定了改动范围，实际 diff 基本没有走偏（案例1那次误加是唯一例外，且已自查撤销）。
