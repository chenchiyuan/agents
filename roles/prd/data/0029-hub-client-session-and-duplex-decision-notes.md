## 决策一：「断线拉起后两查回答四问」并入 F08（续接契约），**不**单立功能卡

比较过两个方案：

- **单立卡**：把效果#3 的裸判定（"断开任意时长 → 两次查询 → 四问作答"）单列成一张卡，直接承载该效果条目。
- **并入 F08（采纳）**：把它作为 F08「续接契约与一轮快照重建」的验收 2，与代次校验、固定流程、断开不产生结论性错误同卡。

采纳并卡的理由不是"少写一张卡"：单立卡的失败面**被 F05（实例投影四字段）与 F06（调用进展字段）完全蕴含** —— 两个字段面齐备且正确时，"四问能否答出"不会有独立于它们的失败方式。按本角色的原子粒度标准（"能被独立测试 **+ 独立交付**"），一个自身没有独立失败模式、失败时必然同时打红另外两张卡的对象，不构成独立交付单元，把它单立会让阶段 4 的 PR 切分出现一个"无论如何都要连同 F05/F06 一起做、验收却重复一遍"的伪独立单元。

而**续接契约本身**（代次校验拒绝假连续 + 固定流程 + 断开不产生结论性错误 + 恢复后可继续调度）是可以独立失败、独立交付的：它能全对而 F05/F06 全错（视图重建不了），也能全错而 F05/F06 全对（客户端拿到"假连续"）。因此合并后的 F08 里，验收 2 是**组合裸判定**（承接效果#3），验收 1/3/4 才是它自己的独立失败面。

**这是非显然的判断**：直觉上"对外可验收的头号效果"应该单立一张卡（先例：0028 的效果条目被拆成 F05/F06/F07 三张实报卡）。这次不这么做的关键区别是——0028 那三张卡各自对应**独立的后端绑定字段**（两个角色两种取值，失败互不蕴含），而本迭代的"四问"是把别人的字段面**再组合一次**，没有引入任何新的可失败对象。

## 决策二：订阅拆两张卡（F03 第一形态 / F04 第二形态）

D-7 把传输形态裁决为"**SSE 优先**；（UDS 长连接）为第二形态；**协议只约束语义**"——"优先"二字既可读作"先做、两个都做"，也可读作"第二形态可选"。

按"独立失败 + 独立交付"判断：**有 HTTP 订阅但长连接面上没有订阅入口**是一个可独立出现、可独立交付、可独立测试的缺口（事实 F-2 已核实层 B 现有 8 条方法中无订阅入口），因此拆开。同时在该卡尾部显式标注了这条张力（"若裁决为第二形态属后续迭代，请收窄本卡"），并把它列入报告疑问——**不在本阶段替主 agent 决定第二形态是否必交付**。

## 决策三：F18（过程契约卡）与 G01（保证项卡）各单立

两张卡都**不引入新的产品能力**，来源分别是 §执行方式约束（过程要求）与 §不做什么（既有面约束）。单立理由与体例先例一致：0028 的 F12（执行方式差距记录）、0018 的 F14~F16、0028 的 F13（既有面零改动）都把"过程契约 / 既有面保持"做成可独立验收的载体。

这**不算新增功能点**：demand.md 的这两节本身就是合同结论的一部分（与"做什么"并列），承接它们不等于发明需求。若把它们散落到各卡的边界里，D-13 的体感度量与"既有语义不回归"这两条就都没有可独立判红的载体——而它们恰好都是**能全绿通过所有新功能卡、却单独被破坏**的约束。

## 决策四：效果#3 第五问（"有无未取结果"）的口径差——不选边，按疑问上报

demand 效果#3 把"两次查询（`agents` + `calls`）"与五问绑在一句话里，但第五问的数据在取件面上，用两次快照查询答不出。本阶段按"四问由两次快照查询回答、第五问由取件面回答（第三次查询）"落卡，**不替主 agent 决定**是收窄效果#3 的措辞还是扩展快照面，也不写入 `deferred-demand-changes.md`（它不是需求层面的错误或变更，不改变任何 D 结论，只是措辞粒度差）。同类处理见 prd.md 疑问 2（"`calls get` 永远可查" vs 内存登记）/ 3（`notice` vs `confirmation`）/ 5（`reconnecting` 与既有状态取值封闭性）。
