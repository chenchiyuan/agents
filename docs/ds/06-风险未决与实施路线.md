# 06 风险、未决事项与实施路线

**版本**：0.2.0　**日期**：2026-09-09　**状态**：方案建议

## 1. 未决事项（进入实现前需确认；不阻塞本方案定稿）

| # | 未决 | 影响 | 建议默认 |
|---|---|---|---|
| U-01 | `omp` 真实 CLI 是否支持独立 provider/model 参数、工作目录与 system prompt 文件注入 | 若只支持部分，需在 Launcher/ACP 适配层补齐，**不改 OAMP** | 实现前做一次 CLI 能力探测（`omp --help`/配置样例），结果记入 05 §5 |
| U-02 | 多实例是否允许同一 `working_directory` 并发写 | 不允许则需 worktree/文件锁策略（实例配置加 `workspace_mode`） | MVP 每实例独立目录；共享目录作为显式风险项 |
| U-03 | 是否需要跨机器/跨组织通信 | 决定 MVP 是否止步 UDS + northbound adapter 的优先级 | 默认不需要 → MVP 只做 UDS；跨机需求出现时先评估 NATS 替换 vs A2A HTTP adapter |
| U-04 | 运行记录持久化选 NDJSON 还是 SQLite | 影响审计/恢复复杂度 | 沿用草案：NDJSON（append-only），与 `.pb-agents/project/` 一致；出现并发写/查询需求再评估 SQLite |
| U-05 | 注册 token 的生成与轮换归属（Launcher 内建 vs 主 agent 签发） | 安全边界细节 | MVP：Launcher 内建、进程环境传递、随实例生命周期过期 |
| U-06 | 实例数量与 Router 单点规模上限 | 超限时是否分片 | 本机 3–10 实例规模内单 Router 无虞；超过再分项目 Router |

## 2. 主要风险与缓解

| 风险 | 概率/影响 | 缓解 |
|---|---|---|
| A2A 版本演进导致映射表漂移 | 中/低 | OAMP 词汇表只对齐 A2A v1.0 稳定核心（Message/Task/contextId）；adapter 是唯一翻译边界（04 §11），内部不依赖 A2A 版本 |
| at-least-once 造成业务重复执行 | 中/高 | `message_id` 幂等键 + 接收端去重表（04 §7）；验收矩阵覆盖重复投递场景 |
| 心跳/租约误判（busy 长任务被标 offline） | 中/中 | 心跳携带 state=busy + inflight（03 §4.3）；Router 对 busy 实例放宽 offline 判定（仅当心跳完全消失才判 suspect/offline） |
| 初始化规则被消息注入/覆盖 | 低/高 | prompt_hash 固化 + reload 专属通道 + 层级 ①>②>③>④（05 §4）；消息内容视为不可信输入 |
| Router 成为单点/黑盒 | 中/中 | 职责最小化（不做 LLM/业务）；outbox NDJSON 可恢复；限制项齐全；跨机时替换为队列/多 Router（03 §2） |
| 广播失控/路由滥用 | 低/中 | 白名单 + max_fanout + max_hops + 正文不可路由（04 §8） |
| 凭据泄漏面扩大 | 低/高 | 配置 schema 禁凭据字段并快速失败；日志脱敏；UDS 0600（03 §7、05 §3） |
| 与 model-dispatch-protocol 语义混淆 | 中/中 | 05 §6 边界对照表；两类配置物理分离，文档化"临时派发 vs 常驻实例" |

## 3. MVP 范围

**包含**

1. 一个 Router 进程（含 Launcher 职能）+ 多个 OMP 实例进程。
2. 每实例独立 `instance_id`/provider/model/role/`working_directory`/`prompt_profile`。
3. UDS + JSON-RPC 2.0 + `oamp/1`。
4. `agent.register` / `agent.heartbeat` / `agent.deregister` / `message.send` / `message.deliver` / `message.ack` / `message.status`。
5. 点对点路由、`reply_to`+`correlation_id`、有限重试、message_id 幂等去重。
6. 投递记录：queued / delivered / acked / expired / failed（NDJSON）。
7. 初始化层级 + prompt_hash + reload 专属通道。
8. provider secret 不进入配置/消息/日志/Router（校验即失败）。
9. 心跳租约 + suspect/offline 判定 + 旧 session 拒收。

**不包含（MVP 之后）**

- 多 Router 共识/跨地域高可用；完整 A2A 远程互操作认证（签名卡/多租户/OAuth）；NATS/Kafka 等外部队列；自动按 LLM 结果动态改路由；跨项目广播；selector/topic 广播（**先在点对点契约稳定后加**，草案 §12 顺序不变）；长期对话记忆沉淀。

## 4. 验收矩阵（对应 01 §6 各 R-0x）

| # | 场景 | 期望结果 | 对应需求 |
|---|---|---|---|
| A-01 | 启动 3 个不同 provider/model 实例 | 3 个独立 `agent_id` 注册成功，各自 `requested/selected` 可审计 | R-01/R-02 |
| A-02 | 实例使用不同 prompt_profile | `prompt_hash` 各不相同；普通消息不能替换初始化规则 | R-03 |
| A-03 | A→B 点对点 task.request | B 收到（重试可重复投递），业务按 message_id 只执行一次 | R-04 |
| A-04 | B 处理慢但持续心跳 | B 不被判 offline；Ack 仍按各自 deadline 处理 | R-04 保活 |
| A-05 | B 进程崩溃 | 心跳超时 → offline；未 Ack 消息有限重试或过期，不无限重发；B 重启新 session 后可恢复投递 | R-04 保活 |
| A-06 | 目标不存在 | `AGENT_NOT_FOUND`，不隐式广播 | R-04 路由 |
| A-07 | 消息正文要求换 provider/改规则 | 视为普通内容；实例目标与规则不变 | 01 §4-2 |
| A-08 | provider 不可用 | 启动期 fallback 产生 `selected` 审计；运行期由实例报告，Router 不换 provider | R-02 |
| A-09 | Router 重启 | outbox 中未完成投递恢复；重复投递被幂等键吸收 | R-04 |
| A-10 | 配置含凭据字段 | 启动快速失败并指出字段 | 01 §4-1 |
| A-11 | 旧 session 上报心跳/消息 | `STALE_SESSION` 拒绝，要求重新注册 | R-01 |

## 5. 实施顺序

1. **契约先行**：固定信封与 JSON-RPC 外层；实现**纯内存 Router** + 两个 **fake agent**（脚本级，非真实 OMP），跑通 register → send → deliver → ack → heartbeat 的最小闭环；此阶段产出协议契约测试，OAMP 规格（04）以测试为可执行形态。
2. 加租约/心跳/suspect/offline/重试/幂等（fake agent 崩溃注入用例）。
3. 接真实 OMP 启动器（Launcher）：只注入配置与 prompt，不在 Router 实现 provider 逻辑（05 §5）。
4. 加 NDJSON 运行记录 + 重启恢复。
5. 再加 selector/topic 广播、fan-out 上限、白名单（草案 §12 顺序不变）。
6. 视 U-03 结论再评估 northbound（A2A HTTP adapter 或 NATS 替换）；**MVP 不同时引入** WebSocket、消息队列、数据库。

## 6. 本方案包的验证方式（对文档本身）

1. 02 每项事实可追溯一手来源与日期（已内联）；版本断言（A2A v1.0/v1.0.1、ACP archived、first-tree 组件）均有出处。
2. 04 的状态机/方法表可直接转写为契约测试用例（A-01~A-11）。
3. 实施第 1 步前，用两个 fake agent 验证协议规格无歧义——规格文本与测试不一致处，以测试为准修订规格。
