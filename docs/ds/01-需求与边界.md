# 01 需求与边界

**版本**：0.2.0　**日期**：2026-09-09　**状态**：方案建议

## 1. 需求来源

用户原始诉求三条 + 一条暗示约束：

| # | 用户需求 | 解读 | 隐含的可验证目标 |
|---|---|---|---|
| R-01 | 启动多个 omp 实例 | 不是并发子 agent 任务，是**多个常驻、可寻址**的 agent 运行时并存 | N 个实例同时存活，各自独立注册、独立可收消息 |
| R-02 | 每个实例指定 LLM provider（deepseek、gpt 等） | 实例级 model/provider 独立，互不影响 | 每个实例的 `requested/selected` 可审计，与其他实例无关 |
| R-03 | 每个实例注入初始化提示词，类似 agents.md，定义执行规则，每个 agent 可以不同 | 实例人格/规则 = 启动时固定注入的上下文，实例间不同 | 不同实例 `prompt_hash` 不同；普通消息不能覆盖 |
| R-04 | agent 之间消息投递、Ack 保活、任意路由 | 消息可寻址到任意 agent；投递需确认；通信双方需感知对方存活 | 任意两点可通信；丢消息有界；死实例被检出且不无限重发 |
| R-05（方法） | 遵循"标准的协议"（需调研） | 交付前先做协议选型研究 | 02 文档给出带来源的选型结论 |
| R-06（参考） | 参考 first-tree | 借鉴其"本机 daemon 连接 agent + 共享上下文注入"的拓扑价值 | 02 §7 记录借鉴点与不借鉴点 |

## 2. 系统形态一句话

> 一个本机 Router（`ompd`）负责注册、路由、投递、Ack 与生命周期；N 个 OMP 实例是独立进程，各自持有 provider/model/初始化规则，通过 UDS 接入 Router；agent 之间只通过 Router 转发消息，不直连。

## 3. 术语表

| 词 | 定义 |
|---|---|
| **OMP 实例 / agent 节点** | 一个独立进程。同一时刻有唯一 `session_id`，跨重启有稳定 `instance_id` |
| **instance_id** | 稳定逻辑身份，配置文件中声明，重启不变，消息寻址目标 |
| **session_id** | 单次进程运行的连接身份；重启必变；Router 用它判定"旧连接不得收新消息" |
| **OAMP** | OMP Agent Messaging Protocol。本包定义的、agent 间消息与生命周期的协议 v1（`oamp/1`） |
| **Router（ompd）** | 本机守护进程，负责 registry、route、relay、lease、持久化。只做通信，不做 LLM/业务 |
| **Launcher** | 负责按配置启动/重启 OMP 实例进程并注入初始化上下文的组件（MVP 内并入 Router 进程或主 agent） |
| **prompt_profile** | 指向实例初始化提示词文件的路径（可引用 role 文件、AGENTS.md 或自建规则文件） |
| **prompt_hash** | prompt_profile 内容的 sha256；随每次实例启动计算并上报 |
| **Agent Card** | A2A 概念；OAMP 的 `agent.register` 是其本地化变体（能力元数据 + 端点 + 会话） |
| **ACP（项目内）** | `model-dispatch-protocol` 定义的统一派发契约（`protocol: acp`），一次派发的语义边界；与外部同名标准无关 |

## 4. 非目标（本包明确不做）

1. **不做** provider 凭据管理：API key/endpoint/token 不进入 OAMP 配置、消息、日志、Router。认证仍由 OMP/宿主环境负责（沿用 `model-dispatch-protocol` 边界）。
2. **不做** 用消息改路由/改 provider：消息正文不得触发换 provider、换模型、换初始化规则。
3. **不做** Router 侧 LLM 会话管理：OMP 内部会话、重试、执行逻辑不因本协议改变。
4. **不做** 把 agent 对话沉淀为长期记忆/知识库（first-tree 的 Context Tree 是未来的 northbound 应用，不是 OAMP 职责）。
5. **不做** 多 Router 共识/跨地域高可用（MVP 单机单 Router）。
6. **不做** 无界广播与自然语言路由：广播必须显式（topic/selector）且有白名单与 fan-out 上限。
7. **不做** 伪 exactly-once：交付语义为 at-least-once + 接收端幂等。

## 5. 与非目标相邻、必须澄清的边界问题（进入实现前需用户拍板）

B-01 OMP 实例是否允许同一工作目录并发写入？若不允许，实例配置需补 worktree/文件锁策略（见 06 §1）。
B-02 是否必须跨机器通信？决定 MVP 传输是否止步于 UDS（见 06 §1）。
B-03 `prompt_profile` 与现有 role 文件（`roles/<role>/<role>.md`）与业务项目 AGENTS.md 的组装规则（见 05 §4 草案，需确认）。
B-04 外部 agent（非 OMP executor，如 codex CLI 实例）是否也接入 Router？本包先按 OMP executor 设计，接缝处保留 executor 字段。
