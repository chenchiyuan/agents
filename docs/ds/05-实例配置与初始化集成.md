# 05 实例配置与初始化集成

**版本**：0.2.0　**日期**：2026-09-09　**状态**：方案建议

## 1. 本文件回答

R-01（多实例）、R-02（实例级 provider/model）、R-03（实例级初始化提示词）如何落到配置与启动链上，且不破坏现有 `model-dispatch-protocol`（`agent-routing.yaml` + ACP 派发契约）与凭据边界。

## 2. 配置文件与路径

```text
.pb-agents/config/omp-instances.yaml     # 实例拓扑（本文件定义）
.pb-agents/config/agent-routing.yaml     # 既有路由/fallback（不变，见 model-dispatch-protocol）
.pb-agents/prompts/<instance-id>.md      # 实例初始化提示词（persona/规则）
.pb-agents/project/runtime/omp/          # 运行记录（Router/实例，见 03 §3）
```

`omp-instances.yaml` 与 `agent-routing.yaml` 同属 `.pb-agents/config/` 项目配置例外区：业务项目可维护；agents 安装/升级不得覆盖；非法配置快速失败，不回退默认值。

## 3. omp-instances.yaml schema

```yaml
version: 1

router:
  socket: .pb-agents/project/runtime/omp/router.sock
  heartbeat_interval_ms: 10000
  heartbeat_timeout_ms: 30000
  lease_ms: 30000
  ack_timeout_ms: 5000
  max_attempts: 3
  max_fanout: 8
  max_hops: 8
  max_message_bytes: 1048576

instances:
  - instance_id: dev-deepseek
    executor: omp
    provider: deepseek
    model: DeepSeek-V4.1-Flash
    fallback: [gpt]                       # 可选；启动前可用性降级，语义同 model-dispatch-protocol
    role: dev                             # 仅声明能力角色，不覆盖 role 文件职责
    prompt_profile: .pb-agents/prompts/dev-deepseek.md
    working_directory: .
    labels: [implementation, backend]
    capabilities: [message, task, stream]

  - instance_id: architect-gpt
    executor: omp
    provider: openai
    model: gpt-5
    role: architect
    prompt_profile: .pb-agents/prompts/architect-gpt.md
    working_directory: .
    labels: [architecture]

  - instance_id: verifier-gpt
    executor: omp
    provider: openai
    model: gpt-5
    role: verifier
    prompt_profile: .pb-agents/prompts/verifier-gpt.md
    working_directory: .
    labels: [verification]
```

字段规则：

| 字段 | 必填 | 规则 |
|---|---|---|
| `instance_id` | 是 | 稳定逻辑身份，跨重启不变；`^[a-z0-9][a-z0-9-]{0,63}$`；全局（项目内）唯一 |
| `executor` | 是 | 默认 `omp`；解析语义复用 model-dispatch-protocol |
| `provider` / `model` | 是/是 | 实例目标；启动前走能力检查与 `fallback` 链，产出 `selected` 审计 |
| `fallback` | 否 | 与 `agent-routing.yaml` 同语义：同 executor 内依次尝试；仅启动前生效 |
| `role` | 否 | 能力角色标签，寻址/审计用；不引入新 role 定义 |
| `prompt_profile` | 是 | 只读初始化提示词文件路径；`prompt_inline` 仅限测试且必须显式标记 |
| `working_directory` | 是 | 必须解析为项目内允许目录；**不可经消息动态修改** |
| `labels` | 否 | selector 路由元数据 |
| `capabilities` | 否 | 上报 Router 的能力列表 |

**禁止项**：任何 `api_key`/`token`/`password`/`authorization` 字段——配置校验检测即快速失败。provider 凭据由 OMP/宿主环境管理，配置只引用 provider 名，不引用 secret（DS-08）。

## 4. 初始化提示词（R-03 落地）

### 4.1 初始化上下文层级

实例启动时按序组装 system/developer 上下文：

```text
① 框架安全边界（不可被实例自身改写）
② prompt_profile 内容
   └─ 典型构成：role 文件要点 + 业务 AGENTS.md/执行规则 + 该实例专属 persona
③ 本次任务 brief（若由调度方启动即携带）
④ 后续经 OAMP 到达的普通 agent 消息
```

- `prompt_profile` 是 **② 的唯一入口**：既可指向自建 `.pb-agents/prompts/<id>.md`，也可由该文件 `include` role 文件与业务 AGENTS.md 片段（组装由 Launcher 完成并计算 hash）。
- 层间优先级：规则覆盖能力 = ①>②>③>④；消息内容永远在规则之下。

### 4.2 不可变性约束（承 04 §10）

1. prompt_profile 只在实例创建/重启时加载，并计算 `prompt_hash = sha256(组装后文本)`。
2. 运行期普通消息不能替换/删除它；变更唯一入口是 `control.reload_prompt`——执行后生成**新 session_id**、重新计算 hash、记录变更原因与操作者。
3. 实例回报自带 `instance_id` / `session_id` / `prompt_hash`，使"这条产出由哪套规则生成"可审计。
4. 初始化提示词不自动继承主 agent 会话；主 agent 只能通过明确 brief/消息传递任务上下文。

## 5. 启动链（与 model-dispatch-protocol / ACP 契约的关系）

```text
读 omp-instances.yaml
  → 逐实例：executor/provider/model 能力检查 + fallback（复用 model-dispatch-protocol 解析与审计）
  → Launcher 生成注册 token，注入进程环境
  → 启动 OMP 实例，注入 {provider/model 选择、working_directory、prompt_profile 组装文本}
  → 实例计算 prompt_hash → agent.register 到 Router
  → 进入 idle，等待 message.deliver
```

- 复用：`requested executor/model → fallback → selected` 的审计结构原样保留；OAMP 只在 **selected 之后**接管消息面。
- 明确不允许：消息临时替换目标 provider/model；agent 静默改他人初始化规则；投递失败自动切 provider；Router 变凭据代理。主 agent 要换模型 = 显式重启/重派实例，走既有 ACP 派发 + fallback 产生新的 `selected` 审计（承草案 §10）。

## 6. 与 model-dispatch-protocol 的边界对照

| 维度 | agent-routing.yaml（既有） | omp-instances.yaml（新增） |
|---|---|---|
| 语义 | 一次子 agent 派发的默认路由 | 常驻实例的拓扑声明 |
| 生命周期 | 派发一次 → 完成 | 注册 → 心跳 → 收消息（长驻） |
| 配置位置 | `.pb-agents/config/agent-routing.yaml` | `.pb-agents/config/omp-instances.yaml` |
| 覆盖关系 | 主 agent/子 agent/role 默认 | 实例级显式指定，实例是独立拓扑单元 |
| 共享 | executor 解析、fallback 语义、凭据边界、selected 审计 | 同左（复用） |

两者不合并：派发路由回答"临时叫一个子 agent 用什么模型"，实例拓扑回答"常驻哪些 agent、各自什么身份与规则"。一个 role（如 dev）可同时存在于两种语义下而不冲突——临时派发与常驻实例是不同协作形态。

## 7. 验证标准（本文件的落地检查）

1. 三个实例、三个 provider/model：各自 `selected` 独立可审计，互不影响（R-01/R-02）。
2. 不同 prompt_profile → 不同 `prompt_hash`；用 A 实例的消息无法改动 B 的规则（R-03）。
3. 配置含凭据字段 → 启动快速失败，报具体字段。
4. `working_directory` 越界/经消息修改 → 拒绝并审计。
5. reload_prompt 后 session_id 变化，旧 session 消息全部失效（STALE_SESSION）。
