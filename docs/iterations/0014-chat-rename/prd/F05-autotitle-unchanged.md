# F05：自动生成规则保持不变（回归约束）

**功能 ID**: F05
**来源**: `demand.md` A-5（自动生成规则不变）；决策 D-2（40 截断规则不变）；澄清 M-1（现状纠偏）/ M-4（前后半）；矛盾处理 C-4；效果 E-9、E-10；边界 N-3 / N-7
**迭代**: 0014-chat-rename

---

## 用户价值

手动改名不会把"新对话自动起名"这件事弄坏——自动标题还是老规矩（第一条消息说了什么就叫什么）；自己改过的名字也不会被后面的消息顶掉。

## 验收标准

> 本卡是**回归约束**：以下行为在本次迭代前后必须逐字一致。本卡不新增任何能力，只声明既有行为保持不变。

1. **新建对话标题仍按首条输入生成**：新建对话发送首条输入后，标题 = 该输入**去首尾空白后截断 40 字符**；若去空白后为空，则为「新对话」（A-5 / D-2 / M-1 / E-9）。判定：发一条超过 40 字符的首条输入，标题为去空白后内容的**前 40 个字符**；发一条全空白输入，标题为「新对话」。
2. **标题仍只在首次写入时生成**：同一对话的**后续输入不改变标题**——未手动改名的对话，其标题保持首条输入生成的结果（A-5 / E-9）。判定：同一对话发第二条、第三条消息，标题与第一条生成时逐字一致。
3. **`@agent` 前缀计入标题**：首条输入形如 `@agent 帮我看看这个问题` 时，标题取自该输入原文（含 `@agent` 前缀）去空白后截断 40 字符的结果（A-5 / N-3）。判定：发一条 `@agent` 开头的首条输入，标题以 `@agent` 开头。
4. **手动改名后再发消息，标题保持手动值**：手动把标题改成与首条输入完全不同的文本后，再发送新消息 → 标题**不被自动规则改写**，仍为手动值（A-5 / D-2 / C-4 / E-10）。判定：改名 → 发送一条新消息 → 读标题 = 手动值；该对话后续再多发几条消息，标题仍为手动值。
5. **手动 100 上限与自动 40 截断并存、互不影响**：自动生成路径仍按 40 截断（不使用手动的 100 上限）；手动编辑路径仍按 100 上限（不沿用 40 截断）（M-4 两条并存）。判定：自动生成的标题长度上限 ≤40；手动编辑可把标题改到 40~100 字符并保存成功。

## 边界（不包含）

- 不改**自动标题生成规则**的任何一条：40 字符截断、「新对话」兜底、以首条输入定标题、`@agent` 前缀计入、只在首次写入时生成（N-3）。
- 不做 **AI 自动重命名 / 智能标题生成**（N-7）——本迭代不引入模型调用、触发时机或成本相关的任何标题生成能力。
- 不含**手动改名本身**的交互、校验、只读边界与同步——分别为 F01 / F02 / F03 / F04。
- 不含既有自动生成**测试断言与文档**的改动（属阶段 3 与实现阶段的契约同步，见 AR-12 / AR-13；`demand.md` §3 已明确生成规则断言与"后续输入不改标题"契约**必须保持通过、不得修改**）。
