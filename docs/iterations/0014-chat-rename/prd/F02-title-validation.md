# F02：标题校验（trim、100 上限、拒绝空值并恢复原值）

**功能 ID**: F02
**来源**: `demand.md` A-2（校验四条）；决策 D-2；澄清 M-3 / M-4 / M-9 / M-10（相邻项）；效果 E-5、E-6；边界 N-3 / N-4
**迭代**: 0014-chat-rename

---

## 用户价值

名字既说得清、又被约束住——不会出现空的、只剩空格的、或者长到显示不下的标题；手滑留了首尾空格也会被清掉，但自己打的空格原样保留。

## 验收标准

1. **保存前去除首尾空白，内部空白保留**：保存时对输入做首尾去空白后再落定；内部空白原样保留；"空 / 全空白"以去首尾空白后为空来判定（A-2 / M-01）`[user_confirmed M-01]`。判定：输入 `"  季度复盘  "` 保存后标题为 `"季度复盘"`；输入 `"季度  复盘"` 保存后标题中间的两个空格不变。
2. **长度上限 100 字符**：手动标题最长 **100 个字符**，计数单位与既有自动生成的 40 字符截断**同一把尺子**（UTF-16 code unit，含 emoji / 组合字符等多单位字符按其所占单位数计）（A-2 / D-2 / M-4 / M-9 / E-6）`[user_confirmed]`。判定：恰好 100 单位的内容可保存成功；101 单位的内容不可保存成功。手动上限 100 与自动截断上限 40 **并存、互不覆盖**（M-4 后半，自动侧见 F05 验收 1）。
3. **超过 100 字符时的反馈形态 = 编辑框硬上限**：输入达到 100 字符上限后编辑框不再接受更多字符（不产生超长中间态，已输入内容不丢失；粘贴超过 100 单位的内容时自动截断到 100，不额外弹出超长错误提示）（M-07 / `demand.md` §7 P-2；2026-09-11 用户确认）`[user_confirmed M-07]`。判定：持续输入超过 100 单位时，框内内容停在 100 单位、不出现可提交的超长内容；粘贴超长内容同样停在上限、已输入内容不丢失；删除字符后可继续输入。
4. **空或全空白拒绝保存并恢复原值（不回退「新对话」）**：输入为空或全为空白时，保存被拒绝，标题**保持编辑前的原值**——既不是空串，也不是「新对话」（A-2 / D-2 / M-3 / E-5）。判定：对一条标题为「季度复盘」的对话，把输入清空（或只留空格）后保存，标题仍为「季度复盘」。
5. **拒绝后退出编辑态**：空 / 全空白被拒绝后，编辑框关闭，标题显示已恢复的原值（用户不需要再手动退出编辑）（M-02）`[user_confirmed M-02]`。
6. **同一组校验规则在保存的完整链路上生效（不依赖单一入口）**：trim、非空、≤100 三项规则在保存链路上统一生效——即使不经过详情区编辑框提交标题变更，非法标题（空 / 全空白 / 超长）也**不会被写入**，标题保持不变（A-2 / `demand.md` §6 I-6；2026-09-11 用户确认）。判定：以编辑框之外的方式提交空标题 / 全空白标题 / 101 单位标题，读取标题均仍为提交前的值。

## 边界（不包含）

- 不含**编辑交互本身**（点击进入编辑、预选、Enter / 失焦 / Esc 的触发与优先级）——那是 F01。
- 不含**只读边界**——那是 F03；本卡只规定"允许提交的内容"，不规定"谁可以提交"。
- 不含**同步与排序**——那是 F04。
- 不做**清空标题**（N-4）——空值一律被拒绝，不存在"无标题对话"。
- 不做**自动生成规则的任何改动**（N-3）——40 字符截断、「新对话」兜底、首条输入定标题、`@agent` 前缀计入，全部保持现状（见 F05）。
- 不做**标题内容过滤 / 敏感词 / 字符集白名单**（demand 未要求）——除长度与空白规则外，任何文本内容均被接受。
- 不做**标题格式规范化**（大小写、全半角、标点转换等）（demand 未要求）。

## 架构维度（阶段 3 已填，2026-09-11；详见 `architecture.md` §3.3 / §6.6 / §5.2）

- **AR-06 校验的执行落点与计数口径落实**：**服务端 = 唯一权威落点**——新增 `readTitle(value)` 加入 `persist.js` 既有的写口校验函数族（与 `readLimit` / `readOffset` / `readArchived` / `readTimestamp` / `readOptionalString` 同级同风格），并由写口 `renameChat({chatId,title})` **内建调用**：非字符串 ⇒ 抛「标题非法: 需为字符串（当前值 …）」；`value.trim()` 为空 ⇒ 抛「标题非法: 不能为空或全为空白」；`title.length > 100` ⇒ 抛「标题非法: 长度需 <= 100（当前 N）」；web 路由把该异常翻译为 **400**（与 `listChats` 非法参数转 400 同款）。**为什么放在写口内部（而不是只在 web 路由里）**：验收 6 要求"同一组规则在保存的完整链路上生效、不依赖单一入口"——写口自校验让**任何**未来的调用方自动继承三条规则；这正是本模块对 `limit` / `archived` / `state` 的既有做法。**前端**只承担硬上限与即时反馈：`maxlength="100"`（AR-07）+ `commitTitle()` 内的 `next === '' || next === chat.title` 早退（拒空 / 未改动**不发请求**，只是省一次往返；**校验仍以服务端为准**，且前端提交的是**原始输入**、由服务端完成 trim 与判定）。**计数口径 = `String.length`（UTF-16 code unit）**，与自动侧 `text.trim().slice(0, TITLE_MAX)` **同一把尺子**（`demand.md` D-5；实测 `'😀'.length === 2`），零新计数代码；trim 用同一个 `String.prototype.trim`（同时清半角 / 全角 U+3000 / NBSP，`demand.md` D-9 的"内部空白保留"自然成立）。**40 与 100 并存**：新增常量 `TITLE_MAX_MANUAL = 100`，与既有 `TITLE_MAX = 40` **互不引用、互不覆盖**（自动生成语句一字未改，见 F05 / AR-12）。**未采用的替代**：给 `chats.title` 加 `CHECK(length(title) BETWEEN 1 AND 100)` —— SQLite 无法用 `ALTER TABLE` 加约束（须整表重建），而"唯一写入点已内建校验"已等价覆盖，且本迭代的边界是零数据层变更。
- **AR-07 超长输入的即时约束承载**：由 `index.html` 的 `maxlength="100"` **声明式**承载——达到上限后浏览器不再接受更多字符（粘贴超长自动截断），**不产生超长中间态、不丢失已输入内容**，删除字符后可继续输入；而 `maxlength` 与 `readTitle` 使用**同一计数单位**（UTF-16 code unit）⇒ 不需要 JS 计数、不需要 `input` / `keydown` 拦截、**不设额外错误 UI**（`demand.md` D-6 明文"不设额外错误 UI"）。服务端 400 是兜底：若 UA 在多 code unit 字符 / IME 组合态上让 >100 单位通过，非法值**仍不会落库**（验收 6 成立）。
