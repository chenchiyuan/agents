**说明（本迭代"用户可见行为"是什么）**：本迭代的交付物是 ① 一个可执行的 SDK（**同一份代码**两种消费方式：CLI + 可 import 的库）② 一份 skill 文本。因此每张卡的验收标准都可以直接在终端里被观察到（stdout / stderr / 退出码 / 是否挂起），或通过**直接阅读 skill 文件文本**核查，不需要读实现源码。

**本迭代的"用户"**：需要与 hub（oamp）协作的**消费方**三类——① shell 前的开发者 ② Node 侧程序 ③ 被 skill 引导的 agent。验收标准一律写成"**谁、在什么条件下、看到什么**"。

**术语口径**：验收标准与边界一律使用**产品语言**——不出现模块名、函数名、类名、字段名、内部存储结构、语句写法。**措辞例外**（均为 `demand.md` 已确认的产品对象标识、用户原话 / 裁决用词，或 E1~E4 的**裸判定原文**，保留可追溯性）：① `API.md`（唯一规范真源，A-4）；② "21 条接口 / 8 个 JSON-RPC 方法"（A-2 / W2 原文）；③ 退出码 `0 成功 / 1 业务失败 / 2 用法错误 / 3 连接失败`、`--human`、`--wait <ms>`、默认 JSON stdout（B-2 / B-3 / C-2 / W4 原文）；④ 8 个方法名 `agent.register` / `agent.heartbeat` / `agent.deregister` / `message.send` / `message.ack` / `router.status` / `router.task_get` / `router.task_list`（W2 原文）；⑤ 既有 CLI 命令名 `router` / `agent` / `status` / `web` / `cluster` / `task`（W2③ 的封装对象，`仓库事实`：`oamp/src/cli.js`）；⑥ `truncated` / `entries[]`（`API.md` 既有字段，C-A 口径收窄的对象）；⑦ 落点 `oamp/`、".claude/skills/"（B-1 / D-1 原文）；⑧ `dependencies: {}` / `engines.node >= 22`（§3 原文）；⑨ NDJSON（B-3 原文）。
