# F11 · `doctor` 契约自检（对着运行中的 hub 校验 `API.md`）

**功能 ID**: F11
**来源**: `demand.md` 第二段 §1 **W5**（`user_confirmed`：A-4 "`API.md` 是真源；SDK 是薄封装 + 契约自检"）；§4 **E2**（自检可判真假的裸判定原文）；§4.6-B3 的坑（写操作端点不可直接探）
**迭代**: 0025-hub-sdk-and-skill
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: `oamp/API.md` 的 21 条接口清单（W2①）与 Router 的 8 个方法（W2②）——自检的比对基准

---

## 用户价值

接口面**悄悄改了能被当场发现并点名**——不用等消费方踩坑才发现"文档和实现早就不是一回事了"。

## 验收标准

1. **自检能力存在且对着运行中的 hub 执行**（W5 / A-4）：存在一个自检入口；对**运行中**的 hub 执行时，逐项给出结果并给出依据（依据能指认到具体的接口 / 方法）。
   *判定*：hub 运行中执行自检 → 输出逐项 `pass` / `fail` 与依据，不出现"一片绿但说不出依据"或"只报总结果"的形态。
2. **制造漂移即转 fail 并点名**（E2）：有人在 `API.md` 里改掉一个端点路径后重跑，自检**必须转为 fail 并指认该端点**。
   *判定*：做一次"制造漂移 → 重跑"的对照，观察是否由 pass 转 fail 且点名。〔判定方式逐字取自 `demand.md` E2 的裸判据〕
3. **自检无写副作用**（§4.6-B3 的坑，**MI-02**）：自检全程**不对 hub 做写操作**，不改变其状态（不产生新对话 / 新调用 / 新确认项等后果）。
   *判定*：自检前后对照 hub 的可观察状态（对话清单、调用 roster、在途确认项）→ 无新增。
4. **未漂移时结果稳定**（W5）：接口面与文档一致时，连续两次自检给出同一结论（不出现随机 pass/fail）。
   *判定*：连跑两次自检 → 逐项结论一致。
5. **自检的对象面与真源一致**（W5 / A-4：`API.md` 保持唯一真源）：自检比对的是**文档与运行中的接口面**，不引入第二份 schema（SDK 侧不自带一份需要同步维护的接口定义）。
   *判定*：改动 `API.md` 即影响自检结论（验收 2 已含）；且不存在"改了文档但 SDK 侧另有一处定义没改"的情形。

## 边界（不包含）

- 不含**校验判据与只读端点范围的具体选择**（对着哪些端点、以何种方式校验、写操作端点如何处置）→ `[架构待填]` T-02。
- 不含"自动修复漂移 / 自动更新文档"——未要求即不做（A-4 只要求自检）。
- 不含 `API.md` 自身内容的改动——**N1** → [G01](G01-hub-interface-unchanged.md)。
- 不含把自检做成常驻服务 / 定时任务——未要求即不做。
- 不含自检在 hub 不可达时的行为（→ [F08](F08-disconnect-degradation.md) 的统一降级）。
- 不含自检入口在子命令结构上的拼写 → T-01。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-02 · 校验判据与只读端点范围**（§5.5 全表）：
  - **R1 清单比对**：文档侧 = `oamp/API.md` §3 的 21 行（`<param>` 机械归一为 `:param`）；运行侧 = **既有** `GET /api/docs` 的 `routes[]`（每次请求从路由登记现算）；**双向**比对（文档有运行无 ⇒ 登记缺失；运行有文档无 ⇒ 文档未覆盖）；
  - **R2 只读可达性**：对 **9 个非流式 GET 端点**各发一次空参 GET，判定"响应**不是**路由兜底"（兜底形态 = `404` + `error: "not found: <方法> <路径>"`）；
  - **R3 UDS 方法存在性**：对 8 个方法各发一次"参数非法 / 未注册 / 只读"探针，判定响应**不是** `-32601 METHOD_NOT_FOUND`（探针逐条见 §5.1 层 B 表）。
- **写操作端点的处置（验收 3 / MI-02）**：**8 条 POST 一律不探**；4 条 SSE 也不探（探测会建立长连接，存在性由 R1 覆盖）—— 21 条无一静默跳过，每条都有 `pass`/`fail`/`skip（附理由）`。R3 的探针全部落在"**参数校验先于副作用**"或"只读方法"上（`src/router.js:109-113`（register 校验）、`:161-184`（heartbeat 未注册静默）、`:186-199`、`:201-204`、`:348-351`、`:379-405` 已逐条核对）⇒ **零状态改变**。
- **T-01 · 入口拼写**：`hub doctor [--human]`（库面 `hub.doctor.check()`）——单一自检面，不是编排命令。
- **验收 2（E2）**：改 `API.md` 任一路径 ⇒ R1 文档侧集合变化 ⇒ 该行转 `fail` 并点名端点 + 打印期望/实际。**验收 4**：三段判据均不依赖时间 / 随机 / 顺序（R1 为集合比对，R2/R3 为确定性探针）⇒ 连跑两次结论一致。**验收 5（无第二份 schema）**：只读 `API.md` + `GET /api/docs`，SDK 侧不存第二份端点定义 / 字段 schema。
- **hub 不可达时**：R1/R2 立即降级为 F08 的统一错误（退出码 3），不半跑。
- **入口的层归属**：`hub doctor` 是 SDK 的**第四个顶层入口**（`api` / `uds` / `cli` 之外的**自检面**）——它不对应单一端点 / 单一方法 / 单一条既有命令，故**不参与 F14 验收 1 的分层判定**；在 skill 的子命令清单里单列并标注"自检（不属于三层封装）"（`../architecture.md` §3.3 P-4 / §5.1）。
