## 用户价值

同一段 skill 文本，**在哪台机器、哪个目录、哪个宿主里都找得到 SDK**——不会因为我恰好不在某个目录而失效。

## 验收标准

1. **模板存在且形态正确**（W7 / C-3）：skill 中给出"**调用方自行解析仓库根 + 绝对路径**"的入口定位模板——模板以通用形式表述（如何求得仓库根 + 如何拼出绝对路径），**不含任何本机绝对路径字面量**。
   *判定*：通读 skill → 存在该模板；正文中检索不到形如 `/Users/...`、`/home/...` 的本机路径字面量。
2. **不依赖 cwd**（W7 / C-3）：按模板实例化后，从**仓库以外的任意目录**执行该命令，SDK 依然被找到并正常执行（结果与在仓库内执行一致）。
   *判定*：`cd` 到仓库外（如系统临时目录）执行模板实例化后的命令 → 命令正常完成（不出现"找不到入口"）。
3. **模板不要求前置切目录**（W7）：模板不含"先 `cd` 到仓库再执行"这类前置要求——定位靠路径解析而非工作目录。
   *判定*：按模板照做时不需要任何 `cd` 前置即可执行成功。
4. **不写死机器相关值**（W7 / C-3）：正文不依赖 `~` 展开、不依赖环境变量前置、不依赖某个固定端口以外的本机特有值来完成定位。
   *判定*：通读定位段 → 定位步骤只用"仓库根 + 相对位置"表达；`~` / 环境变量前置在定位段中不出现。
5. **三种宿主下同一模板都成立**（W7 / E4）：模板在 ①shell ②Node `import` ③另一个 agent（经 shell 调用）三种宿主下都能定位到入口，且定位后得到一致的结果（退出码与 JSON 结构一致）。
   *判定*：三处各按模板各执行一次 → 均能定位并得到一致结果。〔跨宿主判据取自 `demand.md` E4〕

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-05 / T-06 · 模板中的落点**：入口定位模板 = ① **解析项目根**（调用方自行提供其项目的绝对根路径，**不由 cwd 推导**）② SDK 入口 = `<项目根>/oamp/bin/hub.js`（CLI 面）/ `<项目根>/oamp/sdk/index.js`（库面）③ 调用 = `node "<项目根>/oamp/bin/hub.js" <层> <子命令> [选项]`。**skill 的"引用"与"调用 SDK"共用同一条模板**，不会漂移。
- **cwd 无关（验收 2/3/4）的实现基础**：SDK 内部一切路径按 `import.meta.url` 从**模块位置**推导（`BIN` / `API.md` / 包根 —— 与既有 `src/config.js` 的 `PKG_ROOT`、`src/cluster.js` 的 `BIN` 同口径，L2-11）；模板不含 `cd` 前置、不含 `~`、不含环境变量前置、不含本机路径字面量。
- **模板实例化后与运行位置无关**：入口是绝对路径 ⇒ 从仓库以外的任意目录执行结果一致（验收 2）；不需要 `npm link` 或任何安装动作。
- **三宿主（验收 5）**：同一模板在 shell / Node `await import('<项目根>/oamp/sdk/index.js')` / 另一 agent 经 shell 调用三处均成立，且结果一致（退出码与 JSON 结构 —— E4 的判定方式）。
