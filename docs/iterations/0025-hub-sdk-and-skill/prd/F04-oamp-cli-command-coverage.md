# F04 · oamp CLI 既有命令 1:1 封装（零语义变更）

**功能 ID**: F04
**来源**: `demand.md` 第二段 §1 **W2③**（`user_confirmed`：A-2）；**W3**（严格 1:1）；§2 **N4**（封装 CLI 运维命令时零语义变更）；§4.4 **C-B**（划界：只暴露既有命令、不迁移能力）
**迭代**: 0025-hub-sdk-and-skill
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: oamp 既有 CLI 命令面——`router` / `agent` / `status` / `web` / `cluster` / `task` 各命令及其既有子命令（`仓库事实`：`oamp/src/cli.js`、`oamp/README.md`）

---

## 用户价值

启停集群、看集群状态这些既有动作也能从 SDK 走——而且行为和以前**一模一样**，不会因为换了入口就悄悄变样。

## 验收标准

1. **既有命令面逐条可达**（W2③ / W3）：oamp CLI 的既有命令各有一个可寻址入口，对应关系能被逐条列出（**一份"既有命令 → SDK 入口"对照清单**）。
   *判定*：把对照清单与 CLI 自身的命令面逐条比对 → 双向无缺项（不遗漏既有命令、不出现 CLI 没有的新命令）。
2. **零语义变更**（W2③ / N4 / C-B）：同一动作经 SDK 入口执行，与**直接执行 CLI 命令**的结果一致——不新增参数默认值、不改写命令行为、不改变启停与现场。
   *判定*：挑取若干既有命令（至少含一条启停类、一条只读类）分别走两种入口 → 输出、退出结果、现场变化一致；不出现"换入口后行为不同"。
3. **既有命令的只读与写操作各自保持原样**（N4）：只读命令不产生副作用；写命令产生的后果与 CLI 直跑一致。
   *判定*：执行一条只读命令 → 集群与实例状态零变化；执行一条周期性任务类命令 → 后果与 CLI 直跑相同。
4. **入口的定位与调用契约一致**（W4）：既有命令的入口同样遵循统一调用契约（输出形态 → [F05](F05-json-output-and-human-flag.md)；退出码 → [F07](F07-exit-code-semantics.md)；不可达 → [F08](F08-disconnect-degradation.md)）。
   *判定*：对一条会失败的命令走 SDK 入口 → 观察到与统一契约一致的输出与退出码。

## 边界（不包含）

- 不含新增任何 agent 生命周期能力（守护 / 自愈 / 自动重试拉起）——**N3** → [G02](G02-lifecycle-boundary-preserved.md) 验收 3。
- 不含把 agent 启停能力搬进 hub 的 HTTP 面——**N4** → G02 验收 1。
- **不含改变既有命令的语义**（含新增参数、改变默认值、改变输出结构、改变现场处置）——N4。
- 不含 Web 接口面（→ F02）与 UDS 方法（→ [F03](F03-router-uds-method-coverage.md)）。
- 不含带业务语义的高层编排命令（如把多次启停串成 `cluster up` 之外的编排）——**N5**。
- 不含既有命令在子命令结构上的拼写 → `[架构待填]` T-01；不含库 API 表达 → T-03。
- 不含 CLI 自身的行为改动（既有 CLI 保持原样；本迭代只新增接入面）。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-01 · 层 C 的子命令**（§5.1 层 C 全表）：前缀 `cli`，11 条叶子命令 —— `cli router start` / `cli agent start <instance-id>` / `cli status` / `cli task send|status|list|watch` / `cli web start` / `cli cluster up|down|status`（= 既有 6 个顶层命令展开后的**全部可执行形态**）。
- **实现 = 子进程透传**（L2-1）：`spawn(process.execPath, [<包根>/bin/oamp.js, ...args], { stdio })`；`hub cli` 之后的 token **不解析、不重排、不补默认值**。
- **零语义变更（验收 2/3）由结构保证**：同一入口、同一进程模型、同一 TTY 语义 ⇒ 输出 / 退出结果 / 现场与直跑一致；`router start` / `agent start` / `web start` / `task watch` 等长驻命令**不劫持调用方进程**（进程内 import 方案会让它们占用调用方进程，且与 F09 无状态相冲）。
- **契约口径（验收 4）**：stdout/stderr 继承（CLI 面）或捕获为 `{ exit_code, stdout, stderr }`（库面）；退出码**透传**（既有 `0/1/2` ⊂ 四类分类表），**不重分类** —— 这一收窄已在 `../architecture.md` §3.3 **P-2** 登记待主 agent 拍板（理由见该节；若要求 cli 层 JSON 化，将与验收 2 直接冲突，须二选一）。
