# F09 · CLI 无状态（不跨调用缓存）

**功能 ID**: F09
**来源**: `demand.md` 第二段 §1 **W4**（`user_confirmed`：B-3 "CLI 无状态"）；§2 **N9**（不做跨调用状态的本地缓存 / 续查）；§4.4 **C-D**（无状态 ↔ 长任务：阻塞取终态即"一次调用内持有"）
**迭代**: 0025-hub-sdk-and-skill

---

## 用户价值

每条命令都是**独立的一次调用**——顺序怎么排、两个终端同时跑、隔多久再跑，都不会打架，也不用担心本地留了什么过期状态。

## 验收标准

1. **跨调用不留可复用的本地状态**（W4 / B-3）：命令执行**不产生**供后续命令读取的状态；想知道什么就再问一次 hub。
   *判定*：连续执行同一只读命令两次 → 两次各自独立取得结果（第二次不因第一次而走本地快照）；把两次执行之间的时间拉长或缩短，结果不变。
2. **续查靠重新调用而非本地记忆**（W4 / N9）：取调用结果 / 取过程记录这类动作，在**独立的新进程**中执行即可得到结果，不依赖此前任何调用的上下文。
   *判定*：在**两个互不相干的终端**里：终端 A 发起一次调用（不阻塞取终态）→ 终端 B 用调用标识直接取该调用 → B 能取到（B 未参与 A 的调用）。〔观测口径见 MI-03〕
3. **并发执行互不影响**（W4 / B-3）：同一命令在两个终端同时执行，各自结果正确，不出现互相覆盖 / 串结果。
   *判定*：两个终端同时执行同一命令 → 两边输出均为完整正确的结果（无半截、无互相污染）。
4. **无"续订"式的隐式状态**（N9）：不做"上次没看完、这次接着看"的本地续查能力（订阅断开后的续订属明确不做项）。
   *判定*：断开一次订阅后再起一次订阅 → 只得到此后的事件（本地不留断点、不补发）。

## 边界（不包含）

- 不含**跨调用状态的本地缓存 / 续查**——**N9**（断点续订、进度续传、结果快照皆不做）。
- 不含"阻塞取终态"的时限（→ [F10](F10-wait-timeout-limit.md)）：一次调用内持有 ≠ 跨调用持有（C-D）。
- 不含状态载体形态的选择 → 无待填项（本卡只钉"不产生跨调用状态"这一可观察行为，不预设任何载体）。
- 不含订阅的断线重连 / 不补发语义（属接口面既有语义 + N9；形态面见 → [F06](F06-subscription-ndjson-stream.md)）。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **架构维度**：**无待填项**（本卡为纯行为约束：不产生任何跨调用状态载体）。
- **落定（与本卡直接相关的实现约束）**：SDK **零本地写入、零全局可变状态** —— `createHub()` 每次返回新对象；层 A 每请求建立并关闭连接、层 B 每会话由调用方显式 `close()`、层 C 每命令一个子进程；订阅断开后不补发、不落断点（不补发本身亦是 `API.md` §1.2 的既有语义）。见 `../architecture.md` §5.2 规则 4 / §8 C8。
- **MI-03 观测口径的承载**：验收 2（互不相干的新进程可直接续查）与验收 3（两端并发互不影响）由上述结构保证，并由 `test/sdk-cli-contract.test.js` 的"独立进程 + 并发"用例固化（§10 T4）。

## 越界自查

- **未做技术选型**：未规定是否写任何文件、写在哪里、用何种机制——只钉"跨调用无可复用状态"这一行为。
- 验收 2 的"两个互不相干的终端"是**可观察手段**（判真假不依赖实现），未预设实现结构。
- 未把"无状态"扩大解释为"不落任何日志 / 不产生任何输出"——那会越过 B-3 的原意且无法验收。
