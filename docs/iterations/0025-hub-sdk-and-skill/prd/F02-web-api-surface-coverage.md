## 用户价值

接口文档里写明的每一条能力，都能被直接调用到——不必再临场拼 HTTP 请求、不必再自己解析响应。

## 验收标准

1. **21 条逐条可达、无遗漏、无自发新增**（W2① / W3）：`API.md` §3 清单里的**每一条**接口都有一个对应的可寻址入口；入口与接口的对应关系能被逐条列出（**一张 21 行的对照清单**，每条一一对应）。
   *判定*：把对照清单与 `API.md` §3 的 21 行逐条比对 → 双向无缺项（清单里不出现清单外的接口）。
2. **语义原样透传，不代做跨端点语义**（W3 / C-1）：不合并端点、不拆分端点、不在调用侧重写业务语义；**特别地，`truncated` 的正文重建不由 SDK 代做**（C-A 的口径收窄）。
   *判定*：对同一次调用分别走"接口文档示例"与"SDK 入口" → 拿到的结果体字段与取值一致；`truncated` 为真的场景下，SDK 侧得到的仍是**标记为截断的那份结果**（而非一份被拼好的全文）。
3. **服务端错误对消费方可见**（W4 / B-2 的"业务失败"面）：上游返回的错误原文与其错误标识（错误体里的 `code` 一类字段）**不被吞掉、不被改写**，消费方拿得到。
   *判定*：构造一次服务端错误（如请求一个不存在的对象）→ 输出的 JSON 里能看到服务端给出的错误标识；该情形的成败判定另见 [F07](F07-exit-code-semantics.md)。
4. **SSE 类接口同样可达**（W2① / W4）：清单中的订阅类接口（含按对话 / 按调用两个作用域）各有可寻址入口；它们**输出的形态**见 [F06](F06-subscription-ndjson-stream.md)。
   *判定*：逐条执行订阅类入口 → 命令启动即建立订阅并持续输出（不立即退出、不报"未实现"）。
5. **派发闭环可被完成**（W3 的"覆盖派发闭环"口径 / E1 的 ①②③ 类操作）：以 SDK 子命令组合，可完成"发起一次调用 → 取到终态 → 取到过程记录"这一闭环，**全程不出现手写 HTTP**。
   *判定*：按顺序执行三步并由消费方记录所用命令清单 → 清单里不出现 `curl`、socket 手写、自建 HTTP 客户端。

## 边界（不包含）

- 不含 Router UDS 的 8 个方法（→ [F03](F03-router-uds-method-coverage.md)）与 oamp CLI 命令（→ [F04](F04-oamp-cli-command-coverage.md)）。
- **不含 SDK 代做任何跨端点语义**：`truncated` 正文重建、分页续取、批量编排、跨调用的状态保持一律不做——**W3** / **N5** / **N9**；"截断恢复"的可照做形态由 skill 的序列文本承载（→ [F12](F12-hub-skill-three-sections.md) 验收 3）。
- 不含带业务语义的高层编排命令（如 `dispatch` / `await` / 工作流专用命令）——**N5**；子命令清单中不得出现跨端点编排命令（→ [F14](F14-layered-command-structure.md) 验收 3）。
- 不含跨机接入 / 鉴权——**N2**（`API.md` §1.3 既有边界：仅 `127.0.0.1`、零鉴权）。
- 不含订阅类命令的输出形态（→ F06）、退出码语义（→ F07）、不可达时的降级（→ F08）。
- 不含每条入口的**具体拼写**与所在命名空间 → `[架构待填]` T-01；不含库 API 表达 → T-03。
- 不含 `API.md` 自身的内容与接口路径（**N1** 要求其零变更 → [G01](G01-hub-interface-unchanged.md)）。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-01 · 层 A 的子命令**（§5.1 层 A 全表）：前缀 `api`，21 条逐条 1:1 —— `api agents` / `api chats list|get|close|archive|activate|rename` / `api messages send` / `api stream chat|events|calls|call` / `api docs` / `api projects list|create` / `api calls create|list|get|transcript` / `api confirmations list|decide`。flag 名由 `API.md` 字段名**机械推导**（`_` → `-`）；路径参数走位置参数；必填性 / 枚举不在 SDK 侧重实现（交服务端判）。
- **T-03 · 层 A 的库 API**（§5.2）：`api.agents(q)` / `api.chats.*` / `api.messages.send(body)` / `api.stream.*`（返回异步可迭代的 `{event, data}`）/ `api.projects.*` / `api.calls.*` / `api.confirmations.*`；响应体**原样**返回。
- **21 行对照清单（验收 1）的产出方式**：`sdk/surface.js` 的层 A 表逐条导出，由 `test/sdk-surface.test.js` 与 `API.md` §3 解析结果**双向比对**（无缺项、无多出项）。
- **不代做跨端点语义（验收 2 / W3）**：每条入口只发一次请求；`truncated` 的正文重建 **不由 SDK 代做**，"截断恢复"= `api calls get <call_id>` + `api calls transcript <call_id>` 的组合（消费方拼接，序列固化在 skill 文本，见 F12）。4 条 SSE 入口的输出形态见 F06（NDJSON）。
- **服务端错误可见（验收 3）**：上游 `{error, code}` **原样**进入 stderr 的错误对象（层 A 另带 `http_status`），不改写、不吞掉（§5.3 / §5.4）。
