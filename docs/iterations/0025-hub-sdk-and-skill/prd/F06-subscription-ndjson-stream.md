# F06 · 订阅类命令的前台 NDJSON 流

**功能 ID**: F06
**来源**: `demand.md` 第二段 §1 **W4**（`user_confirmed`：B-3 "订阅用前台 NDJSON 流，可管道截断"）；§4 **E1** 的 ④ 类操作（订阅事件）；§4.4 **C-D**（无状态 ↔ 长任务：一次调用内持有）
**迭代**: 0025-hub-sdk-and-skill
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: `API.md` §4 的事件流（按对话订阅 / 全局订阅 / 调用面订阅，三类事件）——订阅对象来自既有接口面，本卡只钉 SDK 侧的输出形态

---

## 用户价值

事件是**流出来的**——一边发生一边到我手上，管道一断就干净结束；不会等在那里假装成一次普通请求。

## 验收标准

1. **订阅是前台流，不是一次性返回**（W4 / B-3）：执行任一订阅类命令后，命令**持续运行并逐条输出**新到事件（不打印一次就退出、不静默等待到超时）。
   *判定*：起一个订阅命令，另一侧触发一次会产出事件的动作 → 订阅侧在事件发生后不久逐条打印出新事件。
2. **流的形态是 NDJSON**（W4 / B-3）：每一行是一条可独立解析的 JSON（行分隔，不是一整份大 JSON 数组）。
   *判定*：把订阅输出喂给逐行解析器 → **每一行**单独可解析为 JSON 对象。
3. **可被管道截断，且截断后进程结束**（W4 / B-3）：下游管道关闭（如 `head` 取够若干行）时，订阅命令随之结束，不残留挂着的进程。
   *判定*：把订阅输出接一个只取少量行的下游 → 命令自行退出；随后查进程列表**无残留**。
4. **事件作用域可被选择**（E1 的 ④ 类操作 / `API.md` §4）：按对话 / 按调用 / 全局三种作用域各有可寻址入口，输出同一种 NDJSON 形态。
   *判定*：三种作用域各起一次订阅 → 各自只输出其作用域内的事件，输出形态一致。

## 边界（不包含）

- 不含**跨调用的续查**：断开的订阅不补发、不本地排队、不落本地状态——**N9**（"事件不补发"是 `API.md` §1.2 的既有语义，本迭代不补偿）。
- 不含订阅输出的**字段形态**（行内字段名与结构）→ `[架构待填]` T-04。
- 不含把事件流包装成回调 / 事件订阅对象之类的库侧形态 → T-03。
- 不含对流的语义加工（聚合、去重、进度百分比等）——W3 / C-1 的"不代做跨端点语义"。
- 不含退出码语义（→ [F07](F07-exit-code-semantics.md)）与不可达时的降级（→ [F08](F08-disconnect-degradation.md)）。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-04 · NDJSON 行形态**（§5.3 / L2-8）：每帧一行 `{"event":"<事件名>","data":<SSE 帧 data 原样>}` + 换行 —— 与 `API.md` §4 的事件表**逐字可对照**，零信息损失、每行独立可解析（验收 2）。
- **读取与写出**：`sdk/http.js` 按 SSE 帧切分（空行分隔），取 `event:` / `data:`，**忽略 `: keepalive` 注释行与 `retry:` 帧**；每帧 `process.stdout.write(行)`（行分隔，不是一整份 JSON 数组）。
- **管道截断（验收 3）**：stdout 关闭 → 写失败（`EPIPE`）→ 结束进程、退出码 `0`（截断属预期用法 B-3）；**不做** SIGPIPE 特判、**不做**自动重连（N9）。
- **作用域（验收 4）**：4 条入口形态一致 —— `api stream chat <chat_id>`（#9）/ `api stream events`（#10）/ `api stream calls --chat-id <chat_id>`（#16）/ `api stream call <call_id>`（#17）。
- **不加工流内容（C-1）**：不做聚合 / 去重 / 进度换算，帧的 `data` 原样下行。
