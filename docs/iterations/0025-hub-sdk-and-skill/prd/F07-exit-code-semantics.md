## 用户价值

脚本里靠**退出码**就能判成败，不用去猜输出文本里的措辞——别人写的自动化也照这个约定接就行。

## 验收标准

1. **成功 = 0**（W4 / B-2）：命令正常完成时退出码为 `0`。
   *判定*：执行一条成功的只读命令 → 观察退出码为 `0`（**三种宿主**：①shell ②Node `import` ③另一个 agent 经 shell 调用各处一致）。〔跨宿主判据取自 `demand.md` E4〕
2. **业务失败 = 1**（W4 / B-2）：命令**跑通了但结果是失败**（如服务端返回错误、被调对象不存在）时退出码为 `1`，且错误信息可读。
   *判定*：构造一次服务端错误 → 退出码 `1`；stderr 有描述性信息；**不出现堆栈**。
3. **用法错误 = 2**（W4 / B-2）：调用方式本身不合法（未知子命令、缺必填参数、参数取值非法、位置参数多余）时退出码为 `2`。
   *判定*：分别构造 ①未知子命令 ②缺必填参数 ③非法取值 → 各次退出码均为 `2`，且提示指向具体错误点。
4. **四类语义互斥且不混用**（W4 / B-2）：`0/1/2/3` 四个取值各对应上述含义，不出现"同一个成因在不同命令下落在不同码"或"一个码表示两种含义"。
   *判定*：把四类场景各跑一次并列成表 → 每类固定落在同一个码上；表的第 4 类（连接失败）的判定方式见 [F08](F08-disconnect-degradation.md)。
5. **退出码与输出可分离消费**（W4）：判定成败**只需退出码**，不需要解析 stdout。
   *判定*：对上述场景各自只看退出码（丢弃 stdout） → 仍能区分成功 / 业务失败 / 用法错误 / 连接失败。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-08 · 四类退出码的归类判定规则**（§5.4，首条命中者生效）：
  - **`2` 用法错误**：本地 argv 解析失败（未知层 / 未知子命令 / 缺必填参数 / 取值非法 / 位置参数多余 / 给该条目不接受的选项）—— **未发出任何连接或请求**（零副作用）；
  - **`3` 连接失败**：连接建立失败（`ECONNREFUSED` / `ENOENT` / `ECONNRESET` / `EPIPE` / 超 2000ms）｜非阻塞条目 5000ms 内无响应（`REQUEST_TIMEOUT`）｜已建立的订阅被**服务端**异常终止｜收到 `UPSTREAM_UNAVAILABLE`（502，hub 明示其上游 Router 不可达）；
  - **`1` 业务失败**：上游 4xx/5xx（`error` / `code` 原样透出）｜可阻塞条目在 `--wait` 内未见终态（`WAIT_TIMEOUT`）｜本地配置错误（`CONFIG_ERROR`）｜层 C 子进程退出码 `1` 透传；
  - **`0` 成功**：其余（含订阅被下游管道截断）。
- **错误对象的形态**：stderr **单行 JSON** `{"code":…,"error":…,"exit_code":…}`（层 A 另带 `http_status`）；`code` / `error` 为上游原文原样（F02 验收 3 的可读面）。
- **订阅被打断的归类**（本卡边界项的细则）：下游截断 ⇒ `0`；服务端断开 ⇒ `3`；不做自动重连（N9 / G02）。
- **库面等价物**：`HubError.exitCode`（`sdk/errors.js`，与 CLI 面同一张表）—— 四类语义互斥、每类固定落一个码（验收 4），且**仅凭退出码即可判成败**（验收 5）。
- **"非法取值 → 2"的判定范围（P-3，待主 agent 拍板）**：SDK 只判**本地可判的那一类**（位置参数齐否 / flag 缺值 / 数值型是否整数 / JSON 型可否解析 / 入口表声明的必填 flag 齐否）⇒ `2`；**服务端可判的取值非法**（业务范围 / 枚举 / 跨字段约束，如 `limit ≤ 200`、`archived ∈ {0,1}`）由服务端返回 `400 INVALID_PARAM` ⇒ `1`（原文与 `code` 原样透出）。理由：本地判全量合法域需要在 SDK 内复制一份 `API.md` 的参数表（撞 W3 薄封装 / F11 验收 5）。详见 `../architecture.md` §3.3 P-3 / §5.1 规则 4。
