# F08 · 断连降级（hub 不可达时单一明确错误）

**功能 ID**: F08
**来源**: `demand.md` 第二段 §1 **W4**（退出码 `3 连接失败`）；§4 **E3**（断连降级的裸判定原文）；§4 六维自检"可验证性"条
**迭代**: 0025-hub-sdk-and-skill
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: hub 未运行时——Web 服务未监听 `127.0.0.1:7788`、或 Router 的 UDS 端点不存在（两条接入路径各自不可达）

---

## 用户价值

hub 没起来的时候，我得到的是**一句明确的话**和一个可判定的退出码——不是一坨堆栈，也不是卡在那里让我猜。

## 验收标准

1. **停服后任一命令给出单一明确错误**（E3）：hub 未运行（或端口无监听）时，任一命令输出**一条明确的错误说明**（指出"连不上 hub / 连接失败"这类事实），且**不输出堆栈**。
   *判定*：停掉 hub 后执行任一子命令 → 观察 stdout / stderr：无堆栈、无误导性的成功输出。〔判定方式逐字取自 `demand.md` E3 的裸判据〕
2. **退出码固定为 3**（E3 / W4）：该情形的退出码为 `3`（连接失败），与业务失败（`1`）、用法错误（`2`）可区分。
   *判定*：同上场景 → 观察退出码为 `3`。
3. **不挂起**（E3）：该情形下命令**立即结束**，不出现长时间等待或永久挂起。
   *判定*：停服后执行命令 → 命令在可感知的短时间内自行结束（不需要人工中断）。
4. **两条接入路径都成立**（W2 / E3）：Web 面不可达与 UDS 面不可达两种情况，各自同样给出单一明确错误 + 退出码 `3` + 不挂起。
   *判定*：分别制造 ①Web 服务未监听 ②UDS 端点不存在 → 各执行对应层的命令，观察三点行为一致。
5. **恢复后无需额外动作即可正常工作**（W4 / B-3）：hub 重新可用后，再次执行同一命令即可正常工作，不需要清理任何本地状态。
   *判定*：停服 → 执行（失败 + 退出码 3）→ 启服 → 再执行同一命令 → 成功（退出码 `0`）。

## 边界（不包含）

- 不含**自动重试 / 自动拉起 hub / 守护进程**——**N3** → [G02](G02-lifecycle-boundary-preserved.md) 验收 3；本卡只要求"明确失败"。
- 不含重试退避、重连策略、本地排队（无状态约束见 → [F09](F09-stateless-cli.md)，**N9**）。
- 不含错误文案的**具体措辞与错误标识形态** → `[架构待填]` T-08。
- 不含认证 / 跨机不可达等场景——**N2**（同机、零鉴权是既有边界）。
- 不含超时这一类（命令发出去了但结果没在 `--wait` 内回来）→ [F10](F10-wait-timeout-limit.md)。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-08 · 连接失败这一类错误的识别形态**（§5.4）：`sdk/http.js`（Web 面）与 `sdk/uds.js`（UDS 面）把连接级错误统一映射为 `HubError{ code: 'HUB_UNREACHABLE', exitCode: 3 }`；stderr 单行 JSON，形如 `{"code":"HUB_UNREACHABLE","error":"无法连接 hub（<地址>；服务未运行？）","exit_code":3}` —— **无堆栈**（验收 1）、退出码固定 `3`（验收 2）。
- **不挂起（验收 3）**：连接建立上限 **2000 ms**（沿用既有 `src/node-client.js:DEFAULT_CONNECT_TIMEOUT_MS` 与 `src/status.js:CONNECT_TIMEOUT_MS` 同值）；非阻塞条目响应上限 5000 ms —— 两个上限都在 SDK 侧，无需服务端配合。
- **两条路径（验收 4）**：Web 面 = 端口无监听 → `ECONNREFUSED` → `3`；UDS 面 = socket 不存在 → `ENOENT` → `3`。补充归类：web 在而 Router 不在时收到的 `UPSTREAM_UNAVAILABLE`（502）同样归 `3`（hub 侧不可用，"等它起来再试"的重试语义与"连不上"同类）。
- **无残留（验收 5）**：零本地写、零重试退避、零排队；恢复后重跑同一命令即成功 —— 由 F09 的同一机制保证（无任何跨调用状态需要清理）。
