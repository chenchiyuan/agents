## 用户价值

下次要和 hub 协作时，**一段可被引用的文本就够了**——不用再临场拼通道、不用再重新发现"截断了怎么办"。

## 验收标准

1. **与 SDK 同包落 `oamp/` 内，且自包含**（W6 / D-1 / C-E）：skill 文件位于 `oamp/` 包内（与 SDK 同包，**不在 `.claude/skills/` 下**）；消费方**仅读取该文件本身**（不加任何外部上下文）即可得到完整的三段式内容 → 可被路径寻址消费。
   *判定*：在 `oamp/` 内找到该文件；通读全文 → 不加外部信息即可照做（具体路径 → `[架构待填]` T-05）。
2. **三段式结构齐备**（W6 / B-4）：内容分为 ① **何时用**（触发条件）② **怎么用**（子命令清单 + 4 条典型序列）③ **红线** 三段，各段有明确无歧义的标题。
   *判定*：逐段核对三节是否存在、是否各自成段；缺任一段即不通过。
3. **"何时用"给出可判定的触发条件**（W6 / B-4）：列出"什么场合该用它"的条件（如：需要派发角色任务、取调用终态、取过程记录、订阅事件、盘点实例状态、走既有运维命令时），不是"需要与 hub 交互时用它"这类无法判定的说法。
   *判定*：把触发条件逐条与场景对照 → 每条都能回答"这个场景算不算"。
4. **"怎么用"含子命令清单 + 4 条典型序列**（W6 / B-4 / E1）：清单**只到子命令名**（结构层级，不含参数表）；4 条典型序列齐备——**派发→取终态 / 截断恢复 / 事件订阅 / 状态盘点**，每条给出可照做的命令顺序。
   *判定*：按 4 条序列逐条照做 → 每条都能走通且**全程不出现手写 HTTP**（清单里不出现 `curl`、socket 手写、自建 HTTP 客户端）。〔判定方式取自 `demand.md` E1 的裸判据〕
5. **"截断恢复"是**序列**不是命令**（W3 / C-A / N5）：该序列由**组合已有子命令**表达（取终态 + 取过程记录，由消费方自行拼接），skill 中**不存在**"一步恢复全文"的专用命令，也不宣称 SDK 代做重建。
   *判定*：读该序列 → 步骤为多个子命令的组合；子命令清单中无此类专用命令。
6. **"红线"三条齐备且可核**（W6 / B-4 / C-C）：① 不裸写 HTTP（应经 SDK）② 不复制 schema（参数与字段以 `API.md` 为准）③ 退出码语义（0/1/2/3 的约定）。
   *判定*：逐条核对三条是否存在；其中"不复制 schema"可用"正文不含参数表 / 字段定义清单"核对（→ 验收 7）。
7. **不复制 schema、不成为第二份文档**（**N8** / C-C）：skill 正文**不出现**参数表、字段定义清单、端点路径表这类会与 `API.md` 分叉的内容。
   *判定*：通读正文 → 结构只到"子命令名 + 序列 + 红线"；出现参数 / 字段级清单即不通过。

## 边界（不包含）

- 不含**完整命令手册**（参数表、字段 schema、端点路径清单）——**N8**；真源仍是 `API.md`（A-4 / W5）。
- 不含**带业务语义的高层编排命令**（`dispatch` / `await` / 工作流专用命令）——**N5**；序列以**文本**固化，不落成命令（[F14](F14-layered-command-structure.md) 验收 3）。
- 不含"其他 skill 如何引用它"的**机制**（加载路径、转发、链接）→ `[架构待填]` T-06；本卡只要求"可被路径寻址消费"（D-1 的代价已由用户知情接受）。
- 不含 skill 的**具体路径** → T-05；不含 SDK 入口的定位写法（→ [F13](F13-skill-sdk-entry-addressing.md)）。
- 不含对 `roles/**` 的任何改动（不要求角色文件引用它）——**W8** → [G03](G03-roles-and-distribution-untouched.md)。
- 不含 `API.md` 自身内容（→ [G01](G01-hub-interface-unchanged.md)）；不含 SDK 能力本身（→ F02~F10）。

## 架构落定（阶段 3）

> 架构维度结论；**产品维度（用户价值 / 验收标准 / 边界）逐字未改动**。详见 `../architecture.md` §5 / §4。

- **T-05 · skill 的具体路径**：**`oamp/skill/hub.md`（单文件、自包含）** —— 与 SDK 同包落 `oamp/` 内、**不进** `.claude/skills/`、不建副本、不建转发（G03 验收 4）。选单文件的理由：N8 禁止复制参数表与 schema ⇒ **没有需要随附的资产**；验收 1 只要求"该文件本身可被路径寻址消费、不加外部信息即可照做"（D-1 的代价用户已知情）。
- **T-06 · 跨 skill 引用机制**：**路径引用模板**（定义"写法"而非"登记"）—— 其他 skill 以 `<项目根>/oamp/skill/hub.md` 引用，**项目根由调用方自行解析**（不由 cwd 推导）；**零**注册表 / 索引 / 加载器 / 软链 / 副本 / 转发；**本迭代不实施任何引用实体**（W8 / A-5：角色接入留独立迭代）。
- **内容面（验收 2~7）**：① 何时用（可判定的触发条件）② 怎么用（**只到子命令名**的三层清单 + 4 条典型序列：派发→取终态 / 截断恢复 / 事件订阅 / 状态盘点）③ 红线（不裸写 HTTP / 不复制 schema / 退出码语义）—— **不出现参数表、字段定义清单、端点路径表**（真源仍是 `API.md`）。
- **截断恢复是序列不是命令（验收 5）**：由 `api calls get <call_id>` + `api calls transcript <call_id>` 组合表达、消费方自行拼接；清单中**无**"一步恢复全文"的专用命令，也不宣称 SDK 代做重建（C-A 的口径收窄）。
- **序列可照做（验收 4 / E1）**：4 条序列全部由 §5.1 的 40 条入口组合而成，逐条执行全程零 `curl` / 零 socket 手写 / 零自建 HTTP 客户端。
