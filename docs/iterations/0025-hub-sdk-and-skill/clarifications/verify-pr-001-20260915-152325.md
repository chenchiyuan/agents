## 7. 下一迭代候选

> 本轮发现的优化点、边界问题或遗留限制。不在当前验收标准范围内，供主 agent 与 planner 决策是否纳入下一迭代。

1. **契约外响应体会以裸 `SyntaxError` 逃出 SDK 边界（无 `.code` / `.exitCode`）**：实测 4xx/5xx 的非 JSON 体（如 HTML 500）⇒ `SyntaxError: Unexpected token '<'`；302 ⇒ `SyntaxError: Unexpected end of JSON input`。T3 验收 8 明确要求"不实现契约外兜底形态"，故**实现是合规的**；但对 pr-003 的 `cli.js` 是接缝风险——若它直接读 `err.exitCode` 落进程退出码，契约外响应会得到 `undefined`。建议：pr-003 在边界兜底，或在 pr-006 的契约用例中把"契约外响应"的期望形态固化下来。
2. **合法 SSE 的 data-only 帧 / 多行 `data:` 会被静默丢弃或截断**：`parseFrame` 要求同一帧内同时出现 `event:` 与 `data:`（任一缺失 ⇒ 返回 `null`，不产出条目）；多行 `data:` 只保留最后一行。既有服务端（`src/transport.js`）恒写单行 `event:` + `data:`，故属契约内；但"静默丢弃"是隐式契约，未在规格中写明。建议在 `§5.3` 显式声明"帧形态恒为单行 event+data，其余形态视为无效帧"。
3. **`REQUEST_TIMEOUT` 的 5000ms 同时硬编码在常量与文案模板中**：`RESPONSE_TIMEOUT_MS = 5000` 与文案 `等待响应超时（${RESPONSE_TIMEOUT_MS}ms；${target}）` 同源（当前无分叉风险），但该值不可经任何出口调整。若后续 `§5.4` 需要调整取值，属同一改动点；建议保持现状并在 pr-006 加一条"文案含上限值"的断言。
4. **`oamp/sdk/**` 不在 `hygiene.test.js` 的凭据词扫描面内**（该事实已在任务图 §0.2 A7 登记）：扫面为 `bin/` + `src/` 平铺 `*.js` + `package.json`。本 PR 新增的 `sdk/` 面因此不受凭据类字段名的卫生断言保护。建议 pr-006 把扫描面扩到 `sdk/**`（属后续 PR 的测试面）。
5. **`errors.js` 的 `classify()` 对 `status` 落在 3xx（非 2xx 且非 4xx-5xx）时走"上游 code 原文"分支**，若 `body` 无 `code` 会产出 `code: undefined`。`§5.4` 未定义 3xx，`API.md` 也不产出 3xx，属未定义边界；`classifyResponse` 对 4xx-5xx 之外的失败状态无条件归 `1`。建议在 `§5.4` 补一句"层 A 的状态码面恒 ⊆ {2xx, 4xx, 5xx}"以关闭该边界。
