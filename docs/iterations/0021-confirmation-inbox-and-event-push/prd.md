## 本次迭代边界说明

### 包含（本迭代要产出的产品行为）

- **待确认 inbox（第三栏）**（W1 → F01）：控制台新增独立第三栏（对话列表 | 待确认 inbox | 对话详情）；**跨对话集中**列出所有等待裁决的确认项；有新条目时不刷新页面即可见；同时多条时全部列出。
- **确认源上浮**（W3 / M1 → F02）：把**受门禁工具调用**（`bash` / `edit` / `delete` / `move`）的授权请求从"按档位自动答复"改为"上浮到 inbox、由人裁决"；条目的选项集合**来自该请求本身**；`allow` 档 ⇒ 上浮给人裁决；`deny` 档 ⇒ **保持自动拒绝**（不上浮、不产生条目）。
- **栏内裁决交互**（W2 / M1 → F03）：点选请求方给出的选项即完成裁决（**选项为主**）+ 可附自由文本（拒绝理由 / 给 agent 的补充说明，**文本为辅**），**一并提交**；裁决完成后该条**从栏内消失**。
- **裁决回路**（M2 → F04）：裁决被回传到发起该请求的 agent 轮次，该轮据此**继续或中止**；一次裁决只作用于其所属的那一条 / 那一轮。
- **未裁决时的挂起语义**（M3 / E4 / N6 → F05）：**默认阻塞且无上限**——不自动放行、不自动拒绝、**无超时退化**；不存在"默认选项 / 自动放行"这类自动裁决策略，控制台也无相应配置面。
- **在途项可见性**（W6 / E5 → F06）：未裁决项在**页面刷新 / 断线重连后仍在栏内**，内容与刷新前一致；只重建**未裁决**项，不重建已裁决项。
- **通知事件类型**（W5 / M5 → F07）：**封闭 3 类** = `chat_completed` / `chat_failed` / `confirmation_required`；产生时机挂靠既有对话状态变化（工作中 → 完成 / 失败）与"确认项进入 inbox"的时刻；**不含** `call_completed`（hub 调用面完成不产生通知）。
- **通知投递**（W4 通道面 / M4 / E3 → F08）：**首个通道 = 浏览器 Notification API**；权限已授予时，三类事件各触发一次浏览器通知；**不依赖用户停留在该对话**。
- **通知服务与通道分离**（W4 分离面 / M4 → F09）：服务承载"什么事件要通知"、通道决定"怎么投递"；扩展 / 替换通道**不改事件类型契约**。
- **既有边界保持**（N1 / N2 / N3 → F10 / F11 / F12）：服务仍仅 `127.0.0.1` 监听、零鉴权、不做多用户（且该边界**只约束服务本身**，不禁止投递路径经浏览器厂商推送服务）；不做已裁决项的历史 / 审计台账；**不改 omp / harness 侧协议**。

### 不包含（边界，源自 `demand.md` 第二段 §3 N1~N7）

- **N1 服务边界不变**（仅 `127.0.0.1`、零鉴权、不做多用户 / 跨机）；**且该边界只约束服务本身**——浏览器厂商推送服务的**投递路径不在禁止范围内**（T-2 第 2 批裁决）——落 F10 验收 1~2。

- **N3 不改 omp / harness 侧协议**——落 F12 验收 1~2。
- **N4 不做通知分级 / 免打扰 / 声音等偏好设置**——落 F08 边界、本文件全局边界。
- **N5 不覆盖 hub 调用面（`/api/calls`）的完成通知**（事件集合不含 `call_completed`）——落 F07 验收 3。
- **N6 不做自动裁决策略配置**（无"默认选项 / 自动放行"，也**无超时退化**）——落 F05 验收 2~3、F05 边界。

- **全局**：不做 `demand.md` 之外的新增功能点；不修改 `demand.md` / `status.md` / `history.md` / `clarifications/` 下已有文件；不改产品代码、不改规范 / SKILL / 脚本。
