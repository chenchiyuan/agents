## 用户价值

我点的"放行 / 拒绝"真能决定 agent 下一步干什么——不是点了没反应。

## 验收标准

1. **裁决回传到请求方**（M2）：一次裁决被回传到**发起该请求的**那一轮 agent 工作。
   *判定*：提交一次放行裁决 → 观测到该裁决已送达该轮（该轮不再停留在等待状态）。
2. **据此继续或中止**（M2 / E2）：选择**放行**时该轮继续推进（该操作被执行）；选择**拒绝**时该轮按既有语义**中止**。
   *判定*：对同一种请求分别提交放行与拒绝 → 前者 agent 推进、后者 agent 中止该轮。
3. **裁决只作用于其所属的那一条 / 那一轮**：一次裁决不为其它在途请求作答。
   *判定*：同时存在两条待裁决项时裁决其中之一 → 另一条仍在栏内等待、其对应轮次仍未推进。

## 边界（不包含）

- 不含 **agent 在未被裁决时**的行为（→ F05，默认阻塞无上限）。
- 不含裁决回传的载体与形态（→ T-06）。
- 不含"拒绝理由文本"在 agent 侧的消费方式（`demand.md` 只要求随选项一并提交 → F03 验收 2）。
- 不含裁决的撤销 / 二次修改（`demand.md` 未要求，本阶段不新增）。
- 不含通知（→ F07 / F08）。
