**迭代**: 0021-confirmation-inbox-and-event-push
**产品对象（引用 `demand.md` 只读实测，非本阶段决策）**: N1 原文（服务只绑 `127.0.0.1`、零鉴权——既有安全边界）

## 用户价值

这次不把服务开到局域网或公网去——本机和以前一样，别人连不上也不需要登录。

## 验收标准

1. **服务边界不变**（N1）：服务仍**仅在本机（`127.0.0.1`）监听**、**零鉴权**、**不做多用户 / 跨机接入**。
   *判定*：从另一台机器 / 局域网访问 → 仍不可达；访问服务仍不需要任何凭据。
2. **该边界只约束服务本身**（T-2 裁决）：通知的**投递路径**经浏览器厂商推送服务**不在禁止范围内**——不得把 N1 读成"投递不得出本机"。
   *判定*：读通知投递路径的说明 → 服务的监听 / 鉴权边界与投递路径分列，投递路径不被读作受限。

## 边界（不包含）

- 不含投递路径的实现（→ T-13）。
- 不含鉴权、多用户、跨机接入的任何新增（N1 封死）。
- 不含服务监听的其它变更（本迭代不改服务边界）。
