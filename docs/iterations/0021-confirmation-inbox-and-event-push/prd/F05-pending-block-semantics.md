# F05：未裁决时的挂起语义（默认阻塞无上限；无自动裁决 / 无超时退化）

## 用户价值

没人拍板时 agent 就等着——它不会自作主张地放行或拒绝，系统也不会背着我替我做决定。

## 验收标准

1. **默认阻塞**（M3）：agent 发出授权请求后，该轮**保持等待**——不自动放行、不自动拒绝。
   *判定*：发出一次请求后放着不裁决 → 该轮不推进、该操作未被执行。
2. **无上限、无超时退化**（E4 / N6）：放置**任意长时间**后重新观察，条目仍在栏内、该轮仍处于等待状态——不存在"超时后按档位收尾"的行为。
   *判定*：搁置任意长时间后再看 → 条目仍在、轮次未推进。
3. **不提供自动裁决策略**（N6）：不存在"默认选项 / 自动放行"这类自动裁决行为；控制台中也没有相应的策略配置面。
   *判定*：找遍控制台 → 无策略配置面；观察行为 → 无自动裁决发生。

## 边界（不包含）

- **不含任何形式的超时 / 过期 / 自动收尾**（N6 封死）。
- **不含自动裁决策略配置**（无默认选项、无自动放行）——策略化被 `demand.md` 明确列为**后续**（P7）。
- **不含策略扩展点是否预留**（P7：本迭代留否由架构阶段定 → T-15）。
- **不含无人看守代价的处置**（R1 / R2 已是**用户明示接受的已知代价**，不作为需求缺陷，本阶段也不派生任何缓解功能点）。
- 不含裁决发生**之后**的行为（→ F04）。
- 不含挂起期间 agent 的具体行为形态（→ T-16）。
