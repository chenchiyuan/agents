## 用户价值

危险操作不再被一刀切放行或一刀切拒绝——人在**具体那一次操作**上拍板，而不是整类操作一起赌。

## 验收标准

1. **授权请求上浮**（W3 / P2）：agent 发起一次**受门禁的工具调用**（`bash` / `edit` / `delete` / `move`）时，该请求**不再被自动答复**，而是作为一条待裁决项出现在 inbox 内。
   *判定*：让一个 `allow` 档角色发起一次受门禁调用 → 栏内出现该条目，且该调用**未在无人介入的情况下被自动放行**。 〔**判定样本**（`[user_confirmed MI-05]`）：**构造样本 + 真实样本各半**——阶段 6 构造一次"受门禁调用 + 栏内裁决 + 刷新 / 断线重连"的样本（覆盖交互与重连半句）；真实半句取自**本迭代自身的执行记录**（R1 场景：hub 后台派发 + `allow` 档挂起），**须在验证报告中标明样本来源与场景**〕
2. **选项集合来自请求本身**（M1 / P4 的呼应）：条目呈现的选项集合 = **请求方给出的选项集合**——不新增、不删减、不替换。
   *判定*：对照该请求给出的选项与栏内呈现的选项 → 一致。
3. **非门禁操作不产生条目**：不经过门禁的操作不进入 inbox。
   *判定*：触发一次不受门禁约束的操作 → 栏内无新增条目。
4. **档位范围：`allow` 上浮、`deny` 保持自动拒绝**（M1 / **T-1 第 2 批裁决** / R3）：
   - `allow` 档角色的受门禁调用 ⇒ **上浮到 inbox、由人裁决**（不再恒放行）；
   - `deny` 档角色的受门禁调用 ⇒ **保持自动拒绝**——不上浮、不产生 inbox 条目，该轮按既有语义中止。
   *判定*：分别以 `allow` 档与 `deny` 档角色各触发一次受门禁调用 → 前者在栏内出现条目并等待裁决；后者栏内无条目、该轮自动中止。

## 边界（不包含）

- **除受门禁工具调用的授权请求之外，不新增其它确认源**——"需要用户确认的事情"的外延已由 P2 锁定，本迭代不扩。
- **`deny` 档的其它语义不变**：档位语义只改 `allow` 档（T-1）。
- **不含上游协议改动**（N3 → F12）：不为"发出请求"而改 agent 侧。
- 不含栏内裁决交互（→ F03）；不含裁决回传与该轮后果（→ F04）；不含未裁决时的挂起语义（→ F05）。
- 不含条目的呈现形态与字段（→ T-02）；不含确认源的接线方式与是否需新增承载体（→ T-05）。
