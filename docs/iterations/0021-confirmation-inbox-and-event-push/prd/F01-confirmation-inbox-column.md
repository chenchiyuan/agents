# F01：待确认 inbox（第三栏的存在与跨对话集中）

**功能 ID**: F01
**来源**: `demand.md` 第二段 §2 **W1**（`user_confirmed`：U-1「agent中需要用户确认的单独一栏列出来」+ P3②「新增第三栏」）；效果 **E1**（可见性面）；边界 **N7**；驱动 **V2**（注意力驱动）
**迭代**: 0021-confirmation-inbox-and-event-push
**产品对象（引用 `demand.md` 只读实测，非本阶段决策）**: F7（既有控制台布局 = 两栏：对话列表 + 对话详情）

---

## 用户价值

所有"在等我拍板"的事集中在一处，不用一个对话一个对话地翻；有新的等着我处理的事，不刷新页面也能看见。

## 验收标准

1. **第三栏存在且独立**（W1 / P3② / N7）：控制台呈现三栏——对话列表 | **待确认 inbox** | 对话详情；待确认内容是**独立的一栏**，不是既有栏内的分区、顶栏抽屉、也不是单独一个页面。
   *判定*：打开控制台 → 同时可读到三栏；待确认内容不位于对话列表栏的分区、顶栏抽屉或独立页面。 〔布局形态与响应式见 T-01〕
2. **跨对话集中**（W1）：来自不同对话的等待裁决项同时出现在同一栏内；该栏的可见范围**不随当前选中的对话变化**。
   *判定*：让两个不同对话各产生一条待裁决项 → 无论详情栏当前选中哪个对话，两条都在第三栏内可见。
3. **全部在途项可见且免刷新**（E1）：有新确认项产生时，**无需刷新页面**即出现在栏内；同时存在多条时**全部列出**，不是只显示最新一条。
   *判定*：触发一条确认请求 → 不刷新页面即观察栏内新增该条；再触发一条 → 两条同时在列。
4. **条目可辨识来源对话**（W1 的"跨对话"面）〔`[model_inferred MI-02]`：demand.md 未明说条目须标示来源对话。**推荐值 = 必须可辨识**（最小 = 可读出所属对话）——否则"跨对话集中"退化为无法归属的列表；**待主 agent 转呈用户裁决，裁决前本条按推荐值暂记**〕：栏内每条可读出它来自哪个对话。
   *判定*：读栏内任一条目 → 可判出所属对话。

## 边界（不包含）

- **不含第三栏之外的任何入口载体**（N7）——不做左栏过滤器分区、不做顶栏抽屉、不做独立页面。
- **不含既有两栏语义的变更**：本迭代不引入其它入口载体，对话列表栏与对话详情栏的既有职责不变。
- **不含栏内排序 / 分组 / 条数上限规则**（`demand.md` 未规定，本阶段**不新增**；见 `prd.md`「疑问与越界」3 与 MI-04）。
- **不含"对话列表 / 对话详情中的等待状态标记"**（`demand.md` 未要求，本阶段不新增）。
- 不含条目的来源与上浮条件（→ F02）；不含栏内裁决交互（→ F03）；不含裁决回传与 agent 侧后果（→ F04）；不含未裁决时的挂起语义（→ F05）；不含刷新 / 重连后的重建（→ F06）。
- 不含通知（→ F07 / F08 / F09）；不含已裁决项的历史查看面（不做，→ F11）。
- 不含栏内条目的承载形态、生命周期与字段构成（→ T-02 / T-08）。
