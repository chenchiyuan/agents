# F11：无确认项历史台账（不做已裁决项历史 / 审计）〔保证项〕

**来源**: `demand.md` 第二段 §3 **N2**（`user_confirmed`：P9 保留 + **T-3 的范围澄清**「本边界只覆盖已裁决项的历史，不覆盖未裁决的在途项」）

## 用户价值

这个栏只装"还要等我处理的事"——处理完就干净，不会堆成另一个消息中心。

## 验收标准

1. **不提供已裁决项的历史查看面**（N2）〔`[user_confirmed MI-03]`：判定面 = **只判用户可见面**（无已裁决项的历史入口 / 列表，且已裁决项不在栏内留存），**不判数据层是否留存**（数据层属阶段 3）〕：控制台中不存在"我看过 / 处理过哪些确认"的历史入口或列表。
   *判定*：找遍控制台 → 无已裁决确认项的查看面；栏内只有未裁决项。 〔不判数据层——见 T-08〕
2. **本边界只覆盖已裁决项**（T-3 的范围澄清）：不把**未裁决的在途项**一并排除——未裁决项必须仍在栏内。
   *判定*：读本边界的适用面 → 只排除已裁决项的历史；未裁决项的可见性归 F06，不被本卡削弱。

## 边界（不包含）

- 不含在途项的可见性（→ F06）；不含裁决完成后条目从栏内消失（→ F03 验收 4）。
- 不含 agent 侧既有的工具审计（既有落地保持，本迭代不在栏内重复建设）。
- 不含"已裁决项的历史"的任何形态（不做）。

## 架构落定（阶段 3）

> 架构维度结论；产品维度**未改动**。详见 `../architecture.md` §6 / §7 T-08。

- **T-08 承载与生命周期**（§6）：在途表 = web 进程内 `Map`（`oamp/src/inbox.js`），**只装未裁决项**；`take(confirmationId)` = **原子取出并移除**（裁决路径），`remove(confirmationId)` = 失效路径移除。表内**无已裁决项**，也**无任何已裁决项的读取入口**（无列表、无查询参数、无导出）。
- **与持久化的关系**：**不落 SQLite**、无新表、无迁移（`persist.js` schema 零改动）；无 TTL、无归档、无审计面 ⇒ N2/F11 的"无历史台账"由**结构**保证，而非靠"不暴露接口"。
- **"只判用户可见面"（MI-03）**：判定面 = 无已裁决项的历史入口 / 列表 + 已裁决项不在栏内留存；**不判数据层**。本方案在数据层也只保留在途项（`take()` 即删）。
- **重启即清空**是特性：同时满足 N2（无台账）与 W6（只要求活着的进程内刷新 / 重连后仍在）。
