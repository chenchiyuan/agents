# F07：通知事件类型与产生时机（封闭 3 类）

## 用户价值

只有真值得叫我一声的事才来叫我——跑完了、挂了、或者卡住等我拍板。

## 验收标准

1. **事件类型封闭 3 类**（W5 / M5）：事件类型为 3 类——**对话完成**（`chat_completed`）/ **对话失败**（`chat_failed`）/ **出现待裁决项**（`confirmation_required`）；不产生第 4 类。
   *判定*：清点本迭代中触发过通知的事件类型 → 只出现这 3 类。
2. **产生时机挂靠既有状态变化**（M5）：对话状态由工作中变为**完成** ⇒ 完成类事件；变为**失败** ⇒ 失败类事件；一条确认项**进入 inbox** 的时刻 ⇒ 待裁决类事件。
   *判定*：分别构造这三种情形 → 各产生对应的一类事件。
3. **不含"调用完成"**（N5）：经 hub 调用面派发的后台调用完成时**不产生**通知——"完成"类事件只覆盖**对话完成**语义。
   *判定*：派发一次后台调用并等它完成 → 不产生完成类事件。

## 边界（不包含）

- **事件类型集合封闭**：本迭代不新增第 4 类；后续新增事件类型不在本迭代范围内。
- **不含"确认项进入 inbox"与通知之间是否去重**（`demand.md` 未规定 → MI-01，推荐值见 F08 验收 2）。
- 不含投递方式与投递行为（→ F08）；不含服务与通道的划分（→ F09）。
- 不含通知的标题 / 内容 / 点击去向（→ T-09）、多条通知的合并 / 覆盖（→ T-10）。
- 不含通知偏好设置（N4 → F08 边界）。
- 不含事件类型定义的承载形态（→ T-14）；不含事件投递路径（→ T-13）。
