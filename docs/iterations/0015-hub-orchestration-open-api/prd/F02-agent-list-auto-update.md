# F02：列表与计数随 agent 上下线自动更新（无需手动刷新）

**功能 ID**: F02
**来源**: `demand.md` W4；效果 E3；边界 N8；现状缺口 F-10（计数只在初载与窗口聚焦刷新）
**迭代**: 0015-hub-orchestration-open-api

---

## 用户价值

别人在终端起停 agent，浏览器这边自己就变了——不用按刷新、不用切窗口，列表和那个数字始终是此刻的真相。

## 验收标准

1. **上线自动反映**：在另一终端启动一个此前不在线的 agent，浏览器**不做任何手动刷新**，列表与顶栏计数在**数秒内**出现该实例、计数 +1（W4 / E3）`[user_confirmed MI-02]`。
   *判定*：盯着列表不操作，观察变化出现；「数秒内」的判定界取 **5 秒** `[user_confirmed MI-02]`；同时该条目出现于列表且计数与条数一致（与 F01 验收 3 同一把尺子）。
2. **下线自动反映**：在另一终端停止一个在线 agent，浏览器**不做任何手动刷新**，列表与顶栏计数在数秒内移除该实例、计数 -1（W4 / E3）`[user_confirmed MI-02]`。
   *判定*：同验收 1；下线以该实例被判离线为准（F01 验收 3 的口径）。
3. **不依赖任何人工动作**：上述变化不依赖刷新页面、切换标签页 / 窗口、重新点击展开等操作；**列表保持展开时也能直接看到变化**（W4 / E3）。
   *判定*：全程不做任何操作，只观察；再重复一次"保持列表展开"的场景。
4. **只反映真实状态**：自动更新只增删实际发生上下线的实例，其余条目的实例标识不被误改（最后心跳时间可随真实心跳正常刷新）。
   *判定*：起停一个实例，检查其余条目的实例标识不变。
5. **连接中断后重新对齐**：与 hub 的连接中断后恢复时，列表与计数**以当前真实状态重新对齐**（不要求补发断线期间的每一条变化）（W4 的断线边界）`[user_confirmed MI-05]`。
   *判定*：断连期间在别处起停实例，恢复连接后列表与计数与真实状态一致。

## 边界（不包含）

- 不含**列表本身的展示与字段定义**——那是 F01；本卡只要求"变化能被自动看见"。
- 不含**全局事件流的接口形态与订阅方式**——那是 F05；本卡是其在界面上的消费方。
- **不做对话消息内容的全局广播**（N8）——自动更新只处理 agent 上下线带来的列表与计数变化。
- **不要求多个浏览器标签页 / 窗口之间同时更新**（需求只要求当前页面无需手动刷新）`[user_confirmed MI-04]`。
- 不含**启动 / 关闭 agent**（N1 / N2）——本卡只反映"别人在别处造成的"状态变化，自身不产生任何状态变更。
- 不含**离线实例的展示**（M-1 / F01 边界）——下线表现为该实例从列表消失。

## 架构维度（阶段 3 已填，2026-09-12；详见 `architecture.md` §4 / §7.3 / §11 AR-02）

> 以下为阶段 3 定案；产品维度逐字未动。驱动方式为「事件为主 + 展开期定时刷新为辅」。

- **AR-02-a 驱动方式**：**主驱动 = 全局 SSE**（新增 `GET /api/events`，事件 `agent_online` / `agent_offline`；事件源 = web 进程按 `OAMP_WEB_TOPOLOGY_POLL_MS`（默认 **2000ms**）拉 `router.status` 做差值，仅当存在全局订阅者时运行）⇒ **事件产生到推送** ≤2s + 传输延迟，**远低于 5s 判定界**（MI-02 / MI-06）。**时延口径（准确表述）**：≤2s 只覆盖"轮询腿 + 推送"，前提是**该上下线已发生**——`agent_online` 与优雅注销即时产生事件；**强杀 / 崩溃须先由租约扫描判离线**（默认 `OAMP_HEARTBEAT_TIMEOUT_MS = 30000`，空闲档按联动公式抬升至 120s）才产生 `agent_offline` ⇒ 端到端 = **判活阈值 + ≤2s**；F02 验收 2 已把下线口径锚定为"以该实例被判离线为准"（详见 `architecture.md` §4.2 时延口径）。**辅驱动 = 面板展开期的 5s `loadAgents()` 全量刷新**（`AGENT_PANEL_REFRESH_MS = 5000`，收起即清，复用 `syncWaitTimer` 的"状态内定时器"手法）——只承担"最后心跳时间的新鲜度"（F01 验收 2 的对照要求）与事件漏失兜底。既有 `window.focus → loadAgents` 保留不动。**不做**页面级常驻轮询、不做多标签同步（MI-04）。
- **AR-02-b 更新落点**：`state.agents` 的**增量**变更（online → upsert，offline → remove）→ `setConn(true)` 重算顶栏文本与计数（`已连接 · N agents online`，口径与文案逐字不变）→ 面板展开时 `renderAgentPanel()` **整体重绘**（不做 DOM diff：在线实例规模为个位到十位，重绘成本可忽略）。关键性质：**面板关闭时计数也会变**（验收 3 的"不依赖重新点击展开"）。
- **AR-02-c 断线对齐**：全局 `EventSource` 的 `onopen ⇒ loadAgents()`（全量重新对齐，符合 MI-05"不补发断线期间的每一条变化"）；服务端 `retry: 1000` + 15s keepalive 自动重连；`publish` 的"无订阅者即丢弃、不缓存不排队"语义零改动。拓扑轮询侧：Router 短暂不可达时该 tick 跳过（不更新基线、不产生虚假上下线），恢复后按真实差值补发。
