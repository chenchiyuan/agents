## 用户价值

别的客户端（codex、omp、claude）读一份文档就能接进来用，不用翻源码、不用问人；文档里的例子复制粘贴就能跑通。

## 验收标准

1. **文档存在且被入口指向**：仓库中存在独立的接口文档（`oamp/API.md`），且 README 的 HTTP 段有指向它的链接（W7 / TC-07 / M-8）。
   *判定*：文件存在；从 README 的 HTTP 段能点到它。
2. **覆盖全部接口**：对话列表（含搜索与过滤）、对话详情、关闭对话、批量归档、激活归档对话、重命名对话、发送消息、在线 agent 列表（只读）、按对话订阅实时事件、**全局事件订阅**——每个都有请求与响应说明（W7 / W6①③ / M-2）。
   *判定*：按 F04 验收 1 的对照表逐项检索，每个接口都能在文档中找到请求与响应两部分。
3. **覆盖统一约定与错误**：文档开头给出接口总览与统一约定（含**统一错误契约**）；每个接口列出其可能出现的错误情形与对应结果（W7 / W6④ / M-8）。
   *判定*：逐接口检查错误小节存在；按 F06 验收 2 的清单对照，文档无遗漏。
4. **覆盖事件清单**：列出事件的类型清单与订阅方式，**至少含 agent 上线 / 下线**（W7 / W6③ / M-6）。
   *判定*：事件清单中能找到上线与下线两个方向，且有可执行的订阅说明。
5. **示例可直接粘贴执行**：文档中的示例（命令行调用 + 事件订阅）**可直接复制粘贴执行并成功**，无需修改（W7 / TC-07 / E7）。
   *判定*：原样照抄文档中的示例到终端执行，逐条成功；不做任何参数替换以外的修改。
6. **独立接入闭环可判定**：一个**只读该文档、不读源码**的人或客户端，能按文档完成——列对话 → 读消息 → 发消息 → 订阅事件 → **收到 agent 上下线事件**（E7）。
   *判定*：照抄文档逐步执行，全程不读源码、不询问作者，最后订阅端确实收到上下线事件；闭环中每一步都能在文档中找到依据。

## 边界（不包含）

- **不实现客户端 SDK / 适配器**（N11）——交付物是接口 + 文档，接入实现属各客户端自身。
- **不含 agent 启停相关说明**（该能力不存在，N1 / N2）。
- **不含鉴权 / 跨机接入说明**（本迭代不做，N4 / N6）。
- **不含 tasks 相关说明**（N5）。
- 不含 **README 既有 HTTP 表之外的文档重构**——只要求新增指向 `API.md` 的链接与必要的状态段说明（既有表是否保留、如何组织属实现细节）。
- 文档内的接口路径、字段与事件名**以架构阶段的契约为准**——本卡只锁"覆盖什么"与"能不能照着跑通"。
