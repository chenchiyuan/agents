# F06：统一错误契约（所有接口一致的错误响应语义）

**功能 ID**: F06
**来源**: `demand.md` W6④；效果 E7 / E8 的可接入性前提；边界 N2 / N4 / N6 / N13；现状缺口 F-11（各接口错误体形态不一）
**迭代**: 0015-hub-orchestration-open-api

---

## 用户价值

客户端不用为每个接口单独猜「出错时它到底回什么」——同一类错误，不管从哪个接口进来，看到的都是同一种说法，写一次错误处理就够了。

## 验收标准

1. **同类错误跨接口响应一致**：对同一类错误（未知对象、参数非法、只读对象被写、请求体过大 / 格式错误），不同接口返回的**错误响应结构一致**、**状态码语义类别一致**（W6④）`[user_confirmed MI-07]`。
   *判定*：至少取两个不同接口，分别触发同一类错误，比对错误响应结构与状态码类别是否一致。
2. **逐接口错误语义可枚举**：每个接口可能出现的错误情形都能被列出，并对应到固定的状态码语义（W6④）。
   *判定*：按接口清单逐条触发其错误情形，观察结果与清单一致；不存在"清单没写、实际会出现"的错误。
3. **错误可读且不静默**：错误响应携带**足以定位原因**的说明（属于哪类错误、涉及哪个对象），且同一类错误的说明形态一致；不出现"请求失败了但既无错误标识也无说明"的静默失败（W6④）`[user_confirmed MI-07]`。
   *判定*：逐类错误观察响应内容，均有可读说明；随机抽 2 个接口的同类错误，说明形态一致。
4. **既有接口的错误语义不回退**：既有接口原本会报错的输入**仍然报错**，不因统一化被吞掉、被改判为成功或被模糊成无差别错误（W6⑤ / N13）。
   *判定*：对既有接口逐条用原先会失败的输入实调，仍然失败，且失败原因仍可区分。

## 边界（不包含）

- 不含**错误响应体的具体字段名与状态码取值**——属架构维度，阶段 3 已定案（见下「架构维度」段）；本卡只锁"同类一致、可枚举、可读、不回退"四项可观察性质。
- **不含鉴权类错误**（本迭代不鉴权，N6）。
- **不含跨机相关错误**（N4）。
- **不含 agent 启停相关错误**（该能力不存在，N2）。
- **不改接口的路径与方法**（F04），也不改业务成功路径的语义（N13）。
- 不含**错误契约的文档化**本身（F07）——本卡只要求契约成立，F07 要求它被写进文档。

## 架构维度（阶段 3 已填，2026-09-12；详见 `architecture.md` §5 全节 / §11 AR-06；**硬契约 ③**）

> 以下为阶段 3 定案；产品维度逐字未动。

- **AR-06-a 契约形态**：响应体 = `{ "error": "<人类可读说明>", "code": "<机器码>" }`。**`error` 仍是字符串，且既有全部文案逐字不变**（既有前端 `api()` 与既有调用方零改动）；`code` 为新增的**封闭枚举**，与状态码**一一映射**：`INVALID_PARAM`=400（参数非法 / 缺失 / 请求体格式错误）、`NOT_FOUND`=404（未知对象 / 未知路径或方法不匹配）、`CONFLICT`=409（只读对象被写 或 对象当前状态不允许该操作，如"未归档无法激活"）、`PAYLOAD_TOO_LARGE`=413（请求体超限，响应仍带 `connection: close`）、`UPSTREAM_UNAVAILABLE`=502（Router 不可达 / 内部故障兜底）。成功响应**不加** `code`；`POST /api/messages` 的派发失败仍是 **200 + `warning`**（业务结果非 HTTP 错误，语义不变）。UDS 协议层的 `ERR` 机器码（`rpc.js`）与本契约**不同层、不合并**。
- **AR-06-b 回填范围与顺序**：实现 = `web.js` 内 `ERR_CODE`（冻结表）+ `sendError(res, status, code, message, headers?)`（**唯一构造点**）；12 处错误出口按 6 步顺序改道：① 引入符号 → ② 逐路由把 `sendJson(res, <4xx/5xx>, {error})` 换成 `sendError(...)`（**同一 message 逐字搬运**）→ ③ `readBody` 失败分支按 `err.status` 映射（400 / 413，保留 413 的 `connection: close`）→ ④ 外层 catch → `502 UPSTREAM_UNAVAILABLE`（文案不变）→ ⑤ 测试 → ⑥ 文档。**既有测试零改写**（唯一疑似需改写者 `/api/stream` 缺参 400 已被保留）。**无需兼容过渡期**（`error` 字符串从未改变，不引入双形态）。
- **AR-06-c 一致性维护**：`API.md` 的接口清单 = `web.js` 的实际路由集合；错误章节 = `ERR_CODE` 的 5 个键；事件章节 = `transport.publish` + `publishGlobal` 的全部调用点 —— 三者以**代码为唯一真源**逐条对照（阶段 5 收尾检查项、阶段 6 复核）。每个接口小节必须列出该接口会出现的**全部** `code`（验收 2 的"可枚举"）。
