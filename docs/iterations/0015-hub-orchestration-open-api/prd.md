## 本次迭代边界说明

### 包含

- **顶栏 agent 只读列表**（W3 → F01）：顶栏「已连接 · N agents online」可点击展开；逐项呈现实例标识 / 在线状态 / 最后心跳时间（相对表示）；只列在线实例，列表条数 = 计数 = 在线实例数；列表内零启动 / 关闭 / 断开入口。
- **列表自动更新**（W4 → F02）：其他终端起停 agent 后，浏览器不做任何手动刷新，列表与计数在数秒内反映变化。
- **心跳两档自适应**（W5 → F03）：有任务时保持现状频繁档（10 秒级）；连续 60 秒无任务后降到 1 分钟一次；收到任务立即恢复频繁档。三条硬约束同等生效——空闲不得被判离线、不得改变实例身份与会话绑定（对话上下文连续）、判活阈值与心跳间隔联动维持不变式。
- **开放接口面**（W6①②⑤ → F04）：网页上每项功能都有对应接口可调通（含只读 agent 列表）；既有接口路径与方法零破坏；无 agent 启停接口；维持本机、无鉴权的既有安全边界。
- **全局事件流**（W6③ → F05）：不依赖具体对话即可订阅，至少覆盖 agent 上线 / 下线；既有按对话订阅形态不变；不做消息内容全局广播。
- **统一错误契约**（W6④ → F06）：同类错误跨接口响应结构一致、状态码语义一致、携带可读说明；逐接口错误语义可枚举；既有接口错误语义不回退。
- **接口文档**（W7 → F07）：独立文档 `oamp/API.md` + README HTTP 段链接；覆盖全部接口 / 事件 / 统一约定 / 错误；示例可直接粘贴执行；只读文档即可完成接入闭环。
- **连接与注册语义不变**（W1/W2 → F08）：仍只有「agent 主动连入」一种方式；注册 / 心跳 / 注销语义、实例标识校验、同名顶替规则、拓扑查询语义均保持现状；既有 agent 零代码改动可接入。

## 拆分理由（原子粒度判断）

**总原则：按"可独立出现的失败"拆卡，并优先与仓库现状中的独立缺口一一对应**（`demand.md` §3.3 的缺口清单与 F-10~F-15 是本迭代拆卡的地基）。

- **列表块拆 2 张（F01 / F02）**：现状里这是**两个独立缺口**——F-10 说明现在只有一个计数、没有任何列表（缺"能看"），同一处又说明刷新只发生在初载与窗口聚焦（缺"实时"）。只做列表不接推送 → F01 过、F02 败；只做推送没有列表 → 不存在可观察对象。两者的观察窗口不同（打开列表看一次 vs 不操作盯着看），因此各自可独立测试、独立交付。
- **F01 承载"字段、只列在线、计数口径、零写操作、空态"**：这些都是"列表这一屏是否正确"的同一观察面，共用一个展开动作；拆开会产生"没有列表却要验收字段"的不可交付卡。
- **心跳只拆 1 张（F03）**：两档行为与三条硬约束是**同一机制的两个观察面**——降频一旦导致掉线或换会话，就不是可交付的降频（数量上表现为"降了频但把人搞掉线了"，这是失败而非部分成功）。但三条硬约束**单列为验收 5/6/7**（C-2 是本迭代唯一硬约束），保证可单独判定、单独失败、单独追溯到 AR-03。
- **心跳与列表不合并**：二者无数据依赖与交付依赖（`demand.md` §4.2 已确认三块完全独立），失败互不蕴含。
- **接口块拆 3 张（F04 / F05 / F06）**：对应三个独立的现存缺口——F-11 说明接口大体已在、但**错误体形态不一**（缺"错误统一"）；F-12 说明 SSE 强制 `chat_id`、**agent 上下线无法被推送**（缺"全局订阅"）；W6①⑤ 则是**接口覆盖与零破坏**的契约面（对应 E8 的对照实调与 E9 的反向验证）。三者的失败互不蕴含：接口齐全但错误体五花八门、接口齐全但订阅不到上下线、都能调通但破坏了既有调用方。
- **文档独立成卡（F07）**：F-15 说明现有文档不足以让外部客户端接入（缺"可照抄的接入路径"），其失败模式是"接口都对，但别人接不进来"，与接口本身的正确性正交，且有专属裸判定 E7。
- **F08 独立成卡（回归约束）而非常规功能**：W1/W2 是"保持不变"的承诺，其失败模式是"新增的接口面 / 心跳改动污染了既有连接语义"（N7 明确点名 register 校验、session 生成、latest-wins 顶替、租约判活）。这是本次改动**新引入**的回归风险，必须有独立可测的承载（否则该风险无人验收）；体例沿用 0014 的 F05（回归卡）。本卡只声明"既有行为保持不变"，**不新增任何能力**。
- **未单立"受影响既有契约同步"卡**：`demand.md` §3 列出的已知受影响契约（README HTTP 表与 Web 控制台段、顶栏渲染与 nav 项、既有测试回填）属实现的已知成本，不构成独立功能能力，列为全局**架构维度** AR-07，不另立卡片（另立会构成 demand 之外的新增功能点）。
- **卡片数量（已裁决，2026-09-11）**：主 agent 提示建议 3~5 张，本阶段按上文"独立缺口 + 独立失败"判据拆为 **8 张**；**主 agent 已裁决接受 8 张、不合并**（每张有独立失败模式，与 E/W 判定面一一对应）。曾列出的合并备选（F01+F02 等 → 6 张）**不启用**。
