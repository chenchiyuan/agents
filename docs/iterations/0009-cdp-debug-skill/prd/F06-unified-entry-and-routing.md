# F06：统一入口与三层链路选路编排

## 功能 ID
F06

## 来源
`demand.md` §1 诉求（"需要页面调试的部分都能使用此 skill……建立开发/验证/测试循环"）、W2（"以用户三层链路为策略骨架"）、需求结论 §1（"一次触发、按需选路、证据闭环"）、澄清依据 §4.2（三层共享同一浏览器实例为前提）。

## 用户价值
把散落在各工具/链路的页面调试能力收编为一个**统一编排入口**：一次触发后按任务特征自动选路（主链路/诊断/登录态或其组合），形成"自动操作 → 失败深诊 → 登录态续调"的闭环，用户不需要自己拼装三层工具。

## 验收标准
- [ ] SKILL.md Workflow 定义**显式选路判据**：三类任务特征（①需自动操作与断言 ②测试失败/异常需排查 ③需保留登录态续调）各自对应链路（主链路/诊断链路/登录态链路），评审者可据此唯一确定路由
- [ ] 组合场景有明确编排规则：需登录态的任务先经登录态链路就绪、再执行主链路/诊断；主链路自动操作失败（断言不通过/页面异常）转诊断链路深诊——接力链路共享同一浏览器上下文（前提见 F09）
- [ ] SKILL.md 明示各链路的工具归属并指向对应章节（主链路→@playwright/mcp 见 F07；诊断→chrome-devtools-mcp 见 F08；登录态→CDP 直连独立 Chromium 见 F09），本 skill 不重复实现链路能力本身
- [ ] 文档明确"主链路 MCP 未配置时的可执行路径"是编排流程的前置分支（指向 F10），不阻塞文档完整性

## 边界（不包含）
- 不包含各链路的具体能力与验收（分别由 F07/F08/F09 处理）
- 不包含 MCP 未配置时的降级机制细节（由 F10 处理，`[架构待填]`）
- 不包含"三层共享同一浏览器实例"的具体连接技术方案（`[架构待填]`，demand §3 项 1——阶段 3 核实）
- 不包含与既有页面工具的分工细则（由 F12 处理）

## 架构维度

> **阶段 3 补全（architecture.md 决策 D1）**：
> - **连接机制（核实通过，无需替代路径）**：单一实例 = 独立 Chromium（CfT，C-6）由 `scripts/cdp-browser.sh start` 启动（`--remote-debugging-port=9222` 可换 + `--user-data-dir=profiles/<name>`）；@playwright/mcp 以 `--cdp-endpoint=http://127.0.0.1:9222`（E3 核实支持）、chrome-devtools-mcp 以 `--browser-url=http://127.0.0.1:9222`（E4 核实支持）附着同一端点 → 三层操作同一浏览器进程、同一 user-data-dir。
> - **"上下文连续"精确语义**：连续 = 同进程 + 同 profile 的 cookie/localStorage/会话状态；不承诺两 MCP 同时附着同一 page target（U5 操作注记：target 附着失败时 navigate 同 URL 复现取证）。
> - **登录态层承担工具（重估收口）**：不设独立登录工具；登录交互走主链路 @playwright/mcp（Form A 下即共享实例），chrome-devtools-mcp 为诊断复核补充；策略层表述"登录态就绪 = 实例 + profile 就绪"，不锁死具体工具（demand §4.2）。
> - **时序**：任何链路先 `cdp-browser.sh status` 未运行则 start；chrome-devtools-mcp 工具首用才连（官方 note）；@playwright/mcp 连接时机未见明文（U1）→ SKILL.md 推荐"先起浏览器再开会话"稳妥路径；MCP 连接错误 → blocked（target_error）+ 恢复指引。
> - 组合编排规则（本卡验收 2/3 的实现基础）：需登录态 → 登录态链路就绪 → 主链路/诊断；主链路失败 → 转诊断链路深诊（D1）。
