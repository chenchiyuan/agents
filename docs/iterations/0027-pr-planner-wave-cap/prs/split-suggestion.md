# split-suggestion.md 格式规范（参考文件，非运行时产物）

**说明**：本文件定义 `prs/split-suggestion.md` 的格式规范，供 pr-planner 在触发"合并受阻"时参照产出真实文件。本文件本身不是运行时产物——真实的 `split-suggestion.md` 只在 pr-planner 执行 Work 阶段"关键路径压平"合并循环、合并前置检查判定违反锚点时才会创建，格式规范见下方模板。

---

## 格式模板

```markdown
# 建议拆分为多个迭代

**触发原因**：合并循环在关键路径长度 {N} 处停止——继续合并候选对
{pr-A} → {pr-B} 会违反 {逻辑原子性/可审查性} 锚点：{具体说明}

## 拆分建议

### 迭代 1（本迭代继续处理）
- 功能点：{F-ID 列表}
- 覆盖 PR：{pr 文件名列表}

### 迭代 2（建议发起新迭代）
- 功能点：{F-ID 列表}
- 覆盖 PR：{pr 文件名列表}

## 依据
分割点：{pr-A} → {pr-B} 依赖边。{pr-B} 及其全部下游 PR 划入迭代 2；其余 PR
（{pr-B} 的祖先链 + 与分割点无依赖关系的独立分支）划入迭代 1。
```

---

## 章节说明

### 触发原因

必须包含三项具体信息：
- 合并循环停止处的关键路径长度（数字 N）
- 触发违反的候选对（{pr-A} → {pr-B}）
- 违反的具体锚点（逻辑原子性或可审查性）及具体说明——不能只写"违反了锚点"而不说明为什么

### 拆分建议

迭代 1 与迭代 2 各列出：
- 功能点：该迭代覆盖的 F-ID 列表（来自各 PR"涉及功能点"字段的汇总）
- 覆盖 PR：该迭代包含的 PR 文件名列表

迭代 1 是"本迭代继续处理"的部分，迭代 2 是"建议发起新迭代"的部分。

### 依据

说明分割点选取依据与拆分边界算法：以触发违反的相邻依赖对 (A→B) 为分割点——B 及其在依赖图中的全部下游（依赖 B 的 PR，递归）划入迭代 2；其余全部 PR（B 的祖先链、以及与该分割点无依赖关系的独立分支）划入迭代 1。这保证迭代 1 不依赖迭代 2 的任何产出，两个迭代可先后独立执行。

---

## 性质

这是"建议"，不是 pr-planner 自行执行的动作——不自行创建新迭代目录、不改动 demand.md，只落盘该建议供主 agent 在方案确认门里呈现给用户做最终选择（见 `roles/workflow-pb/workflow-pb.md` §方案确认门）。
