## 并发可行性判断（为什么这么拆或为什么不拆）

### 判断依据（demand.md 结论 #8/#9 + architecture.md §F05）

本次拆分**必须**以"提高并发度"为前提：拆出一个独立 PR 前必须判断该 PR 与至少一个其他 PR 存在并发重叠窗口（在依赖图中两者互不可达，即可同时执行）。不能提高并发度的拆分判定为反向实践，应合并回其他 PR 或调整依赖关系，不单独拆出。

### 并发重叠窗口计算方法（复用 depends_on 依赖图）

PR-A 与 PR-B 存在并发重叠窗口，当且仅当在依赖图中 A 不可达 B、且 B 不可达 A（两者互不为对方的祖先/后继，没有依赖路径连接两者）。

### 为什么 PR-001 不拆：workflow-pb.md 与 SKILL.md 不能并发编辑

**候选拆分点考虑**：
- 候选 A：workflow-pb.md（F01/F02/F03/F04）独立一个 PR，SKILL.md（F01/F02/F03/F04）独立一个 PR
- 候选 B：F01/F02 一个 PR、F03 一个 PR、F04 一个 PR（按功能点拆）

**拆分点 A 不可行的理由**：两份文件是同一套协议的两层文本（规范源与宿主执行层），改写时需要逐条对照口径一致性（三要素/等价关键字段）——编辑 workflow-pb.md 的 F01 条款后，必须立即在 SKILL.md 对应章节对照写出 F01 条款的 SKILL 层表述，才能确认口径一致；拆为两个 PR 后，编辑者需要在两份文件间反复切换对照，编辑过程不可能并发执行（写 workflow-pb.md 时必须打开 SKILL.md 核对，写 SKILL.md 时必须打开 workflow-pb.md 核对），不存在真实的并发执行窗口。**判定为无并发收益拆分，合并回一个 PR**。

**拆分点 B 不可行的理由**：F01~F04 在两份文件中落点的章节相互穿插（F01 插"阶段定义"表之后、F02 改"启动工作流"、F03 改"需要用户决策的情况"、F04 改"验证目标"），每张卡改完都要在两份文件间对照口径一致性；拆为三个 PR 后，需要反复对照的次数从 1 次（合并 PR 改完一次性对照）变为 3 次（每个 PR 改完对照一次），且三个 PR 编辑时仍需频繁切换两份文件核对对应章节，不存在"可以独立编辑各自章节、互不干扰"的并发执行窗口。**判定为无并发收益拆分，合并回一个 PR**。

### 为什么 PR-002 独立：pr-planner.md 与其他文件无内容耦合

F05 改动完全落在 `pr-planner.md` 一个文件内（Strategy 新增"并发可行性"维度 + Workflow Verify 新增检查项），与 workflow-pb.md/SKILL.md/demand.md 改动的条款无重叠、无引用关系——编辑 pr-planner.md 时无需打开其他三份文件核对任何内容；编辑 workflow-pb.md/SKILL.md/demand.md 时也无需查阅 pr-planner.md 的改动。**四份文件可真正并发编辑**，拆为独立 PR 可让 PR-002 与 PR-001/PR-003 同时执行，提高并发度，满足并发可行性推进条件。

### 为什么 PR-003 不拆：demand.md 四章节内容互相衔接

**候选拆分点考虑**：
- 候选 C：F06（Align 角色反射）一个 PR、F07（Plan 调研摘要）一个 PR、F08（Work 深挖机制）一个 PR、F09（Verify 解耦）一个 PR

**拆分点 C 不可行的理由**：F06~F09 改动的是同一份文件的 Align/Plan/Work/Verify 四个章节，内容互相衔接——F07 依赖 F06 反射产出的"维度列表"格式（需知道维度如何命名和传递）；F08 依赖 F06+F07 的维度列表和优先级排序（Work 挑选"当前深挖维度"的依据）；F09 依赖 F06 的角色反射定义来描述"六维诊断与角色反射维度是两套独立的东西"（需引用 F06 定义说明解耦关系）。拆开后会导致中间状态不一致：
- 若先合并 F06 PR，Align 已有角色反射但 Plan 还在用旧的六维诊断调研 → demand.md 流程在 Align→Plan 断裂
- 若先合并 F07 PR，Plan 要求输入"角色反射产出的维度列表"但 Align 还未产出该格式 → F07 文字引用了不存在的 F06 定义
- 若先合并 F09 PR，Verify 文字说"六维诊断与角色反射维度解耦"但 Align 章节还未定义角色反射 → F09 引用了不存在的 F06 概念

四个章节是一次连贯的机制替换（从"固定用六维诊断驱动所有讨论"替换为"角色反射→调研摘要→深挖收敛"新机制），拆开编辑无法避免部分改写、部分未改写的中间状态，不存在"可以独立改写各章节、互不影响"的并发执行窗口。**判定为无并发收益拆分，合并回一个 PR**。
