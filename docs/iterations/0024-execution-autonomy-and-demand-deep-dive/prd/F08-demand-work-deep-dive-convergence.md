# F08 · demand.md Work 循环替换为"同维度深挖优先+维度收敛状态标记"，无轮次硬上限

**来源**：demand.md 做什么#5（Work 循环部分）；结论 #11 #13

## 用户价值

用户提出的问题会被顺着往深处问，而不是每次换个话题浅浅问一句就跳走；同时用户能随时看到"哪些维度已经问透了、哪些还在问、问到第几轮"，讨论进度是透明的，且不会被一个固定的轮次上限强行截断。

## 验收标准

1. `demand.md` 的"Work（工作）"章节的微循环描述，替换为以下机制（原有的"六维诊断驱动循环"描述被移除或改写，不再驱动 Work 节奏）：
   - 同一维度有更深的问题可问时，优先继续深挖同一维度，不切换到别的维度；
   - 只有当前维度"问不出更深的问题"时才切换到下一个维度；
   - 用户给出好的回应时，不表扬，直接顺着问更深的问题。
2. 该章节要求每个维度显式标记收敛状态，状态取值至少包含：未开始 / 深挖中第N轮 / 已收敛，且这些状态标记在讨论过程中对用户可见（不是只在角色内部记录）。
3. 该章节明确 Work 循环**不设轮次硬上限**，退出条件仅为以下两者之一：所有维度都已标记为"已收敛"，或用户明确表示"够了"/等价的终止意愿。
4. 该章节不包含 `pb-v1-talk` 的 5 轮硬上限机制（demand.md 明确选择不采用这一上限）。

## 边界（不包含）

- 不改变 Align 阶段和 Verify 阶段的机制——本卡只覆盖 Work 循环本身。
- 不规定"维度收敛状态标记"具体用什么符号或格式呈现给用户。**[架构已填]**：采用行内文本列表，附着在每轮提案消息前，格式为`- {维度}:{状态}`，状态取值`未开始`/`深挖中-第N轮`/`已收敛`。理由见 `architecture.md` §变更映射 F08。
- 不修改 `pb-v1-talk` 文件本身。
