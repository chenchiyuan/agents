# F03 · 阶段4/5用户决策点收窄为两项硬暂停

**来源**：demand.md 做什么#2；结论 #4 #5 #6

## 用户价值

进入 PR 规划和 PR 实现阶段之后，用户不会因为非结构性的小问题反复被打断，只有在真正需要人工决策的两种结构性场景下才会被叫回，执行效率不被"礼貌性确认"稀释。

## 验收标准

1. `workflow-pb.md` "需要用户决策的情况"章节中，明确区分"阶段1~3适用"和"阶段4/5适用"两类范围；阶段4/5范围**仅列出两项**：
   - `pr-planner` 报告依赖图有环；
   - 执行角色报告"阻塞"，且主 agent 无法在不修改上游产物的情况下解决。
2. 该章节明确：阶段4/5产物中出现的 `[model_inferred]` 标注**不再触发暂停**（与阶段1~3的处理方式不同，这是有意的范围收窄）。
3. 阶段4/5中执行角色发现的需求层问题，仍按现有 `deferred-demand-changes.md` 机制记录后继续，不暂停、不回退——本次改动不引入新的处理路径，只是明确"这不算需要暂停的用户决策点"。
4. `SKILL.md` 中"§用户决策点与暂停格式"章节同步以上范围收窄，口径与 `workflow-pb.md` 一致。

## 边界（不包含）

- 不改动阶段1~3的用户决策点范围（demand.md 明确要求维持现状）。
- 不新增"轮次上限"式的兜底暂停（demand.md 明确否决这一路径）。
- 不改动 `deferred-demand-changes.md` 本身的记录格式或写入时机。

## model_inferred

无——本卡的验收标准直接来自 demand.md 结论 #4/#5/#6 的原文表述，未做超出原文的推导。
