## 本次迭代边界说明

### 包含

- 把 `workflow-pb.md` 阶段 5 的并发调度协议文字落实为主 agent 实际执行时遵守的调度纪律，达到可观察的并发执行效果（F01）。
- 起始并发数可配置（默认 3）+ 允许向上爬升 + 存在高于起始值的硬上限，这一行为契约本身（F01、F02）。
- 并发槛位释放与 PR 状态（合并/失败/阻塞）绑定，与 worktree 现场清理与否解耦（F03、F04）。
- 失败/阻塞 PR 的 worktree 现场保留、不自动清理这一行为契约（F04）。
- 确认现有两条正确性保证（合并解锁、文件范围无重叠）在并发场景下继续生效，不新增语义耦合检测（F05）。

### 不包含

- 不改 `pr-planner` 的 `depends_on` 依赖判断逻辑本身。
- 不新增语义耦合检测机制。
- 不改变 PR 粒度判断标准（逻辑原子性/可审查性/独立性三条锚点维持不变）。
- 不做具体的并发调度技术实现选型（用什么工具/API 发起并发子 agent 调用）。
- 不锁定爬升算法公式和硬上限的具体数值。
- 不锁定长期理想并发度——起始值 3 和当前爬升机制是过渡期保守选择，不是本次要固化的最终产品决策。
