# MVP 范围边界 - Round 1

## 大原则确认

### 目标
理清 agents 项目 MVP 范围，确定五层能力（原则沉淀、agent 构造器、标准协议、主子协作、反思迭代）的启动顺序和第一步的具体验证对象。

### 范围
- 包含：五层能力的启动顺序、原则来源分层、首个真实 agent 的选择
- 不包含：agent 构造器的具体实现、跨项目复用的技术形式（另见其他维度）

---

## 讨论清单

### CLR-MVP-001: 五层能力是否同时启动
- **模糊点**：用户最初回答"都做"，但五层之间存在依赖关系（构造器依赖原则和标准结构，反思沉淀依赖真实案例）
- **影响范围**：整体项目启动节奏，避免在无真实验证的情况下同时优化五个空中楼阁
- **推荐选项**：顺序启动——先跑通一个真实 agent（原则+标准结构+文档化派发同时产出），再抽象构造器，再做反思沉淀，最后打包复用
- **结论**：同意顺序启动，不砍范围（五层都要做，但不同时做）
- **来源分类**: user_confirmed
- **状态**: 生效
- **确认时间**: 2026-09-01

### CLR-MVP-002: 首个真实 agent 选哪个角色验证
- **模糊点**：pb-v1-* 角色有十几个（implementing/debug/verifier/demo/...），MVP 第一步该验证哪一个
- **影响范围**：决定第一步具体验证哪套原则、产出什么标准结构范本
- **推荐选项**：pb-v1-implementing——对应 base.md 的 developer 角色，约束还原+TDD，是最基础的执行者，验证难度最低，能最快跑通闭环
- **结论**：确认选 pb-v1-implementing 作为首个验证角色
- **来源分类**: user_confirmed
- **状态**: 生效
- **确认时间**: 2026-09-01
