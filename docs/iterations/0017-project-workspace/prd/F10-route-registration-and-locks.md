## 用户价值

新加的项目类接口**不会变成"文档里查不到的黑接口"**——它自己长到文档页、调试台和给 AI 看的索引里；谁漏登记，测试当场变红并指出漏在哪。

## 验收标准

1. **三面自动出现**（C-6 / E8）：新增的项目类 HTTP 面自动出现在文档页、调试台、面向 AI 的索引文件三处，**不需要手改这三处的任何实现**。
   *判定*：刷新三面，逐面核对该接口在场。
2. **对外契约文档路径行**（C-6）：新增路由在 `oamp/API.md` 中有对应的路径行（满足路径级双向覆盖）。
3. **三条漂移锁全绿**（C-6 / E8）：元数据必填锁 / 索引快照逐字节锁 / 契约文档路径级双向覆盖锁全部通过。
   *判定*：运行既有测试命令（`npm test`）。
4. **零依赖锁保持**（N12 / E8）：依赖清单仍为空。
5. **新增登记不改变既有接口行为**（C-6 / N13）：新增登记不引起既有接口的任何可观察行为变化（与 F09 互为补充，**不互相替代**）。

## 边界（不包含）

- 不含新接口的能力本身（→ F01 / F02 / F03）。
- 不含对 `API.md` 文案 / 章节 / 示例完整性的要求（**只要求路径行**，沿用 0016 的锁口径）。
- 不含 OpenAPI / Swagger 一类第二套规范（0016 已确立的边界延续）。
- 不含漂移锁机制本身的改造（三锁与登记机制已在上一迭代交付；本卡只要求它们继续通过）。
- 不含零依赖之外的其它工程质量面（格式化、覆盖率等未被要求的门禁）。
- 不含既有接口的回归验证（→ F09）。

## 架构落地（阶段 3 已填，见 `architecture.md` §6 全节；产品维度未改一字）

- **T-07 / T-14 登记形态**：两条新面**追加在既有路由表末位**（第 12 / 13 条表项，既有 11 条的表序与内文逐字不动）：`GET /api/projects`（`summary` = 项目列表（含对话数与最近活动时间）；`params: []`；`response` = `对象 { projects: [{ project_id, name, repo_url, created_at, chat_count, last_activity_at }] }`；`errors: []`；`kind: 'json'`；`docLink: 'API.md#312-get-apiprojects'`）与 `POST /api/projects`（`params` = `repo_url`（body / string / 必填）+ `name`（body / string / 可选）；`response` = `对象 { project: { project_id, name, repo_url, created_at } }`；`errors: ['INVALID_PARAM','CONFLICT']`；`docLink: 'API.md#313-post-apiprojects'`）。两条路径与既有表项**无前缀吞并关系**（`GET /api/chats/:chat_id` 只吞 `/api/chats/…`）⇒ 不触发可达性断言的插位规则。
- **T-14 三面与索引快照**：`/docs` 与 `/debug` 页面**零改动**——两页均是 `GET /api/docs` 投影的消费方（调试台零硬编码路径、写防护按 `danger = method !== 'GET'` 派生）⇒ 验收 1 的"不需要手改这三处的任何实现"由既有机制天然满足。`oamp/llms.txt` 用**既有脚本**重生成：`node oamp/scripts/gen-llms-txt.mjs`（标题自动变 `## 接口（13 条）`、清单自动 +2 行；**不手改快照**）。
- **T-14 `API.md` 的位置与写法**：`## 3. 接口清单（11 条）` → `（13 条）`；表格增 `| 12 | GET /api/projects |` 与 `| 13 | POST /api/projects |` 两行；正文增 `### 3.12 \`GET /api/projects\``、`### 3.13 \`POST /api/projects\`` 两小节（参数表 / 成功响应 / 错误表，体例照 §3.1~§3.11）。漂移锁③ 只要求**路径行**（本卡边界已明示），§5 示例与 `README.md` 的同步见 `architecture.md` §10.3 **D-03**（待主 agent 确认）。
- **三条漂移锁的通过方式**：① 元数据必填——两条新表项按上表填满 8 个字段，`errors` 取值 ∈ `ERR_CODE` 值集合；② 索引快照逐字节——重生成而非手改；③ 路径级双向覆盖——`API.md` 补齐两处反引号签名；零依赖锁——`dependencies` 保持 `{}`。
- **验收 5（新增登记不改变既有接口行为）**：既有 11 条的方法 / 路径 / 状态码 / 响应体 / 错误文案逐字不变；新错误的码**全部取自既有封闭枚举**（`400 INVALID_PARAM` ×4 种文案与 `409 CONFLICT`，见 `architecture.md` §6.4）；新路径用错动词仍走既有 `not found: <方法> <路径>` 404 兜底（**不引入 405**）。
