# F07：项目上下文的内容与 agent 侧注入（含产物落点约定）

**功能 ID**: F07

**迭代**: 0017-project-workspace
**技术锚点（引用 `demand.md` §3 只读实测，非本阶段决策）**: F-13（角色文件真源 = `OAMP_ROLE_ROOT` 的 `roles/<role>/<role>.md`，明确不读 `.pb-agents/` 副本）、F-11（常驻上下文子进程 cwd 是进程级常量，不随对话变化）、F-12（工具开关随 agent 实例固化）、F-14（`cluster.json` 的 per-role `cwd` 属集群编排配置）

## 用户价值

agent 每次开工前都知道自己在哪个项目、代码在哪、产物该写到哪——不用人再解释一遍；但也别指望系统替它把目录准备好（这不在本次承诺里）。

## 验收标准

1. **内容三要素**（W4 / M-6）：上下文含 ① 项目名 ② 仓库地址 ③ 一段**相对**工作约定。
2. **约定为相对约定、无绝对路径**（W4 / N3 / B-3）：内容中不出现任何本地绝对路径，也不出现"某台机器上的目录"。
   *判定*：读注入内容，检索本地路径字样（如以 `/` 或盘符开头的目录串），应无命中。
3. **约定覆盖三件事**（W4 / W5 / B-3）：① 本地不存在则该仓库需 clone（落点由 agent 自选）；② 在该仓库根目录工作；③ 迭代产物（docs / PR / commit / 分支）写入该仓库。
   *判定*：读约定文本，逐条对照三件事。
4. **由 agent 侧注入**（P-4 / E9）：项目上下文由 agent 侧注入到它面向模型的工作上下文中，不由 web 拼进用户消息正文（与 F06 验收 4 同源，两侧共同保证 E9）。
5. **传达可核对**（E5）：在项目 A 的对话发一条消息 → agent 侧执行记录（任务载荷 / 集群窗口日志）中出现项目 A 的**仓库地址字符串**。
   *判定*：检索该地址字符串，**出现即真**（只判"出现"，**不判 agent 是否真的 clone**，C-4）。
6. **产物落点约定随上下文下达**（W5 / M-5）：上下文明确"PR / commit / 迭代文档 / 分支落该项目仓库"。
7. **不出现超能力承诺**（N14 / C-4）：上下文与产品文案中不出现"系统会自动在项目根目录工作 / 自动 clone 完成 / 已对齐目录"一类承诺。
   *判定*：检索注入内容与页面文案，无此类表述。

## 边界（不包含）

- 不含载体形态与路径范围（→ F06）。
- **不做 clone、不探测项目是否已存在、不代 agent 建目录**（N2 / C-2）。
- **不存本地路径、不在上下文写绝对路径**（N3 / M-1）。
- **不改角色加载路径、不引入 `.pb-agents` 安装机制**（N10 / D-4）。
- **不在运行时建"迭代"实体**：产物落点由这段约定表达，不在数据模型里新增层级（W5 / N11 / M-7）。
- **不承诺环境对齐**（N14 / C-4）：不保证 agent 自动进入项目根目录，也不保证工具开关状态（F-12 属 agent 侧部署）。
- 不含对话与项目的存储、接口、页面行为（→ F01~F05）。
- 不含"项目结构快照"一类注入（agent 自己 clone 后即可读，M-6）。

## 架构落地（阶段 3 已填，见 `architecture.md` §4.1 / §4.2 / §4.3；产品维度未改一字）

- **T-12 措辞（逐字契约，唯一真源 = `web.js` 的模块级常量 `PROJECT_AGREEMENT`）**：`本项目的工作约定（相对约定，不涉及任何本机路径）：① 若本地尚无该仓库，请先 clone 到自选落点；② 在该仓库根目录下工作；③ 迭代产物（docs 文档、PR、commit、分支）均写入该仓库。`——三件事齐备（验收 3）；**指引语气**、不含任何绝对路径 / 盘符 / 主机名（验收 2 / N3）；不含"系统会自动 clone / 已对齐目录 / 已进入项目根目录"一类表述（验收 7 / N14 / C-4）。agent 侧只渲染、不重写。
- **T-04 注入时机 = 首轮一次（常驻路径）/ 每次（一次性路径）**：
  - **常驻路径**（`omp-daemon`）——该 `(chat_id, agent_id)` 会话的**首个成功送达轮次**注入一次：判据 = `ContextSession.sentTurns === 0`，且**只有真正送达才消费名额**（`context_busy` 入队即拒 / `model_unavailable` 在 `session/prompt` 之前失败 / 会话崩溃 ⇒ 均不消费，下一个送达轮次补上）。会话被释放 / 崩溃 / 淘汰后重建 ⇒ **自动重新注入**（新会话需要重新交代项目）。与常驻上下文**累积语义**一致（后续轮次已在前文看到该块），且避免每轮重复注入的 token 成本与指令重复。
  - **一次性路径**（`omp`）——每次派发都注入（该路径 `--no-session`，无累积状态，"每次"是唯一正确语义）。
  - 未携带 `project` ⇒ **不注入**（prompt = 原文，向后兼容）。
- **T-04 注入点模块归属 = agent 进程内两处**：① 渲染 + 一次性路径施加 = `agent.js`（唯一渲染点，输出 `【项目上下文】` + `- 项目名 / - 仓库地址 / - 工作约定` 三行，施加为 `omp -p` 的 prompt 参数前缀）；② 常驻路径的一次性施加 = `context-pool.js` 的 `ContextSession`（`prompt()` 多收一个可选 `projectContext`，`_pump()` 内按 `sentTurns` 决定是否前缀）。**web 不产生任何注入文本、不碰 `messages.text`** ⇒ 验收 4 / E9 结构性成立。上下文池的**键 / FIFO 串行 / 队列上限 / LRU / 并发语义零变化**（只加一个只增不减的计数）。
- **T-08（与 F06 共用）**：`payload.body.project = { name, repo_url, agreement }`；可选字段、非法即视为未携带（不拒收）。
- **验收 5 的观测面（零新增机制）**：常驻路径 = fake ACP 回显 `session/prompt` 文本（`收到：【项目上下文】…<repo_url>…`）⇒ `out.text` 含仓库地址字符串；一次性路径 = `FAKE_ACP_ARGS_LOG` 的 argv 末位；载荷本体含 `project.repo_url`。**只判"仓库地址字符串出现"，不判 agent 是否真的 clone**（C-4）。
- **产物落点约定（W5）**：由 `agreement` 文本第 ③ 条表达，**不在数据模型里新增层级**（不建"迭代"实体，N11）；**不做**项目结构快照一类注入（agent 自己 clone 后即可读）；**不做** clone / 目录探测 / 代建目录（N2 / C-2）。
