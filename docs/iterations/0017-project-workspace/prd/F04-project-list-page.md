# F04：项目层入口（首屏项目列表页）

**功能 ID**: F04
**来源**: `demand.md` W3（入口侧）；决策 S-3 / P-6 / P-11；约束 C-7（UI 层必然变更）；边界 N1 / N4 / N5；效果 E1 / E2
**迭代**: 0017-project-workspace
**技术锚点（引用 `demand.md` §3 只读实测，非本阶段决策）**: F-6（`web/index.html` 单页控制台入口即全局对话列表 + 右栏详情，不存在项目列表页、项目选择器或设置面）

---

## 用户价值

打开控制台第一眼就是"我的项目"——先选项目再干活；不选项目就没有对话可看、也没有地方发消息，不会误在"无项目"的状态下发东西。

## 验收标准

1. **首屏即项目列表**（W3 / S-3 / E1）：未选择项目时打开页面，页面主体是项目列表。
   *判定*：刷新首页，看首屏是什么。
2. **未选项目时看不到对话、不能发消息**（E1）：首屏没有任何对话内容，也没有可用的发消息入口。
   *判定*：试着在不选项目的状态下发一条消息 → 无可用入口。
3. **首屏可新建项目**（W3 / S-4）：提供新建入口，最小输入 = 仓库地址，名称可留空。
4. **首屏可进入项目**（W3 / P-6）：列表中每个项目都能进入其工作台（→ F05）。
5. **列表信息量**（W3 / P-11）：每行显示 项目名 + 仓库地址 + 对话数 + 最近活动时间；后两项由既有对话数据派生，**不需要用户额外录入任何信息**（零新增存储）。
   - "最近活动时间" = 该项目下任一对话最近一次被更新 / 产生活动的时间；项目下无对话时显示空 / 占位而不报错〔`[user_confirmed MI-03]`〕（用户裁决原文：「最近活动取对话更新」）。
   - "对话数" = 该项目下的**全部**对话数（含已归档 / 已关闭）〔`[user_confirmed MI-04]`〕（用户裁决原文：「对话数含全部」）。
   *判定*：建 1 个项目 + 该项目下 2 个对话并发 1 条消息 → 列表中该项目的对话数为 2、最近活动时间不早于该消息时间。
6. **创建后列表即出现该项目**〔`[user_confirmed MI-05]`〕（E2 判定前提，用户裁决原文：「停留列表页」）：创建成功后停留在项目列表页，该项目**原地出现**（无需手动刷新），**不自动跳进**该项目工作台。
   *判定*：新建一次 → 页面停留在项目列表页（视图未跳进工作台），且新项目已在该页出现（无需手动刷新）。

## 边界（不包含）

- 不含工作台内的任何对话操作（→ F05）；不含对话范围过滤（→ F03）。
- **不做 GitHub 集成 / 地址校验**（N1）；**不做项目删除 / 改名 / 归档入口**（N5）；**不做多用户 / 权限视图**（N4）。
- 不含工作台顶栏与返回入口（→ F05）。
- 不含"最近活动时间"以外的统计面（不做活跃度排行、趋势图、最近 N 天等）。
- 不新增项目排序 / 搜索 / 分页等既有页面没有的能力（排序形态留架构 **T-11**）。
- 不含项目设置面（凭据、默认分支、成员等，N1 / N4）。

## 架构落地（阶段 3 已填，见 `architecture.md` §3.1 / §5.1 / §5.2 / §7.3；产品维度未改一字）

- **T-05 页面 / 路由划分与文件组织 = 单页内新增"项目层"视图**（**零新增静态资产、不改 `STATIC_FILES`、`/` 仍映射 `web/index.html`**）：`index.html` 新增 `<section id="projects-view">`（首屏项目列表视图：`#project-repo` / `#project-name` / `#btn-create-project` / `#project-list` / `#project-hint`）；既有 `main.layout`（含 composer）在未选项目时与 `#projects-view` / `#project-bar` 一起挂 `.hidden` ⇒ **看不到对话、没有可用的发消息入口**（验收 1 / 2）；`app.js` 新增项目层取数与渲染；`style.css` **只追加**规则（**必含 `.layout.hidden` / `.projects-view.hidden` / `.project-bar.hidden` 三条**——本仓 `.hidden` 逐组件定义、无全局规则，漏了会表现为"视图切换静默失效"）。**为什么不是两页**：两页方案要多一份顶栏副本、多两个 `STATIC_FILES` 条目，且 `GET /` 的既有断言（`web.test.js` 要求含 `Web Console`，`api-pages.test.js` 要求含 `/docs` `/debug` 两个 href）会从"天然成立"变成"靠复制维持"。
- **T-13 未选项目的状态载体**：`location.search` 的 `project` 参数 + `state.projectId`；`/`（无参数）或 `?project=<未知 id>` ⇒ **项目列表视图**，且**不调** `/api/chats`（不产生跨项目混列的可能）。
- **T-11 派生字段计算方式 = 服务端一条聚合 SQL**（`GET /api/projects`）：`chat_count` = `COUNT(chats.chat_id)`（含已归档 / 已关闭）、`last_activity_at` = `MAX(chats.updated_at)`（无对话为 `null`）；**零新增存储、零 N+1、零前端派生**（验收 5）。前端只做两件展示事：`null` 用既有 `fmtAgo()` 渲染为占位 `—`（不报错）；仓库地址原样展示。
- **项目列表排序**：`created_at DESC, project_id DESC`（**非**按最近活动排序）——新建项目落在首行，验收 6 的"原地出现"最直观；排序表达式不依赖派生聚合值，避免"活动一跳项目就换位、空项目沉底"。
- **验收 6 的落点**：创建成功后**不跳转**（停留项目列表视图），`app.js` 重新 `loadProjects()` 原地重渲染（一次请求，**不引入轮询**——既有前端静态契约"禁 POLL_MS"继续成立）；创建失败（409 / 400）的文案落 `#project-hint`。
- 项目行信息量 = 项目名 + 仓库地址 + 对话数 + 最近活动时间（四项全部来自 `GET /api/projects`，**不需要用户额外录入任何信息**）；无分页 / 搜索 / 排序控件（边界不变）。
