# F03：对话列表以项目为范围

**功能 ID**: F03
**来源**: `demand.md` W2（列表侧）；`派生` 次级口径（§6.3）；澄清 M-2 / M-4；约束 C-3 / C-7（必然变更点 ②）；边界 N4 / N13；效果 E3 / E4（部分）
**迭代**: 0017-project-workspace
**技术锚点（引用 `demand.md` §3 只读实测，非本阶段决策）**: F-5（`GET /api/chats` 的过滤参数为 `q / agent / state / from / to / archived` + `limit / offset`，无项目维度）、F-18（统一错误契约，`400 INVALID_PARAM`）

---

## 用户价值

打开一个项目只看到这个项目的对话——不会把别的项目的聊天记录混进来；也不会有人误以为"没有项目的对话"还留着。

## 验收标准

1. **列表以项目为范围**（W2 / M-2 / E3）：在项目 A 内查询对话 → 只返回归属 A 的对话；项目 B 的对话不出现。
   *判定*：项目 A / 项目 B 各有对话，逐个项目查询，结果互不包含对方。
2. **缺项目参数的列表查询被拒绝**（W2 / `派生` §6.3）：不提供项目范围的列表查询 → `400 INVALID_PARAM`，**不返回跨项目全量列表**；"缺参"含**未提供**与**提供空值**两种形态〔`[user_confirmed MI-08]`〕（用户裁决原文：「一律 400」）。
   *判定*：不带项目范围查询 → 4xx（400）；**带空值参数的查询同样 → 4xx（400）**；带项目范围 → 只返回该项目对话。
3. **切换项目即切换列表内容**（E3）：从项目 A 切到项目 B、或返回项目列表页，项目 A 的对话均不可见。
   *判定*：做三次切换（A → B → 项目列表页），逐次看列表内容。
4. **既有过滤与分页能力在项目范围内保持**（N13）：既有的搜索、按 agent、按状态、按时间范围、归档过滤与分页参数照常生效，语义不变，只是在项目范围内生效。
   *判定*：在项目 A 内使用既有过滤条件查询 → 结果与既有过滤语义一致，且全部属于 A。
5. **跨项目不混列在数据层可核对**（E4）：库中不同项目的对话行分别归属各自项目。

## 边界（不包含）

- 不含新建对话（→ F02）；不含项目列表页 / 工作台 UI（→ F04 / F05）。
- **不提供跨项目全量列表**（`派生` 口径；回退口见 `prd.md`「疑问与越界」1）。
- **不改与项目维度无关的列表行为**：过滤参数语义、排序、分页、错误契约、无 405 的 404 兜底逐条保持（N13）。
- **不按项目分库 / 分片**：对话库仍落本机运行时既有落点，不随项目搬家（C-3 / M-4）。
- 不含按"当前用户"的权限过滤（列表不随用户变化，N4）。
- 不含对话详情、消息内容、归档等操作本身（既有能力保持即可，→ F05 验收 6）。

## 架构落地（阶段 3 已填，见 `architecture.md` §3.2 / §7.4；产品维度未改一字）

- **T-06 参数形态**：在既有 `GET /api/chats` 上**新增必填查询参数 `project_id`**（**不新开路由**：验收 4 要求既有搜索 / agent / 状态 / 时间 / 归档过滤与分页在项目范围内照常生效，新路由会复制出第二套查询面）。`400` 触发条件（MI-08"一律 400"）：**未提供**（`null`）与**提供空值**（`''`）**都判非法** → `400 INVALID_PARAM`，文案 `查询参数非法: project_id 不能为空（对话列表以项目为范围）`——空值**不**沿用既有 `readOptionalString` 的"空值即无参"语义（那正是本次要消灭的口径）。
- **校验落点**：persist 层新增 `readRequiredString(value, 'project_id')` 抛错 ⇒ handler 既有 `try → sendError(400, INVALID_PARAM)` 原样接住，**零新增错误分支**（参数校验的既有落点在 persist，新增项同址）。
- **过滤构造**：既有单行参数 CTE 增第 7 列 `project`，`LIST_FROM` 增 `AND c.project_id = p.project`；`listChats` 与 `countChats` **共用 `LIST_FROM`** ⇒ 结果集与 `total` 同源（不会出现"列表过滤了、总数没过滤"）。**响应形状零变化**：仍是 `{chats, total, limit, offset}`，`chats` 行内字段逐字不变（**不含** `project_id`）。
- **T-01 索引**：`idx_chats_project_updated(project_id, updated_at DESC)` 服务"按项目取列表 + 默认排序 `updated_at DESC`"。
- **不做存在性判定**：`project_id` 指向未知项目 ⇒ 返回空列表（`200`）。F03 未要求"项目不存在"的报错，且在既有查询面里加一次存在性查询会引入第二个判定层、且不泄漏任何数据。
- **前端范围**（验收 3 / 5）：工作台 `loadChats()` 与 `loadArchived()` 一律带 `state.projectId`（归档视图若不带项目参数会 400 ⇒ 既有归档能力必须在项目范围内保持可用）；切换项目 / 返回项目列表 = 整页导航 ⇒ 上一个项目的列表、详情与 SSE 订阅天然清空。
