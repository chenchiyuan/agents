# F05：项目工作台（当前项目上下文与返回入口）

**功能 ID**: F05
**来源**: `demand.md` W3（工作台侧）；决策 S-3 / P-6；边界 N1 / N5 / N13 / N14；效果 E1 / E3
**迭代**: 0017-project-workspace
**技术锚点（引用 `demand.md` §3 只读实测，非本阶段决策）**: F-6（既有三栏布局：左栏对话列表 + 右栏对话详情；`＋ New chat` 目前只是清空详情面板）、F-17（既有前端静态契约测试的断言面）

---

## 用户价值

进了项目以后，顶栏一直告诉你"现在在哪个项目"、随时能退回项目列表；看到的对话、新建的对话都只属于这个项目。

## 验收标准

1. **进入项目即进入工作台**（W3）：从项目列表点进项目 A → 打开 A 的工作台，沿用既有三栏布局（左栏对话列表 + 右栏对话详情）。
2. **顶栏显示当前项目**（W3）：顶栏可见当前项目；最小可判定口径 = **显示项目名**〔`[user_confirmed MI-06]`〕（用户裁决原文：「只显示项目名」）；是否同时显示仓库地址**不构成本卡验收项**。
   *判定*：进入项目 A 的工作台 → 顶栏可见 A 的项目名。
3. **返回入口**（W3 / P-6 / E1）：顶栏提供返回项目列表的入口，点击后回到首屏项目列表。
4. **工作台内对话范围 = 当前项目**（W2 / E3）：左栏对话列表只含当前项目的对话；切到项目 B 或返回项目列表页后，A 的对话不可见。
5. **工作台内新建对话自动归属当前项目**（W2 / S-3）〔`[user_confirmed MI-07]`〕：点击新建即归属当前项目，用户不需要再选一次项目（用户裁决原文：「新建自动归属」）。
   *判定*：在项目 A 的工作台点新建并发送 → 该对话归属 A、出现在 A 的对话列表，**全程无项目选择步骤**。
6. **既有对话能力照常可用**（N13）：发消息、实时订阅、归档 / 关闭 / 激活 / 改名等既有能力在工作台内按既有语义可用，处理顺序与状态机不变。

## 边界（不包含）

- 不含项目列表页本身（→ F04）；不含项目的创建 / 列出（→ F01 / F04）。
- **一次只在一个项目内**：不做跨项目视图、不做"全部项目对话"聚合视图。
- **不做项目删除 / 改名 / 归档**（N5）；**不做 GitHub 集成**（N1）。
- **不改既有对话状态机、过滤语义、错误契约与实时订阅语义**（N13）。
- **不承诺"agent 自动在项目根目录工作"**（N14 / C-4）：工作台不提供"已 clone / 已在项目根目录"一类状态展示或保证。
- 不含项目设置面（凭据、默认分支、成员等，N1 / N4）。
- 不含对话详情内的消息渲染改造（既有形态保持，N13）。

## 架构落地（阶段 3 已填，见 `architecture.md` §5.1 / §5.2 / §5.3；产品维度未改一字）

- **T-05 工作台形态 = 沿用既有单页资产（既有三栏布局）**，不新增页面资产；工作台模式下 `main.layout` 可见。新增顶栏项目栏 `<div id="project-bar" class="project-bar hidden">`（置于 `.topbar` 内、`.topnav` 之后）（其隐藏需在 `style.css` 追加一条 `.project-bar.hidden { display: none; }`——**本仓无全局 `.hidden` 规则**，逐组件单独定义，见 `architecture.md` §5.1）：内含 `<a id="btn-back-projects" href="/">← 项目列表</a>`（验收 3 的返回入口即这条链接）+ `<span id="current-project-name">`（验收 2 的"显示项目名"，MI-06 只要求项目名）。未选项目时该栏隐藏。
- **T-13 当前项目载体 = URL 查询参数 `?project=<project_id>`（唯一载体，`location.search`）**，工作台地址形态 = `/?project=<project_id>`。进入项目 = 整页导航到该地址；返回项目列表 = `href="/"`（浏览器原生满足"点击后回到首屏项目列表"）。选择理由：刷新安全、无内存态歧义；**切换项目 / 返回列表由整页加载天然清空**上一个项目的对话列表、详情、SSE 订阅与归档页状态 ⇒ 验收 4 不需要任何额外清理逻辑（页内切换则必须复刻这套清理，是纯风险面）。
- **顶栏项目名的来源**：boot 时一次 `GET /api/projects`，按 `project_id` 在列表内定位当前项目行（列表不分页 ⇒ **不需要第三条 `GET /api/projects/:id` 面**）；`?project=<未知 id>` ⇒ 回落项目列表视图（不报错、不渲染空工作台）。
- **验收 5（新建自动归属，MI-07）**：`#btn-new` 的既有语义（清空详情面板）**不变**；`app.js` 的 `send()` 在请求体固定带 `state.projectId` ⇒ 首次发送即新建一条归属当前项目的对话，**全程无项目选择步骤**。
- **验收 6（既有能力照常）**：SSE 订阅、归档 / 关闭 / 激活 / 改名、标题行内编辑、`@` 补全、working 等待计时、`isReadonly`、列表内存过滤**一行不改**；唯一改动是 `loadChats()` / `loadArchived()` / `send()` 三处带上项目参数（`architecture.md` §5.3 穷举）。
- **不做环境承诺**（N14 / C-4 显式否决项）：工作台**不提供**任何"已 clone / 已在项目根目录 / 工具开关状态"一类状态展示或保证；页面文案同样不含此类表述。
