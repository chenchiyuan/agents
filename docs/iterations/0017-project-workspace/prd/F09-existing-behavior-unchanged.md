## 用户价值

这次只是给对话加上"项目"这一层：既有在用的接口、控制台和 agent 连接方式**一行都不用改**——出错的回法、订阅的语义、归档 / 关闭 / 改名的顺序全都和以前一样。

## 验收标准

1. **与项目无关的既有可观察行为逐条保持**（N13 / C-7）：统一错误契约（同类错误的状态码与 `{error, code}` 结构、封闭枚举）、已知路径用错动词仍走"找不到"兜底（**不引入 405**）、实时订阅（SSE）语义与事件顺序、对话的归档 / 关闭 / 激活 / 改名的处理顺序与状态机——逐条与本次改动前一致。
   *判定*：按既有用例覆盖的形态逐条实测，结果与改动前一致。
2. **既有测试面零改写通过**（C-7）：既有测试中与项目维度无关的部分**文本零改写**且全绿。
   *判定*：对既有测试文件做版本对比（除 C-7 列出的必然变更点外 diff 为空）+ 运行全部既有用例。
3. **变更面闭合、无越界变更**（C-7）：与项目维度**必然变更**的四处在项目内被显式记录且互不遗漏——① 既有"新建式"消息路径的新对话分支（→ F02）；② 对话列表接口（→ F03）；③ 对话表列集断言（→ F01 / F02）；④ 既有"旧库补列 / 二次打开幂等 / 迁移不引入新表"断言的**语义反转**（旧库不再被补列，而是被重建、旧行消失）（→ F08）；**除这四处之外，无其它既有行为变更**。
   *判定*：全量用例 + 逐条比对，变更点全部落在这四处之内。
4. **协议面零变化**（E7 / N8）：agent↔router 的方法面仍为既有 7 个，无新增 / 无删除。
   *判定*：对照既有协议速览与方法注册处逐条比对。
5. **既有安全边界不变**（N4）：仍为本机监听、无鉴权；本迭代不新增鉴权，也不扩大攻击面。

## 边界（不包含）

- **不含这四处必然变更点本身的功能内容**（分别由 F02 / F03 / F08 承载）；本卡只声明"这四处是已知变更，其余零变化"。
- 不含工程锁与新增接口的登记义务（→ F10）。
- **不做"顺手改进"**：不统一既有空值语义、不改既有错误文案、不调整既有参数校验顺序、不把 404 兜底改成 405、不重构既有分发与状态机。
- 不含新增的项目类能力（→ F01~F08）。
- 不含既有测试的**重整 / 重构**（除 C-7④ 的断言语义反转外，既有断言面零改写）。
- 不含前端视觉风格改造（既有静态契约断言面按 C-7 口径处理）。
