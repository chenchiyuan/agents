## 用户价值

想收紧的时候能收紧——默认放行是**配置**，不是写死。

## 验收标准

1. **档位可配**（W1 / Q3 / E8）：存在**配置面**（配置项 + 启动参数，沿用既有 approval 入参位），改它就能改档位。
   *判定*：改配置 → 再次发起会话 → 行为随之变（默认无门 ↔ 受门禁调用产生门）；观察启动参数（argv）或行为面。
2. **取值域只两值**（A2 / M2 / E8 / N1）：配置面**只接受** `{always-ask, yolo}`（默认 `yolo`）。
   *判定*：读配置面 → **仅这两个取值合法**、其余被拒。
3. **中间档不入域**（N1 / A2）：不落第三档——omp 域的 `write`（以及讨论期的臆造名 `tier`）**均不在取值域**。
   *判定*：枚举取值域 → 无第三档；枚举配置面接受值 → 同上。
4. **非法取值的处置**〔`[user_confirmed]`（MI-01 已回收，裁决原件见 `clarifications/2026-09-14-prd-round1-verdicts.md`）〕：非法 `--approval-mode` / 配置值 ⇒ **拒绝启动并报错**（体例同 0022 的配置校验：非法值响亮失败，**不静默回落**）。**已否决**：告警后按默认 `yolo` 启动；静默用内置默认。
   *判定*：填入一个非法取值（参数面 / 配置面各一次）→ 该实例**起不来**，且报错信息点名该非法取值；**不出现**"启动成功且档位落到 `yolo`"或"启动成功且无任何提示"两种情形（出现即失败）。

## 边界（不包含）

- 不含档位的**默认值**本身（→ F01 验收 3）；不含 `deny` 实例的**覆写优先级**（→ F03 验收 1）。
- 不含档位解析的**归属与"唯一汇聚点"**（→ T-01）；不含配置面的**落点 / 键名 / 参数形态**（→ T-07）。
- **不含中间档的任何行为**（N1 封死；`write` 的"按工具档位部分上浮"方向与用户指令不同，若将来要落，取值名须与 omp 域一致）。
- 不含控制台内的档位可切面（Q3 未要求）。
- 不含档位变化对**已在运行会话**的追溯（`demand.md` 未规定；本卡只判"改配置后再次发起会话"的可见后果）。
- 不含**审计面 / 台账**（N4 / N9 → F13 / F15）。
