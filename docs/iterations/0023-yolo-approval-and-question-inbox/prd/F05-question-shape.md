# F05：提问形状（问题文本 / 选项含多选 / 允许自由文本 / 无选项纯自由文本）

**功能 ID**: F05
**来源**: `demand.md` 第二段 §4 **M3**（`user_confirmed`：Q2 的 `kind` + **A3-P4**）；§5 **E3**（形状半句："条目承载问题文本与可选项（含"无选项纯自由文本"形态）"）；**登记⑧ ③条件化**；§3 **N11**（不改载体）；事实 **K3**（`acp` 的 `askDialog` 形状：每题 `q{i}` + 每题一个 `q{i}__other` 自由文本）/ **K5**（现信封 7 字段无类别字段、选项为字符串集合）
**迭代**: 0023-yolo-approval-and-question-inbox
**产品对象（引用 `demand.md` 只读实测，非本阶段决策）**: K3 / K5（现条目形状与 `acp` 提问形状的差异）；0021 既有载体 = 第三栏 + 选项点选 + 文本提交

## 用户价值

条目上写清了它到底在问什么、能选什么、能不能自己写一段——不用我去猜这个空白框是干什么的。

## 验收标准

1. **问题文本**（M3 / E3）：条目承载提问的**问题文本**。
   *判定*：对照提问内容与条目文本 → 一致。
2. **选项集合（含是否多选）**（M3）：条目承载**请求方给出的选项集合**（不新增、不删减、不替换），并能表达"单选 / 可多选"。
   *判定*：构造一次带选项的单选提问 → 条目只允许选中一项并提交；构造一次**多选**提问（`acp` 原生表单形态）→ 条目允许选中**多项**并一并提交回传。 〔默认链路的提问形状由 T-05 决定，本项在该链路的构造方式不作本阶段判据〕
3. **允许自由文本**（M3 / A3-P4）：条目支持**随选项附加自由文本**作答。
   *判定*：带选项提问 + 附自由文本提交 → 选项与文本**一并**被提交（可从提问侧收到的内容核对）。
4. **无选项的纯自由文本提问**（M3 / A3-P4）：支持"**没有选项、只有自由文本**"的提问形态。
   *判定*：构造一次纯自由文本提问 → 条目仍出现（选项区为空）且文本可提交；该轮据此继续。
5. **作答的必填性**〔`[user_confirmed]`（MI-03 已回收，裁决原件见 `clarifications/2026-09-14-prd-round1-verdicts.md`）〕：选项与自由文本**至少一个非空**；**纯自由文本提问下文本必填**；**空提交不被当成"作答"**（条目保持挂起）。
   *判定*：分别以三种输入试提交 → ① "只填文本不选选项"（带选项提问）**可提交**（有效作答）；② "只选选项不填文本"**可提交**（有效作答）；③ "两者皆空"**不构成作答**——不产生回传、**条目仍在栏内且轮次仍等待**（挂起语义见 F08 验收 1）；纯自由文本提问下仅提交空文本与 ③ 同判。

## 边界（不包含）

- 不含信封 / 形状的**最终字段名**（→ T-02）。
- 不含**多问题**的栏内形态（一问一条 → F06）；不含**作答回传载荷**（→ F07）；不含**未作答语义**（→ F08）。
- **不含更换载体**（**N11**：第三栏与既有交互面——选项点选 + 文本提交——不变；本迭代只扩展**条目形状**）。
- 不含 `kind:'permission'` 类的形状（0021 `F03` 既有：选项为主、文本为辅 → **③条件化**，仅 `permission` 成立；见 F10 验收 3）。
- 不含跨协议**逐字等价**（M4 / M7 明文不要求等价；体感差异 R4 已登记）。
- 不含提问形状的**呈现细节 / 控件形态**（阶段 3；本卡只判"能不能表达"）。

## 口径更替落点（`demand.md` 登记⑧ ③条件化）

- 0021 `prd/F03`「选项为主、文本为辅」（验收 1~4：点选即裁决 / 可附文本 / 一并提交 / 裁决后消失）**仅在 `kind:'permission'` 条目上继续成立**（→ F10 验收 3）。

- **两套口径不并存**：同一卡内按 `kind` 显式分化——`permission` 类走 0021 原口径，`question` 类走本卡口径。
