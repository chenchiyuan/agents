# F09：提问通道的两条链路承载（默认 `rpc` = 宿主工具 / `acp` = 原生 elicitation）

## 用户价值

默认那条路就能问——不用为了让它能提问而换成另一种启动形态；换链路也不影响我在这儿回答。

## 验收标准

1. **默认链路（`rpc`）具备提问能力**（W5 / A1 / K12）：默认链路的提问由 hub 注册的**宿主工具**承载——agent 主动调用 ⇒ 上浮 ⇒ 作答 ⇒ 回传 ⇒ **该轮继续**。
   *判定*：在**默认链路**构造一次提问 → 条目出现 + 可作答 + 该轮继续（通路形态与 K12 实测通路一致：调用 ⇒ 上浮 ⇒ 作答 ⇒ 回传 ⇒ 正常收尾）。
2. **`acp` 链路具备提问能力**（W5 / A1 / K3）：`acp` 链路用 omp **原生 `ask` → `elicitation/create`** 承载；**非 `Approve|Deny` 的 elicitation 不再被一律 `decline`**。
   *判定*：在 `acp` 链路构造一次提问 → 条目出现 + 可作答 + 该轮继续。
3. **两条链路落同一收件箱、同一信封形状**（W5 / A1 / M7）：两条链路产生的提问条目出现在**同一收件箱**、**同一类别**（`kind:'question'`），字段集合与语义等价。
   *判定*：分别在两条链路构造提问 → 对照两条条目：**同一栏**、**同一类别**、承载的字段集合与语义一致。
4. **不依赖会话 UI 形态**（A1 / **N3**）：默认链路**保持既有会话形态**（不为此换用另一种 RPC 形态）。
   *判定*：复核默认链路的会话形态 → 与会话是否具备 UI 无关（提问通路的可用性不依赖会话具备 UI）。

## 边界（不包含）

- 不含宿主工具的**注册时机 / 命名 / 参数 schema**，也不含 `acp` 表单到信封的**映射细节**（→ T-05）。
- **不含跨协议逐字等价**（A1 / M7 明文不要求；R4 的"两条链路提问形状不等价"已登记为**必然差异**，栏内体感不同不作缺陷）。
- 不含 omp 原生 `ask` 的既有语义**自动继承**（R2：`timeout` / `recommended` / 多选 / `askDialog` 形态**不自动继承**；其中"超时自动选"已由 A4-P13 明确不做 → F08 验收 2）。
- 不含提问的**形状**（→ F05）、**条目数**（→ F06）、**回传载荷**（→ F07）、**未作答语义**（→ F08）。
- 不含一次性 `omp -p` 路径与 `!` shell 路径（**N5**：无反向请求通道，维持现状、不上浮）。
- 不含 **omp / harness 侧改动**（**N3** → F12：所需能力均为上游既有，K3 / K12 实测可跑）。
