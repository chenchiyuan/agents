# F01：档位默认 `yolo`（默认配置下零工具门）

**功能 ID**: F01
**来源**: `demand.md` 第二段 §2 **W1**（默认面，`user_confirmed`：U-1 + U-2 + Q3 + A2）；§4 **M2**（两档语义的 `yolo` 句）；§5 **E1**、**E8**（默认半句）；**U-1 / U-2**；事实 **K9**（`yolo` 会跳过客户端权限门）
**迭代**: 0023-yolo-approval-and-question-inbox
**产品对象（引用 `demand.md` 只读实测，非本阶段决策）**: F1（现状 profile 写死 `always-ask` ⇒ 人的注意力被花在每一次受门禁的工具调用上）；F10（omp 侧档位默认即 `yolo`，subagent 强制 `yolo` —— U-2 的类比目标）

---

## 用户价值

默认不再被每一次受门禁的调用打断——工具照跑，注意力留给真正需要我的时刻。

## 验收标准

1. **默认档零工具门**（W1 / E1 / M2）：**默认配置下**（未显式配置档位、且无用户自定义的强制询问策略）起一轮**含工具调用**的对话，全程**不产生** `Allow tool: …` 类上浮请求，工具照常执行并产生后果。
   *判定*：整轮内 agent 侧的上浮 / 审计面**零** `Allow tool:` 项，且被调用的工具**确实产生了后果**（文件 / 输出）。 〔判定方式逐字取自 E1 的裸判据〕
2. **`yolo` 的语义 = 工具直接执行**（M2）：该档位下工具调用与执行之间**不存在"等待人裁决"的中间态**。
   *判定*：同一轮内观察 → 无待裁决条目产生、无等待态；工具调用与执行连续发生。
3. **"未配置"等价于默认 `yolo`**（E8 默认半句）：不做任何档位配置时，档位取值即 `yolo`。
   *判定*：不做任何档位配置即发起会话 → 观察启动参数（argv）或行为面 → 与显式 `yolo` 一致。 〔措辞例外：`argv` 为 E8 裸判定方式原文〕
4. **授权边界的落点可见**（U-2）：人的授权面落在**任务级**（整轮默认放行），不再是逐次工具调用。
   *判定*：一轮内多次受门禁调用 → 上浮面零新增条目（人的介入次数与工具调用次数无关）。

## 边界（不包含）

- 不含档位的**可配面**（配置项 / 启动参数 / 取值域校验 → F02 验收 1~3）。
- 不含 **`deny` 实例**的档位覆写与自动拒绝（→ F03）。
- 不含 **`yolo` 档下偶发门**的处理（用户自定义强制策略 / provider 安全校验仍可能强制 → F10 验收 2）。
- 不含受门禁调用的**工具集合**与门的上浮机制（0021 既有；本迭代不改）。
- 不含**提问类**的上浮与作答（→ F04~F09；提问上浮不随档位变）。
- 不含一次性 `omp -p` 路径与 `!` shell 路径（**N5**：无反向请求通道，维持现状）。
- 不含档位在控制台的**可切面**（Q3 的配置面 = 配置项 + 启动参数，未要求控制台可切）。
- 不含档位配置面的落点 / 键名形态（→ T-07）与档位解析归属（→ T-01）。
