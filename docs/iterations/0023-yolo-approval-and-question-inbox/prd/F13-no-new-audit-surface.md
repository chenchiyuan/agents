## 用户价值

这次不给"少确认"顺手加一套新台账——代价明摆着，用户已经接受。

## 验收标准

1. **不新增工具审计面**（N4）：**不补 `rpc` 侧的审批行、不新建审计载体、不新增审计行类型**。
   *判定*：枚举审计面 → **无新增行类型、无新增载体**。
2. **`yolo` 后消失的 ACP 审批行登记为已知代价**（N4 / R1 / A5-P9）：`acp` 链路的 `TOOL_APPROVED` / `TOOL_DENIED` 行随 `yolo` 消失——**用户显式接受**，**不作为缺陷、不派生补偿**。
   *判定*：以 `yolo` 档跑一轮受门禁调用 → 该两行**不出现**；且审计面**不存在**"自动批准"一类伪行。
3. **`TOOL_CALL` 保留**（N4 / K6）：每次工具调用一条的既有行为**不受本迭代影响**。
   *判定*：`acp` 链路一次工具调用 → 审计面**仍有该行**（与档位无关）。
4. **适用范围收窄**（**登记⑧ ⑤**）：0021 的"受门禁调用恰一行审计"**仅在非 `yolo` 档成立**（`always-ask` / `deny`）。
   *判定*：`yolo` 档零审批行；`always-ask` / `deny` 档有行。 〔本项与 0021 `F05` 架构落定 `T-16` 的关系即"适用范围收窄"，**原条款不删**〕
5. **语义口径自洽**（N4 的理由面）：`yolo` 语义下**不存在"批准"这一事件**——因此该损失是语义结果，不是缺失。
   *判定*：读审计面说明 → 无"自动批准"事件定义。
