## 用户价值

我写的答案真的送到它手上、那一轮接着说——不是答完像没答、还多出一条莫名其妙的用户消息。

## 验收标准

1. **回传答案本体（含自由文本）**（W4 / M5 / A3-P6 / E4）：提问条目的作答——**选中的选项 + 自由文本**——**回传给提问方**；**作答的成立条件** = 选项与自由文本**至少一个非空**（纯自由文本提问下文本必填）——**空提交不构成作答、不解锁回传**〔必填性口径 `[user_confirmed]`（MI-03 已回收，原件见 `clarifications/2026-09-14-prd-round1-verdicts.md`；形状面同判 F05 验收 5）〕。
   *判定*：输入一段自由文本答案 → **提问侧答案文本与输入一致**；带选项作答时选项亦回传；**选项与文本皆空提交 → 提问侧零回传、该轮仍等待、条目仍在栏内**。 〔前两半句的判定方式逐字取自 E4 的裸判据〕
2. **该轮据此继续**（W4 / E4）：作答后该轮**从等待变为继续**（**不再以 cancelled 收尾**）。
   *判定*：观察轮次状态从等待变为继续 + 提问侧拿到答案后确实继续执行。
3. **停掉「文本 → 追加一条 `chat` 输入」旁路**（W4 / A3-P6 / E4 / **登记⑧ ④改写**）：`kind:'question'` 条目的文本**不再**被当作一条对话输入追加。
   *判定*：**同一动作在对话记录里零新增用户消息**。 〔判定方式逐字取自 E4〕
4. **`permission` 类口径不变**（**登记⑧ ④改写**的另一半 / 0021 `F03` §文本的落地）：`kind:'permission'` 条目的文本仍按既有口径落地（文本 = 拒绝理由 / 补充说明）。
   *判定*：以 `permission` 类条目附文本提交 → 文本按既有口径落地（既有路径不变）。

**口径分化声明（④改写）**：按 `kind` 分化——`permission` 类维持原文；`question` 类**必须**回传文本且**停掉**该旁路。**两套口径不并存于同一条目**。
