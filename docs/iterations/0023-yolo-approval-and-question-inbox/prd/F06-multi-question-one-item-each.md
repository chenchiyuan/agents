## 用户价值

它一次问三件事，我就在栏里看到三条，逐条回答——不用在一个表单里来回对号入座。

## 验收标准

1. **一问一条**（M4 / A3-P5 / E9）：agent **一次提 N 个问题**时，栏内出现 **N 条独立条目**（每条一个问题），**不是 1 条表单**。
   *判定*：让 agent 一次提 N 问（`acp` 单帧多问形态）→ **数栏内条目数（= N，非 1 条表单）**。 〔判定方式逐字取自 E9 的裸判据〕
2. **逐条可独立处理**（E9）：每条可独立作答，互不阻塞——作答其中一条不改变其余条目的可见性。
   *判定*：只作答其中一条 → 该条消失、其余条目仍在。
3. **`acp` 侧齐答后一次性回包**（M4 / A1）：`acp` 单帧多问时由 hub **逐问登记**；同一帧的各问**齐答后一次性回包**。
   *判定*：`acp` 链路一次提 N 问 → 未齐答前该轮**不推进**；齐答后该轮**继续**。
4. **不引入 `questions[]` 大信封**（A3-P5 明文）：不使用"一条条目承载整表单"的形态。
   *判定*：读条目形状与裁决面 → 沿用既有（**一条 = 一次裁决**：选项 + 文本）；不存在"表单式"条目或整表单提交的裁决面。

## 边界（不包含）

- 不含 `acp` 组内暂存的**形态**（→ T-03）。
- 不含跨协议**逐字等价**（M4 / M7 明文不要求；R4 的"栏内体感不同"已登记为必然差异）。
- 不含提问的**形状本身**（→ F05）、**作答回传载荷**（→ F07）、**未作答语义**（→ F08）。
- 不含默认链路的"一次多问"**构造方式**（宿主工具天然逐问：一轮内多次调用 ⇒ 多条条目；参数 schema → T-05）。
- 不含覆盖面之外路径（一次性 `omp -p` / `!` shell → **N5**，不上浮）。
