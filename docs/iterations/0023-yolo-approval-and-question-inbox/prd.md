## 本次迭代边界说明

### 包含（本迭代要产出的产品行为）

- **档位默认 `yolo` 且可配**（W1 / Q3 / A2 / F13 → F01 + F02）：默认配置下（无用户自定义强制策略）受门禁调用**不产生工具门**；档位**可配**（配置项 + 启动参数，沿用既有 approval 入参位）；**取值域只落 `{always-ask, yolo}`**（默认 `yolo`），中间档 `write` / 讨论期的 `tier` **不入域**（N1）。
- **`deny` 档能力保留**（W2 / Q1 / A5-P12/P3 → F03）：实例显式 `--permission deny` ⇒ 该实例档位**强制 `always-ask`**（门存在），**优先于**显式 `--approval-mode`；其受门禁调用**不上浮**、走既有自动拒绝三步（`reject_once` + `session/cancel`）、轮次以 `permission_denied` 收尾；档位解析必须存在**唯一汇聚点**（落点 `[架构待填]`）。
- **提问面上浮**（W3 / Q2 / A1 / A3-P7 / A4-P10/P11 → F04 + F05 + F06 + F08 + F09）：agent 主动提问类交互请求（默认 `rpc` = 宿主工具调用；`acp` = 非 `Approve|Deny` 的 elicitation）**不再被自动取消 / 拒绝**，而是**登记进收件箱**、等待人作答；提问类上浮**不随档位变化**；**不代答拒绝、不自动作答、不设超时**；形状支持「问题文本 + 选项集合（含是否多选）+ 允许自由文本 + **无选项的纯自由文本提问**」；多问题 = **一问一条**（不引入 `questions[]` 大信封）。
- **提问可被回答**（W4 / A3-P6 → F07）：作答结果（**含自由文本**）**回传给提问方**，该轮据此继续（不再以 cancelled 收尾）；并**停掉「文本 → 当成一条 chat 输入」的旁路**（仅 `kind:'question'` 条目；`kind:'permission'` 条目维持既有口径）。
- **两条链路都具备提问能力**（W5 / A1 / M7 → F09）：默认链路**保持既有会话形态**；该链路的提问由 hub 经 `set_host_tools` 注册的**宿主工具**承载；`acp` 链路用 omp **原生 `ask` → `elicitation/create`**；**两者落同一收件箱与同一 `kind:'question'` 信封形状**，**不要求跨协议逐字等价**。
- **工具门通路保留**（W6 / A5-Q3′ / 登记⑧①③ → F10）：`always-ask` 档下受门禁调用仍上浮为 `kind:'permission'` 条目（0021 机制不退化、不删除），且**必须实际验收**（它是 `deny` 能力的唯一载体）；`yolo` 档下偶发门仍按 `permission` 条目处理。
- **能力位与档位声明分离**（M8 / A4-P10 → F11）：`approvalGate` 描述"该协议是否有工具门这一机制"，**不随档位变**；"本次生效形态"由**档位声明**单独表达。
- **既有边界保持**（N3 / N4 / N8 / N9 / N10 → F12 / F13 / F14 / F15 / F16）：不改 omp / harness 源码与协议；不新增工具调用审计面、不补偿 `yolo` 后消失的 ACP 审批行（已知代价）；服务仍仅本机监听、零鉴权、不做多用户；不做确认项历史 / 审计台账；不引入第三方依赖。
