## 拆分理由（原子粒度判断）

**总原则：按「可独立出现的失败」拆卡；保证项按「独立可被破坏的约束」单列。**

- **W#1 拆两张（F01 / F02）而非一张"探针卡"**：两者失败模式互不蕴含——① 一次性回执缺失（三条命令与输出没落成证据）② 常驻探针缺失或例外通道未被约束（`--model` 泄漏到正式派发）。载体也不同：前者是已发生事实的落盘，后者是运行时段内已发生、需要留痕与约束的调用。
- **W#2 一张（F03）不拆**：两处 `model` 写入同一文件同一段，是**一个不可分割的动作**（一次配置改动）；拆成两卡会产生两张卡改同一文件、互相不具备独立交付性。其"逐角色绑定正确性"的独立失败面由 F05 / F06 在**运行时**承担，不在文件面重复。
- **W#3 拆四张（F04 / F05 / F06 / F07）**：四种独立可出现的失败——① 集群没起来或角色不全（`pb-*` 实例数 ≠ 10）② dev 的绑定字段不生效 ③ verifier 的绑定字段不生效 ④ 未绑定角色的默认链路被破坏。②③ 是两个独立字段的独立失败（D-4 明确两个角色两种取值），④ 是**反向断言**（证明"没写就不改"），与前两者不同类。四者的判定载体一致（只读面），但判定对象与失败含义互不蕴含。
