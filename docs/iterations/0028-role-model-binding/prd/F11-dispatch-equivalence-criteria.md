# F11 · 派发等价性判据与并发取证

**来源**：demand.md 做什么#5；§执行方式约束表（等价性判据行）；决策 D-10（判据三信号）/ D-16（截断算缺口）/ D-17（全阶段覆盖）/ D-18（并发取证）

## 用户价值

派发通道换了（hub 常驻节点取代宿主子代理）之后，"这次协作是否与原来等价"有一组固定信号可以逐次核对，而不是凭感觉说一句"差不多"；同时，并发派发这个最容易出问题的场景被显式取了一次证。

## 验收标准

1. **三条信号（D-10）**：阶段 2~6 的**每一次**角色派发（D-17：全阶段覆盖）都满足——① 有 `call_id` 且 `hub api calls get <call_id>` 可读；② **终态信封可得**（`state` ∈ {`completed`, `failed`}）；③ 该次产出**可无人工搬运地拼回全文**：产出全文可由终态 `text` 或 `hub api calls transcript <call_id>`（或其合并结果）连续读出，且下游产物直接引用该产出，过程中不存在"人工从多处拼接中间产物"的步骤 [已确认 MI-5]。
2. **缺口的判定与去向（D-16）**：出现下列任一情况即为等价性缺口，**逐次**记录（同类现象可聚合为一条），并在 F12 的差距记录中有对应四要素条目——① 终态信封 `truncated` 为 `true`；② 产出需要两步拼接才能得到全文；③ 终态信封不可得，或 `call_id` 查不回。
   **已发生的缺口（如实登记，供核对）**：**G-5** —— `prd` 派发（call `task-8e84f95f-b783-4477-8054-abf0b36f31ec`）的终态信封 `truncated: true`、`text` 3632 字符；经 `hub api calls transcript` 拼回 7078 字符 ⇒ 按 D-16 判定为等价性缺口，条目位于 `docs/iterations/0028-role-model-binding/deferred-demand-changes.md` §执行方式差距 的 G-5（同类现象后续聚合到该条）。
3. **并发取证（D-18）**：阶段 5**首次**派发时，同一轮内连续发起 **≥2 个** `hub api calls create`，并**分别**取到各自的终态；证据含 ≥2 个互不相同的 `call_id` 与各自终态字段，且两条属于不同角色节点或不同 PR [已确认 MI-5]。
4. **覆盖声明（D-17）**：本卡判据适用于阶段 2~6 的**全部**角色派发，不只阶段 5——不得以"阶段 5 已取证"为由豁免其它阶段的逐次核对。

## 边界（不包含）

- **不把"多轮上下文连续"纳入等价性判据**（`demand.md` 明确排除：会牵出常驻会话语义）。
- 不要求把每次派发的中间产物搬运落盘（与验收 1 ③ 的判据恰好相反）。
- 不定义"截断"的阈值、过程记录上限或转录长度口径（那是既有实现的事实面，本迭代不改）。
- 不承担差距记录的格式、分区与 C-1~C-4 的收录（F12）。
- 不要求为阶段 5 之外的阶段制造并发场景（并发取证只针对阶段 5 首次派发）。

## 架构维度

无待填项（判据完全建立在既有调用面与既有转录面上）。

## model_inferred

- **已确认 · MI-5（验收 1 ③ 的判定形态）**："可拼回全文"落地为"可连续读出 + 下游直接引用 + 无人工搬运步骤"，依据是 D-10 原文词组；口径保留不变。
- **已确认 · MI-5（验收 3 的并发形态下限）**：阶段 5 首次派发的两条并发调用须属于**不同角色节点或不同 PR**——为使并发取证具备证明力的最小形态（同一角色的两次调用无法区分"并发调度"与"同节点排队"）；口径保留不变。
