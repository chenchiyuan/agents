# F04 · 第二集群全角色启动就绪

**来源**：demand.md 做什么#3（前半："在迭代工作区起第二集群（全 10 角色）"）；达到什么效果#2 的前置；决策 D-13 / D-19

## 用户价值

验证跑在一个与主集群互不打扰的集群里——证明过程不污染正在使用的集群，也不必等到收口才敢验证；而且 10 个角色一个不少，是"完整启动路径"而不是挑几个起来的抽样。

## 验收标准

1. 存在一个以**迭代工作区**为根的集群实例，其角色实例可按只读面列出（`GET /api/agents` 或等价的 hub 只读命令），其中 `instance_id` ∈ {`pb-architect`, `pb-demand`, `pb-dev`, `pb-planner`, `pb-pr-planner`, `pb-prd`, `pb-progress-observer`, `pb-retrospective`, `pb-verifier`, `pb-workflow-pb`} 的 **10 个实例全部在线**（判定时排除既有事实中 `instance_id = web` 的固有节点）。
2. 该集群与主工作区集群在**三项**上互不重合，且三项取值逐项可核对：① session 名不同（主集群缺省 `oamp-cluster`）② web 端口不同（主集群缺省 `7788`）③ socket 与集群日志落点不同（不在同一包根下）。
3. 迭代期间**未对主工作区集群执行任何启停或配置改动**（`up` / `down` / 改配置三类动作零次）；主集群的既有 session 与配置在收口前保持原样。
4. 该集群的角色级配置即本迭代的绑定配置：在 F03 落盘且该集群加载该配置之后，其 `roles.dev` / `roles.verifier` 含 F03 的两处 `model` 取值；启动过程不因这两个取值报错（校验通过、集群完整起来）。
5. 启动事实可核对：启动命令、启动时间与上述三项隔离取值可写成一条可复核的记录（载体形态见 A-01 / A-02）。

## 边界（不包含）

- 不打乱、不重启主工作区集群（D-13）——收口阶段的那一次重启由 F08 承担，属于本卡边界之外。
- 不要求第二集群在收口后被 `down` 或清理（demand 未要求；现场保留不违反本卡）。
- 不承担三条实报模型的取证（F05 / F06 / F07）。
- 不新增或改动运行时代码、启动脚本与集群配置的**字段集合**（只使用既有字段与既有启动路径；F13 验收 1）。
- 不做启动期模型存在性预检（`demand.md` 明确不做；验收 4 只要求"不因取值报错"）。

## 架构维度

**已填 · A-01**（见 `architecture.md` §3.1 / §4 A-01）：

- **副本形态与落点**：`<迭代工作区>/cluster.second.json` —— 工作区根 `cluster.json` 的**逐字副本 + 仅两键差异**（`session` → `oamp-cluster-0028`、`web.port` → `7789`；`router.socket` 保持 `null`）。必须落在工作区根：`cluster-config.js` 的 `root = dirname(configPath)` 同时决定角色文件预检路径与角色 `cwd` 缺省基准。
- **副本从哪来 / 何时刷新**：来自工作区根 `cluster.json`（迭代分支版本）；在 **F03 的 PR 合入迭代分支之后、第二集群启动之前**生成（这是副本携带合入后绑定的唯一保证）。判据 = `diff` 两文件恰 2 行差异、其余逐字一致。
- **启动落点**：`node <工作区>/oamp/bin/hub.js cli cluster up --config <工作区>/cluster.second.json --wait 120000`（层 C 原样透传既有 `oamp cluster up`）。收口不要求 `down`（本卡边界），需要时同 `--config` 反跑。
- **三项隔离取值的来源与核对**：① session = 副本取值（`tmux ls` 两个 session 并存）② web 端口 = 副本取值（`lsof -nP -iTCP:7789 -sTCP:LISTEN`）③ socket / 集群日志 = **既有包根推导**（`<工作区>/oamp/.runtime/` 下），与主集群不在同一包根——无需配置、不需要显式 `router.socket`。
- **副本性质登记**：未纳入版本控制（运行态产物，与 socket / 日志同类），因此不出现在 F13 验收 1 的 `git diff --name-only` 判据面内；其存在与性质在承载 F13 证据的小节里显式登记。
- **启动记录载体**：本卡验收 5 的"可复核记录"落承载本卡的 PR 文件「验收证据」小节（与 A-02 同一载体约定）。

除此之外无待填项。
