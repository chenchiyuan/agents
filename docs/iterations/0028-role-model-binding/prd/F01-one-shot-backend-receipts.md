# F01 · 一次性后端可用性回执（3 条）

**来源**：demand.md 做什么#1（前半："一次性路径已完成实测"）；达到什么效果#1；决策 D-8 / D-9

## 用户价值

三个后端到底通不通，有 3 条可以直接复制重跑的命令与原始输出兜底——不用等集群起来、不用等某次派发失败才发现某个后端没通。

## 验收标准

1. 承载本项证据的产物中，存在 **3 条一次性路径回执**，分别对应 deepseek（默认）、gpt、grok 三个后端；每条含**完整命令**（逐字可复制执行）与**原始输出（含观测结果）**——这两项是**验收字段**。命令的耗时数值如实记录在同一处，但**不作为验收字段**（受机器负载摆动的值不得当判据）[已确认 MI-1（含修改）]。
2. 3 条回执的命令均为**一次性路径形态**（不经 hub、不建 chat、不落对话），三条之间除 `--model` 取值外形态一致——即三个后端是在同一路径、同一形态下被比较的。
3. 3 条回执的观测结果均为成功（后端返回了预期文本）。**出现失败的后端时**：该条如实记为失败（不隐藏、不用另一次成功替代），并把该后端与失败现象作为一条差距条目交给 F12 承载。
4. 本项**不新建独立的探针文件**（D-9）：证据落点 = 承载它的 PR 验收证据；具体载体与字段形态由阶段 3 决定（A-02）。
5. 3 条回执是"5 条探针回执"整体判据（效果#1）的一半；另一半（2 条常驻）归 F02。本卡只承担一次性路径的 3 条。

## 边界（不包含）

- 不单独建探针文件或探针专用产物（D-9）。
- 不承担常驻路径探针（F02）。
- 不判定后端的质量、延迟优劣或性价比——只记事实（命令 + 输出）。
- 不因某个后端失败而改动绑定清单：绑定取值由 D-4 固定、落 F03；失败按验收 3 记入差距记录。
- 不做集群启动期的模型存在性预检（`demand.md` 明确不做）。

## 架构维度

**已填 · A-02**（见 `architecture.md` §4 A-02）：

- **载体**：承载本卡的 PR 文件（`docs/iterations/0028-role-model-binding/prs/pr-0NN-*.md`）在七字段之后追加的「验收证据」小节，每条回执一个三级标题条目；**不新建独立探针文件**（D-9）。不落 `status.md`（其表头已由 R-5 锁死为台账七列，放不下"命令 + 原始输出"）。
- **字段形态**（逐字照录）：`命令`（完整命令，可复制重跑）/ `原始输出`（含观测结果）/ `观测结果`（成功｜失败 + 现象）/ `时点` / `耗时`（如实记录、**不入判据**，MI-1）。
- **命令形态**：omp 一次性路径（`-p` 且 `--no-session`；命令文本中不出现 `hub`、不出现 `api messages` / `calls create`），三条除 `--model` 取值外逐字相同。

除此之外无待填项。

## model_inferred

- **已确认（含修改）· MI-1**（验收 1 的字段口径）：口径为「完整命令 + 原始输出（含观测结果）是验收字段，耗时如实记录但不入判据」——耗时一项由用户裁决从判据中移出（理由：受机器负载摆动的值不得当验收标准）。
