# F02 · 常驻后端探针（gpt / grok 2 条）

**来源**：demand.md 做什么#1（后半："补 gpt 与 grok 的常驻路径探针"）；达到什么效果#1；决策 D-8 / D-14 / D-15 / D-21

## 用户价值

集群节点实际走的那条路径也验过了——一次性路径通不等于常驻路径通；这条探针是"绑定值写下去以后节点真的跑得起来"的提前保险。而它开的口子（临时指定模型）只开在探针期，验完就关。

## 验收标准

1. 常驻路径下存在 **2 条探针回执**：一条针对 gpt 后端、一条针对 grok 后端，分别落在**两个不同的角色节点**上（本迭代已在 `status.md` 声明目标为 `pb-dev` 与 `pb-verifier`；实际节点若不同，以实际记录为准，但"两条不同节点"这一要求不变）。每条含：**完整派发命令**（含 per-call `model` 参数）、**`call_id`**、**终态信封**（`state` / `model` / `error` / `exit_code` 等可读字段）。
2. 两条探针的终态 `model` 分别解析到 gpt 后端与 grok 后端（判定口径 = 实报值指向同一后端，不要求与请求字符串逐字相等；理由见 F05 验收 4 / MI-3）。
3. **探针取证时目标集群尚未加载角色级绑定**（`cluster.json` 的两处 `model` 未生效）[已确认 MI-2]：两条回执的实报值只能来自 per-call `model` 参数，而不是角色级绑定。若实际在已加载绑定的配置上取证，**本项判为未达成**（不视为"口径差异"），并把该口径缺口交 F12 记录。
   **本项已由既成事实满足、无需重跑**（2026-09-15 事实）：两条常驻探针发生于 20:52——call `task-bfd83f28-2078-434b-8a16-eac455d2e999` 于 `pb-dev` 实报 `openai/gpt-5.6-luna`，call `task-39204abd-38ab-4971-b785-3eed6b0bb835` 于 `pb-verifier` 实报 `powerby/grok-4.6`；当时目标集群配置（仓库 `main` 的 `cluster.json`）**无任何 `model` 键**。
4. 例外通道可核对且**只存在于探针期**：这 2 条是本迭代**唯一**携带 per-call `model` 的调用——判据 = 阶段 2~6 的全部派发命令中，除这 2 条外不含 `--model`（与 F09 验收 3 同源判据）；探针完成后不再出现携带 `model` 的派发。
5. 两条探针回执不单独建文件（D-9），落在承载它的 PR 验收证据中；载体形态由阶段 3 决定（A-02）。
6. 两条探针落在**同一个 chat** 内（D-21）：探针建立本次迭代唯一 chat，该 chat 的归属与唯一性判据归 F10；本卡只要求"两条同 chat"。

## 边界（不包含）

- 不覆盖 deepseek 的常驻探针（D-15 明确只做 gpt / grok 两个后端；deepseek 有现行集群持续运行事实 + F01 的一次性回执）。
- 不修改 per-call `model` 的既有语义（不改任何代码；例外只是一次性的调用参数）；不把该通道保留为长期可用能力。
- 不把探针扩展成"集群启动期模型预检"（`demand.md` 明确不做）。
- 不承担第二集群的启动与就绪（F04），也不承担绑定生效的三条实报（F05 / F06 / F07）。
- 不判定探针产出的内容质量——探针只验"后端在该路径下可用"。
