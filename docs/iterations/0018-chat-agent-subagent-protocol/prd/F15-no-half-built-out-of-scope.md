## 用户价值

「这次不做」是明确的决定，不是「先埋一半」——文档里说没有的东西，代码里就真的没有，不会有人照着半成品以为它有了。

## 验收标准

1. **「本次不做」条目在代码中零半成品**（E10）：取消 / 终止 / steer、隔离工作区与产物回传、工作量档位、持久化转录、工具级进度、token / 成本、远端同会话渲染一致、客户端适配器等条目，在代码与文档中均**无半成品实现、无预留入口**。
   *判定*：按关键词逐一检索代码与文档 → 代码零命中；文档中只出现在差异清单（或「不做什么」声明）内。
2. **差异条目与实现一一对应**（E10）：差异清单中「提供了但形态不同」的条目（如按调用 id 取终态 / 取转录）确实有对应能力存在；「不提供」的条目确实不存在。
   *判定*：逐条核对 ①~⑲——每条要么可指出对应能力，要么检不到实现。
3. **不做项不破坏最小闭环**（W 们的边界收敛）：去掉这些项后，「发起调用 → 拿到结构化结果 → 看到进度」这条链路仍然完整可用（以 F03~F13 验收全部通过为准）。
   *判定*：F03~F13 验收全绿时本卡自动成立（本卡不新增交互）。

## 边界（不包含）

- 不含任何新增功能（本卡为边界执行锁）。
- 不含既有面回归（→ F14）、不含登记与工程锁（→ F16）。
- **不把差异条目改写成「未来待办」**：差异清单只说明「本次不做 / 不等价」及其原因，不承诺排期（清单编号与归类为 `派生`，回退口见 `demand.md` §6.3-1）。
- **不做 `oamp/` 之外的仓库改动**（N20）：harness / 客户端侧的「不做」不在本仓库兑现。
- 不含既有文档两处「两者不合并」结论的改写（F-16 佐证：本迭代不合并两类协议，只新增一层调用协议）。
