## 用户价值

同一个对话里跟同一个角色聊，它是「同一个它」——记得住前面说过的话；换个对话问同一个角色，是一条干净的上下文，不会串味。

## 验收标准

1. **同 chat 同名 = 同一 agent、共享上下文**（W8 / E8）：在 chat A 向某角色交代一个信息，随后在**同一 chat 同一角色**的下一轮调用能用到它。
   *判定*：chat A 两轮（「记住 X」→「X 是什么」）→ 第二轮答出 X。
2. **跨 chat 隔离**（W8 / E8）：在 chat B 向**同名角色**提问，不带 chat A 的上下文；两 chat 交替调用同一角色时，各自上下文互不进入对方。
   *判定*：换一个 chat 再问同一问题 → 回答不体现 chat A 交代过的信息；A / B 交替调用多轮 → 各自记忆互不渗漏。
3. **既有上下文语义不变**（W8 / N16）：上下文延续仍按既有键（聊天归属 + agent 标识）生效——同键串行、异键并发、全局上限与淘汰策略逐条不变。
   *判定*：对照既有上下文行为逐条核对（同键串行 / 异键并发 / 上限与淘汰），与改动前一致；上下文池的键与并发配置无变化。
4. **`one_shot` 例外与默认路径的关系明确**（差异 ⑲ / Q-1 裁决 ①）：调用方显式选择「放弃上下文延续」的例外路径时，不具备验收 1 的共享语义；该例外在差异清单中有条目。
   *判定*：同 chat 同角色走例外路径两轮 → 第一轮交代的信息在第二轮不可得；差异清单第 ⑲ 条可读（→ F01 验收 5）。
5. **一个实例可承载多个 chat 作用域的 agent 身份**（W8）：同一角色的常驻实例被多个 chat 分别调用时，各 chat 作用域身份互不混淆。
   *判定*：同一角色在 chat A / chat B 各跑一轮 → 两个 chat 的上下文各自独立（交叉提问得不到对方的信息）。

## 边界（不包含）

- **不含上下文池的改动**（N16）：本卡是「**现状被确认为契约**」，不改键、不改串行 / 并发语义、不改上限与淘汰。
- **不引入 agent 实例的创建 / 终止 / 复活 / park**（N2）。
- 不含寻址（→ F03）与归属校验（→ F11）。
- **不消除差异 ①**（被调用者生命周期：常驻实例 vs 每次派发临时 agent）——该差异仍登记在差异清单。
- 不判定「记住了什么内容」：本卡只判「共享 / 隔离」这一行为，上下文里放什么是 agent 自身能力。
