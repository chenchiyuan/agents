## 用户价值

一眼看全「现在有哪些调用、各自什么状态」——一屏就能回答「我刚才发的那两次跑完没有」，不用逐个 id 去查。

## 验收标准

1. **每次调用一行**〔`[user_confirmed MI-02 / MI-03]`〕（W5 / E7；用户裁决 = 项级独立 + 展示面、无过滤无编排）：存在「列出调用」的数据面；**每次调用**占一行（批量提交的两项 ⇒ 两行），行内含**调用 id / agent / 状态 / 起止时间 / 模型**。
   *判定*：发两次调用后列一次 → 看到两行，且每行五项信息齐备；一次提交两项 → 同样看到两行（各自一个调用 id）。
2. **起止时间口径**〔`[user_confirmed MI-07]`〕（E7；用户裁决 = 受理 / 终态时间、进行中为空）：开始时间 = 调用被受理的时间；结束时间在有终态后可见、进行中为空 / 未填写，且不早于开始时间。
   *判定*：进行中列一次 → 结束时间空；结束后再列一次 → 结束时间可见且 ≥ 开始时间。
3. **状态与事实一致**（E7）：roster 中某行的状态，与该调用按 id 查询到的状态一致。
   *判定*：同一时刻对照两种读取 → 状态一致。
4. **无成本 / token / 工具级字段**（N12 / 差异 ⑭）：roster 不出现成本、token，也不出现工具级详情。
   *判定*：检索 roster 内容 → 上述字段零出现（协同 F15 验收 1）。
5. **作用域不越界**〔`[user_confirmed MI-03]`〕（N17；用户裁决 = 展示面、无过滤无编排）：roster 是**展示面**，不提供按状态过滤、不提供编排操作、不作为任务管理 / 编排面；「读自己发起的调用」按**范围限定**理解，不引入鉴权可见性隔离。
   *判定*：检索 roster 面 → 无过滤 / 编排入口；列一次即可得到行集合。

## 边界（不包含）

- 不含进度流（→ F08）、不含终态字段内容（→ F06）、不含转录（→ F10）、不含按 id 查询（→ F05）。
- **不做全量任务列表 / 按状态过滤 / 编排面**（N17；口径见 MI-03，已确认）。
- **无成本与 token**（N12 / 差异 ⑭）：无数据源，不造假。
- 不含控制台页面呈现（→ F13）。
- **不承诺跨重启保留**（N11，差异 ⑩）：roster 取自本进程内的调用记录。
- 不含鉴权与多用户视图（N19）。
