## 用户价值

每次调用都有一个能拿在手里的号——拿着它能问「这次跑完了吗、结果是什么」，不用盯着聊天流一条条翻。

## 验收标准

1. **一次调用 = 一个可寻址的调用 id**（W3 / M-5 / E4）〔`[user_confirmed MI-02]`〕：发起调用的受理结果中带**调用 id 与 agent 名**；该 id 可用于后续查询，且不新建第二套资源体系（批量提交时**每项各得一个调用 id**）。
   *判定*：发起一次 → 响应里能取到调用 id 与 agent 名；用该 id 查询 → 命中的是同一次调用；一次提交两项 → 得到两个互不相同的调用 id，各自可独立查询。
2. **按调用 id 取终态**（W3 / E4）：调用结束后，凭调用 id 可读到这次调用的终态（字段内容 → F06）。
   *判定*：发起 → 等结束 → 用该 id 查询 → 得到终态。
3. **未结束的调用查询有明确状态**（W3）：调用进行中查询 → 得到「进行中」一类状态，而不是报错或空结果。
   *判定*：发起后立即查询 → 得到进行中状态；结束后再查 → 得到终态。
4. **读取范围限定**（W3 / C-2 / N17）：只提供「按调用 id 读自己发起的调用」；**不提供**全量任务列表 / 按状态过滤 / 编排操作（0015 N5 的其余部分**不解除**）。
   *判定*：检索调用面 → 无「按状态过滤 / 全量列表 / 编排」类入口；按调用 id 查询可用。
5. **调用身份沿用既有任务标识**（W3 / M-5）：发起响应与按 id 查询中出现的是**同一个**标识，文档中不存在第二套调用 / 任务标识体系。
   *判定*：对照两处标识 → 同一个；检索文档 → 无第二套标识。
6. **调用身份不呈现血缘命名**（N7，差异 ④）：调用 id 不采用父子血缘 / `Parent.Child` 形式，同一调用在各读取面呈现一致。
   *判定*：对照调用面与 roster / 查询中的呈现 → 一致且无血缘命名。

## 边界（不包含）

- 不含终态字段内容（→ F06）、不含终态投递（→ F07）、不含过程可见（→ F08）、不含 roster（→ F09）、不含转录读取（→ F10）。
- **不提供全量任务列表 / 按状态过滤 / 编排面**（N17）：0015 N5 的解除范围严格限于「按调用 id 读自己发起的调用」（C-2）。
- **不做嵌套调用 / 父子血缘 / `Parent.Child` 命名**（N7，差异 ④）。
- **不照搬产物 URI scheme**（差异 ⑨）：产物获取 = 按调用 id 取终态（内容 → F06）。
- **不做取消 / 终止 / steer**（N3，差异 ⑯⑮）。
- **不做持久化**（N11，差异 ⑩）：调用记录与终态在本进程内可读，重启即丢（→ F10）。
- 不含鉴权与多用户可见性（N19）：本卡不定义「自己」的鉴权含义，只锁定「不做编排面」这一范围限定（口径见 F09 的 MI-03，已确认：按范围限定理解，不引入鉴权可见性隔离）。
