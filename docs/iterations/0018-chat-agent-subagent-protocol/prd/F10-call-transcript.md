## 用户价值

事后能把这通调用「从头翻一遍」——中间过程都在，不用回聊天记录里一条条捞；同时它不会假装自己留得住——重启就没了，这件事写在明处。

## 验收标准

1. **按调用 id 取转录**〔`[user_confirmed MI-08]`〕（W3 / R3；用户裁决 = 含终态那次事件）：调用结束后，凭调用 id 可读到该调用的过程记录（从发起到终态，**含终态那次事件**），含中间步骤。
   *判定*：跑一次多次输出的调用 → 取转录 → 过程条目按序可见。
2. **本进程内可读**（W3 / P-6）：服务当前进程存活期间可读；读取不要求调用方在发起时做任何准备（无需事先声明"我要留转录"）。
   *判定*：对一次已结束的调用直接取转录 → 可读。
3. **不持久、重启即丢，且表现明确**（W4 / N11 / 差异 ⑩）：重启服务后先前调用的转录不可读，并**明确表现为「不存在」**——不报内部错误、不返回伪造内容。
   *判定*：取到转录 → 重启 → 再取 → 得到明确的不存在 / 空结果（非 5xx、非伪造内容）。
4. **超上限时表现明确**〔`[user_confirmed MI-08]`〕（N11 / 差异 ⑩；呈现形态见 T-08）：过程记录超过既有上限时，读取结果明确呈现「被截断」——**不报错**、不静默少给。
   *判定*：制造一次超过上限的过程记录 → 读取结果带截断提示。
5. **不引入持久化**（N11 / 差异 ⑩）：代码与文档中不存在转录落库 / 跨重启保留的实现或承诺（协同 F15 验收 1 的零半成品检索）。
   *判定*：检索 → 零命中；既有「增量不入库」的声明不被推翻。

## 边界（不包含）

- 不含终态的投递与查询（→ F07 / F05）、不含实时流（→ F08）、不含 roster（→ F09）。
- **不做持久化转录**（N11，差异 ⑩）：不落库、不跨重启保留。
- 不含产物 URI scheme（差异 ⑨；产物获取 = 按调用 id 取终态 → F05 / F06）。
- 不含编排面的历史查询（N17）。
- 不含跨调用 / 跨 chat 的聚合检索。
