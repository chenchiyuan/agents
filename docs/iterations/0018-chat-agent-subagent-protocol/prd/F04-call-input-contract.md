**来源**: `demand.md` W2（入参侧）；裁决 P-5（按推荐：I2 / I3 / I6 / I7 必须等价）；澄清 M-7；边界 N4 / N5 / N8 / N9 / N10 / N12；效果 E3

**技术锚点（引用 `demand.md` §3 只读实测，非本阶段决策）**: F-2（既有消息入参含 chat 归属 / 项目归属 / agent 标识 / 文本 / 模型 / 一次性标记）、F-3（既有三种派发形态）、F-14（agent 先 ack 再并发执行，fire-and-forget）、F-17（一次性路径每次独立进程、不共享上下文）

## 用户价值

一次调用就能把「要它做什么、共享哪些说明、要不要按给定结构回、要不要等结果、用哪个模型」说全——和原生 sub agent 的入参是同一种表达。

## 验收标准

1. **任务文本 + 可选共享说明**（W2 / I2 / E3）：一次调用携带任务文本（必填）与可选的**本次调用共享说明**；二者在该调用内分别存在，共享说明不污染任务文本。
   *判定*：带与不带共享说明各调一次 → 均能发起；带说明时 agent 侧可见该说明，且任务文本仍是原文（无前缀污染）。
2. **结构化输出要求**（W2 / I3 / E3）（校验落点见 T-09）：调用可携带「期望的返回结构」与「结构校验模式」两项；agent 的返回按所给结构给出。
   *判定*：带一项期望结构发起 → 终态的结构化输出与之对应；不带 → 退回文本返回且不报错。
3. **批量多项**〔`[user_confirmed MI-02]`〕（W2 / I2 / E3；用户裁决 = 每项 = 一个独立调用）：一次提交多项任务 → agent 侧收到多项、给出多项结果。
   *判定*：一次提交两项 → agent 侧收到两条、结果面出现两条，且得到**两个互不相同的调用 id**（每项 = 一个独立调用）。
4. **执行模式可选**〔`[user_confirmed MI-05]`〕（W2 / I6；用户裁决 = 不设人为上限、断连不终止）：调用方可选「阻塞取终态」或「后台执行」两种模式；阻塞**不设人为上限**，客户端断连 / 放弃等待**不终止**调用（调用仍在后台完成）。
   *判定*：阻塞模式 → 返回时即带终态（阻塞至终态，不出现超时降级或「超时失败」）；后台模式 → 立即受理并给出调用 id，终态由投递给出（→ F07）；阻塞期间主动断连 → 该调用仍能在后台完成，终态可经订阅或按 id 查询取得。
5. **模型优先级**（W2 / I7）：调用参数优先于角色 / 实例默认；未提供时按既有默认行为执行（不新增默认来源、不报错）。
   *判定*：显式指定模型发起一次 → 终态的实际模型为所指定值；不指定发起一次 → 与既有默认一致。
6. **入参不含被排除的维度**（N4 / N5 / N8 / N9 / N10）：入参中不出现隔离工作区、工作量档位、共享文件系统路径、只读计划模式，也不出现本仓库 ACP 派发契约字段。
   *判定*：逐项检索入参定义与文档 → 上述五项零出现（协同 F15 验收 1）。

## 边界（不包含）

- 不含寻址（→ F03）、不含归属的必填与校验（→ F11）、不含结果面（→ F05~F10）。
- **不做隔离工作区与产物回传**（N4，差异 ③）。
- **不做工作量档位与钳制**（N5，差异 ②）。
- **不做共享文件系统根与跨宿主机产物命名空间**（N8，差异 ⑤）：调用方与 agent 不共享文件系统。
- **不做只读计划模式**（N9，差异 ⑥）。
- **不引入本仓库 ACP 派发契约字段**（N10，差异 ⑦）。
- **不改既有消息入口的响应形态与语义**（N18）——新入参叠加，不重写既有契约（→ F14）。
- 不含工具级进度与 token / 成本（N12，差异 ⑬⑭）。
- 不含任务取消 / 终止 / steer 类入参（N3，差异 ⑯⑮）。
