## 用户价值

「符合 sub agent 协议」变成一份可以对表的清单——哪条等价、哪条不等价、为什么不等价，打开文档就能逐条核对，不用听人解释。

## 验收标准

1. **参照契约钉死**（W1 / M-1 / P-1）：文档中明确「sub agent 协议」的参照物 = **harness `task` 工具契约**，并按**调用面 / 响应面 / 展示面**三面列出该契约的逐条不变量（调用面 I1~I11、响应面 R1~R7、展示面 D1~D7），每条给出对照结论。
   *判定*：打开 `oamp/API.md` 能找到该节；对照表条目数与三面条目总数一致（11 + 7 + 7 = 25 条）；每条可读出一个结论（必须等价 / 部分等价 / 本次不做）。
2. **差异清单逐条可读**（W1 / E1 / E10）：不等价与本次不做的条目集中成一份清单，**①~⑲ 逐条**给出内容与依据（① 被调用者生命周期 · ② `effort` · ③ `isolated` · ④ 调用命名 · ⑤ 共享 `local://` 根 · ⑥ plan mode · ⑦ ACP 派发契约字段 · ⑧ 终态字段缺口 · ⑨ 产物形态 · ⑩ 转录不持久 · ⑪ 生命周期控制 · ⑫ 终态词表 · ⑬ 工具级进度 · ⑭ roster 字段裁剪 · ⑮ steer · ⑯ 取消 · ⑰ 远端同会话渲染 · ⑱ 客户端适配 · ⑲ `one_shot` 的例外地位）。
   *判定*：清单存在且条目齐备（19 条）；逐条可读出「差异内容」与「依据」，条目之间不混写。
3. **不静默不同**（W1）：对照表中凡**非**「必须等价」的行，**必须**能在差异清单中找到对应条目——覆盖关系可核对，不存在「表里说部分等价、清单里查不到」的缺口。
   *判定*：逐条核对——所有非「必须等价」的对照行在清单中均有对应编号。
4. **不可得字段的诚实标注**（W4 差异 ⑧ / W5 差异 ⑭ / N12）：清单中「字段无数据源」类条目（usage / tokens / 成本 / `aborted` 语义；roster 的成本与 token）明写「不提供 / 无数据源 / 不造假数据、不估算」。
   *判定*：该两条措辞含「无数据源 / 不提供」；文档其他位置**不出现** usage / token / 成本的字段承诺。
5. **`one_shot` 例外地位登记**（Q-1 裁决 ① / 差异 ⑲）：`one_shot` 在差异清单中有条目，明确定位为「**调用方主动放弃上下文延续**的显式例外」，且与默认路径（同 chat 同名共享上下文，→ F12）形成对照。
   *判定*：清单第 ⑲ 条可读，措辞同时含「显式例外」与「默认路径」。
