# F03：按角色名寻址与角色可发现性

**功能 ID**: F03
**来源**: `demand.md` W2（寻址侧）；裁决 P-5（按推荐）；澄清 M-6 / M-12；约束 C-4（role 在 web 侧推导、零协议改动）；边界 N2 / N6 / N15 / N19；`派生` 次级口径 §6.3-2（无 role 实例的空值形态，可回退）；效果 E2
**迭代**: 0018-chat-agent-subagent-protocol
**技术锚点（引用 `demand.md` §3 只读实测，非本阶段决策）**: F-8（既有 agent 列表只暴露实例标识 / 会话标识 / 状态 / 心跳——角色对 HTTP 客户端不可发现）、F-9（实例名唯一公式 `instance_id = 'pb-' + role`、不允许 override；但允许任意实例名，控制台自身即以 `web` 注册、无 role）、F-1（agent 节点由人或集群命令启动并主动连入——hub 不启停 agent）

---

## 用户价值

客户端传的是**角色名**（如 `dev`），不是某个进程的实例编号——和原生 sub agent 里「按 agent 名选」是同一种发法；角色不在就直接告诉我，不会假装收下了。

## 验收标准

1. **按角色名发起调用**（W2 / M-6 / E2）：调用请求以角色名指认目标 → **对应角色的 agent** 收到该任务。
   *判定*：照文档示例用角色名发起一次 → 该角色 agent 的窗口 / 日志出现该任务。
2. **目标不可用时明确失败**〔`[user_confirmed MI-01]`〕（E2 / N2；用户裁决 = 统一一类 4xx、不新增错误码族）：角色不在线、或不存在对应角色、或目标是无法按角色名寻址的实例时，调用被**明确拒绝**（4xx 且带既有统一错误契约的错误码；上述三种情形**不作区分**、不新增错误码族），**不得**返回「已受理」式的 200；且 hub **不启动**该 agent。
   *判定*：停掉某角色的 agent 后调一次 → 明确失败；用不存在的角色名调一次 → 明确失败；两次均无 agent 被拉起（无新进程、无新注册）。
3. **角色对 HTTP 客户端可发现**（W2 / M-6）：存在可读到「当前哪些角色可被调用」的查询面；对既有命名公式形态的实例，其角色名可被读出，并与实例一一对应。
   *判定*：查询该面 → 在线角色逐个在列，且读出的角色名可直接用于发起调用并命中同一 agent。
4. **无 role 实例的空值形态**（`派生` §6.3-2）：非既有命名公式形态的实例（如控制台自身、无角色）其角色字段返回**空值**，不被误报为某个可寻址角色。
   *判定*：查询该面 → 该实例角色为空，且不被当作可寻址角色。**回退口**：若要求「无 role 实例不可被调用面寻址」，属更严口径，可收紧（不影响其余卡与 W2 主体结论）。
5. **寻址不改变协议面**（N15 / C-4）：角色与实例的对应关系由既有命名关系推导得出，agent ↔ router 的协议方法面（数量与名称）无变化。
   *判定*：对照既有协议速览逐条数方法（协同 F14 验收 4）。

## 边界（不包含）

- 不含调用的入参内容（→ F04）；不含结果面（→ F05~F10）。
- **不照搬 `.omp/agents` 完整发现优先级链**（项目 → 用户 → 插件 → 内置）（N6）：寻址只按角色名。
- **不引入 agent 的创建 / 终止 / 复活 / park**（N2）：目标不可用时只报明确失败，不拉起、不重启、不停止。
- **不改 agent ↔ router 协议方法面**（N15）。
- **不做嵌套 / 父子血缘命名**（N7，差异 ④；落点亦见 F05 边界）。
- 不含权限与鉴权（N19）。
