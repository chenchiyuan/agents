# F06：结构化终态字段

**功能 ID**: F06
**来源**: `demand.md` W4（字段侧）；裁决 P-6（按推荐）；边界 N11 / N12 / N18；差异 ⑧；效果 E4（字段侧）
**迭代**: 0018-chat-agent-subagent-protocol
**技术锚点（引用 `demand.md` §3 只读实测，非本阶段决策）**: F-13（常驻执行路径的成功体含文本 / 模型 / 上下文标识 / 进程标识 / 停止原因 / 时长 / 退出码——**无 usage / tokens / 成本**）、F-5（消息类型与内容类型均为闭集）、F-6（任务表已维护状态与结果）、F-12（增量输出行数封顶）

## 用户价值

调用结束给的是「一份能程序化读的结果」，不是一段要人去猜的文本——客户端拿它就能当 subagent 的返回值用，缺什么也写在明处，不会有假数字。

## 验收标准

1. **文档承诺的字段在终态中出现**（W4 / E4）：终态含**调用 id / agent 名 / 终态 / 时长 / 实际模型 / 截断标记 / 结构化输出（或文本）**；逐项可与文档字段表对照。
   *判定*：照文档字段表逐项打勾 → 逐项命中，无缺项。
2. **终态词表统一**（W4 / R7）：终态取值覆盖「完成 / 失败 / 受阻」，或给出非零退出标记；取值来自封闭词表，不出现随意文案。
   *判定*：制造一次成功、一次失败 → 终态取值落在词表内且两者可区分。
3. **结构化输出按期望结构返回**（W4 / R5，与 F04 验收 2 配套）：调用带期望结构时，终态的结构化输出与之对应；不带时提供文本。
   *判定*：带期望结构发起 → 结构化输出可用；不带 → 文本可用。
4. **不可得字段不造假**（W4 / 差异 ⑧ / N12）：终态与文档中**不出现** usage / tokens / 成本 / `aborted` 语义的字段、占位或估算值。
   *判定*：检索终态与文档 → 上述字段零出现；差异清单 ⑧ 有条目说明原因（→ F01 验收 4）。
5. **截断标记可信**〔`[user_confirmed MI-06]`〕（W4；用户裁决 = 任一既有上限触顶即为真）：当本次调用交付的**输出或过程记录**被既有上限截断时，标记为真；两者都未触顶时为假。
   *判定*：制造一次超上限的输出 → 标记为真；常规输出 → 为假。

## 边界（不包含）

- 不含过程与进度（→ F08）、不含终态投递（→ F07）、不含转录读取（→ F10）。
- **不提供** usage / tokens / 成本 / `aborted` 语义（差异 ⑧）：不造假数据、不估算。
- **不做工具级进度与 token / 成本展示**（N12，差异 ⑬⑭）。
- **不做持久化**（N11，差异 ⑩）：终态在本进程内可读。
- 不含页面 / 控制台呈现（→ F13）。
- 不改既有消息路径与既有错误契约（N18）→ F14：终态是新调用面的交付形态，不重写既有响应与错误语义。

## 架构（阶段 3 已填；真源 = `architecture.md`）

> 本段只填架构维度；产品维度逐字未动。

- **T-02 终态信封的字段名与既有路径的关系**：信封 = `{call_id, agent, state, duration_ms, model, truncated, text, structured_output, error, exit_code}`（`state` 封闭词表 `submitted | working | completed | failed`；**不含** usage / tokens / 成本 / `aborted`，差异 ⑧）；**单一构造点** `composeCallEnvelope(task)`（输入 = 既有任务表条目），三处共用（阻塞响应 / `GET /api/calls/:call_id` / SSE `call_result` 帧）。与既有路径的关系：既有 `warning`（派发失败仍 200）与对话 `out` 行**逐字不变**；信封是**新读取面**的产物，不改既有响应形态；调用面派发失败**额外**映射为 4xx/502（不再吞成 200），对话侧仍按既有行为补 `out{error:'dispatch_failed'}`。
- **T-13 返回字段命名与形态**：与 F04 共用同一张表（入参 §2.2 / 返回 §3.1）；`model` = 执行侧实报的**生效值**（读不到即 `null`，不用请求参数冒充）；`exit_code` 可得时给出（shell / 一次性路径；daemon 路径 `null`）。
- **T-08 截断标记与转录截断的关系**：**同一口径、同一纯函数** `callTruncated(task) = task.updatesTruncated || task.updates.some(u => u.detail?.event === 'truncated')`（MI-06「任一既有上限触顶即为真」）——终态信封的 `truncated` 与转录响应的 `truncated` 由它同时产出；两处数据源都在同一任务表条目上，不新增上限、不改既有上限。
- **T-12 验证组织形态**：落 `oamp/test/call-protocol.test.js` 组 D（字段逐项 / 词表区分 / 结构化输出 / **响应键集合断言（零 usage·token·成本）** / 截断：fake ACP 造 >1000 条更新 ⇒ `truncated:true`）。
