- **契约锚定与文档交付**（W1 / W7 → F01 / F02 / F16）：以 harness `task` 工具契约为参照，交付「三面逐条对照表（I1~I11 / R1~R7 / D1~D7）+ 差异清单（①~⑲）+ 可粘贴示例（发起 / 取终态 / 订阅）」；新增路由 / 事件登记进声明式路由表并同步索引文件与契约文档；零新依赖。

## 拆分理由（原子粒度判断）

**总原则：按「可独立出现的失败」拆卡；保证项按「独立可被破坏的约束」单列。**

- **W1 与 W7 拆三张（F01 / F02 / F16）而非合并为「文档卡」**：两者同落 `API.md`，但失败模式三者互不蕴含——① 对照表与差异清单**完整性 / 不静默不同**（F01：表里说部分等价、清单里查不到 → 红）；② 接口说明与**可粘贴示例可用性**（F02：文档写得对但示例粘上去跑不通，或示例字段与实现不一致 → 红）；③ **工程合规**（F16：新路由漏登记、索引漂移、引入新依赖 → 红）。三者的判定载体也不同（读文档逐条核对 / 终端粘贴执行 / 跑既有锁用例），合并会把三类独立失败压成一个不可分辨的整体。体例与 0017 把「登记义务与工程锁」单列为 F10 一致。
- **W2 拆两张（F03 / F04）**：W2 有两个观察面——**寻址侧**（按角色名发起、角色可发现、不可用时明确失败）与**入参侧**（任务文本 / 共享说明 / 期望结构 / 批量 / 执行模式 / 模型优先级）。失败互不蕴含：入参齐备但角色不可按名寻址 → F03 红；寻址通了但入参缺项（例如不能批量、不能带期望结构）→ F04 红。裸判定也分属两条（E2 ↔ F03；E3 ↔ F04）。
- **W3 / W4 / W5 拆九张（F05~F10 / F13）**：三面各自的验收独立——
  - **F05（身份与按 id 取终态）**：失败模式是「拿不到号」或「号查不回结果」；
  - **F06（终态字段）**：失败模式是「拿得回，但字段不齐 / 出现假数据」；
  - **F07（终态投递）**：失败模式是「订阅收不到终态」，与「能不能按 id 主动取」正交（E5 与 E4 是两条裸判定）；
  - **F08（过程可见）**：失败模式是「只有终态、过程不可见」——F07 绿而 F08 红完全可能；
  - **F09（roster）**：失败模式是「列不出每次调用」；
  - **F10（转录）**：失败模式是「过程记录取不回 / 声称持久但重启即空」——与「实时可见」（F08）不是同一面；
  - **F13（控制台）**：失败模式是「数据面有、界面上没有」——判定载体是浏览器而非 curl。
  若把 W3+W4+W5 合成一张大卡，上述七种独立失败会退化为「整卡不通过」，无法定位。
- **W5 在 F08 / F09 / F13 之外不再拆**：完成通知（D3）并入 F07（投递侧）——它是「终态事件带调用 id」的同一断言；「可按调用订阅」（D6）并入 F08 验收（订阅面按调用），因为它的失败与「按调用订阅能否命中」同源。
- **W6 与 W8 拆两张（F11 / F12）**：两者共享「chat 坐标」但语义不同——**归属**（调用必须属于某个 chat / 项目，无归属不可发起：E11）与**身份**（同 chat 同名共享上下文、跨 chat 隔离：E8）。失败互不蕴含：归属校验生效但身份规则被破坏（跨 chat 串上下文）→ F12 红、F11 绿；身份语义正确但存在无归属调用路径 → F11 红、F12 绿。且 F11 还承载「`project` 与 `context` 并存不合并」，与身份规则正交。
- **F12 不引入任何改动**：W8 是「现状被确认为契约」（既有上下文池键 `(chat_id, agent_id)` 与用户表述同构，N16 明写不改），故本卡的价值在于把 E8 变成可验收项，而非新增能力；其「架构待填」为空是诚实结论，不是漏写。
- **F14 / F15 / F16 单立（保证项）**：分别对应「既有面不能变」「不做项不能留半成品」「新面必须登记且不引依赖」三类**独立可被破坏**的约束；体例沿用 0017 的 F09 / F10（来源条款为 N / E / W-工程侧而非 W 主体）。
- **未单立的项**：① N1~N21 是边界（不做某事）而非交付物，落各卡边界 / 验收 + 全局边界（其中 N1 / N3~N14 / N19 由 F15 与 F16 承接其可验收面）；② `demand.md` §3「大概怎么做」的产品级形态（契约层 / 调用面 / 身份与结果 / 展示面 / 与既有链路衔接 / 工程约束）是**实现路径的形态描述**，逐条分配到对应功能卡，不另立卡；③ 差异 ①~⑲ 是**核对对象**而非功能点，落 F01（清单完整性）+ 各卡边界（逐条对应）。
