## A. oamp 现状（scout: ScoutOampRuntime）

### A.1 形态

单包零依赖 Node ESM（`oamp/package.json`，Node >= 22，无构建步骤）。一个 CLI 启动 4 类长驻进程 + 3 类短命客户端（`oamp/src/cli.js:60-127`）：

| 进程 | 入口 | 传输角色 |
|---|---|---|
| Router | `oamp router start` → `src/router.js` | UDS `net.Server`，NDJSON/JSON-RPC 2.0 |
| Agent 节点 | `oamp agent start <instance-id> [--role r] [--model m] [--tools on\|off] [--permission allow\|deny]` → `src/agent.js` | UDS 客户端，收 `message.deliver` |
| Web/hub | `oamp web start [--port n]` → `src/web.js` | HTTP 服务（127.0.0.1）+ 以实例名 `web` 注册的 UDS 客户端（`web.js:35`, `:1025-1037`） |
| Cluster | `oamp cluster up\|down\|status` → `src/cluster.js` | 仅 tmux 编排，拉起 router/web/`pb-<role>`（`cluster.js:192-200`） |

### A.2 「hub」= 两个协议面 + 一个 CLI 面

「hub」在本仓库不是模块名，指 Router + web HTTP 层（`docs/iterations/0015-hub-orchestration-open-api/demand.md:23`）。

**(a) 内部 UDS JSON-RPC——Router 方法面（`router.js:108-410`）**

| 方法 | 类型 | 参数 | 结果 | 锚点 |
|---|---|---|---|---|
| `agent.register` | req | `{instance_id}` | `{instance_id, session_id, state, lease_timeout_ms, last_heartbeat, lease_follows_interval}` | `router.js:109-159` |
| `agent.heartbeat` | notify | `{instance_id, session_id, next_interval_ms?}` | 无响应 | `router.js:161-184` |
| `agent.deregister` | req | `{instance_id, session_id}` | `{removed:true}` | `router.js:186-199` |
| `message.send` | req | `{message:{message_id, protocol:'oamp/1', type, task_id?, to:{instance_id}, payload:{content_type, body}}}` | `{accepted, message_id, status:'delivered'\|'recorded', task_id?}` | `router.js:201-346` |
| `message.ack` | req | `{message_id, instance_id, session_id, status}` | `{acked:true,status}` | `router.js:348-377` |
| `router.status` | req | 无 | `{nodes:[{instance_id, session_id, state, last_heartbeat}]}` | `router.js:379-383` |
| `router.task_get` | req | `{task_id}` | `{task}` 或 `null` | `router.js:384-394` |
| `router.task_list` | req | `{state?}` | `{tasks:[...]}` | `router.js:395-402` |

消息类型是闭集 `task.request | task.update | task.result | notice`（`router.js:23`）；`content_type` ∈ `text/plain|text/markdown|application/json`（`router.js:20`）。
Router 不排队：离线目标的 `task.request` 直接 `AGENT_OFFLINE` 硬失败（`router.js:329-341`）；`task.update`/`task.result` 在 origin 离线时只写任务表并返回 `status:'recorded'`（`router.js:262-272`），Router 重启即丢（`registry.js:45-47`）。

**(b) 客户端 HTTP + SSE——13 条路由（`web.js:318-793`，文档 `API.md:157-617`）**

全部绑 127.0.0.1、无鉴权、`no-store`、body 上限 64 KiB；错误体 `{error, code}`，code 闭集 `INVALID_PARAM(400)/NOT_FOUND(404)/CONFLICT(409)/PAYLOAD_TOO_LARGE(413)/UPSTREAM_UNAVAILABLE(502)`（`web.js:90-102`）。

`GET /api/agents`(`web.js:321-346`) · `GET /api/chats`(`:349-387`) · `GET /api/chats/:id`(`:389-408`) · `POST /api/chats/:id/close`(`:411-441`) · `POST /api/chats/archive`(`:444-480`) · `POST /api/chats/:id/activate`(`:483-512`) · `POST /api/chats/:id/rename`(`:515-566`) · `POST /api/messages`(`:606-722`) · `GET /api/stream?chat_id=`(`:569-587`) · `GET /api/events`(`:590-603`) · `GET /api/docs`(`:725-736`) · `GET /api/projects`(`:739-750`) · `POST /api/projects`(`:753-792`)

SSE：chat 流 = `message`/`task_update`/`chat_state`/`notice`（`transport.js:38-95`）；全局流仅 `agent_online`/`agent_offline`（`web.js:166-184`）。**无重连重放**，断线期间增量输出永久丢失（`API.md:646-655`）。

**(c) CLI 面**：`router start` | `agent start <id>` | `status` | `task send|status|list|watch`（走 UDS 直连，`task.js:130-250`；`task send` 注册瞬时发送者身份，默认 `main`，`task.js:18`）| `web start` | `cluster up|down|status`。

### A.3 chat → agent 全链路（12 跳，逐跳锚点）

1. `POST /api/messages {chat_id?, project_id?, agent_id, text, model?, one_shot?}` → `web.js:620-722`；`agent_id` 可由 `@agent ` 前缀解析（`web.js:637-647`）。
2. 先落库 `db.insertInput(...)`（`in` 行，`meta:{task_id}`，`web.js:694`），再 `publishMessage(in)` + `publishState('working')`（`web.js:695-696`）。
3. payload 三形态（`web.js:697-701`）：`!` 前缀 → shell；`one_shot:true` → `{executor:'omp', prompt, ...}`；默认 → `{executor:'omp-daemon', chat_id, prompt, ...}`。
4. `tasks.set(taskId, entry)` 先于 await（`web.js:702-705`，防同 socket 读到达的 `task.update` 早于 send 响应）。
5. `sendTask()` → `ensureSender()`（惰性注册实例 `web`，维持心跳）→ `client.send(...)`，一次重试（`web.js:1025-1056`）。
6. Router：`registry.createTask({taskId, from:'web', to:agentId, label, messageId})`（`router.js:289-310`）→ 先记 pending delivery 再投递（`router.js:325-334`）→ `deliverTo`（`router.js:97-102`）→ 响应 `{accepted, message_id, status:'delivered', task_id}`。
7. Agent 侧 `node-client.js:85-113` 校验 `message.deliver` → 回 `{received:true}` 并自动 ack `accepted`；hook = `createTaskDeliverHandler`（`agent.js:461-489`），解析失败 → `ack(rejected)` → Router 任务表 `failed(rejected_by_agent)`（`router.js:363-376`）。
8. 执行（`runTask` `agent.js:361-365`）：
   - `omp-daemon` → `runDaemonTask`（`agent.js:300-358`）：`ctx.pool.getOrCreate(chatId, instanceId)` → `session.prompt(prompt, {model, timeoutMs, onChunk})`；chunk → `task.update {kind:'chunk', text}`；成功体 `{text, model, context_id, pid, stop_reason, duration_ms, exit_code}`。
   - `omp` → `runOmpTask`（`agent.js:180-279`）：spawn `omp -p --no-session [--no-tools] [--model X] [--append-system-prompt role.md] [--approval-mode ...] <prompt>`；stdout/stderr 逐行 → `task.update {kind:'stdout'|'stderr', line}`，200 行封顶后补一条 `truncated`（`agent.js:236-248`）；终态 `{state, executor, exit_code, duration_ms}`。
   - shell → `runShellTask`（`agent.js:368-458`）：同流形态，无 text 体。
9. 反向：`sendTaskMessage` → `client.send(origin, {type:'task.update'|'task.result', ...})`（`agent.js:169-179`）。
10. Web 消费：`handleDeliver`（`web.js:989-1023`）→ `task.update` 转 SSE（**不入库**）；`task.result` → `finishTask` → `db.insertOutput`（一行 `out`）+ SSE `message(out)` + `chat_state`（`web.js:915-942`）。
11. 丢结果兜底：`scheduleReconcile`/`reconcileTask` 每 5 s 轮询 `router.task_get`（6 次 → 30 s 慢速，30 min TTL）补齐 `out`（`web.js:944-986`）。
12. 展示：`web/app.js` per-chat `EventSource('/api/stream?chat_id=…')`（`app.js:493`），`handleEvent`（`:515-551`）把 `task_update` 追加进流式气泡（`appendChunk` `:553-564`）；`message`/`chat_state` 触发重取并重渲染（`:348-366`）。终端侧无 chat 视图，`oamp task watch` 只显示 Router 任务表（`task.js:215-280`）。

### A.4 「subagent」在 oamp 中不存在

`grep -i 'subagent|sub_agent'` 于 `oamp/src` 零命中。最接近的三个类比物：

- **Agent 节点** = 由人或 `oamp cluster` 启动的 OS 进程，不是被「调用」创建（`cli.js:82-92`, `cluster.js:192-200`）。
- **每任务子进程** = 节点内 `spawn(omp|/bin/sh, args)`（`agent.js:206`, `:395`），或每 chat×agent 常驻一个 `omp acp` 子进程。
- **调用数据结构**（精确）：Send 信封 `{protocol:'oamp/1', message_id, type, task_id?, to:{instance_id}, payload:{content_type, body:<string>}, from?, created_at?}`（`from`/`created_at` 禁止由发送方提供，`router.js:38-41`）；Task 条目 `{task_id, from, to, state:'submitted'|'working'|'completed'|'failed', label, created_at, updated_at, updates[], result|null}`，`updates` 上限 1000 后置 `updatesTruncated`（`registry.js:47`, `:195-217`）；`updates[]` 项 = `{at, state, detail}`，detail ∈ `{event:'started'|'truncated'}` / `{kind:'stdout'|'stderr', line}` / `{kind:'chunk', text}`。
- **背压**：`agent.js:449-458` fire-and-forget，agent 先 ack 再并发执行；并发只在 context pool 内受限（每 chat×agent 一个在飞 turn、FIFO 队列深度 8、池大小 `OAMP_CTX_MAX` 默认 8）。

### A.5 Agent 定义、注册、选择

- 角色定义在包外：`OAMP_ROLE_ROOT`（默认仓库根，`role-binding.js:16-22`）→ `<root>/roles/<role>/<role>.md`（`role-binding.js:25-27`）。
- 实例名唯一公式 `instance_id = 'pb-' + role`（`role-binding.js:12-32`），不允许 override（`cluster-config.js:23-24`）。
- 集群配置 = 仓库根 `cluster.json`：`{session, web:{port}, router:{socket}, roles:{<role>:{enabled?, model?, tools?, permission?, cwd?}}}`（`cluster-config.js:120-160`）；当前 10 个角色，dev 显式启用 tools+permission allow。
- 启动时一次性绑角色：`--role` > `pb-<role>` 推断 > 无（`agent.js:600-612`）；角色文件缺失 exit 2。模型链：`payload.model > OAMP_OMP_MODEL > --model(role) > config.defaults.model > builtin`（`agent.js:305`）。
- **调用期选择只能按在线 `instance_id`**（`registry.getEntry(m.to.instance_id)`，`router.js:315-327`）。`GET /api/agents` 只暴露 `{instance_id, session_id, state, last_heartbeat}`——**role 不可通过 HTTP 发现**，hub 客户端无法按角色/能力寻址，只能用预先知道的实例名。

## B. Harness 的 sub agent 协议（scout: ScoutSubagentProtocol）

**唯一真相源：`omp://tools/task.md`**（工具 `task`；模型侧提示词 `packages/coding-agent/src/prompts/tools/task.md`；实现入口 `packages/coding-agent/src/task/index.ts`，该包不在本仓库）。

### B.1 调用（输入契约）

- 形态由 `task.batch`（默认开）决定：批量 `{context, tasks: item[]}`（两者必填，`context` 渲染进每个子 agent 的 `CONTEXT` 系统段）或扁平 `{...item}`。
- item = `{name?, agent?, task, effort?, outputSchema?, schemaMode?, isolated?}`；`task` 必填，trim 后为空即拒。
- `agent` = **task-agent 类型名**，精确名首命中发现链：项目 `.omp/agents` → 用户 `.omp/agents` → OMP 扩展根（CLI → 项目设置 → 用户设置 → npm/link 插件）→ Claude marketplace 插件 → 内置（`scout`, `designer`, `reviewer`, `security-reviewer`, `librarian`, `task`, `sonic`）（`omp://task-agent-discovery.md` §Discovery inputs and precedence）。大小写敏感。
- `outputSchema`（单次调用）> agent frontmatter `output` > 继承父会话 schema；`schemaMode` `permissive|strict`（默认 permissive）。
- `isolated` 仅在 `task.isolation.mode != none` 且非 plan mode 时存在；分支合并 `omp/task/<id>` 或 `.patch` 捕获；**isolated agent 不可复活**。
- `effort` 仅在 `task.enableEffort=true`（默认关）时存在，按 `task.maxEffort` 钳制。
- 护栏：父 `spawns` 策略、`task.disabledAgents`、`PI_BLOCKED_AGENT` 自递归、`task.maxRecursionDepth`（默认 2，达上限子 agent 失去 `task`）、plan mode 下强制只读有效 agent。
- 并发：会话级 `Semaphore`（按 `task.maxConcurrency` 动态调整）；idle TTL `task.agentIdleTtlMs` 默认 420000 ms；`task.softRequestBudget` 200；`task.maxRuntimeMs` 默认 0。

### B.2 返回值（响应契约）

- **异步（`async.enabled=true`）**：文本 `Spawned agent `<id>` (job `<jobId>`). The result will be delivered when it yields.` + `details:{projectAgentsDir, results, totalDurationMs, progress[], async:{state, jobId, type:"task"}}`；进度持续流入同一 tool block。
- **落定**：`task-summary.md` 渲染摘要（5000 字符预览）+ `details.results: SingleResult[]` = 身份（`index/id/agent/agentSource/task/description/assignment`）、状态（`exitCode/error/aborted/abortReason/retryFailure`）、输出（`output/stderr/truncated/durationMs/tokens/requests/contextTokens/usage`）、模型（`modelOverride/resolvedModel/resolvedModelIsFallback`）、`structuredOutput`（schema 来源/模式/校验/数据/错误）、产物元数据（`outputPath/patchPath/branchName/branchBaseSha/nestedPatches/outputMeta`）、`extractedToolData`。
- **产物 URI**：`agent://<id>` → `<id>.md`；嵌套 `agent://<id>/<child>`；JSON 抽取 `agent://<id>/<path>`、`agent://<id>?q=<query>`。`history://<id>` → `<id>.jsonl` 渲染为精炼转录，**live 与 parked 均可读**。
- **终止契约**：子 agent 必须以隐藏的 `yield` 结束（≤3 次提醒，最后一次强制 `toolChoice=yield`）。
- **时间维度**：每次 spawn 注册一个 job（`id` = agent id，`queued`，`ownerId`）；进度经 `onUpdate` 合并（`PROGRESS_COALESCE_MS=150`，尾部 8 KiB / 最后 8 行非空）；输出上限 `MAX_OUTPUT_BYTES=500000`、`MAX_OUTPUT_LINES=5000`；终态结果以 **async-result 注入**父会话，追加 `<id> is now idle — message it via hub to follow up; transcript at history://<id>`。
- **生命周期**：进程级 `AgentRegistry` 中 `running | idle | parked | aborted`；idle-TTL 经 `AgentLifecycleManager` park；`hub` 消息或 Agent Hub 可复活；isolated → `parked` 且无复活器；`"Main"` 永不 park。总线事件 `task:subagent:event`/`:progress`/`:lifecycle`。
- **可嵌入 wire 形态**（`omp://rpc.md`）：`set_subagent_subscription: "off"|"progress"|"events"` 控制 `subagent_lifecycle | subagent_progress | subagent_event` stdout 帧；`get_subagents`；`get_subagent_messages {subagentId|sessionFile, fromByte}`（含 `reset` 语义）。SDK 侧 `outputSchema`, `outputSchemaMode`, `requireYieldTool`, `taskDepth`, `parentTaskPrefix`（`omp://sdk.md`）。

### B.4 展示契约

- **人类权威面 = Agent Hub**（`omp://agent-hub.md`）：roster 行 = 状态（`running|idle|parked|aborted`）、agent 身份、父、未读 IRC 数、模型角色 + 实际模型 + 年龄、任务/当前活动、成本、活跃/经过时间、请求数、工具调用数、token；header 聚合状态 + 用量。Inspector = 当前工具 + 参数、最后意图、重试状态、上下文窗口占用、血缘、输出/patch 路径、隔离 worktree 分支元数据。缺数据显示 `usage —`，**绝不估算**。快捷键 `Alt+A`/`Ctrl+S`/双击 `←`；操作 `j/k`、`Enter`、`t`、`Tab`、`r`（复活 parked）、`x`（kill/release）。
- **流式面**：`onUpdate` 合并 + 尾部上限。
- **通知面**：async-result 注入文本 + `task:subagent:*` 总线事件。
- **远端客户端渲染先例**：`omp://collab.md` 镜像 `bus` + `agents` 帧，使 guest 的 HUD 与 Agent Hub **原生渲染** host 的子 agent——harness 内唯一「另一客户端看到与本地客户端完全一致的 subagent」的既有机制。
- Advisor 行（`__advisor*.jsonl`）仅可观测：不可消息、不可复活、不可 kill，且被排除在 agent 可见的 `hub`/`history://`/`agent://` 之外。

## C. 需求侧必须在阶段 1 收口的问题（scout 提出的开放问题，未经用户确认，不得当作结论）

1. **「sub agent 协议」的准确定义**：本仓库无该协议定义；必须钉死客户端侧参照契约（调用入参字段、结果形状、进度事件），否则「等价替换」没有参照物。仓内候选参照有二且互相不同：harness `task` 工具契约（§B）与 `principles/execution/model-dispatch-protocol.md`（ACP 一次性派发契约，§B.6）。
2. **调用身份**：hub 调用仍是「chat 消息」（要求 chat_id → chat 即调用），还是新的无 chat、按 `task_id` 寻址的调用资源？现状 `POST /api/messages` 强制 chat 模型。
3. **寻址粒度**：role 名 vs instance_id？role 在进程启动时绑定且对 HTTP 客户端不可见，是否需要 hub 解析 role → 在线实例？
4. **阻塞 vs 流式**：hub 调用是否必须可 await（单次响应带终态产物），还是现有 fire-and-forget + SSE 在补上按 `task_id` 的流之后即可接受？这决定是否破坏 `API.md:437-488` 已文档化契约。
5. **进度通道归属**：新增 `GET /api/tasks/<id>/stream`（新路由 → RouteMeta + 三处漂移锁 + API.md 新章节）还是扩展既有 per-chat SSE？注意 `GET /api/docs`/`llms.txt`/`API.md` 由路由表生成且带漂移锁（`web.js:810-845`）。
6. **结果产物形状**：原样回传 Router 任务结果体（`context_id/pid/model/exit_code`）还是归一化信封？「blocked」当前无生产者。
7. **离线/丢失语义**：等价性是否要求调用状态可持久（当前 `task_id` 只活在 Router 内存，重启即丢）？原生 subagent 调用不存在「已记录但不可观测」这种状态。
8. **范围守卫**：0015 记下「hub 不启动、不关闭 agent」是最强边界（`0015/demand.md:23`, `:140`）。需确认本需求不会以「调用」之名重开 agent 生命周期管理。
