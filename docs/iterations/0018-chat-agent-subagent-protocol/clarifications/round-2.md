### 2.1 P-2 专项落定：agent 身份规则（本轮新增的用户原话级结论）

**用户原话（逐字）**：

> 同hub和agent之前的约定， 同chat下，同名agent是一个agent，共享上下文。 不同chat下agent是不同agent

**落定内容**：

1. **agent 身份 = `(chat, agent 名)` 二元组**；同 chat 同名 ⇒ 同一个 agent、**共享上下文**；不同 chat ⇒ **不同 agent**（即使同名）。
2. **与既有 `omp-daemon` 上下文池键的关系（`侦察` F-10 / 0017 F-10）**：既有池键正是 **`(chat_id, agent_id)`**——同键 FIFO 串行（队列上限 8）、异键完全并发、全局上限 8 按 LRU 淘汰。⇒ **既有实现已符合该规则**，本迭代**零改动**把它确认为契约（N16 保持"不改上下文池键与串行/并发语义"）。
3. **与寻址的关系**：配合 P-5 的按 role 寻址，"agent 名"在 hub 的对应物 = **role 名**（`instance_id = 'pb-' + role` 一一对应，F-9）⇒ 调用面在**指定 chat + agent 名**的坐标下定址。
4. **与生命周期差异的关系**：进程载体仍是常驻实例（一个实例承载多个 chat 作用域的 agent 身份）；harness 的"每次派发临时 agent"仍在**差异 ①** 登记。
5. **未被该裁决覆盖的一处 ⇒ Q-1（待确认，不外推）**：既有 `one_shot:true` 路径（F-17：`web.js:697-701` → `executor:'omp'` → `omp -p --no-session`，**不共享上下文**）与该规则的关系，用户原文未表态。按"以 `user_confirmed` 原文为准、不替用户外推"：**结论段按原文记录 W8（默认语义 = 同 chat 同名共享上下文）**，`one_shot` 的存废/例外地位隔离为 **Q-1**，不影响 W1~W7 与其余差异条目。
