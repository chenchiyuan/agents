# F06：版本号升级与变更说明

## 功能 ID
F06

## 用户价值
让协议文件的版本号和变更历史准确反映本次迭代带来的结构性改动，供后续开发者追溯为什么迭代分支层被引入、哪些章节受到影响。

## 验收标准
- [ ] workflow-pb.md 的版本号从 v0.7.0 升级至 v0.8.0（结构性改动：新增迭代分支层、改变合并目标和解锁判据）
- [ ] workflow-pb.md 在"变更历史"章节或对应 changelog 文件（`data/workflow-pb-changelog.md`）中新增 v0.8.0 变更说明，至少包含：
  - 新增"迭代分支"概念
  - "主分支"指代对象从 main 改为迭代分支
  - 阶段 5 解锁判据同步改为"合并进迭代分支"
  - 生效范围延续"仅从下一个使用本工作流的迭代起生效"原则
- [ ] 变更说明能让读者理解：为什么要新增迭代分支层（main 应始终只包含已验证的稳定状态）

## 边界（不包含）
- 不包含具体的协议内容修订（由 F01~F05 处理）
- 不包含追溯已完成迭代（demand.md §3、demand.md §9 明确不做）
- 不包含孤立分支 `iteration/0004-model-dispatch` 的清理（demand.md §3 明确不做）

## 架构维度

已补全为决策 D5（见 `architecture.md` §决策 D5）：

- **版本号升级**：`roles/workflow-pb/workflow-pb.md` 头部 `**版本**: 0.7.0` 改为 `**版本**: 0.8.0`——结构性改动（新增迭代分支层、改变合并目标、改变解锁判据）符合次版本号递增惯例。
- **变更说明位置**：修正——第 45 行是「v0.7.0 变更说明（相对 v0.6.0）」这个小节标题本身所在行，不是该节内容结束之后的位置。准确位置：在 `roles/workflow-pb/workflow-pb.md` 第 45~53 行「v0.7.0 变更说明」整节内容之后（即第 54 行空行之后、第 55 行「## v0.6.0 变更说明」标题之前）插入新节「## v0.8.0 变更说明（相对 v0.7.0）」，格式参考既有 v0.5.0/v0.6.0/v0.7.0 变更说明的结构（触发/方案/具体改动）。
- **changelog 详细记录**：在 `roles/workflow-pb/data/workflow-pb-changelog.md` 头部追加 `## v0.8.0（2026-09-07）` 条目，包含：触发（用户需求："main 应始终代表已验证稳定状态"）、方案（新增迭代分支层 `main ← 迭代分支 ← PR`）、具体改动清单（见下方「对 workflow-pb.md 的目标改动」§1~§5 的文字级改动位置）、未改变的部分（PR 文件七字段格式、阶段数量、执行角色本身）。
