## 本次迭代边界说明

### 包含

- **chat 容器与生命周期**（C-1）：新建 / 标题 / 状态 / 创建更新时间 / 可关闭（只读语义）。
- **对话持久化**（C-2）：只落两类内容——A 的输入（用户消息）与 B 的输出（最终答复文本）；输入先落盘、输出终态落盘。
- **历史查询**（C-3）：列表 + 时间/状态/agent/关键词过滤 + 打开历史 chat 读取完整输入/输出序列。
- **一次调用 + 过程实时展示 + 协议层可替换**（C-4 / D-1）：一次聊天 = 一次调用；过程在对话内实时可见（E-4）；实时通道由可替换的传输抽象承载，本版只实现一种 HTTP 原生流式传输。
- **上下文规范**（C-5 / C-6 / D-2）：上下文键 = `(chat_id, agent_id)`；同 chat 同 agent 累积、新 chat 全新上下文、同 chat 多 agent 互不串扰；上下文由 agent 自己持有与管理。
- **模型指定与默认**（D-4）：调用可指定模型；未指定时默认 gpt-5.6。
- **配置面**（用户决策 §9-1，已裁定保留 2026-09-10）：数据位置由配置文件驱动、默认 `data/sql.db`、环境变量可覆盖。
- **基线兼容**（现状基线 / N-5，已裁定保留 2026-09-10）：0010 既有一次性执行与界面交互不回归；既有测试回归口径见 F08 验收 3。

### 不包含（边界，源自 demand N-1~N-5）

- **N-1** 不持久化过程（流式 chunk、工具调用中间态）——过程仅内存 + 实时推送（落 F02 边界、F04 边界）。
- **N-2** 不做跨 chat 的上下文共享（chat 即隔离边界）（落 F05 边界）。
- **N-3** 本版不做 WebSocket（只留替换接口，不引入相应依赖）（落 F04 边界）。
- **N-4** 不做鉴权 / 多用户（沿用迭代 0010 N6 边界）（全局边界 + F01/F02/F03/F04 边界）。
- **N-5** 不做历史迁移（0010 内存会话数据不迁移；新库从空开始）（落 F02 边界、F03 边界、F07 边界）。
- **全局**：不做 demand.md 之外的新增功能（chat 分组/删除归档/导出、模型费用统计、语义检索、多客户端协同等均已列入对应卡边界）。

## 拆分理由（原子粒度判断）

- **F01 / F02 / F03 三拆**：C-1（容器与生命周期）、C-2（落盘口径）、C-3（查询）是三个独立可测方向——容器语义可用单条断言测（新建/关闭/状态），落盘口径要用"记录计数与类目"测（E-5），查询要用"过滤与序列"测（E-3）。三者失败模式互不覆盖，且任一可单独交付不阻塞其余，故拆开。
- **F04 独立成卡，且不拆成"调用契约"与"实时展示"两张**：C-4 的两半共享同一条可观察链路（提交 → 过程可见 → 终态），拆开会导致验收标准互相引用同一组端到端用例而产生重复;而它与 F02 的分工是"实时可见"（本卡）vs"只落输入输出"（F02），边界清晰、互不重叠，故合并为一张、与 F02 正交。
- **F05 独立成卡且作为核心卡**：C-5/C-6 是本迭代的产品内核（用户明列反例），且其判定方式（内容记忆 + 实例标识复用 + 跨 chat 隔离）与其余卡完全不同，必须独立成卡才能被单独验收（E-1/E-2）。
- **F06 独立成卡**：D-4 的判定不依赖上下文与持久化（可用单轮问答验证模型标识），且是"每轮可覆盖"的独立参数面，合入 F04 会让调用契约卡同时承担模型语义。
- **F07 独立成卡**：用户决策 §9-1 的验收点是"路径解析与优先级"（默认/指定/env/非法），与 F02 的"内容口径"正交，合卡会让 F02 承担配置语义。**来源已裁定保留（2026-09-10 主 agent）。**
- **F08 独立成卡**：既有能力不回归是跨卡约束（一次性执行、界面交互、既有测试），落进任何单张卡都会造成"该卡同时承担回归语义"；独立成卡后可由 PR 规划阶段直接映射为回归 PR。**来源已裁定保留（2026-09-10 主 agent）；验收 3 口径按裁定修订。**
- **前端改造不单独成卡（按 brief 授权判断）**：列表 / 详情 / 流式渲染是 F01 / F03 / F04 的用户可见观察面，独立成卡会与其验收标准重复且无法独立交付；@ 提及补全与 `!` 命令式提交属既有交互保留（F08 验收 4）。
- **未采纳"关闭语义写入 F05"**：关闭是容器生命周期动作（F01），其上下文释放副作用归 F05（AR-03/AR-12），两卡以"关闭后是否还能提问、上下文来自哪里"作为交接点，已由 AR-03/AR-12 补全（阶段 3）。
