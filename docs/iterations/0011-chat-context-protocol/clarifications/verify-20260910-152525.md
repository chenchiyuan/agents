## 下一迭代候选

- **`resp.task_id` 与注册键的一致性守卫**：当前 Router 恒回显发送方提供的 `task_id`（`src/router.js:279/330`），故 `tasks.set(taskId, …)` 的键与 `handleDeliver` 的查找键必然相等；一旦将来 Router 改为自分配/改写 task_id，登记键会静默失配（表现为实时增量丢失 + 条目泄漏，且终态落盘仍正常——与本次修复的缺陷同形难以发现）。可在 `dispatched !== taskId` 时告警，或把注册键改为 `resp.task_id` 后再回填。
- **`tasks` Map 无 TTL/兜底清理**：派发成功后若 agent 在回 `task.result` 前永久失联（Router 侧任务表有终态、web 侧无通知），条目会常驻内存。此为既有性质（修复前"成功登记后不回结果"同样泄漏），本补丁未引入新类别，但登记窗口前移后窗口时长略有增加，值得与上下文池淘汰机制一并评估。
- **E-4 加强断言的定位**：实测该断言对本竞态无区分力（对照组 3/3 通过）。若后续需要"回归守护"清单，应把新增用例（而非 E-4 断言）登记为本次缺陷的守护用例，避免误以为 E-4 已覆盖此竞态。
- **用例端口分配无 `EADDRINUSE` 回退**（承 PR-005 验收候选）：`test/web.test.js` 的 `pickPort()` 取 `41000 + rand(2000)`，无冲突重试；本机高并发或有占用时存在 flake 概率。本次 5×2 连跑未触发。
