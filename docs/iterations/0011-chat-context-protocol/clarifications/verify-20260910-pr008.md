## 下一迭代候选

> 本轮发现的优化点、边界问题或遗留限制。均不阻塞合并，供主 agent 与 planner 决策。

1. **定时器归属键在「起点翻转」时产生 1 次多余重建**：`syncWaitTimer` 的键为 `${chat_id}:${start}`（`app.js:234`）。当同轮内 `start` 先取到兜底值、随后翻转为真实 `in.created_at` 时，键变化触发 `stopWaitTimer()` + 重建。浏览器插桩实测同轮内连续创建两个 1s 定时器（id 97 `@1789034084419` → cleared `@1789034084420` → id 98），间隔 1ms，**无重叠、无泄漏**（live 始终 ≤1），仅多余重建。可收敛为"仅当 start 由 `null` 变为有效值时才校正"。
2. **兜底分支未防御陈旧的 `chat.updated_at`**：若本轮 `in` 消息尚未可见而 `chat.updated_at` 仍是上一轮的终态时刻，`已等待` 会瞬态显示远大于真实的秒数（受控探针实测：陈旧 `updated_at` → 显示 `45s`）。正常时序下该窗口 <1ms 且首个 500ms 采样点已为 `0s`，用户不可见；若要彻底消除，可在 `workingStartAt` 对 `updated_at` 加"不早于本轮派发"的合理性校验。
3. **计时/阈值缺自动化行为回归**：新增用例为源码静态契约（正则断言，`web.test.js:1026-1043`），而 pr-006 / pr-007 均有真实拓扑行为用例（`web.test.js:616`、`web.test.js:684`）。建议补一条真实拓扑用例（fake ACP 首片延迟）锁住"递增 + 跨阈值 + 停表"，使浏览器实测发现的问题具备自动回归能力。
4. **`tickWait` 的提示追加未与计时锚点同护**：`if (back)` 只护住文本更新，若 `#wait-elapsed` 缺失而 `#status-line` 存在，仍会追加提示（`app.js:217-226`）。当前所有渲染路径都先经 `syncWaitTimer`，实际不可达，属防御性缺口。
