# F02：对话持久化（只落输入 / 输出）

**功能 ID**: F02
**来源**: `demand.md` C-2（web 服务持久化，只存两类内容）；N-1（过程不落盘）、N-5（不迁移）；D-3（持久化形态用户决策）；裸判定 E-3、E-5
**迭代**: 0011-chat-context-protocol

---

## 用户价值

关掉页面或重启服务后对话不丢；并且记录里只有"我说了什么、B 答了什么"，不被过程噪声污染。

## 验收标准

1. **一一对应**：一次提问在持久化中产生恰好两条记录——1 条输入（用户原文）+ 1 条输出（B 的最终答复文本）；一次聊天 = 一次调用，输入与输出一一对应（C-2/C-4）。
2. **过程不入库（裸判定 E-5）**：一次问答期间产生的多个过程片段（流式增量、工具/中间态）不产生任何持久化记录；该次问答结束后统计该 chat 的记录数仍为 2（N-1/E-5）。（测试方式：执行一次会产生多段过程输出的任务，结束后核对持久化内容。）
3. **输入先落盘**：用户提交后输入即被持久化——即使 B 尚未返回或该轮最终失败，重启服务后该输入仍可查（C-2/E-3）。
4. **失败可观察**：B 处理失败时该 chat 状态为「失败」并可见（F01-3）；该轮是否额外落一条携带错误信息的输出记录 `[架构待填]`。
5. **仅两类记录**：持久化内容只存在输入与输出两类条目，不存在过程明细、心跳/日志等其他条目（N-1/E-5）。
6. **重启可读回（裸判定 E-3）**：重启服务后，此前落盘的 chat 与其输入/输出仍可读回，内容与落盘时一致（E-3）。
7. **空库启动**：持久化存储初始为空，不迁移 0010 的内存会话数据（N-5）。

## 边界（不包含）

- 不持久化过程（流式片段、工具调用中间态、任务运行明细）（N-1）。
- 不做重试 / 补偿 / 幂等去重机制（demand 未要求）。
- 不做历史数据迁移与导入（N-5）。
- 不做多用户隔离与鉴权（N-4）。
- 不做持久化的加密 / 压缩 / 多副本 / 备份（demand 外）。
- 上下文不因持久化而恢复——E-3 只承诺历史记录可查（见 F05）。

## 架构维度（阶段 3 填）

- `[架构待填]` 持久化形态与存储结构（记录方向仅"输入/输出"两类）、字段最小集。
- `[架构待填]` 输入落盘与输出落盘的精确时机（含失败轮次的落盘点）。
- `[架构待填]` 失败轮次的记录形态（是否落一条输出记录及其错误信息字段）。
- `[架构待填]` 数据存储位置与"初始为空"的建库路径（与 F07 配置面衔接）。
