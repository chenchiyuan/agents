# F02：对话持久化（只落输入 / 输出）

**功能 ID**: F02
**来源**: `demand.md` C-2（web 服务持久化，只存两类内容）；N-1（过程不落盘）、N-5（不迁移）；D-3（持久化形态用户决策）；裸判定 E-3、E-5
**迭代**: 0011-chat-context-protocol

---

## 用户价值

关掉页面或重启服务后对话不丢；并且记录里只有"我说了什么、B 答了什么"，不被过程噪声污染。

## 验收标准

1. **一一对应**：一次提问在持久化中产生恰好两条记录——1 条输入（用户原文）+ 1 条输出（B 的最终答复文本）；一次聊天 = 一次调用，输入与输出一一对应（C-2/C-4）。
2. **过程不入库（裸判定 E-5）**：一次问答期间产生的多个过程片段（流式增量、工具/中间态）不产生任何持久化记录；该次问答结束后统计该 chat 的记录数仍为 2（N-1/E-5）。（测试方式：执行一次会产生多段过程输出的任务，结束后核对持久化内容。）
3. **输入先落盘**：用户提交后输入即被持久化——即使 B 尚未返回或该轮最终失败，重启服务后该输入仍可查（C-2/E-3）。
4. **失败可观察**：B 处理失败时该 chat 状态为「失败」并可见（F01-3）；该轮的落盘口径：额外落一条输出记录（`text` = 可见错误摘要，`error` = 机器码）——见「架构维度」AR-05。
5. **仅两类记录**：持久化内容只存在输入与输出两类条目，不存在过程明细、心跳/日志等其他条目（N-1/E-5）。
6. **重启可读回（裸判定 E-3）**：重启服务后，此前落盘的 chat 与其输入/输出仍可读回，内容与落盘时一致（E-3）。
7. **空库启动**：持久化存储初始为空，不迁移 0010 的内存会话数据（N-5）。

## 边界（不包含）

- 不持久化过程（流式片段、工具调用中间态、任务运行明细）（N-1）。
- 不做重试 / 补偿 / 幂等去重机制（demand 未要求）。
- 不做历史数据迁移与导入（N-5）。
- 不做多用户隔离与鉴权（N-4）。
- 不做持久化的加密 / 压缩 / 多副本 / 备份（demand 外）。
- 上下文不因持久化而恢复——E-3 只承诺历史记录可查（见 F05）。

## 架构维度（阶段 3 已填，2026-09-10；详见 `architecture.md` §4.1~§4.7、§8）

- **形态与结构**：SQLite 单文件（`node:sqlite` 的 `DatabaseSync`，Node 内置、零第三方依赖），两张表——`chats(chat_id,title,agent_id,state,created_at,updated_at,closed_at)` 与 `messages(id,chat_id,direction,agent_id,text,model,duration_ms,error,created_at,meta)`。`direction` 仅 `'in'`/`'out'` 两类；`model`/`duration_ms`/`error`/`meta` 为审计与"输入↔输出↔任务"关联所需的最小补充字段（`meta` 存 `task_id`/`context_id`/`pid`）。写入函数只有 `insertInput()`/`insertOutput()` 两个、`direction` 在函数内写死 → 结构上无法产生第三类记录（对应验收 5）。
- **落盘时机**：输入 = `POST /api/messages` 校验通过后、派发任务**之前**同步写入（对应验收 3）；输出 = web 收到 `task.result` 时写入（成功写答复文本，失败写错误摘要）。过程（流式 chunk、工具中间态）**永不入库**，只经 SSE 推送（对应验收 1/2）。
- **失败轮次的记录形态**：**落一条 `direction='out'` 记录**——`text`=人可见错误摘要（如「模型不可用：openai/xxx」），`error`=机器码（`model_unavailable` / `timeout` / `context_crashed` / `dispatch_failed`）；派发失败（目标 agent 离线等）同样立即补一条失败 out 记录，以保"一次提问恰好两条记录"（对应验收 1/4）。web 启动时把本次启动前遗留的 `working` 置为 `failed`（不补记录）——该轮输出确实缺失，状态如实反映。
- **存储位置与空库启动**：路径由配置解析（`OAMP_DB` > `config.json: data.db` > 默认 `data/sql.db`，相对包根 → `oamp/data/sql.db`）；打开前 `mkdir -p` 建目录；建表为幂等 `CREATE TABLE/INDEX IF NOT EXISTS` + `PRAGMA foreign_keys=ON`，**不引入迁移版本表**（本迭代无迁移）→ 首次运行即空库（对应验收 6/7，与 F07 衔接）。
