# F08：基线兼容与回归（0010 既有能力不回归）

**功能 ID**: F08
**来源**: `demand.md` §4 现状与差距（迭代 0010 基线）、N-5（不迁移但也不破坏）；**`demand.md` 未单列"兼容"条款** → 见 `prd.md`「疑问与越界」第 3 条 `[model_inferred]`
**迭代**: 0011-chat-context-protocol

---

## 用户价值

引入对话与上下文能力不砸掉现有用法——已经能跑的一次性执行与界面交互照旧可用，升级是加法而不是替换。

## 验收标准

1. **一次性执行路径保持可用**：显式要求一次性执行的提交（0010 既有的 shell 命令执行、一次性模型问答两种形态）行为不变——该次执行不累积到所在 chat 的上下文，后续调用也不复用该次执行的上下文。
2. **两种形态可区分**：新增的"同 chat 上下文累积"能力与"一次性执行"在同一系统内可区分——用户显式选择一次性执行时按验收 1 判定；未显式选择时按 F05 的上下文规则判定。
3. **既有测试全绿**：0010 既有测试集合在本迭代末仍全部通过（作为回归判据存在，不构成新增功能）。
4. **界面既有交互保留**：@ 提及补全、以 `!` 开头的命令式提交、消息列表与详情展示样式在改造后仍可用。

## 边界（不包含）

- 不承诺 0010 内存会话数据的迁移（N-5）。
- 不承诺一次性执行路径继续演进（本卡只锁"不回归"）。
- 不引入 0010 之外的新执行形态（demand 未要求）。
- 本卡不改变 F01~F07 的任何产品行为，只锁"既有能力不被破坏"。

## 架构维度（阶段 3 填）

- `[架构待填]` 执行路径的路由与默认值切换方式（新默认不破坏显式指定的一次性路径）。
- `[架构待填]` 既有 web 交互与既有测试集合的改造影响面盘点。
