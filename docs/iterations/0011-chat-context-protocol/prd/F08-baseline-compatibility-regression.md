## 用户价值

引入对话与上下文能力不砸掉现有用法——已经能跑的一次性执行与界面交互照旧可用，升级是加法而不是替换。

## 验收标准

1. **一次性执行路径保持可用**：显式要求一次性执行的提交（0010 既有的 shell 命令执行、一次性模型问答两种形态）行为不变——该次执行不累积到所在 chat 的上下文，后续调用也不复用该次执行的上下文。
2. **两种形态可区分**：新增的"同 chat 上下文累积"能力与"一次性执行"在同一系统内可区分——用户显式选择一次性执行时按验收 1 判定；未显式选择时按 F05 的上下文规则判定。
3. **既有测试回归（2026-09-10 主 agent 裁定）**：`oamp/test/` 下现有 11 个 `*.test.js` 中，除 `web.test.js` 等价重写外，其余 10 个（`agent-heartbeat` / `cli` / `delivery-contract` / `event-log` / `hygiene` / `omp-executor` / `reconnect` / `router-registry` / `status` / `task`）**原样保持全绿**；`web.test.js` 所覆盖的既有用户可见能力由重写用例**等价覆盖**，等价断言项如下（判定方式：重写后的 `web.test.js` 逐条覆盖 a~d，断言强度不低于原用例、可判定同一事实）：
   - **a) 发送 → 任务 → 输出回流**：提交一条消息 → 返回 chat 标识与任务标识；随后该 chat 详情可查到该条消息、任务达到完成态、B 的输出内容回落到该 chat 的可见结果中；该 chat 出现在列表中且状态为已完成。（对应原断言：`chat_id`/`task_id` 非空返回、标题含首条输入文本、任务 `exit_code === 0`、stdout 行包含发送内容、列表项状态 `completed`。）
   - **b) 追加消息到既有 chat**：对既有 chat 追加第二条输入 → 返回同一 chat 标识，该 chat 的输入/输出序列为 2 条且第二条达到完成态。（对应原断言：`chat_id` 相同、`messages.length === 2`、第二条任务 `state === 'completed'`。）
   - **c) 错误面**：缺 agent 标识的提交 → 被拒绝并返回明确错误；空白输入 → 被拒绝并返回明确错误；请求不存在的 chat 详情 → 返回明确的"不存在"错误。（对应原断言：前两者 HTTP 400、未知会话返回非成功状态。）
   - **d) 控制台页面与在线 agent 列表**：控制台静态页可访问，且可列出当前在线的 agent。（对应原断言：`/` 返回 200 且含页面标识、`/api/agents` 返回 `dev-1` 且 `state === 'online'`。）
   - 本项作为回归判据存在，不构成新增功能；新增能力（F01~F07）的验收不属于本项。
4. **界面既有交互保留**：@ 提及补全、以 `!` 开头的命令式提交、消息列表与详情展示样式在改造后仍可用。

## 边界（不包含）

- 不承诺 0010 内存会话数据的迁移（N-5）。
- 不承诺一次性执行路径继续演进（本卡只锁"不回归"）。
- 不引入 0010 之外的新执行形态（demand 未要求）。
- 本卡不改变 F01~F07 的任何产品行为，只锁"既有能力不被破坏"。
- 不承诺 `web.test.js` 原文件字面保留（按裁定为等价重写）；不承诺其被替换掉的内部实现细节（会话内存表、任务明细 join 方式）仍然存在。

## 架构维度（阶段 3 已填，2026-09-10；详见 `architecture.md` §9、§9.3、§16.1）

- **执行路径路由与默认切换**：web 侧判定顺序 = `!` 前缀 → shell 执行器（0010 原样）；`one_shot:true` → 一次性模型执行器（0010 原样：`omp -p --no-session --no-tools`）；否则 → 常驻路径（本迭代新增默认）。三条路径由 payload 的 `executor`/`command` 字段决定、互不干扰（F08-1/F08-2）；常驻路径要求 `chat_id` 非空，缺失 → agent 拒收 → web 落失败 out 记录。`tools:true` 仅在一次性分支有效。
- **既有 web 交互保留清单（F08-4）**：`@agent` 补全（数据源仍来自 Router status 查询，路由与数据源都不动）、`@agent 文本` 服务端兜底解析、`!` 开头命令式提交、消息/详情展示样式（保留 0010 视觉，新增关闭按钮 / 模型输入框 / 一次性开关 / 系统提示条）；1.5s 轮询**移除**改实时推送（轮询无法满足 F04-2"终态前可见增量"的判定）。
- **既有测试影响面（F08-3 落地口径）**：`web.test.js` 的消息路径必须重写（其断言建立在"Router 内存会话 + `message_id` join 任务明细 + 真实一次性执行"之上，而这些正是本迭代被替换的行为）；等价重写口径见验收 3 a~d，并另加新增能力（实时推送 / 落盘 / 隔离）断言；其余既有测试文件保持原样全绿。
- **改造影响面（阶段 4 PR 规划依据）**：新增 `src/persist.js`、`src/transport.js`、`src/context-pool.js`、`src/acp-client.js` 与 5 个新测试文件；改造 `src/web.js`（路由重写）、`src/agent.js`（daemon 分支 + notice 处理 + SIGINT dispose）、`src/config.js`、`.gitignore`(+`data/`)、前端 3 文件；**删除** Router 的 `chat_*` 三个 case 与 registry 的会话表及其 5 个方法（clean cutover：web 不再使用 Router 内存会话表）；其余（`rpc`/`node-client`/`task`/`status`/`cli`/`log`、`bin/`、`scripts/`、`package.json` 零新依赖、协议信封与错误码、心跳/租约/替换语义、Router 任务表与 `oamp task` CLI）不动。
