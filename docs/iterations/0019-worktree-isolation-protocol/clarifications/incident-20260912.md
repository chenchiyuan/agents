## 3. 观察到的四类损害（事实，非推断）

1. **未跟踪产物在共享工作区滞留**：S-0018 的阶段 1~2 产物（`docs/iterations/0018-…/` 全部文件）在 17:52 之前一直是**未跟踪**状态，与 S-0017 的未跟踪文件（`verify-stage6-*.md`）混在同一工作区——任何一方的 `git add -A` / `git clean` / 分支切换都可能误纳入或误删对方产物。
2. **提交落到他人的分支**：`028ca8a`（0017 的阶段 6 收尾提交）落在 `iteration/0018-chat-agent-subagent-protocol` 上，且未进 main。后果：0018 分支混入与自身无关的提交；0017 的收尾产物一度只由 0018 分支一个 ref 持有（若 0018 被删除，该提交将只存在于 reflog）。
3. **分支切换被他人未提交改动阻塞**：S-0018 的 `git checkout` 连续失败两次（先被已跟踪改动、后被未跟踪文件挡住），必须走「备份 → 移开文件 → `checkout -m` → 手工解冲突 → 恢复」的非标准路径，且中途产生了 `UU` 冲突状态。
4. **同一文件被两个会话交替读写**：0017 `history.md` 先被 S-0017 追加（17:42:52，未提交）、被 S-0018 读出并纳入并集解冲突、最终被 S-0017 提交进 main —— 同一文件的三个版本在 10 分钟内交替出现；`verify-stage6-*.md` 亦出现工作区版本与已提交版本第 160 行 `:695-699` / `:695-698` 的一字符差异。
