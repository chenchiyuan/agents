草稿 v0 先按第二段结构填了一版（大半推断，作为诊断对象），随后逐维跑诊断。**诊断对象 = "每会话独立工作区"这一机制雏形及其与现行规范的接缝。**

### 维度 2 · 逻辑闭环（★ 本轮最严重缺口）

**比对方式**：以"同仓库多会话共用单一工作树（同一 index + 同一 HEAD）"为已确认的 why，逐条检验"每会话独立工作区"这个 what 能否推出目标效果。

| 事故损害 | 雏形是否足以消除 | 缺失前提 |
|---|---|---|
| 1 未跟踪产物混合 | 能 | **P-A 进入契约**：会话必须真的在自己的工作区里运行 |
| 2 提交落到他人分支 | 能 | P-A；残留风险 = 显式跨工作区命令（`git -C` / `--work-tree`）不受约束 |
| 3 切换被他人改动阻塞 | 能 | P-A |
| 4 同一文件被交替读写 | 能 | P-A；**风险形态改变**：从"运行时互相改写"变为"合并期冲突"（可见、可回滚，不静默丢内容） |

**由此识别的四条结构性前提（用户未提及，机制雏形未覆盖）**：

- **P-A 进入契约缺失** → P-2 / P-5：现行规范对"会话从哪个工作树启动"零约束，第 4.5 步只规定"切到迭代分支"，不规定"在哪个工作树切"。
- **P-B 工作区自洽性缺失** → P-8：`.pb-agents/` 被 `.gitignore` 忽略 ⇒ `git worktree add` 产生的空工作区没有角色文件 ⇒ 每个新工作区在 SKILL Step 0 硬停。
- **P-C 合并期新暴露** → P-6：git 层同一分支不能同时被两个工作区检出，而现行"迭代分支合并进 main"假定主 agent 可在自己的工作区 `checkout main`。
- **P-D 共享可变状态残留** → P-9 / P-7：worktree 隔离工作树/索引/HEAD，**不隔离**仓库级 refs（stash 条目）与分支命名空间；事故中"stash 已无内容可 stash"是同类症状。

**同时完成的反向比对（what → why）**：四类损害均可追溯到"共用同一工作树"这一根因，未出现"用户给的 what 与用户陈述的痛苦脱节"的情况 ⇒ **本轮不发起需求改写提案**（区别于 0017 迭代 C-4 那种"能力边界声明"型输出）。

### 维度 3 · 边界完整性

- **用户明说 3 条**：不共用同一工作树；0018 现场不被触碰；迭代对象是 workflow-pb 流程本身。
- **AI 推导 10 条**（N1 ~ N10），每条附"为什么这次不做"；其中两条因影响面大而升格为待裁决项（"是否做机制化守卫"→ P-11；"clone 是否进默认形态"→ P-1）。
- **主动收敛判断**：`clone 形态`/`自动化守卫`/`跨机器保证`/`0018·0017 现场处理` 四项均可从最小闭环中去除且闭环仍成立——但前三项**用户原话或现状留有余地，不由 demand 单方面删除**，全部转为候选裁决项。

### 维度 4 · 内部一致性（C-1 ~ C-6）

| # | 冲突 | 性质 | 处置 |
|---|---|---|---|
| C-1 | 第 4.5 步"主 agent 根目录保持在迭代分支" vs 并行会话 | 指代不清（非语义冲突） | → P-5 |
| C-2 | "迭代分支合并进 main"（`checkout main`）vs 多工作区 | **git 层硬冲突** | → P-6 |
| C-3 | SKILL"角色文件根路径固定 `.pb-agents/roles/`" vs 新工作区缺该目录 | **硬冲突（必停路径）** | → P-8 |
| C-4 | 规则 A 的 "worktree" 术语 vs 新增的"会话级 worktree" | 术语重载（非矛盾） | → P-4（并确认 PR worktree 的 base 与解锁判据不变） |
| C-5 | "只改文本、不引入新机制"的设想 vs P-B 必须处理 | 结构性张力 | → P-8 一并裁决 |
| C-6 | 雏形 = worktree vs P-D 残留风险 | 形态选择决定风险范围 | → P-1 与 P-9 需一并呈现 |

**特别记录**：C-2、C-3 是**当前机制雏形不加处理就必然失败**的两处（不是"更好的做法"，是"会直接卡住"）；这是本轮把 P-6、P-8 标为"真正需要拍板"的依据。

### 维度 5 · 可验证性（E1 ~ E7）

7 条效果全部通过裸判定测试，均为可观察信号（工作区路径是否不同 / 另一方分支上是否出现对方提交 / 暂停迭代的工作区与分支是否仍在 / 新建工作区能否通过 Step 0 等），**无主观感受词**，不点名具体工具与数字。

**刻意留白且仍可裸判定的一处**：E5 只判定"条款是否自带可客观判断的违反判据"，**不判定是否被自动拦截**（机制化强制属 P-11，未裁决前不写成效果）。
