## 一、P-16：提案 → 裁决 → 落定

### 1. 提案（v1.2.0 收口时提出）

见 `clarifications/demand-round-3-proposals.md`（全文未改动）。当时的状态：**唯一的待裁决项**，保持 `[model_inferred]`、不进入任何下游条目。

- **问题**：是否把"跨工作区写入（绝对路径 / `git -C` / `--work-tree`）不得发生"写成一条负面约束条款？
- **三个选项**：① 写为文本级负面约束 + 判断方式（demand 推荐）；② 不写、只记案例（属个别操作失误）；③ 写为更强的"恢复流程标准化"（demand **不推荐**——会削弱 P-12 ①「现场原样保留、只由归属方清理」）。
- **证据**：复盘 Q-a A-4.5（"隔离不是强制：绝对路径写入可以跨工作区生效"）+ `0017/history.md:204`（pr-003 dev 在自己的 worktree 内工作期间误写主工作树三笔 edit，靠 `cp` 备份 + `git checkout --` 还原）。

### 2. 裁决（用户原话）

> ① 写为负面约束 + 判断方式（推荐）

**采纳选项 ①**，且裁决同时给出三条硬要求（主 agent 转达）：条款的写操作范围必须落在本会话工作区内、恢复他人工作区内容须先备份、**必须写明该条款不可能被 git 强制**。

### 3. 落定（v1.3.0 的改动）

| 落点 | 内容 |
|---|---|
| **W12**（新增，`user_confirmed`） | 跨工作区写入负面约束 + 判断方式：会话的写操作（含文件写入、`git -C`、`--work-tree`）**必须落在本会话的工作区内**；以绝对路径写入非本会话工作区**不得发生**；若必须恢复他人工作区的内容，**先取备份再操作**。判断方式：任取一次会话执行记录，其产生的写入/提交所指向的路径均位于本会话工作区之内；若记录中出现对非本会话路径的写入，则该记录必须同时体现"先备份、后操作"两步。**条款性质已写明：不可能被 git 强制**（worktree 是目录分离，不是访问控制） |
| **N10**（新增，`user_confirmed`，边界补正） | **不把 W12 表述为可被 git 强制执行的机制**（不引入 hook / 访问控制 / 路径守卫）——依据 P-16 ④ 与 N4（P-11 ① 只做文本级"条款 + 判断方式"）；写成硬门会误导下游把"未阻止"当成"条款失效" |

| **§1.4**（新增） | 第四轮裁决原文表 + P-16 的证据来源 + **R-8 转正说明** |
| **§5 效果注**（更新） | "刻意不写成效果的项"中，原"防住显式跨工作区命令（是否写条款仍未裁决 → P-16）"改为"**跨工作区写入被阻止**（W12 是文本级约束，不可能阻止动作发生——N10 已写明该性质）" |
