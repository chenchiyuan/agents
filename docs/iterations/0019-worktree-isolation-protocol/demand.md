# 第二段 · 需求结论

## 1. 目标与价值

**目标（`user_confirmed`）**：让**同一仓库上并行的多个主 agent 会话**各自拥有互不干扰的工作区，使"一个会话的操作 / 未提交改动 / 分支切换"在物理上无法影响另一个会话，从而消除本次事故的四类损害（丢写、提交串分支、切换被阻塞、同一文件被交替读写）。

**价值（`user_confirmed` + 复盘实证）**：复盘 P-1 把它表述为"**会话身份与工作区身份之间没有任何绑定**"——现行规范对这一绑定零约束，等于把正确性寄托在"人恰好不会同时开两个会话"这一假设上。本迭代把该假设替换为一条可判断的规范；且按用户约束，只改工作方式本身、只依赖 git 原生能力。

- **capability 边界（`user_confirmed`，来自复盘 A-1）**：本机制隔离**工作目录 / 索引 / HEAD** 三层；**不隔离** refs（含 stash 与分支命名空间）、对象库、config/hooks/remotes；"同一分支不能两处检出"是 git 硬约束；**隔离不是访问控制**（绝对路径写入可跨工作区生效）。

- **本文件锁定的结构性事实（`实测`）**：会话级工作区一旦成立，"仓库根目录"的一切指代被重载；新机制必须与 **Step 0 角色文件检测**（C-3/C-7）、**阶段 5 PR worktree**（C-4/C-8）、**迭代分支合并进 main**（C-2）三处接缝同时自洽。

## 6. 为什么这么做

**为什么（`user_confirmed` + 复盘实证）**：用户在同一工作树上真实遭遇四类损害并明确归因于共用同一工作树；复盘 P-1 把它上升为"**会话身份与工作区身份无绑定**"这一机制缺口（四类损害逐条落在工作目录/索引/HEAD 三层），且该缺口在 0017 的 PR 粒度上已被同一机制（worktree）证成可解（G-1）。D-1 虽已关闭（第二写入方停止），但**机制缺口未修复**——这是本迭代仍然成立的理由。

**为什么这次、为什么只改这些（`user_confirmed`）**：工作区归属是四类损害的公共前置条件，改动这一处即可覆盖四项症状；用户第二轮约束①限定"只改工作方式本身"，故 N1/N7 明确排除阶段序列与产品代码。非 git 共享资源（P-15）之所以**必须**进来，是因为复盘 A-4.3 证明它们是 worktree 结构上无法覆盖、且 0017 已真实撞到的一类（端口/负载），若不声明，本迭代"消除损害"的承诺会在最容易被撞到的环节留下缺口。
