# F01：会话工作区形态（worktree 唯一规范化形态）

**功能 ID**: F01
**来源**: `demand.md` W1（P-1 ①，`user_confirmed`）；边界 N6；效果 E1 / E2；实证 `retro-0017-phase1.md` Q-a A-1 / A-2 / G-1（**证据来源，非需求来源**）
**迭代**: 0019-worktree-isolation-protocol
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有规范「提交管理约束·规则 A（worktree 隔离）」与阶段 5 的 PR worktree 机制；`iteration/{迭代ID}` 分支层

---

## 用户价值

并行开两个会话，各自的活互不打架——一边改代码、切分支、留下未提交改动，另一边完全不受影响。

## 验收标准

1. **规范把 worktree 定为默认且唯一被规范化的形态**（W1 / P-1 ①）：规范文本中存在一条明确的形态条款，规定并行会话各用独立 worktree、不共用同一工作树；且该条款的措辞是"默认 + 唯一"——不含"或者用 clone / 或者各建一份副本也可"这类等价形态选择。
   *判定*：读规范文本，找得到该条款，且逐句检查无并列形态被同等规范化 → 通过；出现第二种被规范化的形态 → 不通过。
2. **clone 只作兜底声明、不定义流程**（W1 / N6）：规范对 clone 只声明"无法共享同一 `.git`（跨机器 / 跨用户 / 无写权限）的场景**不受本协议保证**"，**不为其定义任何执行步骤**（不写怎么建、怎么切、怎么合并，也不写 clone 场景下的阶段流程）。
   *判定*：在规范文本中检索 clone 相关表述——只出现声明句、不出现步骤句 → 通过；出现任一执行步骤 → 不通过。
3. **两个并行会话的工作区路径不同，且互不改变对方内容**（E1）〔`[user_confirmed MI-05]` 判定样本 = 本迭代阶段 6 按新规范在同一仓库构造的两个工作区〕：任取一次并行（构造样本亦可）的两个会话：两者各自的工作区路径不同；一个会话在其工作区内做写入 / 提交 / 分支切换后，另一个会话工作区里的**被跟踪文件与未跟踪文件内容均不变**。
   *判定*：取该次执行的记录与两个工作区路径，在另一方工作区逐项对照文件内容（含未跟踪文件）与改动前后状态 → 任一处内容变化即不通过。
4. **切换分支互不阻塞、互不覆盖**（E2）〔`[user_confirmed MI-05]`：判定样本同验收 3〕：一个会话在其工作区内执行分支切换时，另一个会话的**当前分支**与其**工作区内容**前后不变——另一方的未提交改动既不挡住这次切换，也不被这次切换覆盖。
   *判定*：同一次记录中，对照另一会话在切换前后的当前分支与未提交改动清单 → 出现"切换被阻塞"或"未提交改动消失 / 被覆盖"即不通过。
5. **两条能力边界被如实声明**（N6 / W1）：规范不声明本机制保证跨机器 / 多人协作场景的隔离。
   *判定*：检索规范文本，不存在"跨机器也保证隔离"这类表述。

## 边界（不包含）

- 不含工作区落点目录、命名、创建命令、识别方式（→ `[架构待填]` T-01 / T-05）。
- 不含启动契约与硬停（→ F03）；不含"每迭代一个工作区"的绑定（→ F02）。
- **不为 clone 定义任何流程**（N6）；**不保证跨机器 / 多人协作**（N6 / P-13 ①）。
- 不含阶段 5 的 PR worktree 机制改动（→ F07；规则 A 的实质语义不变，见 F14 验收 3）。
- 不含共享 refs / 对象库 / config / hooks 的隔离（那些是**不覆盖项**，由 F12 的隔离边界声明承载）。
- **不追溯已完成迭代**（N3）：本形态条款从下一个迭代起生效，0019 自身不迁移。
