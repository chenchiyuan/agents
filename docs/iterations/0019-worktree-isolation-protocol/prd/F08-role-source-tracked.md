## 用户价值

在新工作区里不用装任何东西就能开工——角色定义随检出就有，不必先跑一个安装脚本、也不必有人记得跑。

## 验收标准

1. **读取来源 = 被 git 追踪的角色定义**（W8 / P-8 ①）：规范把角色定义的读取来源改为**被 git 追踪的内容**（本仓库场景 = 被跟踪的 `roles/**`）。
   *判定*：读规范条款；在一个新建工作区内按规范找角色定义 → 读到的文件属于被跟踪内容即通过；读到被忽略 / 未被跟踪的内容即不通过。
2. **新工作区零动作可读**（E9）：在一个新建的工作区内，**未执行任何安装或初始化动作**，即可读到规范定义的**完整**角色定义（Step 0 的检测天然通过）。
   *判定*：按新规范新建一个工作区 → 不跑任何安装脚本、不做任何初始化 → 按规范路径读到全部需要的角色定义（不缺角色、不缺文件）→ 通过；任一步骤缺失或读不全，即不通过。
3. **SKILL 的 CRITICAL 已改写且不自相矛盾**（W8 / C-3）：SKILL 中"不得退回读 `roles/` 源码目录"的 CRITICAL 已被改写，改写后与新来源一致——改动后的两处（CRITICAL 与 Step 0 检测）**不存在互相矛盾或与来源条款矛盾的两条要求**。
   *判定*：读改写后的两处文本，逐句核对 → 出现"必须用 A 路径"与"不得用 A 路径"并存的表述即不通过。
4. **`.pb-agents/` 与安装脚本降级为可选分发手段**（W8 / C-7）：规范 / SKILL 中 `.pb-agents/` 与 `tools/install-pb-agents.sh` 的定位从"工作流运行前提"降为"**仅面向外部业务项目的可选分发手段**"；**不存在"未安装则停止推进"的运行前提条款**。
   *判定*：读改写后的相关段落 + 全文检索安装检测表述 → 仍存在"未安装即停止推进"的前置要求即不通过。
5. **上下游两场景共用同一份规范**（W8）〔`[user_confirmed MI-06]`〕：规范写清**上游研发场景**与**下游部署场景**如何共用同一份规范；"零动作"的准确含义被写清 = **不需要人手动跑安装脚本、不需要额外动作**；且**零动作承诺只覆盖"角色定义真源随检出即得"的场景（本仓库）**——下游业务项目仍可有"先分发角色文件"一步，但该步骤**不算本协议的运行前提**。
   *判定*：读规范文本，两场景各有一句可判断的说明、且下游含义句存在 → 任一处缺失或含义与 W8 原文不符即不通过。
6. **只读约束保持**（W8 / 既有条款）：角色定义来源的只读属性不变——规范不要求在执行期修改角色定义；角色 `data/` / `memory.md` 不随分发部署的既有约束不变。
   *判定*：读规范 / SKILL 相关段落 → 出现"执行期写入角色定义"的要求即不通过。
