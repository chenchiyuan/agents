## 验收标准

1. **本迭代不承接 D-2**（N2）：0019 的产物与规范改动中**不包含** `/api/chats`、`/api/messages` 登记元数据缺 `project_id` 的修复；也不为它新增任何条款。
   *判定*：检索本迭代的改动清单与全部产物 → 出现该修复或其相关条款即不通过。
2. **三处 status 互相引用**（E12）：任取 **0017 / 0018 / 0019 三处 `status.md`**：对 **D-2** 的登记**互相引用、指向同一承接方**（"单独的小迭代，0019 完成后起"）。
   *判定*：读三处文本，检查引用链——0017 指 0018/0019、0018 指 0019、0019 指明承接方与起始条件（或三处共同指向同一承接方）→ 任一处断链或指向不同承接方即不通过。
3. **无跨迭代编号歧义**（E12 / 复盘 C-4）：三处文本中 **`D-2` 的指代唯一**——不出现同一编号在跨迭代引用时指向不同事项的情况（复盘指出 0019 曾另有一个同名 D-2）。
   *判定*：逐处读 `D-2` 的出现位置与所指 → 出现两义即不通过。
4. **承接方与起始条件写明**（N2）：登记中写明 D-2 **由单独的小迭代承接、在 0019 完成后起**（不写"下一迭代"这类未绑定指代）。
