# F04：指代重载（"根目录"统一改写为会话工作区根目录）

**功能 ID**: F04
**来源**: `demand.md` W5（P-5 ①，`user_confirmed`）；C-1（已关闭冲突）；实证 `retro-0017-phase1.md` Q-b B-1 前提 1（证据来源）
**迭代**: 0019-worktree-isolation-protocol
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有「调度指南·启动工作流」第 4.5 步（"此后阶段 2~5 期间主 agent 根目录保持在该分支上"）、「状态追踪协议」与「文档路径协议」中的相对路径约定

---

## 用户价值

规范里不再有"说的到底是哪个根目录"的歧义——每个会话读到的路径含义，就是它自己的地盘。

## 验收标准

1. **指代统一改写**（W5 / C-1）：规范中一切"主 agent 根目录 / 仓库根"的隐含主体**统一改写为"该会话所在的迭代工作区根目录"**；改写后规范文本中**不存在仍按"仓库根 = agents 仓库主工作区"判读的残留条款**。
   *判定*：全文检索相关措辞（根目录 / 仓库根 / cwd 相关表述），逐条读改写后的条款——任一条按旧含义判读会导出指向仓库主工作区的动作，即不通过。
2. **显式声明"主工作区不作为任何迭代的工作区"**（W5）：规范中存在一条显式声明，写明**仓库主工作区不作为任何迭代的工作区**。
   *判定*：读规范文本，找得到该句（措辞不限定，语义须唯一）→ 找不到即不通过。
3. **改写不改变条款的实质语义**（W5 / N1）：改写只替换主体指代——条款的动作顺序与触发时机不变（如启动工作流第 4.5 步的分支创建动作、迭代分支合并三步、状态 / 文档路径协议的相对路径判读方式）。
   *判定*：逐条对比改写前后的动作序列（改前文本可从版本历史取）→ 出现动作增删或顺序变化即不通过。
4. **相对路径协议的判读主体同步**（W5）：`status.md`、`docs/iterations/{迭代ID}/**` 的路径约定被明确为"相对该会话所在的迭代工作区根目录"。
   *判定*：读「状态追踪协议」/「文档路径协议」的改写后文本 → 主体仍不明确或仍隐含仓库根即不通过。

## 边界（不包含）

- 不含具体的改写清单与措辞（→ `[架构待填]` T-06）。
- 不含合并动作执行位置（→ F05）；不含启动契约的校验判据（→ F03）。
- 不含阶段序列、推进条件、文档目录结构本身的改动（N1 / N9）——本卡只改"主体指代"，不改文档路径协议的内容。
- 不含"仓库主工作区"的识别方式（如何知道哪个工作区是主工作区）——那是实现细节，落 `[架构待填]` T-07 / T-08。
