## 用户价值

没人会"顺手"改到别人的地盘上；万一必须动别人的东西，也先留一份备份——出事能还原。

## 验收标准

1. **负面约束条款存在**（W12 / P-16 ①）：规范中存在一条条款，规定会话的写操作（**含文件写入、`git -C`、`--work-tree`**）**必须落在本会话的工作区内**；以绝对路径写入**非本会话工作区不得发生**。
   *判定*：读规范文本，条款存在且三类写操作形态均被点名 → 缺任一类即不通过。
2. **记录逐条对照**（E13）〔`[user_confirmed MI-07]`：载体不限、不新增登记义务〕：任取一次会话的执行记录（会话日志、`history.md`、提交 diff、progress 报告均可，只要"写入动作 → 目标路径"可核对）：其产生的**写入 / 提交所指向的路径均位于本会话工作区之内**。
   *判定*：取一次执行记录，逐条核对写入目标路径与工作区路径的包含关系（阶段 5 的子 agent 以"其被派发时所在的工作区"为准，见 `[user_confirmed MI-02]`）→ 出现区外路径且未走验收 3 的备份流程，即不通过。
3. **备份优先**（W12）：若记录中出现对非本会话路径的写入，则**同一记录必须同时体现"先取备份、后操作"两步**；缺任一步即违反。
   *判定*：对照记录中的操作顺序（备份动作须出现在写操作之前）→ 顺序颠倒或备份缺失即不通过。
4. **条款性质被写明**（N10 / P-16 ④）：条款中写明"该约束**不可能被 git 强制执行**"（worktree 是目录分离，不是访问控制）；规范全文**不引入** hook / 访问控制 / 路径守卫来"实现"该条款。
   *判定*：读条款文本找得到该性质声明；检索规范文本无新增守卫机制 → 任一处缺失即不通过。
5. **条款自带判断方式**（E5 / P-11 ①）：该条款附带可被第三者使用的判断方式（未参与讨论的人可据一次真实记录判定"违反 / 未违反"），且判断方式**不依赖会话自我声明**。
   *判定*：把条款 + 判断方式交给未参与讨论的人，对一次真实记录判定 → 结论与规范预期一致即通过。

## 边界（不包含）

- 不含条款的落点章节与具体措辞（→ T-13，见 `architecture.md` §8.3）。
- **不把该条款写成可被强制执行的机制**（N10）：不引入 hook、访问控制、路径守卫；不承诺"跨工作区写入会被阻止"。
- 不含对"写入记录"的登记义务——本卡不要求新增登记载体（判定载体口径见 MI-07）。
- 不含共享 refs 与分支命名空间的负面约束（→ F12）；不含 stash / 对象库相关约束（→ F12）。
- 不含跨机器场景（N6）。
- 不含会话工作区内部的写入规范（那是既有条款范围）。

## 架构落地（阶段 3 已填，见 `architecture.md` §8.3 / §7 Q-3；产品维度未改一字）

- **T-13 落点与措辞**：规范新增 `### 规则 F：跨工作区写入禁止`（位置：`## 提交管理约束` 内、`### 约束生效范围` 之前）。条款正文点名三类写操作形态（**文件写入 / `git -C` / `--work-tree`**）、要求必须落在本会话工作区内、要求恢复他人工作区时"先取备份、后操作"，并**显式写明该条款不可能被 git 强制**（worktree 是目录分离、不是访问控制；不引入 hook / 访问控制 / 路径守卫）；紧跟一行 `判断方式：`给出可被第三者使用的核对法（取一次执行记录逐条比对"写入动作 → 目标路径"；出现区外路径时必须同时存在位于其**之前**的备份动作）。
- **闭集例外（仅两项）**：① 会话工作区的**创建**动作（必然发生在目标工作区之外）；② **收口三步及其前置游离动作**（固定在仓库主工作区执行，见 F05）。不写例外会让本条款与 F05 自相矛盾（详见 `architecture.md` §7 Q-3）；除此之外不存在获准的跨工作区写入。
- **判定载体不新增**：E13 的"执行记录"载体不限（会话日志 / `history.md` / 提交 diff / `progress.md` 均可），**不新增任何登记义务**（`[user_confirmed MI-07]`）。
- **不做**：不引入 hook / 访问控制 / 路径守卫（N4 / N10）；不承诺"跨工作区写入会被阻止"。
