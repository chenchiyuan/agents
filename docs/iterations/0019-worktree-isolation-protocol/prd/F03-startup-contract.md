# F03：启动契约与硬停（会话必须在专属工作区内启动）

**功能 ID**: F03
**来源**: `demand.md` W4（P-2 ①，`user_confirmed`）；效果 E1；实证 `retro-0017-phase1.md` Q-b B-1 前提 1 + U-6（cwd 自迁移能力**不可核实**）
**迭代**: 0019-worktree-isolation-protocol
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有「状态追踪协议」与「文档路径协议」（全部按 cwd 相对路径判读）；会话上下文获取的前置检查位

---

## 用户价值

会话一开始就知道"我必须在自己的地盘上干活"——不在，就不许动工，也不会稀里糊涂在别人的工作区里改出东西。

## 验收标准

1. **启动即校验工作区 + cwd 判据**（W4）：规范规定会话**必须在专属工作区内启动并运行**；会话的 cwd = 该工作区根目录（全部文档协议按 cwd 相对路径判读）。
   *判定*：读规范条款；并任取一次会话启动记录（本迭代阶段 6 可用构造的工作区之一，见 `[user_confirmed MI-05]`），确认其 cwd 即其工作区根目录 → cwd 落在别处即不通过。
2. **判据可客观判断**（W4）：规范给出启动校验的**判据**（可观察、可复现），任何第三者据此可对一次启动判定"合规 / 不合规"，不依赖会话自我声明。
   *判定*：把该判据交给一个**没参与本迭代讨论的人**，让他对一次真实启动记录判定 → 与规范预期结论一致即通过。（判据的具体形态见 `architecture.md` §3.3；T-02）
3. **不满足即硬停**（发现即停）〔`[user_confirmed MI-01]`〕（W4）：启动校验不通过时，会话**发现即停**——不进入任何阶段工作、不产生任何写入，随即停止推进，并**输出可用于创建该迭代工作区的命令**。
   *判定*：构造一次"在不属于本迭代的工作区中启动"的场景 → 观察是否**未推进任何阶段**即停止，且输出中包含可用于创建该迭代工作区的命令 → 出现"照常推进"或"没有创建命令"即不通过。
4. **阶段 5 子 agent 的工作区归属**〔`[user_confirmed MI-02]`〕（W3 / W4）：阶段 5 的子 agent 在其**被派发时所在的工作区**（该 PR 的 worktree）内工作，**不因此被判定违反启动契约**；写入父层会话工作区或他人 PR worktree 仍属违反（见 F09）。
   *判定*：读规范条款 + 任取一次阶段 5 派发记录，核对子 agent 的 cwd 与其 PR worktree 的关系 → 判定口径与规范声明不一致即不通过。
5. **约束主体是主 agent 会话**（W4）：启动契约的约束对象是主 agent 会话（迭代的调度会话），不是每一次角色派发。
   *判定*：读规范条款的约束主体表述 → 表述为"每一次派发都必须重新校验工作区"即不通过（超出 W4 范围）。

## 边界（不包含）

- 不含判据的具体形态与硬停输出的呈现方式（→ T-02，见 `architecture.md` §3.3）。
- 不含工作区创建命令的具体写法与落点（→ T-01 / T-05，见 `architecture.md` §1.5 / §3.2）。
- 不含跨工作区写入的负面约束（→ F09）；不含现场保留（→ F10）。
- **不做自动化守卫 / hook 强制**（N4）：本卡只要求"文本级校验判据 + 硬停行为"，不引入任何强制机制。
- 不含对子 agent 的独立启动校验（约束主体见验收 5）。
- 不含用户决策点与暂停格式的既有契约改动（那是既有条款，见 F14）。

## 架构落地（阶段 3 已填，见 `architecture.md` §3.3 / §8.5；产品维度未改一字）

- **T-02 判据形态**（三条 git 原生判据同时成立即合规，任一不成立即硬停）：① `git rev-parse --show-toplevel` == 会话 cwd；② `git rev-parse --git-dir` ≠ `git rev-parse --git-common-dir`（证明当前处于链接工作区，**并据此排除"在仓库主工作区里启动"**）；③ `git branch --show-current` == `iteration/{迭代ID}`。判据可被任何第三者复现，不依赖会话自我声明（F03 验收 2）。
- **T-02 硬停输出形态**：`【启动校验未通过】` + 判定行（cwd / 期望路径 / 当前检出）+ 创建命令（`git worktree add .pb-agents/worktrees/{迭代ID} -b iteration/{迭代ID} main`，在仓库主工作区执行）+ 状态行（发现即停：未进入任何阶段、未产生任何写入）。**不复用**既有「⛔ 需要你的决策」暂停格式——那是用户决策点专用形态（F14 验收 7）。
- **T-05 命令序列与呈现位置**：命令见上；呈现位置 = 规范新增 `### 规则 D：启动契约`（条款 + `判断方式：`行），SKILL Step 0 第 1 步只写执行动作并引用该条款，**不重复判据措辞**。
- **建立时点（Q-1 = A，2026-09-12 用户裁决）**：会话工作区在**会话启动之前**（阶段 1 之前）建立，随后会话在该工作区根目录内启动——本卡验收 1 的"cwd = 该工作区根目录"由此有可校验的对象；硬停输出中的创建命令即该建立命令（`architecture.md` §3.2 命令 1 / §3.3）。
- **边界落定**：约束主体 = 主 agent 会话（一次迭代校验一次，不在每次派发重复校验）；阶段 5 子 agent 以其**被派发时所在的工作区**为准（`[user_confirmed MI-02]`）；不做 hook / 自动化守卫（N4）。
