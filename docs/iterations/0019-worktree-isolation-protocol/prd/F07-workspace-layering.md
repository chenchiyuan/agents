# F07：父子层与 PR worktree 定位

**功能 ID**: F07
**来源**: `demand.md` W3（P-4 ①，`user_confirmed`）；边界 N8；C-4 / C-8（已关闭冲突）；实证 `retro-0017-phase1.md` Q-a G-1（PR 粒度并发证成，证据来源）
**迭代**: 0019-worktree-isolation-protocol
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有阶段 5「PR 实现」的 PR worktree 机制（base = 迭代分支）、既有「提交管理约束·规则 A」中的 worktree 术语

---

## 用户价值

阶段 5 的临时工作区有明确归属——它是干活的工具，不是谁的家；长驻的会话工作区不会被 PR 现场占掉，PR 现场也不会被当成长驻地盘。

## 验收标准

1. **父子层声明**（W3 / P-4 ①）：规范声明会话 / 迭代工作区为**父层**，阶段 5 的 PR worktree 为其下**短生命周期层**，且 PR worktree 的 **base 仍为迭代分支**。
   *判定*：读规范文本，父子层与 base 两处均可核对 → 任一处缺失即不通过。
2. **显式禁止**（W3）：规范中存在显式声明"**PR worktree 不得被当作会话工作区使用**"。
   *判定*：读规范文本，找得到该句（措辞不限定，语义须唯一）→ 找不到即不通过。
3. **可判定的违规形态**〔`[user_confirmed MI-02]` 父子层判定口径〕（W3）：任取一次阶段 5 执行记录：会话工作区与 PR worktree 是**不同目录**；PR worktree **不跨越其 PR 的生命周期**（不出现某个 PR worktree 被用作阶段 1~4 的会话工作区，也不出现 PR 结束后该目录继续充当长驻工作区）。
   *判定*：对照记录中两者的目录路径与存活区间（创建 / 结束时点）→ 出现同一目录兼具两身份、或存活区间跨越 PR 生命周期，即不通过。
4. **既有阶段 5 机制不变**（N8）：PR 的创建 / 解锁 / 合并判据不变——base = 迭代分支、**合并进迭代分支才解锁下游**、失败 / 阻塞现场保留；规则 A 的实质语义不变。
   *判定*：逐条对比改动前后阶段 5 调度文本与规则 A → 出现判据变化即不通过。
5. **术语不歧义**（C-4）：改动后规范中"worktree"一词在需要区分处有明确限定（会话 / 迭代工作区 vs PR worktree），不出现单用"worktree"而读者无法判断指哪一层的条款。
   *判定*：全文检索 "worktree" 的每一处出现，逐条判断指代是否唯一 → 出现无法判断的条款即不通过。

## 边界（不包含）

- 不含 PR worktree 的落点目录与命名细则（→ `[架构待填]` T-01 / T-03）。
- 不含 PR 的解锁算法、并发槛位算法（N1；本卡只要求"不变"）。
- 不含会话工作区自身的形态与启动契约（→ F01 / F03）。
- 不含现场保留（→ F10）与跨工作区写入约束（→ F09）。
- 不含阶段 5 子 agent 的写入边界判定细则（见 F03 验收 4 / F09，判定口径见 MI-02）。
