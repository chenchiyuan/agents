# F11：非 git 共享资源声明与两条约束

## 用户价值

事先知道哪些东西是"隔离不了"的——端口和机器负载，早点说清楚，出问题时不会把偶发失败误判成回归、不会两个会话抢同一个端口。

## 验收标准

1. **声明清单逐项可核对**（W10 / P-15 ①）：规范中存在一条**非 git 共享资源声明**，列出不被隔离的资源：**默认端口 / CPU 与负载 / 临时目录 / 进程内作业注册表**。
   *判定*：读规范文本，四项逐条可核对 → 缺任一项即不通过。
2. **约束①：真实服务不得并发占用默认端口**（E11 / W10）〔`[user_confirmed MI-08]`："真实服务"= 会话实际启动的长驻服务；**不要求修改默认端口值**〕：规范写明该约束；判据 = 任取一次**两会话并发运行真实服务**的场景，二者**不争用同一端口**——两次运行的**监听端口不同**，**或**规范明确要求并发场景**显式指定非默认端口**。
   *判定*：取该场景的运行记录核对其监听端口（或核对规范是否含"并发场景显式指定非默认端口"的要求）→ 两次运行端口相同且规范无该要求，即不通过。
3. **约束②：受负载影响的偶发失败不得当回归依据**（E11 / W10）：规范写明该约束；判据 = 任取一次"某用例在并发负载下失败"的记录，判定其是否为回归的依据是**同一代码在安静环境下重跑是否通过**，而**不是单次失败本身**。
   *判定*：对照该记录是否含"安静环境重跑"的证据（重跑结果）→ 仅以单次失败下结论即不通过。
4. **只做最小声明与约束**（W10 / N7）：本卡**不引入任何机制**——不要求改 `oamp/` 产品代码、不要求加锁 / 排队 / 调度 / 资源池，只为这四类资源做声明并给出上述两条约束。
   *判定*：检索本迭代的全部规范改动，对其是否触及 `oamp/**` 或新增资源管理机制 → 出现即不通过。
5. **与既有测试面的既有做法自洽**（W10）：规范不否定既有测试面已在使用随机端口这一事实（声明只约束"真实服务"的并发场景，不要求测试面改正）。
   *判定*：读声明措辞，其约束对象为"真实服务"而非"全部服务 / 全部测试"→ 约束面被扩大即不通过。

## 边界（不包含）

- 不含声明的落点章节与两条约束的措辞（→ `[架构待填]` T-10）。
- 不含默认端口值的修改（**不在本迭代范围**；改动默认端口会触及 `oamp/` 产品代码，与 N7 冲突）。
- 不含进程内作业注册表的任何机制改动（P-2 复盘项未纳入本迭代范围，见 `demand.md` §3.4 末段）。
- 不含临时目录的清理动作与命名约定（N5；签名中仅要求"声明其不被隔离"）。
- 不含负载敏感用例清单的维护与新增（既有记录只作为约束②的判据来源）。
