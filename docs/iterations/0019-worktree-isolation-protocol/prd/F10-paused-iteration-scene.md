# F10：暂停 / 终止迭代的现场保留

**功能 ID**: F10
**来源**: `demand.md` W9（P-12 ①，`user_confirmed`）；效果 E6；实证 `retro-0017-phase1.md` G-4（他人现场保持只读不动，证据来源）
**迭代**: 0019-worktree-isolation-protocol
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有工作流条款「失败 / 阻塞现场必须原样保留，禁止主 agent 清理」（阶段 5 第 4 点）与「状态追踪协议」的 `❌失败(现场保留)` / `⏸阻塞(现场保留)` 定义

---

## 用户价值

停下的迭代现场原样留在那儿，谁都不会"帮忙"清理掉——排查和恢复的线索不会消失。

## 验收标准

1. **现场原样保留**（W9 / P-12 ①）：规范要求暂停 / 终止迭代的**工作区与分支原样保留**，不被自动清理（不由其它会话清理，也不因迭代状态变化被清理）。
   *判定*：读规范条款 → 条款不存在或仅覆盖分支不覆盖工作区，即不通过。
2. **清理权归属明确**（W9）：规范写明**仅其归属会话或用户可清理**。
   *判定*：读规范条款，找得到归属表述 → 找不到即不通过。
3. **不被他人常规操作移除**（E6）：任取一个被暂停或终止的迭代：其**工作区目录与分支仍存在于磁盘**，且不因另一会话的常规操作（提交、分支切换、清理动作）而被移除。
   *判定*：对照该迭代的工作区目录与分支在他人操作前后的存在性 → 任一项消失即不通过。
4. **与既有"现场保留"条款不冲突、不遗漏**（W9 / 既有条款）：既有失败 / 阻塞 PR 的现场保留语义**不变**；新增条款与之并列时**不产生矛盾**（例如不出现"暂停迭代要保留"与"某类现场要清理"并存的冲突表述）。
   *判定*：逐条对比改动前后的现场保留相关条款 → 出现语义冲突或既有条款被削弱，即不通过。
5. **不新增清理动作**（N5）：本卡不引入任何"清理历史残留"的动作或清单（残留清单维持更正后的现状，不改动）。
   *判定*：检索规范文本，无新增清理条款 → 出现即不通过。

## 边界（不包含）

- 不含条款与既有"现场保留"条款的关系处理（新增并列 vs 合并改写）与落点（→ T-12，见 `architecture.md` §8.5）。
- **不含正常收口迭代的工作区清理动作**——W9 只覆盖"暂停 / 终止"，本卡**不为其新增任何清理条款**（N5：不新增清理动作；W9 未覆盖该情形，本卡不对其作要求）。
- 不含失败 / 阻塞 PR 的**既有**保留条款的改写（只要求语义不变，见验收 4）。
- 不含工作区落点目录与清理命令（→ T-01 / T-05，见 `architecture.md` §1.5 / §3.2）。
- 不含跨机器场景（N6）。

## 架构落地（阶段 3 已填，见 `architecture.md` §8.5 / §5.1-W8；产品维度未改一字）
