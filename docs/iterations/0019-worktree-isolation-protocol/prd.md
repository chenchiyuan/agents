## 本次迭代边界说明

### 包含（本迭代要产出的规范内容）

- **会话工作区形态**（W1 → F01）：并行会话各用独立 worktree、不共用同一工作树；worktree 是**唯一被规范化的形态**；clone 只作"无法共享同一 `.git`（跨机器 / 跨用户 / 无写权限）"的**兜底声明**，**不为其定义流程**；不保证跨机器 / 多人协作场景（N6）。
- **每迭代一个工作区**（W2 → F02）：工作区绑定 `iteration/{迭代ID}`，阶段 1~6 期间保持在该分支上；提交只出现在本会话分支（E3）。
- **启动契约**（W4 → F03）：会话必须在专属工作区内启动并运行；判据可客观判断；会话 cwd = 该工作区根目录（全部文档协议按 cwd 相对路径判读）；不满足时**硬停**并输出创建命令。
- **指代重载**（W5 → F04）：规范中一切"主 agent 根目录 / 仓库根"的隐含主体统一改写为"该会话所在的迭代工作区根目录"；显式声明"仓库主工作区不作为任何迭代的工作区"。
- **合并动作定位**（W6 → F05）："迭代分支合并进 main"固定在**仓库主工作区**执行；会话工作区**永不 checkout main**（E8）。
- **分支命名**（W7 → F06）：会话创建的所有分支名必须含迭代 ID（PR worktree 分支规范化为含迭代 ID 的形式；E7）。
- **父子层**（W3 → F07）：会话 / 迭代工作区为**父层**，阶段 5 的 PR worktree 为其下**短生命周期层**（base 仍为迭代分支）；显式声明"PR worktree 不得被当作会话工作区使用"。
- **角色定义来源**（W8 → F08）：读取来源改为**被 git 追踪的内容**（本仓库场景 = 被跟踪的 `roles/**`）；`.pb-agents/` 与 `tools/install-pb-agents.sh` 从"工作流运行前提"降级为"仅面向外部业务项目的**可选分发手段**"；改写 SKILL 中「不得退回读 `roles/` 源码目录」的 CRITICAL；写清上游研发场景与下游部署场景如何共用同一份规范（E9）。
- **跨工作区写入约束**（W12 → F09）：会话的写操作（含文件写入、`git -C`、`--work-tree`）**必须落在本会话的工作区内**；以绝对路径写入非本会话工作区**不得发生**；必须恢复他人工作区内容时**先取备份再操作**；并写明该条款**不可能被 git 强制**（N10、E13）。
- **现场保留**（W9 → F10）：暂停 / 终止迭代的工作区与分支**现场原样保留**，仅其归属会话或用户可清理（E6）。
- **非 git 共享资源**（W10 → F11）：最小**声明**（默认端口 / CPU 与负载 / 临时目录 / 进程内作业注册表）+ **两条可判断约束**（真实服务不得并发占用默认端口；受负载影响的偶发失败不得当回归依据）（E11）。
- **隔离边界声明**（E10 → F12）：逐项列出覆盖的共享状态（工作树 / 索引 / HEAD）与不覆盖的（仓库级 refs 含 stash 与分支命名空间、对象库、config/hooks/remotes），并附未覆盖项的负面约束 + "冲突后移到合并期"的已知代价声明。
- **形态约束**（W11 / N4 / E5 → F13）：全部手段落在 git 原生命令 + 文本规范内（**不依赖任何工具**：无安装脚本前置、无 hook、无守护进程）；每条新增 / 改写条款自带"判断方式"；不引入自动化守卫。
- **既有约束保持**（N1 / N3 / N5 / N7 / N8 → F14）与 **D-2 承接登记留痕**（N2 → F15）。

## 拆分理由（原子粒度判断）

**总原则：按"可独立出现的失败模式"拆卡，不按 W 编号机械一对一；保证项与声明项按"独立可被破坏的约束"单列。**

- **W1 与 W2 拆两张（F01 / F02）**：两个独立失败模式——①规范把 clone 或其它形态也当成合规形态并为其定义流程（F01 红 / F02 绿）；②工作区不与迭代 ID 绑定，会话在自己随意命名的分支上干活、迭代分支空置（F02 红 / F01 绿）。E1 / E2（隔离层的直接后果）落 F01，E3（提交落在哪条分支）落 F02。
- **W3 单立（F07）**：父子层是**阶段 5 接缝**的唯一约束——它约束的是"PR worktree 的身份"，与"会话工作区是什么形态"（F01）和"合并动作在哪执行"（F05）都不同；其显式禁止条款（"PR worktree 不得被当作会话工作区使用"）本身就是一个可被独立删除、独立判定的句子。
- **W4 单立（F03）**：启动契约是 E1 的直接承载（会话**真的**在专属工作区里运行，而不只是规范允许）；它的失败模式（会话在主工作区里启动却照常推进）与"形态条款写没写对"完全正交。
- **W5 单立（F04）**：指代重载是一处**全文性**接缝；它的失败模式是"条款写对了，但残留条款仍按旧主体判读"，只能靠逐条读文本判定，无法由其它卡的验收替代。
- **W6 单立（F05）**：合并动作的执行位置是 C-2（git 硬约束）的唯一出口，E8 是其专属裸判定；与 F04 的区别是——F04 改的是"读起来的含义"，F05 改的是"动作发生在哪里"。
- **W7 单立（F06）**：分支命名的失败模式（两会话同名分支争用）与隔离机制本身的正确性无关——即使隔离完全正常，命名仍可能冲突；E7 是其专属裸判定。
- **W8 单立（F08）**：角色定义来源是 C-3 / C-7 的唯一出口，也是"新工作区能否开工"的**前置条件**；它的失败模式（新工作区 Step 0 必停）会让其它一切条款都无从执行，因此必须是独立的可判定单元。
- **W9 单立（F10）**：现场保留是"跨会话不破坏他人现场"的约束，G-4 已证明它真实被需要；失败模式（他人会话顺手清理）与隔离正确性正交。
- **W10 单立（F11）**：非 git 共享资源在结构上**不可能**被 worktree 覆盖（复盘 A-4.3），与其它所有卡都不同；E11 是其专属裸判定，且两条约束各配一条可观察判据。
- **W11 并入 F13（与 N4 / E5 合并）而不单立两张**：三者约束的是**同一件事**——本迭代产出物的形态（手段只能用 git 原生 + 文本；每条条款自带判断方式；不引入 hook 守卫）。分开会产出三张在同一段文本上重复断言的卡。W11 是其中的 `user_confirmed` 需求源，故 F13 仍为需求功能点。
- **W12 单立（F09）**：跨工作区写入是 A-4.5 的唯一出口，且 demand 明确要求它**自带判断方式**并写明"不可能被 git 强制"；它的失败模式（记录中出现跨区写入且无备份步骤）与其它卡都不同。
- **F12 单列（**声明项**）**：E10 要求的是一段**规范内容本身**（边界声明 + 未覆盖项负面约束 + 已知代价），它既不是某个动作的执行位置，也不是某个条款的改写，必须有自己的落点。**它在 W 清单中无对应条目**（见「疑问与越界」1），故标〔声明项〕并按 E10 + P-9/P-10 追溯。
- **F14 单立（回归锁）**：本迭代的交付物**就是规范文本的改写**，"与工作区归属无关的条款被顺手改坏"是本迭代最真实的回归风险（N1 / N8 两条零改动项正是为此存在）；不单立则无法区分"合理改写"与"越界改写"。体例沿用 0017 的 F09（回归锁）与 0016 的 F02。
- **F15 单立（**保证项·登记义务**）**：E12 的判定对象是三处 `status.md` 的引用链，与机制条款零交集，但它是 `user_confirmed` 的 D-2 ① 的硬要求；体例沿用 0017 的 F10（登记义务卡）。
- **未单立的项**：① N9 列出的四个留白点（落点目录 / 判据形态 / 命名细则 / 文本组织）是**架构待填项**而非功能能力，落 T-01~T-04 与各卡 `[架构待填]` 段；② N3（不追溯 / 0019 自身不迁移）是全局生效范围声明，落 F14 验收 6 与本文件边界；③ N5 / N8 是零改动项，落 F14；④ 复盘未纳入项（P-2 ~ P-7、C-3、C-5 #6、G-2/G-3）不在本迭代范围，不立卡。
