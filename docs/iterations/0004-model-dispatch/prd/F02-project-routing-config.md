# F02 — 项目路由配置与模型绑定

**功能 ID**: F02  
**来源**: `demand.md` §3「配置归属与模型绑定」  
**迭代**: 0004-model-dispatch

---

## 用户价值

让业务项目能够独立维护模型路由和默认值，并在配置缺失或错误时得到明确、可诊断的行为，同时保护框架文件、运行记录和凭据边界。

---

## 验收标准

1. 项目级路由配置的固定位置为 `.pb-agents/config/agent-routing.yaml`；在该位置提供配置时，派发行为使用该项目配置表达的默认值和 role 路由。
2. 该配置被视为业务项目的可写配置：安装或升级 agents 后，既有配置内容仍存在且未被覆盖或删除。
3. `.pb-agents/roles/`、`.pb-agents/principles/` 等框架 copy 的只读归属不因路由配置改变；`.pb-agents/project/` 仍承担运行记录职责，路由配置不被当作运行记录。
4. 路由配置能够表达：配置版本、主 agent 默认 `executor/model`、子 agent 默认 `executor/model`，以及按 role 指定的子 agent `executor`、`model` 和可选的有序 fallback 列表。
5. role 的模型绑定只出现在该独立路由配置中；role 文件仍只描述 role 能力，不因配置而增加模型绑定内容。
6. 配置文件不存在时，主 agent 和子 agent 均使用内置默认目标 `omp + gpt`。
7. 配置存在但语法非法或字段非法时，派发在继续启动任务前快速失败，并向调用方报告具体错误；不得将非法配置静默当作缺失配置并退回默认值。
8. 路由配置中出现 API key、token、密码或要求 agents 解析的 provider secret 时，该内容不得被接受为 agents 的路由凭据，也不得成为 agents 管理、存储或解析的输入。

---

## 边界（不包含）

- 不包含配置加载器、解析库、校验器或错误传递机制的技术选型。
- 不包含安装和升级流程的具体实现。
- 不包含运行记录的数据模型、存储实现或审计展示方式。
- 不包含 provider secret 的生成、读取、轮换、认证或登录流程。
- 不包含配置文件之外的模型选择入口。

---

## 架构维度

- 路由输入边界固定读取业务项目 `.pb-agents/config/agent-routing.yaml`；先区分文件缺失与存在，再执行语法、版本、必填默认字段、role 字段类型/允许字段及凭据禁入校验。缺失使用内置默认，非法配置带字段/位置上下文快速失败，不静默回退。具体解析库与错误通道实现待主 agent 根据实际代码确定。
- 安装/升级只更新 `.pb-agents/roles/`、`.pb-agents/principles/` 等框架 copy，不覆盖或删除项目配置；路由配置继续由业务项目维护。具体保护机制实现待主 agent 根据实际代码确定。
- 路由配置只作为派发解析输入，运行记录仍归 `.pb-agents/project/`，二者不共用文件或职责。记录格式与落地组织实现待主 agent 根据实际代码确定。
