# F06 — 结果状态与降级审计

**功能 ID**: F06  
**来源**: `demand.md` §5「启动前模型降级」第 63 条、§6「统一 ACP 派发契约」第 79–88 条、§8「本迭代包含与不包含」  
**迭代**: 0004-model-dispatch

---

## 用户价值

让主 agent 能区分任务未启动、目标已启动但执行失败和成功完成三种结果，并在发生降级时还原原始意图、实际目标和原因，从而支持可靠决策与事后审计。

---

## 验收标准

1. 响应的 `status` 只能表达 `completed`、`failed` 或 `blocked` 三种结果语义。
2. `completed` 表示目标已执行并形成可交付结果；响应同时保留执行结果。
3. `failed` 表示请求的目标已经启动，但执行过程失败；不得把该状态描述成任务未启动。
4. `blocked` 表示任务未形成可交付结果且未完成目标执行，例如所有候选模型不可用或 brief 缺失；不得把该状态描述成目标已启动后失败。
5. 每个结果保留 `role`，并同时记录 `requested.executor/model` 与 `selected.executor/model`，使原始请求目标和实际执行目标可分别审计。
6. 发生模型 fallback 时，结果标记 `fallback_applied=true`，并记录原始有序 fallback 候选链、降级原因和实际选定目标；未发生 fallback 时标记为未应用，不虚构降级原因。
7. 发生 executor 不可用、候选模型全部不可用或 brief 缺失而任务未启动时，结果仍能明确呈现阻断/失败原因，并且不产生“已启动”的执行结果。
8. 子 agent 启动后的执行失败，其结果保持 `failed` 语义，不因派发能力静默生成另一个模型的重跑结果；主 agent 是否再次派发由后续显式决定。

---

## 边界（不包含）

- 不包含运行记录的具体数据模型、存储介质、保留期限或审计界面。
- 不包含失败后的自动重试、自动换模型或自动重派策略。
- 不包含如何探测模型/ executor 可用性。
- 不包含 CLI 内部错误分类、会话管理或任务执行实现。

---

## 架构维度

- 结果归一化边界将未启动且无可交付结果归一为 `blocked`，已启动后执行错误归一为 `failed`，形成可交付结果归一为 `completed`；同步把 `role`、`requested/selected`、fallback 审计和 result/reason 返回主 agent。
- 归一化结果按业务项目运行记录归属写入 `.pb-agents/project/`，不得写回配置或框架 copy；最小记录保留状态、双目标、fallback chain/reason、result/reason。记录格式、持久化和查询实现待主 agent 根据实际代码确定，启动后失败不触发静默重跑。
