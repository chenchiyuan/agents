### 标准 6：审计断言的口径正确性

**判定：pass**（分解为三条子项）

1. **断言取的是渲染行解析出的 fields，而非进程内 recorder**：pass。
   e2e 链路中 agent 是 `spawn` 出的独立进程（`acp-daemon.test.js:457`），测试侧无法持有其 logger 对象；审计断言的数据源是子进程 stdout 字符串（`dev.stdout()`），经 `parseEventLines()`（`:641-649`，按 `[ts] <role> <NAME> <fields>` 正则取行）与 `parseFields()`（`:625-638`，解析 `key=value` 片段）得到 `fields` 对象后再断言（`:683-690`）。
2. **对匿名/缺省路径不会误判为失败**：pass。
   新断言中"四键非空"只施加于 `--role dev` 的常驻实例（`acp-daemon.test.js:505-510` + `:683-690`）；匿名路径（`dev-1`）只断言 argv（`:537-541`、`:555-556`），不涉审计字段。为验证该口径不产生假失败，另做了一次实证：把审计用例的实例改为匿名 + `--tools on --permission allow`（副本 `test/zz-anon-audit-scratch.test.js`），实测匿名实例**确实**产出渲染审计行：

   ```
   [2026-09-11T04:54:51.058Z] agent TOOL_APPROVED instance=anon-1 chat_id=chat-8f4aa6a4-… context_id=ctx-74033-1 pid=74033 tool=edit title="Create /tmp/role-smoke.txt" tool_call_id=tc-9001 option=allow_once
   ```

   → 匿名实例的渲染行**缺 `role=` 键**（其余身份键在），因此"四键非空"若施加于匿名实例会失败。用例把该断言严格限定在角色实例上，方向正确，不会误判。该实验也顺带证明"渲染层跳过 null"是可观测事实（`src/log.js:24`），与变异 B 的转红结果互相印证。
3. **与 §4.5 两层口径一致**：pass（断言侧）。
