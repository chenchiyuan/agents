# F04：工具能力开关（按角色可配）

**功能 ID**: F04
**来源**: `demand.md` W5 前半（D-1 / TC-02）；效果条款 E2（工具真实可用）、E4；实测事实 V-6 / V-7；仓库事实 F-7；验收 5 判定面经用户确认（M-01，2026-09-10）
**迭代**: 0012-roles-agent-cluster

---

## 用户价值

角色**真能干活**——能读写文件、执行命令，而不只是聊天；同时也允许按角色关掉工具（纯咨询类角色不会被赋予动手能力）。

## 验收标准

1. **默认全开**：未做任何配置时，角色实例具备文件读写与命令执行能力（TC-02：默认开、按角色可关）。
2. **真实可用，且对默认对话路径生效**：集群运行中经 web 控制台向 `pb-dev` 发"在仓库根创建文件 `role-smoke.txt`，内容为 hello"，回答结束后该文件在磁盘存在且内容为 hello（E2）。此验收使用的正是默认（常驻）对话路径——即现状"默认路径硬编码禁用工具"的缺陷已被消除（F-7 / V-7）。
3. **可按角色关闭**：把配置中 `pb-prd` 的工具开关置为关闭并重启集群后，向 `pb-prd` 发同一条"创建文件"指令 → 不产生该文件，或以明确的回绝结束（E4 原文的二选一）。
4. **开关粒度到角色**：验收 3 执行的同一时刻，未被关闭的角色（如 `pb-dev`）仍能创建文件——一次关闭不影响其他角色的工具能力（E4 后半）。
5. **关闭档不静默失败**：工具被关闭时，该轮以明确的结论结束（明确回绝或说明能力不可用），用户能区分"没干活"与"干不了" `[user_confirmed]`（M-01，2026-09-10 用户确认）。
6. **工具开关可配置**：工具开关是按角色可写的配置项；开关的取值变更经重启后生效（与 N11 一致，不做热重载）。

## 边界（不包含）

- 不含 permission 策略本身（F05）——但两卡存在显式耦合：工具放开后若没有 permission 应答，会引入永久挂起缺陷（V-6），因此 F04 验收 2 的成立以 F05 的应答落地为前提；反之 F05 验收 4 必须在工具已放开的实例上执行。
- 不做工具调用的细粒度沙箱 / 命令白名单 / 路径限制 / 按工具类别分档（N6；TC-03 未采纳"读写放行、命令询问"第三档）。
- 不含角色自定义工具集 / 工具白名单（demand 未要求）。
- 不含工具调用明细的其他观测面（terminal 事件日志的既有形态见 F05 的审计条款；本卡不做新日志面）。
- 不含工具能力的回归保护以外的既有执行路径改造（`shell` 执行路径与工具开关无关，不在本卡）。
