# F07：按角色工作目录（`cwd`）

**功能 ID**: F07
**来源**: `demand.md` W8（TC-08 用户改判）、D-6；效果条款 E8；实测事实 V-5
**迭代**: 0012-roles-agent-cluster

---

## 用户价值

"角色在哪儿干活"是**可配事实**而不是写死的仓库根：需要时把某角色指到别的目录（例如让 dev 在指定目录里干活），没配的角色仍然待在仓库根。

## 验收标准

1. **字段存在且缺省生效**：集群配置文件中每个角色支持 `cwd` 字段；未配置该字段的角色，其工作目录 = 仓库根（W8 / D-6）。
2. **配置生效**：在配置里给某角色（如 `pb-dev`）设 `cwd` = 一个临时目录并重启集群后，向其发"在当前目录创建 `cwd-check.txt`"指令 → 该文件出现在这个临时目录（而非仓库根）（E8 前半）。
3. **缺省角色对照**：同一集群中未配 `cwd` 的角色（如 `pb-architect`）收到同一指令 → 文件出现在仓库根（E8 后半，缺省值生效）。
4. **tmux 窗口按 cwd 启动**：tmux 中该角色的窗口/进程在其 `cwd` 下启动——窗口内进程的工作目录 = 配置值（W8；判定观察面见 AR-19）。

## 边界（不包含）

- 不含路径解析基准的决策（相对仓库根 vs 相对配置文件）与非法/不存在路径的失败语义（AR-18）。
- 不做 worktree 生命周期管理——即使 `cwd` 指向某个 worktree，本迭代也不创建 / 清理 worktree（沿用 0010 以来的边界）。
- 不做 per-chat / per-task 的目录切换（只按角色静态配置）。
- 不做运行期改变 cwd（与 N11 一致：配置变更经重启生效）。
- 不含集群脚本的生命周期语义（F06）——本卡只锁 `cwd` 这一字段的配置与生效。
