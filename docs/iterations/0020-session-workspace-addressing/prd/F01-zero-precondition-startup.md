# F01：零前置会话启动（任意位置启动 + 工作区自建）

**功能 ID**: F01
**来源**: `demand.md` 第二段 §2 **W1**（`user_confirmed`：U-1 / U-3 / U-5 + P-2① + P-3①）；效果 **E1**；第一段 F3（本迭代自身即在仓库主工作区启动）与冲突⑤（0018 `status.md:24` 的"必须由用户执行"）
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有「规则 C：会话工作区隔离」的建立时点句"随后会话在该工作区根目录内启动"、既有「规则 D：启动契约」的"会话必须在自己的会话工作区内启动并运行"（v0.9.0 原文，**本迭代要取代的对象**）

## 用户价值

在项目里任意位置把 agent 客户端开起来就能开工——不用先建目录、不用先 cd、不用重开会话，忘了前置也不会被挡在门外。

## 验收标准

1. **启动位置不受约束**（W1）：规范与 SKILL 中，会话的启动位置**不受约束**——不存在"会话必须在某目录（含自己的工作区）内启动"的准入表述。
   *判定*：读改动后的规范与 SKILL，逐句检查涉及启动位置的表述 → 出现"必须在 X 目录内启动""cwd 必须等于 X"之类以目录位置为启动条件的句子即不通过。
2. **人不承担任何前置**（W1 / U-3 / U-5）：规范中不存在要求**人**预先执行的动作——不要求 cd、不要求任何前置命令、不要求预先存在的目录、不要求重开会话。
   *判定*：逐句检查新增 / 改写条款中指向人的动作要求 → 出现"必须由用户执行 / 请先 cd / 请先创建工作区 / 请重开会话"类句子即不通过。
3. **工作区不存在时由会话自行建立**（W1）：会话开工前若其迭代工作区不存在，由**会话自己**建立；建立成功后**继续推进**（不停下、不等人）。
   *判定*：构造一次"迭代工作区不存在 + 会话在项目内任意位置启动"的场景 → 观察会话是否自行建立该工作区并继续推进（不出现等待人的动作） → 出现"要求人先建"或"直接硬停"即不通过。
4. **零前置可交付**（E1）：任取一次迭代启动，会话在**任意目录**（含仓库主工作区）启动、工作区不存在时**自行建立**，仍能把阶段 1 的产物落到**其迭代工作区内**，且**仓库主工作区零改动**。
   *判定*（`demand.md` 给出的裸判据）：取该次启动的执行记录 + 两个位置的 `git status` 前后各一次 → 产物出现在迭代工作区、仓库主工作区前后一致即通过；产物落在主工作区、或主工作区出现改动即不通过。 〔`[user_confirmed MI-01]` 样本来源 = **构造 + 真实各半**：阶段 6 构造一次"目标工作区不存在 + 会话在任意位置启动"的样本（覆盖"自建"半句）；本迭代自身的真实执行记录覆盖"任意位置启动 / 产物落迭代工作区 / 主工作区零改动"半句〕
5. **建立动作的执行者不预设**（C-3 的闭合方式）：条款措辞对"谁执行建立"保持中性——工作区由会话自己执行建立，但条款不得反过来预设"建立必然由人执行"或"建立必然是某固定主体"。
   *判定*：读条款措辞 → 出现被执行者锁死的预设（"由人建立"等）即不通过。

## 边界（不包含）

- **不含"仓库外任意 cwd"的保证**（N8）：U-1 说的是"在**项目中**启动"；仓库外的情形不在本卡范围。
- 不含工作区建立命令的具体写法与落点解析（→ T-03，阶段 3）。
- 不含硬停面本身（→ F09）：本卡只要求"工作区不存在时能建、建完继续"，失败时的行为归 F09。
- 不含地址如何推导（→ F06）；不含地址声明落到哪里（→ F07）；不含简报如何携带地址（→ F08）。
- 不含"对人 / 对会话"两类主体是否被**显式分写**（→ F19，本卡只要求行为上人零前置）。
- 不含任何清理动作（N9）。
- 不引入 hook / 守卫脚本 / 检测器（N3 → F21）。

## 架构落地（阶段 3 已填，见 `architecture.md` §3.1-N-02/N-04/N-17/N-18、§5.2、§8.1-C/D；产品维度未改一字）

- **T-03 解析与建立**：解析链（**不读取 `pwd`、不使用启动目录作为输入项**）——仓库主工作区 = `git rev-parse --path-format=absolute --git-common-dir` 输出的**父目录**（同仓库内任意位置求值相同，即 F06 验收 1 的核对方式）；工作区地址 = `<仓库主工作区>/.pb-agents/worktrees/{迭代ID}`。**建立（仅当该地址不存在，由会话执行）**：`git -C <仓库主工作区> worktree add .pb-agents/worktrees/{迭代ID} -b iteration/{迭代ID} main`；**成功依据** = `git worktree list` 输出含该地址，且 `git -C <该地址> branch --show-current` 输出 `iteration/{迭代ID}`；成功后**直接继续推进**（不等候、不请示）。命令形态 / 落点 / 分支名沿用 v0.9.0，**仅执行者预设与时点改变**——落点 = 改写后的 `### 规则 D：工作区地址的解析与建立（原「启动契约」改写）` 第 4 条。
