## 用户价值

阶段 5 干活的子 agent 不会因为"我在哪儿"被判定违规——它按简报给它的绝对地址干活，判定也按那个地址来。

## 验收标准

1. **以简报给定的 PR worktree 绝对地址为准**（W18）：阶段 5 子 agent（planner / dev / verifier 等）的寻址主体口径 = **简报给定的 PR worktree 绝对地址**，操作以其为准。
   *判定*：读规范与 SKILL 中阶段 5 的派发条款 → 口径表述为"以简报给定的绝对地址为准"即通过。
2. **旧口径删除**（W18 / F7）：规范与 SKILL 中**不再引用**"以被派发时所在的目录 / 工作区为准"这一口径。
   *判定*：检索该口径表述 → 命中即不通过。
3. **`git -C` 寻址**（W18 / W2）：子 agent 的 git 写操作同样以 `git -C <绝对地址>` 形态执行。
   *判定*：读条款；并取一次阶段 5 派发记录核对写操作形态 → 出现依赖 cwd 的形态即不通过。
4. **子 agent 的写入仍受禁令约束**（W18 / 规则 F 不变）：子 agent 写入其简报地址之外（父层会话工作区或他人 PR worktree）仍属违反，规则 F 的实质语义与例外集不变。
   *判定*：读条款的指代关系 → 出现对规则 F 的放宽或例外扩充即不通过。
5. **样本可判**：任取一次阶段 5 派发记录，子 agent 的写入目标与简报地址的关系可逐条核对。
   *判定*：取一次派发记录 + 其中每条写入路径 → 全部落在简报地址之下即通过。

## 边界（不包含）

- 不含 PR worktree 的落点与父子层约定（既有条款，→ F13 验收 2）。
- 不含 PR 文件的七字段格式与阶段 5 并发调度（→ F13 验收 4）。
- 不含给子 agent 做启动校验（**不设启动门**，→ F09 验收 2）。
- 不含简报字段形态本身（→ T-04 / F08）。
- 不含阶段 5 以外角色（如阶段 1~4 的执行角色）的寻址表述——它们由 F02 / F08 的一般纪律覆盖。

## 架构落地（阶段 3 已填，见 `architecture.md` §2.5 / §3.1-N-11/N-16、§3.2-K-05/K-06、§5.2；产品维度未改一字）

- **T-04 简报字段呈现**：阶段 5 的子 agent 简报**沿用同一字段** `工作区地址：<绝对路径>`（不新增字段名），但**取值 = 该 PR worktree 的绝对地址**（`<会话工作区>/.pb-agents/worktrees/{迭代编号}-pr-{NNN}-{slug}` 的绝对路径）；与既有 `PR worktree 分支：{分支名}` 行构成"地址 + 分支"一对，阶段 5 额外必填块**其余两行逐字不动**（`architecture.md` §2.4）。
- **T-08 落点与章节命名**：规范侧三处——① `### 规则 D` 的判断方式与"约束主体"句（"阶段 5 的子 agent 以**其简报给定的 PR worktree 绝对地址**为准"）；② `### 规则 F` 判断方式行的主体口径（`:200`，**取代**「以其被派发时所在的工作区为准」）；③ `### 阶段 5（PR 实现）：依赖解锁式并发调度` 步骤 2（`:384`，执行位置由"该会话工作区内"改为"该 PR worktree 的绝对地址 + `git -C`"）。**SKILL 侧** = `:174` Step 5 步骤 2 的同样改写（K-06）+ §Brief 构建规则新增字段行（K-05）。
- **T-09 同步**：真源 = 规范 `### 规则 D` / `### 规则 F` / `### 阶段 5`；SKILL 只写调度动作（"按简报地址解析并 `git -C <地址>` 创建 / 操作"）与引用，**不复制主体口径的措辞**。
- **旧口径删除（本卡验收 2）**：`grep -rn '被派发时所在'` → 规范 `:167` / `:200` 两处与 SKILL 0 处，改写后**全文 0 命中**（`architecture.md` §3.6）；本卡验收 3 的 `git -C` 形态由 `### 规则 H` 的通则承担。
- **写入仍受禁令（本卡验收 4）**：规则 F 正文与闭集例外两项**逐字不动**——子 agent 写入其简报地址之外（父层迭代工作区 / 他人 PR worktree）仍属违反；PR worktree 落点与父子层约定（0019 Q-4）**零变化**（本卡边界）。
- **不设启动门（本卡边界）**：子 agent 不做任何启动校验——`architecture.md` §5.4 的唯一硬停面只属会话（约束主体 = 主 agent 会话，一次迭代校验一次），SKILL 的 CRITICAL/Step 0 改写不引入子 agent 校验动作。
