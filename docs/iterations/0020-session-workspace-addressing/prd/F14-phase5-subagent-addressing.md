# F14：阶段 5 子 agent 的寻址主体口径

**功能 ID**: F14
**来源**: `demand.md` 第二段 §2 **W18**（`user_confirmed`：P-15① 按推荐）；实证 F7（v0.9.0「以被派发时所在的工作区为准」的口径在实际执行中**未成立**）
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有阶段 5 的 PR worktree 落点与父子层约定（0019 Q-4，**本迭代不改**）；既有「规则 F：跨工作区写入禁止」与其闭集例外（仍为 2 项）；既有「派发执行角色时的 brief 构建」

## 用户价值

阶段 5 干活的子 agent 不会因为"我在哪儿"被判定违规——它按简报给它的绝对地址干活，判定也按那个地址来。

## 验收标准

1. **以简报给定的 PR worktree 绝对地址为准**（W18）：阶段 5 子 agent（planner / dev / verifier 等）的寻址主体口径 = **简报给定的 PR worktree 绝对地址**，操作以其为准。
   *判定*：读规范与 SKILL 中阶段 5 的派发条款 → 口径表述为"以简报给定的绝对地址为准"即通过。
2. **旧口径删除**（W18 / F7）：规范与 SKILL 中**不再引用**"以被派发时所在的目录 / 工作区为准"这一口径。
   *判定*：检索该口径表述 → 命中即不通过。
3. **`git -C` 寻址**（W18 / W2）：子 agent 的 git 写操作同样以 `git -C <绝对地址>` 形态执行。
   *判定*：读条款；并取一次阶段 5 派发记录核对写操作形态 → 出现依赖 cwd 的形态即不通过。
4. **子 agent 的写入仍受禁令约束**（W18 / 规则 F 不变）：子 agent 写入其简报地址之外（父层会话工作区或他人 PR worktree）仍属违反，规则 F 的实质语义与例外集不变。
   *判定*：读条款的指代关系 → 出现对规则 F 的放宽或例外扩充即不通过。
5. **样本可判**：任取一次阶段 5 派发记录，子 agent 的写入目标与简报地址的关系可逐条核对。
   *判定*：取一次派发记录 + 其中每条写入路径 → 全部落在简报地址之下即通过。

## 边界（不包含）

- 不含 PR worktree 的落点与父子层约定（既有条款，→ F13 验收 2）。
- 不含 PR 文件的七字段格式与阶段 5 并发调度（→ F13 验收 4）。
- 不含给子 agent 做启动校验（**不设启动门**，→ F09 验收 2）。
- 不含简报字段形态本身（→ T-04 / F08）。
- 不含阶段 5 以外角色（如阶段 1~4 的执行角色）的寻址表述——它们由 F02 / F08 的一般纪律覆盖。

## 架构待填（阶段 3 填写）

- **T-04**：简报字段形态（子 agent 简报中地址字段的呈现）。
- **T-08**：阶段 5 派发条款在规范与 SKILL 中的落点与章节命名。
- **T-09**：规范与 SKILL 的同步方式（何处为真源、何处只引用）。
