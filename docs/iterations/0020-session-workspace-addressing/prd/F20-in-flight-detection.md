# F20：做事时检测（简报随带 + 执行者自检）

**功能 ID**: F20
**来源**: `demand.md` 第二段 §2 **W9**（`user_confirmed`：V-5「做事的时候带检测就行」）；效果 **E7**；第一段 M-10（承载形态为低风险推断，字段形态留阶段 3）；边界 **N3**
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有「派发执行角色时的 brief 构建」字段清单；既有执行角色的产出 / 记录惯例（`history.md`、progress 报告等）；既有「规则 F」的越界判定

---

## 用户价值

检测发生在干活的现场而不是开工前的门禁——执行者顺手核一下地址，而不是被拦在门外再放进来。

## 验收标准

1. **检测挂在执行现场**（W9）：检测由两处承担——① **派发简报随带**（简报含地址声明与检测项）；② **执行者执行时自检**（执行者在做事现场核对自身寻址）。
   *判定*：读条款 → 两处都写明即通过；只有其中一处、或检测被写成"启动前执行"即不通过。
2. **不设启动前准入门**（W9 / N3）：检测**不构成**开工的前置条件——不通过检测不得表现为"不许开始"。
   *判定*：读条款 → 出现"检测不通过即不进入阶段工作"即不通过（那是 F09 唯一硬停面之外的启动门）。
3. **可被观察到（裸判定）**（E7）：任取一次派发，**简报含地址声明与检测项**；任取一次执行记录，其中**含执行者的自检结果**。
   *判定*：取一次派发简报 + 一次执行记录逐项核对 → 任一缺失即不通过。 〔`[user_confirmed MI-06]` 载体口径 = **不限，但必须含"地址 + 判定结论"两项**（会话输出 / `history.md` / progress 报告均可）〕
4. **检测项与地址声明同源**（W9 / W11 关联）：检测项以**工作区地址**为判据对象（核对"我写入的地方 = 声明的工作区地址"），与三层声明的源保持一致。
   *判定*：读条款 → 检测项指向的地址来源与源（产物）不一致即不通过。
5. **检测不引入工具**（W9 / N3 → F21）：检测手段落在"读声明 + 执行者自检"范围内，不引入脚本、钩子、守卫、检测器。
   *判定*：读条款 → 出现工具依赖即不通过。

## 边界（不包含）

- 不含检测项的具体承载形态、字段名、自检结果的记录格式（→ T-05）。
- 不含**事后**核查判据（→ F12 验收 3）：本卡判"现场自检"这一面，F12 判"事后核查"这一面，两者不可互替。
- 不含启动门与硬停（→ F09）。
- 不含简报的地址字段本身（→ F08 / T-04）。
- 不含任何自动化守卫（**不引入**，N3 → F21）。
