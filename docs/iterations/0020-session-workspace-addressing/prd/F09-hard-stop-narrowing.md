## 用户价值

不该停的地方不许停——不能被"你没站在对的目录里"挡在门外；真停的时候也只是陈述事实，不命令人去做事。

## 验收标准

1. **唯一触发面**（W13）：硬停只保留给「**本会话工作区无法确定或无法创建**」这一种情形。
   *判定*：读规范与 SKILL 的全部停止 / 硬停 / 中断类条款，逐条归类触发条件 → 出现该情形以外的硬停触发面即不通过。
2. **删除一切以 cwd 为判据的启动门**（W13 / E5）：规范与 SKILL 中**不再出现**以 `pwd` / `--show-toplevel` 为合规判据的启动门。
   *判定*（`demand.md` E5 给出的裸判据）：检索上述判据句 → 命中即不通过。
3. **无"必须由用户预先执行"的前置**（W13 / E5）：规范与 SKILL 中不存在要求人预先执行的启动前置。
   *判定*：检索"必须由用户执行 / 用户需先…"类句子 → 命中即不通过。
4. **输出不含祈使句**（W13 / E6）：硬停发生时，输出**不要求用户去做某事**（不出现"请先…""你必须去…"）。
   *判定*：构造一次"工作区无法创建"的场景，读输出的全部句子 → 出现指向人的动作要求即不通过。 〔`[user_confirmed MI-02]` 判定口径 = 不出现**指向人 / 用户的动作要求**（"请…""你必须先…""建议你先…"），只陈述事实（触发原因 / 当前状态 / 未完成事项）〕
5. **停的时点与状态**（W13 / E6）：触发即停——**不进入任何阶段工作、不产生任何写入**。
   *判定*：同上构造场景，观察停止前后是否发生了阶段动作或写入 → 出现任一即不通过。 〔`[user_confirmed MI-03]` 时点口径 = **发现即停**：不进入任何阶段工作、不产生任何写入（沿用 0019 MI-01 已裁定的同族口径）〕
6. **SKILL 同步**（W13 的载体面）：SKILL 的 `CRITICAL` 与 `Step 0` 不再保留启动校验动作（不残留"启动校验 → 不通过即停"的动作序列）。
   *判定*：读 SKILL 对应段落 → 仍存在启动校验步骤即不通过。
