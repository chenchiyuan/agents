## 用户价值

隔离边界声明不再是"读完各人各有解释"的段落——章节自己带判断方式，谁都能据此判一次运行有没有越界。

## 验收标准

1. **章节级判断方式行存在**（W21 / E16）：`### 隔离边界声明` 含一条**章节级** `判断方式：` 行（不是只存在于其子项里）。
   *判定*：读该章节 → 找不到章节级判断方式行即不通过。
2. **覆盖该章节全部子项**（W21）：判断方式对该章节的四类内容（覆盖了什么 / 不覆盖什么 / 非 git 共享资源 / 已知代价）**均可判定**——第三者读完能对一次运行判定"是否违反本节结论"。
   *判定*：把章节 + 判断方式交给**未参与本迭代讨论的人**，对一次真实执行判定 → 与规范预期结论一致即通过；无法判定或结论歧义即不通过。
3. **D-1 闭合**（E16）：该偏差被判定闭合（存在 + 可判定两条同时成立）。
   *判定*：验收 1 与 2 同时通过即闭合。
4. **不改本章既有实质内容**（F13 保证面）：本节原有的四类结论与既有负面约束、已知代价表述**逐条不变**；本卡只**补一行判断方式**。
   *判定*：取该章节改动前后的 diff → 出现结论句的改写即不通过。
5. **新增条款自带判断方式的体例一致**（W19 / E12 的关联）：本行与本次新增 / 改写条款的 `判断方式：` 行体例一致。
   *判定*：把本行与新增条款的判断方式行并列比对体例 → 形态不一致即不通过。 〔体例形态 → T-11 / T-08〕

## 边界（不包含）

- 不含"隔离不覆盖 cwd / 不可被 git 强制 / 事后核查判据"的**声明内容**（→ F12）；本卡只判**章节级判断方式行**的存在与可判定性。
- 不含章节的措辞与位置（→ T-11）。
- 不含 0019 其余偏差（N10）。
- 不含非 git 共享资源清单的改动（既有条款不变）。
- 不含 0019 文件本身的修改（N5；本卡在**本次迭代的产物**中承接该偏差）。

## 架构落地（阶段 3 已填，见 `architecture.md` §8.1-G 末段（N-10）+ §8.0（体例）；产品维度未改一字）

- **T-11 补写形态**：**位置** = `### 隔离边界声明` 的**章节末尾**（「已知代价」段之后，独立成段）；**形态** = 以 `判断方式：` 开头的独立一段，与该节条款**同段层级、同属一个 `###`**（不新增 `####` 子标题、不写入独立小节）；**覆盖面** = 该节四类内容逐项可判（① 覆盖：写入是否只改变本工作区的工作树 / 索引 / HEAD；② 不覆盖：是否依赖 refs / stash / 分支命名空间 / 对象库 / config·hooks·remotes 传递会话级状态，或把 cwd 当作归属判据；③ 非 git 共享资源：四项资源各自的约束是否被违反；④ 已知代价与事后核查：冲突是否被后移到收口合并期、越界写入是否按 4 步判据判定且未被表述为"会被阻止"）。措辞全文见 `architecture.md` §8.1-G。
- **与子项判断方式行的关系**：**章节级行判"本节结论是否成立"**（四类逐一对照一次运行 + 一次派发简报）；**子项行（非 git 资源表内的两条）判"该条约束是否违反"**——两者并列、粒度不同、互不替代（沿用 0019 的"条款 + 紧跟一行判断方式"体例，非新体例）。
- **T-08 体例统一方式**：本行与本次新增 / 改写条款的判断方式行（规范 `### 规则 C` / `### 规则 D` / `### 规则 H` / `### 协议产物` / `### 约束主体` 各一行）**同为"条款正文 + 紧跟一行 `判断方式：`"**——同段层级、`判断方式：` 起首、不编号、不换体例（`architecture.md` §8.0）；本卡验收 5 的并列比对因此形态一致。
- **不改本章实质内容（本卡验收 4）**：本节既有四类结论句与既有负面约束 / 已知代价表述**逐条不变**；本行的加入是**新增一段**，不是改写既有句 ⇒ diff 只含新增行（F13 保证面）。D-1 的闭合 = 本卡验收 1 + 2 同时成立（`architecture.md` §9.2）。
