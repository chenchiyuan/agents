# F05：落点语义澄清（三个近名落点互不替代）

**功能 ID**: F05
**来源**: `demand.md` 第二段 §2 **W7**（`user_confirmed`：主 agent 明示"这一句是需求级必须"；依据 F13 / F15 / F17）；边界 **N12**；效果 **E4**
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 三处既有落点事实——`docs/worktrees/`（本迭代新增的协议产物文档位置，被跟踪）、`.pb-agents/worktrees/`（工作区池，被 `.gitignore` 第 2 行忽略）、`docs/iterations/{迭代ID}/`（迭代产物）

---

## 用户价值

三个名字长得像的目录不会再被当成一回事——不会有人把工作树建进被跟踪的文档目录里，也不会有人去"池子"里找迭代文档。

## 验收标准

1. **三处区分可读到**（W7 / E4）：规范与产物中**均能读到**三者的语义区分——① `docs/worktrees/` = **协议产物的文档位置**（被跟踪，**不承载任何运行态工作区**）；② `.pb-agents/worktrees/` = **会话 / PR 工作区池**（运行态，被忽略）；③ `docs/iterations/{迭代ID}/` = **迭代产物**（每迭代一份，不承载跨迭代的协议声明）。
   *判定*：在两处文本中逐项核对三条语义 → 缺任一条、或任一条语义写反（如把 `docs/worktrees/` 说成工作区落点）即不通过。
2. **真源一处 + 产物一行承接**（W7）：区分句的**真源写在规范条款一处**；产物以**一行区分句**承接，两处不形成各自完整的定义。
   *判定*：读两处文本的措辞与篇幅关系 → 出现两处独立完整定义即不通过（N11 同源）。
3. **不把 `docs/worktrees/` 当工作区落点**（N12 / E4）：任何会话 / PR worktree **不得**建在该目录下。
   *判定*（`demand.md` E4 给出的裸判据）：`ls docs/worktrees` 无工作区目录，且 `git worktree list` 的输出中**无 `docs/worktrees/` 前缀项** → 任一条命中即不通过。
4. **产物所在目录不承载运行态内容**（W7 / R-4 的关联）：该目录下不出现随会话变化的运行态内容（从"动态地址"侧判定见 F07 验收 3，两卡分工：本卡判目录语义，F07 判声明落点）。
   *判定*：在两个不同会话的检出中比对 `docs/worktrees/` 下的文件清单与内容 → 出现差异即不通过。
5. **区分句可被任意位置启动的会话读到**：区分句的分发随产物落点（→ F03 验收 2）；规范侧条款随检出即得。
   *判定*：由 F03 验收 2 覆盖，本卡不重复判据。

## 边界（不包含）

- 不含 `.gitignore` 的任何改动（W4 / R-3）：本卡不通过"忽略 / 反忽略"手段实现区分。
- 不含目录命名之外的新机制：N12 是**禁止**，不新增能力（不新增"工作区落点校验器""目录守卫"等，N3 → F21）。
- 不含区分句的措辞与篇幅（→ T-15）；不含产物组织形态（→ T-01）。
- 不含工作区落点本身的定义（既有事实 → F04 验收 1；本卡只做"三者互不替代"的澄清）。
- 不含历史工作区的清理（N9）。
