# F04：产物内容骨架（必须覆盖 5 类信息）

**来源**: `demand.md` 第二段 §2 **W6**（`user_confirmed`：V-3「定义好工作区间和规范」+ 主 agent 明示的三项覆盖 + F15 的落点事实）；效果 **E3**（其"覆盖 5 类信息 + 不含脚本"面）；边界 **N11**（不写成第二真源）
**迭代**: 0020-session-workspace-addressing

## 用户价值

打开一份文件就知道工作区间在哪儿、按哪版规范干活、怎么寻址、别把三个近名目录搞混——不用把散在规则里的判据自己拼起来。

## 验收标准

产物必须覆盖以下 **5 类信息**，逐类可判：

1. **① 本项目的工作区间定义**（W6①）：包含三层内容——i. 会话 / 迭代工作区落点 `<仓库主工作区>/.pb-agents/worktrees/{迭代ID}`；ii. PR worktree 落点与层级 `<会话工作区>/.pb-agents/worktrees/{迭代编号}-pr-{NNN}-{slug}`（**子层**）；iii. **工作区的范围**（哪些路径属于某个工作区、哪些是跨工作区共享的）。
   *判定*：在产物中逐项找到对应陈述 → 任一项缺失即不通过。 〔呈现形态见 T-02；"非第二真源"的判定口径为 `[user_confirmed MI-08]`，见验收 6〕
2. **② 本项目生效的规范与其版本**（W6②）：规范文件路径 + 版本号。
   *判定*：在产物中可读到二者；只写路径不写版本、或只写版本不写路径，即不通过。 〔写法见 T-10〕
3. **③ 寻址纪律引用**（W6③）：显式寻址（绝对路径 + `git -C`）、地址声明的三层落点、越界写入的判定是**事后核查**——**引用规范条款，不重述**。
   *判定*：读产物相应段落 → 以引用形态出现即通过；把规范条款整段重述（形成第二处定义）即不通过（N11）。
4. **④ 落点语义澄清的一行区分句**（W6④ / W7）：产物承接 W7 的区分句一行（真源在规范条款一处）。
   *判定*：产物中可读到该行（内容判定见 F05 验收 1）；产物中形成第二处完整定义即不通过。
5. **⑤ 声明不含任何脚本 / 钩子 / 守卫**（W6⑤ / V-4 / E3）：产物中**不出现**任何脚本、钩子、守卫、命令块，并明写"本产物不含脚本 / 钩子 / 守卫"。
   *判定*（`demand.md` E3 裸判据）：读产物全文 → 出现可执行脚本、钩子定义、守卫逻辑或供复制的命令块即不通过。
6. **不自行创立约束（实例化投影，不是第二真源）**（N11 / R-5）：产物的每一条**规范性**陈述都能回指到规范条款；产物只声明本项目的工作区间与生效版本，不出现规范中没有的新约束。
   *判定*：把产物中每条规范性陈述逐条回指规范条款 → 出现无对应条款的约束即不通过。 〔`[user_confirmed MI-08]` 判定口径 = **引用形态判据**：产物中一切规范性陈述均以指向规范条款的引用形态出现，不出现规范中没有的新约束〕

## 边界（不包含）

- 不含产物的组织形态、字段名、小节顺序、是否用表格（→ T-01 / T-02）——本卡只锁定"必须覆盖哪些信息"。
- 不含动态地址：任何**一次运行**的具体地址不得写进产物（W11 硬约束 → F07 验收 3）。
- 不含脚本 / 钩子 / 守卫本身的形态（**不引入**，N3 → F21）。
- 不含产物落点与跟踪状态的判定（→ F03 验收 1~2）。
- 不含落点语义区分句的措辞与篇幅（→ T-15）。
- 不含"本项目的工作区间"之外的任何项目级规范内容（本迭代只新增这一份产物）。
