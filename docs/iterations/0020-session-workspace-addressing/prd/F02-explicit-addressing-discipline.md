# F02：显式寻址纪律（绝对路径 + `git -C`）

**功能 ID**: F02
**来源**: `demand.md` 第二段 §2 **W2**（`user_confirmed`：U-4 + P-1 保留方向）；效果与 F01 / F07 共用 **E1** / **E10** 的判定面；实证 F4（cwd = 仓库根、相对路径写入落在主工作区）
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有的「文档路径协议」（原以 cwd 为相对路径基准）、「规则 F：跨工作区写入禁止」

---

## 用户价值

会话在哪儿启动都不影响产物落在哪儿——每一条写入与每一次 git 写操作都能被指出"落到了哪个绝对地址"。

## 验收标准

1. **文件写入用工作区地址下的绝对路径**（W2）：规范要求所有文件写入以**绝对路径**进行，且落在该会话声明的工作区地址之下。
   *判定*：读条款；并取一次执行记录，逐条核对写入目标路径是否为绝对路径、是否落在声明的工作区内 → 出现以相对路径作为写入目标且无法定位落点即不通过。
2. **git 写操作用 `git -C <地址>`**（W2）：规范要求所有 git **写**操作以 `git -C <工作区地址>` 的形态执行。
   *判定*：取一次执行记录，逐条核对 git 写操作的形态 → 出现依赖 cwd 的裸 git 写命令（无 `-C`、无其他显式地址）即不通过。
3. **不依赖 cwd、不依赖任何工具**（W2 / N3）：寻址纪律**不引入任何工具依赖**——无包装脚本、无钩子、无守护进程、无环境变量前置。
   *判定*：检索新增 / 改写条款中的工具依赖表述 → 出现"需要先安装 / 先启用某工具才能寻址"即不通过。
4. **不得声称"写错会被阻止"**（W2 与 W16 / N7 的边界）：条款不得把寻址纪律表述为可以阻止跨工作区写入。
   *判定*：读条款 → 出现"必然不会写错 / 越界会被拦住"类断言即不通过（正确表述见 F12）。

## 边界（不包含）

- 不含地址如何解析（→ F06）；不含地址声明落在哪三处（→ F07）；不含简报如何携带地址（→ F08）。
- 不含跨工作区写入的负面约束与"先备份后操作"义务（**既有规则 F 的实质语义不变**，见 F13；本卡只规范"本会话自己的写入怎么寻址"）。
- 不含读操作的强制形态：读取以工作区地址为根、**相对路径不得作为唯一寻址方式**由 F08 承载（简报面）。
- 不含规则 F 闭集例外的扩缩（不扩展，仍为 2 项——见 F03 验收 4）。
- 不含条款措辞与落点（→ T-08）；不含任何命令的具体写法（→ T-03）。
