## 用户价值

读规范的人不会拿着已被废掉的旧句子当判据——哪句失效、哪句保留，写在明处，不用自己去比对版本。

## 验收标准

1. **被取代清单逐句完成**（W15 / E8）：规范中存在逐句显式 supersede 声明，逐项列出：① 规则 D 判据 1 / 2 / 3（**作为启动门**的用法）；② 规则 C「会话必须运行在自己的会话工作区里」；③ 规则 C「随后会话在该工作区根目录内启动」；④ 规则 D 硬停形态块；⑤ 启动工作流首段（"本工作流在本会话的会话工作区（见规则 C）内运行 + 启动时先做会话工作区校验"）。
   *判定*：与该 5 项 v0.9.0 原文**逐句对照** → 缺任一项、或清单粒度写成整节而非句子，即不通过。
2. **保留项逐条声明**（W15）：明确声明**保留**——每迭代一个工作区、工作区落点、PR worktree 子层（不含在本轮被取代的范围内）。
   *判定*：读清单的保留部分 → 缺任一条、或保留项与被取代项混写导致归属不清，即不通过。
3. **取代的语义边界写清**（W15）：被取代的是这些句子的**启动门 / cwd 判据用法**；其承载的实质语义（如"每迭代一个工作区"）由保留项存续，不得读成"整条规则被废止"。
   *判定*：读声明 → 出现"规则 C / 规则 D 整体废止"或"工作区机制取消"的读法即不通过。
4. **声明体可被任意位置启动的会话读到**：该声明随规范本体（被跟踪内容）分发。
   *判定*：与 F03 验收 2 同源（规范本体随检出即得），本卡不重复判据。
5. **实态与声明分离**：本卡只判"声明"，"规范里已不存在这些门"由 F09 验收 2~3 判定；两卡结论必须一致。
   *判定*：读 F09 与 F11 两处结论 → 出现"声明已取代但旧门仍在"的组合即不通过。

- 不含变更说明的位置与版本号（版本跃迁已在 `demand.md` 定：规范 v0.9.0 → v0.10.0、SKILL v1.12.0 → v1.13.0；变更说明组织形态 → T-12）。
- 不含 0019 E 清单的三分类（→ F15）；不含 0018 的失效登记（→ F16）。
- 不含"删除一切 cwd 启动门"的实态判定（→ F09）。
