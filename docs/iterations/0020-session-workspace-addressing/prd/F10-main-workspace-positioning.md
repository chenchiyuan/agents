# F10：主工作区定位重述（可启动、不可作工作区）

**来源**: `demand.md` 第二段 §2 **W14**（`user_confirmed`：P-4① 按推荐）；效果 **E9**；第一段冲突④与 C-4 的闭合方式
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有「规则 C」的"仓库主工作区不作为任何迭代的会话工作区"；既有「规则 F：跨工作区写入禁止」的闭集例外（仍为 2 项，→ F03 验收 4）

## 用户价值

主工作区可以是我开客户端的地方，但不会是任何一个迭代的工地——两边的角色不再混着读。

## 验收标准

1. **可作启动位置**（W14）：规范**显式**允许在仓库主工作区启动会话。
   *判定*：读改动后文本 → 找不到该允许性表述、或仍存在"不得在主工作区启动"的表述即不通过。
2. **不得作任何迭代的工作区**（W14）：规范**显式**声明主工作区**不作为任何迭代的工作区**（沿用既有语义）。
   *判定*：读改动后文本 → 该声明缺失或被弱化即不通过。
3. **对主工作区的写入仍受禁令约束**（W14）：对主工作区的写入仍受**跨工作区写入禁止**约束（闭集例外之外）。
   *判定*：读条款的指代关系 → 出现"主工作区可以任意写入"的表述、或规则 F 对该处的适用被排除，即不通过。
4. **三句同时可读（裸判定）**（E9）：改动后文本中，"可作启动位置""不作为任何迭代的工作区""写入仍受禁令"三者**同时**可读到。
   *判定*：逐句核对 → 任一句缺失即不通过。
5. **无冲突残留**（C-4 已闭合）：不残留"主工作区既不能启动、也不能被写入"的旧读法。
   *判定*：与验收 1~4 合并核对。

## 边界（不包含）

- 不含规则 F 例外集的扩缩（**不扩展，仍为 2 项**，→ F03 验收 4）。
- 不含"会话可在任意位置启动"的一般性要求（→ F01 验收 1）——本卡只做**主工作区**这一处的定位重述。
- 不含硬停面（→ F09）；不含执行主体分离声明（→ F19）。
- 不含规则 A / 规则 B 的实质语义（**零变化**，→ F13 验收 4）。
- 不含条款措辞与落点（→ T-08）。
