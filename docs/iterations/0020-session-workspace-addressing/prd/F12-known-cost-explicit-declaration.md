# F12：已知代价显式化（不可阻止、只能事后核查）

**功能 ID**: F12
**来源**: `demand.md` 第二段 §2 **W16**（`user_confirmed`：P-13① 按推荐）；效果 **E14**；第一段缺口①的闭合方式；边界 **N7**
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有「隔离边界声明」章节（覆盖 / 不覆盖 / 非 git 共享资源 / 已知代价四类内容）；既有「规则 F：跨工作区写入禁止」与其闭集例外（仍为 2 项）

## 用户价值

不会有人以为"写了寻址纪律就等于写错了会被拦住"——边界明说，检查靠事后核查，误判的可能性被提前消掉。

## 验收标准

1. **隔离不覆盖 cwd 的显式声明**（W16）：规范中存在显式声明——隔离只覆盖工作树 / 索引 / HEAD 三层，**cwd 从来不是隔离的一部分**。
   *判定*：读规范该声明 → 缺失即不通过。
2. **不可被 git 强制的显式声明**（W16 / E14）：规范中存在显式声明——跨工作区写入**不可能被 git 强制** ⇒ 越界写入**不会被阻止**、只能**事后核查**发现；并写明判定是事后核查而非阻止。
   *判定*：读规范文本 → 缺任一半（"不覆盖 cwd" / "不可被强制、只能事后核查"）即不通过。
3. **给出核查判据**（W16 / E14）：规范给出事后核查的**判据**（可被未参与讨论的第三者执行）。
   *判定*：把该判据交给未参与讨论的人，对一次真实执行记录判定"是否越界写入" → 结论与规范预期一致即通过；判据缺失或不可执行即不通过。 〔承载形态 → T-05〕
4. **不得把"未阻止"读成"条款失效"**（W16）：规范中存在该反向比对句——"未被阻止"不等于"条款作废"，越界写入仍是被判定为违规的行为。
   *判定*：读规范文本 → 该句缺失即不通过。
5. **不承诺阻止**（N7）：规范与 SKILL 中不存在"跨工作区写入会被阻止 / 会被拦截"的断言。
   *判定*：检索规范与 SKILL → 命中即不通过。
6. **与规则 F 的分工可读**：本卡声明的是"条款的性质与判定方式"；规则 F 的**负面约束本身与"先备份后操作"义务保持原样**（→ F13 验收 3）。
   *判定*：读两处条款的指代关系 → 出现对规则 F 实质语义的改写即不通过。

## 边界（不包含）

- 不含核查判据与检测项的承载形态（→ T-05）。
- 不含规则 F 的实质语义与例外集改动（**零变化**，→ F13 验收 3 与 F03 验收 4）。
- 不含"做事时检测"的现场自检（→ F20；本卡判**事后**核查这一面）。
- 不含非 git 共享资源的清单（既有条款不变，→ F13）。
- 不含任何强制机制（**不引入**，N3 → F21）。
- 不含声明在章节中的落点（→ T-08；与 F17 的章节级判断方式行相邻，但 F17 判判断方式、本卡判声明内容）。

## 架构落地（阶段 3 已填，见 `architecture.md` §8.1-G（N-08 / N-09）+ §5.5；产品维度未改一字）

- **T-05 事后核查判据的承载形态**：**落在 `### 隔离边界声明` 的「已知代价」段内**（不新增章节、不新增记录格式），引用 `### 规则 F` 的判断方式，**不重述其措辞**；判据形态 = **4 步读文本**（① 取该会话 `status.md` 的 `**工作区地址**` 字段；② 取该次派发简报的 `工作区地址` 字段；③ 取该会话执行记录中每条写入动作的目标路径；④ 逐条判"是否位于声明地址之下"——区外路径若其**之前**存在备份动作则不判违反，否则判违反）。第三者（未参与讨论者）按这 4 步即可执行（本卡验收 3）。
- **T-08 落点与章节命名（与 `### 隔离边界声明` 的关系）**：**三条声明全部落在该节内**，分两处补写——① 「不覆盖（逐项 + 负面约束）」清单内追加一条 **cwd**（"cwd 从来不是隔离的一部分——隔离覆盖的是工作树 / 索引 / HEAD 三层；会话在哪个目录启动与其产物落在哪个工作区无关"）；② 「已知代价」段追加 **不可被 git 强制 / 越界不会被阻止 / 只能事后核查 / "未被阻止"≠"条款作废" + 4 步核查判据**（措辞全文见 `architecture.md` §8.1-G）。**与 F17 的分工**：本卡的声明内容属该节，F17 只补**章节级 `判断方式：` 行**（N-10）——两卡相邻但判据对象不同（本卡判声明内容、F17 判判断方式行的存在与可判定性）。
- **与规则 F 的分工可读（本卡验收 6）**：规则 F 正文与闭集例外两项**逐字不动**（`architecture.md` §3.5 / §7.2 P6）——本卡只声明"条款的性质与判定方式"，不触碰其负面约束与"先备份后操作"义务。
- **不承诺阻止（本卡验收 5 / N7）**：规则 F 既有句「本条款不可能被 git 强制执行」逐字保留；新增声明与之同向（越界不会被阻止）；SKILL 侧由 K-08 新增"不得声称越界会被阻止"的一条 Safety 承接 ⇒ 两载体均无"会被拦住"类断言。
