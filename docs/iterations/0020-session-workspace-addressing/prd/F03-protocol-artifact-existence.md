## 用户价值

会话在自己的工作区里就能读到"这个项目的工作区怎么划、按哪一版规范干活"——不用被谁口头告知，也不用先建什么东西。

## 验收标准

1. **产物存在且落点正确**（W4 / W5）：`docs/worktrees/README.md` 存在（W5 已裁决的**判据基准**文件名）。
   *判定*：读该路径 → 不存在即不通过。
2. **随检出即得（被 git 跟踪）**（W4 / R-1 / E3）：该文件**被 git 跟踪**，在任何会话工作区内随 `git worktree add` 检出即可读到，不需要任何安装 / 初始化动作。
   *判定*（`demand.md` E3 给出的裸判据）：`git ls-files --error-unmatch docs/worktrees/README.md` 成功；并在一次新建工作区中确认该文件随检出存在 → 命令失败、或新工作区里读不到即不通过。
3. **不改 `.gitignore`**（W4 / R-3）：本迭代**不修改**仓库根 `.gitignore`，不新增任何负例忽略规则。
   *判定*：取本迭代改动文件清单 → 出现 `.gitignore` 即不通过。
4. **不扩展规则 F 的闭集例外**（W4 / R-4）：跨工作区写入禁止的**闭集例外仍为 2 项**。
   *判定*：读规则 F 的例外清单 → 例外数变为 3 或以上即不通过。
5. **判据句从产物派生（协议先行）**（W3 / V-1）：规范条款对"工作区间"与"生效规范"的表述**以该产物为声明来源**——产物先声明，条款引用它，而不是把工作区间判据散落在多条规则正文里各自定义。
   *判定*：读产物与相关条款 → 产物中可读到工作区间 / 生效规范的声明、条款以引用形态指向它即通过；条款各自独立定义工作区间即不通过。
6. **可被任意位置启动的会话读到**（§4 结构性事实）：产物落点不在被忽略目录下，因此"会话在任意位置启动"不影响其可读性。
   *判定*：由验收 2 的被跟踪判据 + 一次"在仓库主工作区启动的会话读到该文件"的记录共同覆盖。
