# F19：约束主体显式分离（人零强制 / 会话有纪律）

**功能 ID**: F19
**来源**: `demand.md` 第二段 §2 **W23**（`user_confirmed`：P-16① 按推荐）；第一段 M-4 已闭合（「使用者」的外延 = 人 / agent 两类主体）；与 W1 / W13 / W16 同源
**迭代**: 0020-session-workspace-addressing
**产品对象（引用 `demand.md` 只读事实，非本阶段决策）**: 既有规则的约束主体表述（v0.9.0 把"必须由用户执行"的建立前置写进操作说明，冲突⑤）；既有「规则 F」的"先备份后操作"义务

---

## 用户价值

规矩到底管谁写在明处——不拿"纪律"去要求人，也不拿"没强制"当会话的借口。

## 验收标准

1. **对人零强制可读到**（W23）：规范中存在对**人**的零强制表述——无前置 / 无目录要求 / 无 cd / 无重开会话要求。
   *判定*：读规范相应条款 → 四项逐条可读到即通过；缺任一项、或与之为相反要求的条款并存，即不通过。
2. **对会话有纪律可读到**（W23）：规范中存在对**会话**的纪律表述——① 声明地址；② 显式寻址；③ 越界须先备份。
   *判定*：三条逐条可读到即通过。
3. **违反的判定方式归事后核查**（W23 / F12 关联）：纪律的违反**被事后核查判定**（不声称被阻止）。
   *判定*：读条款 → 出现"违反会被阻止 / 会被拦截"即不通过（正确表述见 F12）。
4. **两类主体显式分写**（W23）：规范中把"对人"与"对会话"**分开声明**，两者不混在同一句里造成歧义。
   *判定*：读条款结构 → 两类主体混写在同一句、导致"人也要承担纪律"或"会话也不受约束"的读法，即不通过。
5. **与相邻卡逐条不冲突**（W23 的闭合一致性）：本声明与 F01 验收 1~2（人零前置）、F09 验收 2~3（无启动门）、F12 验收 1~5（已知代价）、F13 验收 7（护栏不变）**逐条不冲突**。
   *判定*：把五处条款并排逐句对照 → 出现相互否定的表述即不通过。

## 边界（不包含）

- 不含"人零前置"的行为要求本身（→ F01 验收 1~3）；本卡判"显式分写"这一声明义务。
- 不含硬停输出形态（→ F09 / T-06）；不含已知代价的具体声明（→ F12）。
- 不含条款措辞与落点（→ T-08）。
- 不含对既有 CRITICAL 的改写（除本迭代必修的启动校验句 → F09 验收 6）。
- 不含任何新的强制手段（N3 → F21）。
