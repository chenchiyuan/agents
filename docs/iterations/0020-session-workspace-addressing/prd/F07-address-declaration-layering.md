## 用户价值

同一件事只在一个地方说了算——三处说法不一致时有明确裁决规则（以源为准并留痕），而不是各读各的。

## 验收标准

1. **三层关系存在且可读到**（W11）：源 = 协议产物（项目级**静态**声明：工作区间规则 + 生效规范版本）；投影 1 = `status.md` 字段（迭代级地址）；投影 2 = 简报字段（派发级地址）。
   *判定*：读规范与产物，三层的名称、层级、各承载什么可逐条读出 → 缺少任一层、或层级关系含糊（无法判断谁为准）即不通过。
2. **不一致时以源为准并登记差异**（W11 / E10）：当三处陈述不一致时，**以源（产物）为准**，且差异被**登记**。
   *判定*：构造或取到一次三处不一致的情形 → 核对是否可观察到"以产物为准"的处置**留痕** → 无留痕、或以投影为准即不通过。 〔`[user_confirmed MI-04]` 登记载体 = **不限**：凡可被第三者读到"以源为准"处置留痕的载体均可（会话输出 / `status.md` / `history.md` / progress 报告），**不新增固定登记义务**〕
3. **动态地址不得写进协议产物**（W11 硬约束 / C-13①）：**本次运行的动态地址只落 `status.md` 与简报**，不得写进 `docs/worktrees/README.md`。
   *判定*（`demand.md` E10 给出的裸判据）：产物内容**不随会话而变化**——在两个不同会话的检出中比对同一产物，内容相同即通过；出现某次运行的地址即不通过。 〔`[user_confirmed MI-05]` 判定口径 = 以"产物内容不随会话变化"为判据（两个不同会话的检出中比对同一产物），不做词形枚举〕
4. **三处一致性的可核查性**（E10）：任取一次运行，三处对"工作区间 / 地址"的陈述**一致**；不一致时差异被登记且以产物为准（见验收 2）；且产物中不含任何一次运行的动态地址（见验收 3）。
   *判定*：取一次运行的产物 / `status.md` / 简报三处文本逐项比对 → 三处一致即通过。
5. **硬约束不与他条相撞**（W11 / C-13① 的闭合）：验收 3 成立（动态地址不落产物）时，必然不产生"每次会话一次仓库改动"的后果，因而与规则 A / 规则 B（变更走 PR worktree）**不冲突**——本卡不为此新增任何条款。
   *判定*：由验收 3 通过 + F13 验收 4（规则 A / 规则 B 实质语义不变）共同覆盖。

> **需求背景（`demand.md` 已确认，非本卡新增要求）**：W11 硬约束所依据的因果 = "动态地址若落进被跟踪的产物，每次会话都会产生一次仓库改动，与规则 A/B 相撞"（C-13① 的闭合方式）。**是否把该因果写进规范正文属阶段 3 的措辞决策**（→ T-08），本卡不将其列为验收项。
