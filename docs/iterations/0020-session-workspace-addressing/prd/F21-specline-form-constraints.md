## 用户价值

遵守这套规范不需要先装什么——规则写在文本里，读完就能自己判断有没有做到。

## 验收标准

1. **不引入 hook / 守卫脚本 / 强制检测器**（W8 / N3）：规范与 SKILL 的改动中**不出现**任何 hook、守卫脚本、强制检测器；改动文件清单**不含任何脚本文件**。
   *判定*：检索新增 / 改写条款并取改动文件清单 → 出现脚本、hook 定义、检测器，或清单中出现 `.sh` / 可执行脚本，即不通过。
2. **不引入工具依赖**（N3）：遵守任一条新增 / 改写条款所需的**全部手段**落在 git 原生命令 + 文本规范内——无安装前置、无守护进程、无环境依赖。
   *判定*：对每条新增 / 改写条款问"遵守它需要什么" → 出现任何工具前置即不通过。
3. **不设启动前准入门**（N3 / W13 关联）：规范中不存在开工前的准入门。
   *判定*：与 F09 验收 2~3 同源（本卡不重复判据）。
4. **条款自带判断方式**（N3 / W19 的 E12 面）：本次**新增 / 改写**的每一条条款都带 `判断方式`（未参与讨论者可据此判定"违反 / 未违反"）。
   *判定*：逐条读新增 / 改写条款 → 出现无判断方式的条款即不通过。（与 F15 验收 5 的 E12 同源，分工：本卡判**形态约束**的全域，F15 判 **0019 承接**的条目。）
5. **产物内不含脚本 / 钩子 / 守卫**（W8 / E3）：协议产物中不出现脚本、钩子、守卫逻辑或可复制的命令块。
   *判定*：与 F04 验收 5 同源（同一条判据，产物侧）。
6. **形态约束可被裸判定**：任何第三者读完规范即可核验本卡全部验收项，不需要运行任何程序。
   *判定*：由验收 1~5 的检索 / 阅读判据覆盖。

## 边界（不包含）

- 不含任何工具选型或技术手段（**不引入**）。
- 不含条款措辞与落点（→ T-08）；不含产物组织形态（→ T-01）。
- 不含"做事时检测"的承载形态（→ F20 / T-05；本卡只判"检测不引入工具"这一形态面）。
- 不含 supersede 的文本组织方式（→ T-07）。
- 不含既有条款的形态改写（除本迭代必修条目外，既有条款形态不变，→ F13）。
