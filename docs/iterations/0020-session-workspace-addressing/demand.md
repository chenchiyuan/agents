# 第二段 · 需求结论

## 1. 目标与价值

**目标（`user_confirmed`）**：把 v0.9.0 的「启动契约（cwd 判据 + 硬停）」改造为「**寻址契约**」，并把它**载体化为一份声明式协议产物**：协议先以 `docs/worktrees/README.md` 声明「工作区间」与「规范」；会话可在项目中的任意位置启动；会话开始时确定并声明自己的迭代工作区地址，此后所有文件写入与 git 写操作**显式寻址**该地址；**不用脚本硬规范**；检测发生在**做事的现场**而非启动前的准入门；硬停只保留给「本会话工作区无法确定或无法创建」。**对人的强制面归零**。

**价值（`实测` + `user_confirmed`）**：
- 对**人**：消除 U-5 所指的强制 —— 现状下人要"先建工作区、再 cd 进去开会话"（0018 `status.md:24` 明写"必须由用户执行"），忘了就被**发现即停**（F3：本迭代自己即被挡在门外）。
- 对**机制**：把绑定的载体从"宿主对 cwd 的处理"（协议不可控，F7）换成"显式地址 + git 原语"，并使契约本身**有可读、随检出即得的载体**（R-1），不再散落在判据句里。
- 对**事故**：直接修复 F4 的成因 —— 简报无地址字段 + 文档协议以 cwd 为相对路径基准 ⇒ 执行角色只能按 cwd 猜落点。

## 4. 大概怎么做（机制轮廓）

- **形态**：**协议先行 → 解析 → 声明 → 寻址 → 存在性 → 做事时检测** ——
  ① 协议先行：`docs/worktrees/README.md`（被跟踪、随检出即得）声明「工作区间 + 规范 + 寻址纪律引用 + 落点语义澄清」（W3~W7）；
  ② 解析：从共享 `.git` 推出仓库主工作区，再据迭代 ID 推出工作区地址 `<仓库主工作区>/.pb-agents/worktrees/{迭代ID}`（W10）；
  ③ 声明：动态地址写入 `status.md`（迭代级）与每次简报（派发级），与产物构成三层（W11）；
  ④ 寻址：写入用绝对路径、git 写操作用 `git -C <地址>`（W2）；
  ⑤ 存在性：工作区不存在时按固定命令建立，失败才硬停（W1/W13）；
  ⑥ 做事时检测：简报随带 + 执行者执行时自检（W9），越界由事后核查判定（W16）。
- **保留的既有边界（`实测`）**：隔离仍只覆盖**工作树 / 索引 / HEAD** 三层；不隔离 refs（含 stash 与分支命名空间）、对象库、config/hooks/remotes；"同一分支不能两处检出"仍是 git 硬约束；**cwd 从来不是隔离的一部分** —— v0.9.0 把它当入口条件，是**代理判据**。
- **仍留白给阶段 3（N6）**：产物的组织形态与字段名、检测项的承载形态、解析命令、硬停输出形态、supersede 的文本组织方式。
- **本文件锁定的结构性事实（`实测`）**：契约一旦被载体化，它自己也要能被**任意位置启动的会话读到** —— 新落点 `docs/worktrees/` 位于被跟踪的 `docs/` 树下（F17），故随检出即得；同时它落在 `docs/` 里，**不是迭代产物**，与 `.pb-agents/worktrees/`（工作区池）近名异义（W7/N12）。

## 6. 为什么这么做

**为什么（`实测`）**：v0.9.0 把"会话身份 ↔ 工作区身份"的绑定实现为**入口绑定**，判据是 cwd。三条一手事实否定这个判据：① F4（cwd 与写入落点不等价）；② F5（会话在自己的 worktree 里仍会误写主工作树，cwd 判据完全无效）；③ F7（该判据对阶段 5 子 agent 的口径实测未成立）。同时它把人卷了进来（F3、0018 `:24`），与 U-5 直接冲突。

**为什么这次、为什么只改这些（`user_confirmed`）**：用户以 U-1/U-3/U-5 排除了入口绑定的强制形态；以 U-2/U-4 指定替代方向（worktree 保留 + 把 git 的工作方式定义清楚）；以第二轮原话进一步要求把契约**载体化**为声明式协议产物、不用脚本、做事时检测；以第三轮原话把产物落点定在**被跟踪的 `docs/worktrees/`**，从而消除"会话读不到自己的协议"这一失败模式，且无需改 `.gitignore`、无需扩规则 F 例外、不产生第二真源。D-1 / D-7 之所以纳入，是因为它们正是 0019 阶段 6 报告「下一迭代候选」的第 3 / 第 8 项，承接它们是既有登记链的自然落点。

**为什么落点定在 `docs/worktrees/` 而不是 `.pb-agents/`（`user_confirmed` + `实测`）**：`.pb-agents/` 被 `.gitignore` 整体忽略（F13），产物在那里**不随检出即得**，会话在**自己的工作区里读不到自己的协议**；且由 `gitignore(5)` 明文（F14），负例规则在被排除目录下不生效——要"纳入跟踪"必须改写 `.gitignore`。而 `docs/worktrees/` 被跟踪（F17），三个问题同时消失；它与 0019 W8 的"真源 = 随检出即得的被跟踪内容"取向**同族**（R-6）。
