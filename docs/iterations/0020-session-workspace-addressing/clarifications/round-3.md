## 三、三项需求级处理（主 agent 明示必须）

### 3.1 产物命名与内容骨架

**文件名（需求级固定为判据基准）**：`docs/worktrees/README.md`

- **推荐理由**：本仓库已有**同类先例** —— `docs/ds/` 就是一个"`docs/<主题>/` 协议规格包目录 + 目录自述 `README.md`（带 `状态/版本/日期/演进自` 头）+ 编号文件"的形态（`实测` F17）；目录自述使产物可被直接引用、无需额外约定。
- **备选**：① `docs/worktrees/protocol.md`（"协议"语义更重）；② `docs/worktrees/worktrees.md`（与 `docs/memory-system.md` 之类单文件协议文档同形）。三者取一即可；**本迭代以 `README.md` 为判据基准**（否则"产物是否存在"不可裸判定 —— 这是把它定为需求级的原因）。
- **`[架构待填]`**：产物的**组织形态**（字段名、小节顺序、是否用表格）留阶段 3 —— 需求只定"必须覆盖什么"。

**内容骨架（需求级「必须覆盖以下 5 类信息」）**：

1. **本项目的工作区间定义** —— 会话/迭代工作区落点 `<仓库主工作区>/.pb-agents/worktrees/{迭代ID}`；PR worktree 落点与层级 `<会话工作区>/.pb-agents/worktrees/{迭代编号}-pr-{NNN}-{slug}`（子层）；以及**工作区的范围**（哪些路径属于某个工作区、哪些是跨工作区共享的）。
2. **本项目生效的规范与其版本**（规范文件路径 + 版本号）。
3. **寻址纪律引用**（显式寻址：绝对路径 + `git -C`；地址声明的三层落点；越界写入的判定是事后核查）—— **引用规范条款，不重述**。
4. **落点语义澄清**的一行区分句（见 3.2）。
5. **声明不含任何脚本 / 钩子 / 守卫**（V-4）。

### 3.2 命名语义澄清（新目录的歧义）

仓库中存在**三个近名但语义不同的落点**，规范与产物都必须说清、**互不替代**：

| 落点 | 是什么 | 跟踪状态 | 承载什么 |
|---|---|---|---|
| `docs/worktrees/` | **协议产物的文档位置** | **被跟踪** | 声明（工作区间 + 生效规范 + 寻址纪律引用）—— **不承载任何运行态工作区** |
| `.pb-agents/worktrees/` | **会话 / PR 工作区池** | 被 `.gitignore` 忽略 | 运行态工作区（含各迭代工作区与 PR worktree） |
| `docs/iterations/{迭代ID}/` | **迭代产物** | 被跟踪 | 每迭代一份的过程与产物文档（不承载跨迭代的协议声明） |

- **真源写法**：规范条款一处（单一处定义）；产物以**一行区分句**承接（不产生新约束）。
- **配套边界（N12）**：**不把 `docs/worktrees/` 用作任何工作区（含 PR worktree）的落点**，不在该目录下执行 `git worktree add` —— 该目录被跟踪，在其中创建工作树会把运行态内容写进被跟踪目录。

### 3.3 三处地址落点的分层（源改落点）

按 v0.2.0 的结论保留分层，仅把「源」的落点从 `.pb-agents/` 改为 `docs/worktrees/README.md`（= W11）：

| 层 | 落点 | 承载 | 性质 |
|---|---|---|---|
| **源** | `docs/worktrees/README.md` | **静态**：工作区间规则 + 生效规范与其版本 | 项目级 |
| 投影 1 | `status.md` 字段 | 本迭代的会话工作区 | 迭代级 |
| 投影 2 | 简报字段 | 本次派发的绝对地址（`git -C` 用） | 派发级 |

- 不一致时**以源为准**并登记差异；
- **硬约束**：本次运行的**动态地址只落后两者**，**不得写进协议产物** —— 否则每次会话都会产生一次仓库改动，与规则 A/B（变更必须走 PR worktree）相撞。
