# F01 · 收敛路径反射（开场展示 + 依赖先于被依赖 + 上游推翻重反射）

**来源**：D-2（反射而非模板）；D-3（收敛顺序）；衡量标准 1（无固定收敛骨架；硬约束"依赖先于被依赖"；必须可见痕迹"收敛路径"）；执行方向"新增收敛路径反射"；事实 F-1（现状平铺维度、按缺口大小排序，无依赖顺序）

## 用户价值

用户在一开始就看得到"这次要走几圈、每圈框定什么、为什么这样排"，不再面对一串平铺、顺序随机的问题。

## 验收标准

1. **开场反射可见**：新版 `roles/demand/demand.md` 明文要求：收敛开始时由 AI 针对本次话题反射并**向用户展示**本次收敛路径，展示内容至少包含三要素——圈数、每圈框定什么、为什么这样排 [D-3；衡量 1 "必须可见的痕迹：收敛路径"]。
2. **唯一硬约束 = 依赖先于被依赖**：新版明文把"依赖先于被依赖"写为收敛顺序的硬约束；除此之外不规定任何固定的圈序 [D-3 "唯一硬约束"；衡量 1]。
3. **无固定收敛骨架**：新版全文中不存在"第 1 圈必须是 X、第 2 圈必须是 Y"或等价的固定圈序/固定维度序列（例：不出现"先需求→再目标→再边界…"作为强制顺序）[衡量 1 "不存在固定收敛骨架"；D-2]。
4. **上游被推翻时重反射**：新版明文要求：已框定的上游结论被推翻时，AI 重新反射收敛路径，并**标出因此作废的下游结论** [D-3]。
5. **反射对象是五项**：收敛路径框定的对象是五项（需求/目标/边界/衡量标准/执行方向），而不是 v0.7.0 的"角色反射维度列表按缺口大小排优先级" [D-1；D-3；事实 F-1]。

QA 判定方式：通读新版 demand.md，逐条检索 1~5 的明文；对 3 做反向检索（是否存在任何强制圈序表述）。

## 边界（不包含）

- 不规定收敛路径的展示模板或字段格式（格式形态见 `architecture.md` §4）。
- 不规定圈数上下限（D-13 "不设轮次上限：保留"，见 F08）。
- 不规定"依赖"如何判定的具体算法——由 AI 针对当前内容反射 [D-2]。
- 不涉及 pb-v1-talk skill [边界·不做]。

## 架构维度

**A-01（已填定，详见 `architecture.md` §3.1 / §3.2 / §3.6）**：Strategy 锚点 1「收敛路径」写反射问法，并明说"五项列举顺序只是名称顺序，不是收敛顺序"；Workflow「2. 目标对齐」末尾展示路径；「3. 计划」写上游推翻→重反射并标作废下游；首部 CRITICAL C2 = 依赖先于被依赖（含后果），Safety 有对应的尾部验证形式。
**A-02（已填定，详见 `architecture.md` §4）**：只写必含要素（圈数 / 每圈框定哪一项 / 为什么这样排；重反射时加作废的下游），不给样板、不给正例、不设固定标题。
