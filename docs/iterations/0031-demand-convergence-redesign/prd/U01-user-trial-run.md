# U01 · 试跑验收（合并后用户执行）

**来源**：衡量标准 6（"试跑验收（迭代合并后由用户执行）：用一个真实需求跑一次阶段 1，抛给用户的每个问题都附'为什么这题归你'、都对应五项之一的缺口，且用户主观判断决策压力明显下降"）；需求（"用户决策压力大，需求收敛低效"）

**性质**：用户验收卡。**合并后用户执行**，不作为阶段 2~6 任何推进条件；阶段 5/6 不以本卡为通过判据。

## 用户价值

用户在真实需求上亲自确认：新 demand 真的让自己少拍板、问得更准。

## 验收标准（合并后用户执行）

1. **前置**：本迭代已合并入 main；用户选定一个真实需求，按新版 `roles/demand/demand.md` 跑一次阶段 1。
2. **每题附"为什么这题归你"**：该次对话中 AI 抛给用户的**每一个**问题都附有"为什么这题归你" [衡量 6；对应 F03 验收 3]。
3. **每题对应五项之一的缺口**：该次对话中每个问题都可被用户指认出对应五项之一的缺口 [衡量 6；对应 F02]。
4. **决策压力主观判断**：用户主观判断决策压力相较 v0.7.0 明显下降（用户给出是/否结论）[衡量 6]。

判定：2、3 为逐题计数（全部满足才算通过）；4 为用户主观结论。

## 边界（不包含）

- 不在本迭代内执行（本迭代不按新流程重走 [边界·不做 3]）。
- 不规定试跑需求的选择标准与记录格式。
- 试跑未通过的处理走新迭代，不回退本迭代（沿用 workflow-pb「阶段回退」规则）。
