# F07 · 池内路由（同会话粘性 / 新会话选最空闲 / 显式声明不延续）

**来源**：demand.md 做什么#5（"hub 在池内做路由（同会话粘性、新会话选最空闲）"）；§大概怎么做（并发："新增按 `(chat_id, agent_id)` 的粘性路由表；调用方可显式声明'新会话/不需要延续'"）；决策 D-31；效果#5 后半；事实 F-7（`ContextPool` 按 `(chat_id, agent_id)` 同键排队、上下文随实例存续）；否决路径：无状态负载均衡（D-31 / 不做什么#5）

## 用户价值

多实例**不等于失忆**——同一对话对同一角色的连续多轮仍落在同一个实例上，上下文不断裂；只有不同对话才被分散。

## 验收标准

1. **同会话粘性**：同一 `chat_id` 对同一角色连续多轮派发（池内 ≥2 个在线实例）⇒ 各轮**固定路由到同一个实例**（已建立上下文的实例被复用）[效果#5 后半；D-31]。
2. **新会话选最空闲**：两个不同 `chat_id` 同时派发给同一角色 ⇒ 落在**不同实例**上，且选择依据是"池内当前最空闲"（不是随机、不是固定第一个）[D-31]。
3. **显式声明不延续**：调用方存在**显式途径**声明"新会话 / 不需要延续" ⇒ 该次派发按"选池内最空闲"处理，即使该 `chat_id` 此前已绑定某实例 [D-31；载体归 A-07]。
4. **粘性只决定"落在哪"**：不改变既有调用信封、既有对话状态语义与既有同键串行语义（同一实例内的排队规则不变）[事实 F-7；G01 验收 1/3]。
5. **路由结果对调用方可见**：上述 1/2/3 三条可由外部观测判定（沿用既有实例标识面），无需读内部状态 [D-31 的可判定性；F06 验收 5]。

## 边界（不包含）

- **不做跨实例的上下文迁移 / 会话状态搬迁**（已否决路径）[D-31；不做什么#5]。
- **不做"任意实例接单"的无状态均衡** [不做什么#5]。
- **不做粘性绑定的寿命 / 淘汰策略产品化**（实例下线后的失效口径见 MI-11）。
- **不在本卡决定"显式声明不需要延续"的参数形态与命名**（[架构待填] A-07）。
- **不改变单实例情形下的既有行为**（同 F06 验收 2）。
- 不做路由的可配置策略面（除 demand 明列的两条规则外，不新增第三、第四条路由规则）。

## 架构维度

**A-07（已填定，全文见 `architecture.md` §4 A-07）**

- **路由表的键与生命周期** = `src/pool-routing.js` 内的进程内 `Map`，键 = **`(chat_id, role)`**，值 = `instance_id`。键在 web 而非 Router 的理由：`chat_id` 只存在于 web 侧（Router 任务条目**不携带 `chat_id`** ⇒ 无法在 Router 侧做会话粘性），且决策必须发生在"选目标 → `message.send`"之前。生命周期 = 进程内、**无 TTL、无淘汰定时器**（每次选择时顺带丢弃"绑定实例已不在池"的条目）；条目上界 = 有派发历史的 `(chat_id, role)` 对，与既有 `principals` 表同阶。
- **"最空闲"的度量口径** = 见 A-06：次序键 `(queued, busy, inflight, instance_id)` 取字典序最小（`queued`/`busy` 来自 `router.task_list` + 既有 `deriveAgentWork`；`inflight` = 本进程在飞预留计数；`instance_id` 升序保证**确定性**、可复现）。
- **"不需要延续"声明的承载形态（MI-10）** = `POST /api/calls` 的**项级可选布尔字段 `new_session`**（与既有项内字段 `output_schema` / `schema_mode` / `mode` / `model` 同层；缺省不出现 ⇒ 既有请求形状零变化，G01 验收 10）。语义 = 本次派发忽略既有绑定、按最空闲重选并**重绑**（下一轮若无该声明则粘到本次选中的实例 ⇒ "新会话从这里开始"）。`API.md` §3.9 参数表随之同步。
- **与既有 `(chat_id, agent_id)` 上下文键的关系**：`ContextPool` 的 `agent_id` 实参 = 实例 id（`agent.js` 传 `ctx.instanceId`）⇒ 粘性键 + 选中实例**恰好重构出**该键空间中的一项；粘性表只回答"落到哪个实例"，**不替代、不改写** `ContextPool` 的键语义与同键串行语义（F06 验收 4 / 本卡验收 4）。
- **失效口径（MI-11）** = 绑定实例不在池 ⇒ 直接按最空闲重选并重绑，**不报错**（同一会话不因实例更替报错；代价 = 跨轮上下文可能断，D-30 的必然结果）。
- **可观测性（验收 5）** = 复用**既有实例标识面**：`GET /api/agents` 行的 `instance_id` + 既有五字段投影（`busy` / `current_call_id` / `queued` / `since`，0029 已建），以及转录条目的 `from`（= 上报实例 id）⇒ 无需读内部状态、不新增第二套标识。
- **不做**：跨实例上下文迁移、无状态均衡、粘性淘汰策略产品化、除"同会话粘性 / 新会话最空闲"两条外的任何路由规则（本卡边界）。

## model_inferred

- **MI-10**（验收 3 的口径）：demand 只写"调用方显式声明"，未定义声明面形态。本卡按"**存在一个调用方可用的显式声明途径**（形态与命名归架构阶段）"落卡，等主 agent 确认。
- **MI-11**（验收 1 的边界情形）：demand 未定义粘性绑定在目标实例下线后的行为。本卡按"绑定失效 ⇒ 回落'池内最空闲'，同一会话不因实例更替而报错"落卡，等主 agent 确认（该口径意味着跨轮上下文可能断——此为 D-30"hub 不管生命周期"的必然代价）。
