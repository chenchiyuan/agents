# F07 · 池内路由（同会话粘性 / 新会话选最空闲 / 显式声明不延续）

**来源**：demand.md 做什么#5（"hub 在池内做路由（同会话粘性、新会话选最空闲）"）；§大概怎么做（并发："新增按 `(chat_id, agent_id)` 的粘性路由表；调用方可显式声明'新会话/不需要延续'"）；决策 D-31；效果#5 后半；事实 F-7（`ContextPool` 按 `(chat_id, agent_id)` 同键排队、上下文随实例存续）；否决路径：无状态负载均衡（D-31 / 不做什么#5）

## 用户价值

多实例**不等于失忆**——同一对话对同一角色的连续多轮仍落在同一个实例上，上下文不断裂；只有不同对话才被分散。

## 验收标准

1. **同会话粘性**：同一 `chat_id` 对同一角色连续多轮派发（池内 ≥2 个在线实例）⇒ 各轮**固定路由到同一个实例**（已建立上下文的实例被复用）[效果#5 后半；D-31]。
2. **新会话选最空闲**：两个不同 `chat_id` 同时派发给同一角色 ⇒ 落在**不同实例**上，且选择依据是"池内当前最空闲"（不是随机、不是固定第一个）[D-31]。
3. **显式声明不延续**：调用方存在**显式途径**声明"新会话 / 不需要延续" ⇒ 该次派发按"选池内最空闲"处理，即使该 `chat_id` 此前已绑定某实例 [D-31；载体归 A-07]。
4. **粘性只决定"落在哪"**：不改变既有调用信封、既有对话状态语义与既有同键串行语义（同一实例内的排队规则不变）[事实 F-7；G01 验收 1/3]。
5. **路由结果对调用方可见**：上述 1/2/3 三条可由外部观测判定（沿用既有实例标识面），无需读内部状态 [D-31 的可判定性；F06 验收 5]。

## 边界（不包含）

- **不做跨实例的上下文迁移 / 会话状态搬迁**（已否决路径）[D-31；不做什么#5]。
- **不做"任意实例接单"的无状态均衡** [不做什么#5]。
- **不做粘性绑定的寿命 / 淘汰策略产品化**（实例下线后的失效口径见 MI-11）。
- **不在本卡决定"显式声明不需要延续"的参数形态与命名**（[架构待填] A-07）。
- **不改变单实例情形下的既有行为**（同 F06 验收 2）。
- 不做路由的可配置策略面（除 demand 明列的两条规则外，不新增第三、第四条路由规则）。

## 架构维度
