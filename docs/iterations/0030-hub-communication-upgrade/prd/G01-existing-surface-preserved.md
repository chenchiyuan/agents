# G01 · 既有面保持与范围守卫（**保证项**）

**来源**：demand.md 不做什么#1~#9；做什么#1（"SSE 广播保持现状，作体感加成，不承担送达责任"）；决策 D-20 / D-22 / D-24 / D-25 / D-30 / D-31 / D-32 / D-34 / D-35；事实 F-2 / F-4 / F-7

> **本卡不引入任何新能力**：它把 demand 已确认的既有面约束与"不做什么"变成一条可独立验收的载体（体例先例：0018 的 F14~F16、0028 的 F13、0029 的 G01）。

## 用户价值

这是**加法不是重写**——既有调用方、既有订阅方、既有控制台不因这次改动而行为变了，也没人被迫升级。

## 验收标准

1. **SSE 广播保持 best-effort**：既有订阅面的事件类集合与语义与迭代前**逐字一致**（不新增、不删减、不改含义）；广播仍是"在线才收到、不补发、不缓存"，且**不再**被当作送达的唯一路径（判据：迭代前后同一形态会话的事件类集合对比）[做#1；D-20]。
2. **`state` 词表与终态集合不变**：仍为既有四值（`submitted` / `working` / `completed` / `failed`），不新增第三个终态；取消仍落 `failed` [D-23；F04 验收 6]。
3. **既有 `error` 字段保留**：键位、拼写、取值形态（含既有文案）不变，不因本迭代被删除或改名 [D-23；F04 验收 5]。
4. **既有取件端点形状兼容**：`GET /api/pickup` 与 `POST /api/pickup/:call_id/ack` 的既有参数、响应结构与既有语义不破坏（变的是"何时写入"的触发条件，不是端点契约）；既有确认语义（确认后不再出现在未取件集合）保持 [事实 F-2；做#1]。
5. **不做 Router 任务表全面持久化**：Router 任务表仍纯内存、重启即丢，继续以既有"产物为权威"兜底 [不做什么#1；D-22]。
6. **不做产物核实机制**：不引入产物清单 / 产物校验字段，不做 hub 侧核实 [不做什么#2；D-25]。
7. **不做隔离边界的协议层设计**：不改 UDS 路径与 worktree 隔离的协议约束（继续靠执行纪律规避）[不做什么#3；D-24]。
8. **不做实例生命周期管理与无状态负载均衡**：hub 不启停 / 不伸缩实例；池内路由保持同会话粘性 [不做什么#4 / #5；D-30 / D-31]。
9. **不修与本次决策集无关的既有缺陷**：`transcript` 1000 条前缀截断（HB-07 遗留）与惰性启动竞态（`completed` 但产物缺失，HB-03 遗留）均不在本迭代修 [不做什么#6 / #7]。
10. **不让既有使用者被迫升级**：不新增必填参数，不改变既有响应字段集与取值域；本迭代的新行为对新调用方是"默认获得"（缺省身份兜底即此设计），对旧调用方是"行为不变" [D-21；F02 验收 5]。
11. **绑定范围与角色定义约束**：只绑 `dev` / `verifier`；模型值不进 `roles/*/*.md`；`cluster.json` 的既有角色级绑定不动 [不做什么#8 / #9；D-34 / D-35；F08 验收 6]。
12. **无 `demand.md` 之外的新增功能点**：本迭代的规格面 = 本文件 `prd/` 下的卡片集合，无额外能力 [workflow-pb 阶段 2 推进条件]。

## 边界（不包含）

- **不把本卡当作"任何既有文件都不许改"**：本迭代**正是要**改运行时（送达写入点、超时判据、角色→实例路由、终态语义）；本卡只锁"既有**语义**不回归"。
- **不把既有未定项当作"必须保持"的语义**：终态语义正是 F04 要结构化的对象，本卡只锁"`state` 词表与 `error` 键位不变"。
- 不做既有面的重构 / 重命名 / 迁目录（只做加法与补线）。
- 不新增测试框架 / CI / 第三方依赖。
- 不修改 `demand.md`；不新增 `demand.md` 之外的功能点。
