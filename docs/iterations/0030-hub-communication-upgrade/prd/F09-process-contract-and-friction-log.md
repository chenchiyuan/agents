# F09 · 过程契约与摩擦搭置（**过程契约卡**）

**来源**：demand.md §执行方式约束#1 / #3 / #4 / #5 / #6；决策 D-33（本迭代执行通道 = 本地 subagent）；工作流规范 `roles/workflow-pb/workflow-pb.md`（§Brief 构建规则 / §阶段回退 / §文档路径协议）

> **本卡不引入任何新的产品能力**：它把 demand 已确认的**本迭代过程要求**变成可核查的证据面（体例先例：0028 的 F12、0029 的 F18）。

## 用户价值

"边改 hub 边不用 hub"这件事本身**可核对**——通道单一、每次派发有据可查、摩擦不丢；下一迭代不用回头采访就知道这次顺不顺。

## 验收标准

1. **通道单一**：阶段 2~6 的**全部角色派发**走**本地 subagent**（宿主 `task` 派发），brief 按 workflow-pb §Brief 构建规则**全文注入**角色定义；不出现"经 hub 派发"充当角色协作手段 [约束#1；D-33]。
2. **每次派发一行可核对记录**：迭代台账逐条含 角色 / 用途 / 通道 / 子 agent 自报模型 / 终态（与 F08 验收 4 为**同一张表**，不新起第二本账）[约束#3]。
3. **brief 形态可抽检**：任取一条派发记录，其时 brief 满足"角色定义全文注入 + 工作区地址字段显式给出"两条 [约束#1；workflow-pb §Brief 构建规则]。
4. **摩擦当场搭置**：使用中出现的摩擦与需求层问题逐条写入迭代目录 `deferred-demand-changes.md`，**不回退、不暂停**；每条三要素齐（问题 / 为什么判定为需求层面问题 / 本迭代如何处理）[约束#5；workflow-pb §阶段回退]。
5. **并发证据按 subagent 通道形态取证**：阶段 6 的并发真实执行证据以 **git 事实**为主（worktree 落点 / 分支时间窗 / 提交交错），**不要求** hub 调用记录作证据 [约束#4；0029 D-19 取证形态变更]。
6. **产物落点**：本迭代全部产物落在工作区 `docs/iterations/0030-hub-communication-upgrade/`（本文件与本目录即该约束的落实）[约束#6；workflow-pb §文档路径协议]。

## 边界（不包含）

- **不把摩擦搭置当作阻塞理由**：不因搭置而暂停、回退或改需求 [约束#5]。
- **不做过程度量的工具化采集 / 机械门禁**：台账人工记录即可（HB-10 已实测"纯文本启发式不足以判定证据合格"，不得作门禁）[HB-10 结论]。
- **不把 hub 当派发通道**：hub 在本迭代只作**被改造对象**与取证面 [约束#1]。
- **不新增产品能力**：本卡只约束过程证据形态，不产生新的运行时行为要求。
- **不改变既有 `status.md` / `history.md` 格式规范**（沿用 workflow-pb 与 `data/formats.md`，不在本迭代发明新格式）。
- 不把本卡当作"派发必须成功"的约束（失败与阻塞同样要留痕）。
