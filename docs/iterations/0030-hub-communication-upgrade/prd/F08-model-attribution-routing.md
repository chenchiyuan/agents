## 用户价值

这次执行的**每条派发都答得出"跑在哪个模型上"**——异源验证（gpt vs grok）不是写在文档里的意图，而是可当场核对的事实。

## 验收标准

1. **`dev` 派发模型可核对**：本迭代任何一次 `dev` 角色派发，其子 agent **自报**模型为 `openai/gpt-5.6-luna`（判据 = 子 agent 系统提示中的模型名，F-11 已实测该判据可用）[效果#6；D-34]。
2. **`verifier` 派发模型可核对**：任何一次 `verifier` 角色派发，其子 agent 自报模型为 `powerby/grok-4.6` [效果#6；D-34]。
3. **其余角色 = 当刻全局默认**：未绑定的角色派发时，自报模型**等于当刻的全局默认值**（判据口径见 MI-12：不写死某个模型名字符串）[效果#6；D-34]。
4. **逐条留证**：每次派发在迭代台账留一条记录，含"角色 / 用途 / 通道 / 子 agent 自报模型"（台账的其余列与形态由 F09 定义）[约束#3；效果#6 的验证方法]。
5. **硬约束不被违反**：模型值**不出现**在 `roles/*/*.md`（F-12：`tools/check-model-dispatch-protocol.sh` V-06 + CLR-MD-004）；角色文件只描述能力；模型值集中存放在**一处**（D-35 的"别名引用 + 集中存放"意图）[D-35；不做什么#9]。
6. **绑定清单与 0028 定案一致**：只有 `dev` / `verifier` 两个角色显式绑定，不新增其它角色的显式绑定 [D-34；不做什么#8]。
