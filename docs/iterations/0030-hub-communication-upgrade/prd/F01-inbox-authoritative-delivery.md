# F01 · 收件箱权威送达（全调用必达）

**来源**：demand.md 做什么#1（"把收件箱升格为唯一权威送达路径"）；§大概怎么做（送达）；决策 D-20；效果#1；事实 F-1（通知模型 = 广播给在线连接）/ F-2（`pickup` 是选择性的：只有传 `requester` 才写入）；HB-02（完成信号不可送达）

## 用户价值

派发出一个后台任务后，结果**不再取决于"当时有没有人在听"**——它一定落在属于我的收件箱里，等我回来取。

## 验收标准

1. **不订阅也能取到**：调用方以 `mode=background` 派发一次调用，**不建立任何订阅**、不保持在线，该调用到达终态后 ⇒ 该调用方仍能从取件面取到这次调用的终态结果 [做#1；效果#1]。
2. **送达与订阅无关**：同一批调用分两组对照（有在线订阅 / 无任何订阅）⇒ 两组在取件面上的结果**集合与内容一致**（"有没有订阅者"不改变送达结果）[D-20："两者并行、互不依赖"]。
3. **写入是必然的而非选择性的**：任一 `mode=background` 调用，只要存在一个可确定的身份（显式声明或缺省派生，见 F02），其终态**必然**出现在该身份的取件面上；不存在"因为没显式传 `requester` 所以取不到"的调用 [事实 F-2 现状：只有传 `requester` 的调用才写入]。
4. **只承载终态、每条终态恰一条**：同一 `call_id` 在取件面上至多出现一条条目；`submitted`/`working` 等非终态调用不出现（取件面不是过程流）[体例沿用 0029 F07 验收 4]。
5. **与既有调用面一致（不是第二真源）**：取件拿到的终态内容与既有调用面（`GET /api/calls/<id>`）的终态信封一致（不伪造正文、不做独立状态覆盖）[D-14 延续]。
6. **确认语义沿用既有**：`POST /api/pickup/:call_id/ack` 确认后该条目不再出现在"未取件"集合；重复确认不报错、无副作用 [既有面保持，见 G01 验收 4]。

## 边界（不包含）

- **不改 SSE 广播的语义与事件类**：广播仍是 best-effort 体感路径，本卡不让它承担送达责任，也不因本卡而改变既有 4 条推送面 [做#1；G01 验收 1]。
- **不承诺"事件不丢"、不做事件回放/补发**：晚订阅补发（HB-02 的 F04 项）不在本迭代，取件面也不承载过程事件 [HB-02；0029 D-16 同类边界]。
- **不做产物核实**：不判断"产物是否落盘"、不引入产物清单字段 [不做什么#2；D-25]。
- **不做鉴权**：取件不校验取件者是否有权取该条目（身份只是过滤键，不是权限体系）[体例沿用 0029 D-2]。
- **不新增第三个终态、不改 `state` 词表** [G01 验收 2；F04 边界]。
- **不做 Router 任务表持久化**：取件面之外的调用登记仍随进程重启即丢 [不做什么#1；D-22]。
- 不做取件面的分页/游标/归档/历史台账（集合天然有界；体例沿用 0029 A-06 的"不引入游标"）。

## 架构维度

**A-01（已填定，全文见 `architecture.md` §4 A-01）**

- **接入点 = 既有唯一终态发布点** `publishCallResult`（`src/web.js:2215`）：写入条件由 `call.requester !== null` 改为**无条件**（身份取 `call.principal`，见 A-02）；**不新增发布点、不新增第二终态源**。
- **取件条目字段** = `{call_id, principal, agent, chat_id, terminal_at, envelope}`（`envelope` = 该发布点产出的终态信封；`INSERT OR IGNORE` 幂等、不覆盖首条 ⇒ 验收 4「每条终态恰一条」由主键保证）。
- **索引与按身份过滤** = 表 `inbox(call_id PK, principal, agent, chat_id, terminal_at, envelope)` + 索引 `inbox(principal, terminal_at)`；读取 = `SELECT … WHERE principal = ? ORDER BY terminal_at ASC` ⇒ 取件面**不再逐条查 Router**（N 次 UDS 往返归零、且重启后可读）。
- **与既有调用面一致（验收 5）**：信封由**同一函数** `composeCallEnvelope` 在唯一写点产出并落库，取件面与 `GET /api/calls/<id>` 读同一份事实（终态后不可变）。
- 存储与清理形态见 A-09（F03 卡）；身份取值与派生见 A-02（F02 卡）。
