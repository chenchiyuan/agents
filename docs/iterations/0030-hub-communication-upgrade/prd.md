## 术语口径（均为本迭代内的读法，不构成本阶段的任何决策）

| 术语 | 本文件的读法 |
|---|---|
| **调用方（接入方）** | 接入 hub 的客户端：本机 CLI、编排器、控制台、本迭代的主 agent 自身。本迭代的"用户" |
| **身份（principal）** | 送达的目标身份：显式声明的 `requester`，或按 `chat_id` 派生的缺省身份（F02） |
| **权威路径 / 送达** | 终态结果**必然落进收件箱**、可被该身份随时取走；与"在线时被推送到"是两件事（D-20） |
| **best-effort** | 明示的不保证：SSE 广播"在线才收到、不补发、不缓存"，不承担送达责任 [D-20；事实 F-1] |
| **取件** | 调用方**主动取走**已终态的结果，并可确认（既有 `GET /api/pickup` + `ack` 面）[事实 F-2] |
| **终态** | 既有封闭词表中的 `completed` / `failed`；`submitted` / `working` 为非终态 [事实 F-4] |
| **失败原因（`reason`）** | 终态信封上的封闭枚举：`agent_error` / `cancelled_by_client` / `infra_error` / `timeout` / `rejected` [D-23] |
| **进展信号** | 该调用在执行期间产生的新事件（复用既有 `last_event_at` / `task.update` 口径）[D-26；事实 F-6] |
| **空闲判据 / 绝对安全网** | 距最后一次进展信号超过 10 分钟 ⇒ 判死；距开始超过 4 小时 ⇒ 判死（初值，可调）[D-26~D-28] |
| **池 / 池化** | 同一角色的**当前在线实例**集合；hub 只在池内路由，不启停实例 [D-30 / D-32] |
| **粘性路由** | 同一 `(chat_id, agent_id)` 组合固定复用同一实例，直至该实例不在线 [D-31] |
| **裸判定** | 不读内部状态、只看调用方可观测面的判定方式（本迭代全部效果条目的验收形态） |

## 本次迭代边界说明

### 包含

## 拆分理由（原子粒度判断）

**总原则：按「可独立出现的失败」拆卡；横切判据与保证项按「独立可被破坏的约束」单列。**

- **F01 与 F02 拆（权威送达 / 缺省身份兜底）**：① "终态必然写入收件箱"与 ② "没声明身份也能被写入"是两个独立失败面——写入路径可能只在显式 `requester` 时生效（① 部分成立、② 失败），也可能有了缺省身份却仍未改造写入触发条件（① 失败、② 成立）。载体不同：一个在终态发布路径，一个在调用面身份派生。**依据**：D-20 与 D-21 本身就是两条独立决策，事实 F-2 证明现状恰是"① 部分、② 缺失"。
- **F03 单立（持久化）**：它是"必达承诺是否依赖进程存活"这一独立失败面；与 F01 的写入触发条件互不蕴含（进程内必达成立、重启即丢，是现状可想象的最常见形态）。
- **F04 单立（终态语义）**：与 F05 同源于"失败可判别"，但载体是**信封字段形态**而非判死逻辑。"取消了却报 `context_crashed`"（事实 F-4 / HB-05）与"跑太久被砍"（HB-01）是两个独立可失败的缺口，故拆开；D-29 的归属见 §机制间的顺序张力。
- **F05 单立（超时判据）**：判据替换是可独立验收的行为面，且必须覆盖**全部**既有上限生效位置（F05 验收 7）——这是 HB-01 的直接修复面，不与语义卡合并。
- **F06 与 F07 拆（池化分流 / 池内路由）**：demand 效果#5 本身列了两条独立判定（"并发派发能被分散到不同实例"与"同一对话连续多轮仍固定同一实例"）。两卡可分别失败（池化无粘性 ⇒ 多轮漂移、上下文断裂；粘性无池化 ⇒ 无可路由对象），且交付单元不同（池成员判定 vs 路由决策表）。
- **F08 单立（模型归属）**：它是效果#6 的承载，判据是"子 agent 自报模型"，失败面（派发落在错误模型上）与 hub 运行时行为**完全独立**——送达/终态/超时/并发全对，派发仍可能跑在默认模型上。它同时是唯一带**已落盘搭置记录**（D-35 载体不可实现）的卡，必须单列以便在阶段 4→5 门被单独处理。
- **F09 单立（过程契约卡）**：来源是 §执行方式约束（过程要求），承载"通道单一 + 留证 + 搭置 + 取证形态"这一独立可被破坏的约束，体例沿用 0028 F12 / 0029 F18。
- **G01 单立（保证项）**：来源是 §不做什么 9 条 + 做#1 的"SSE 保持现状"。它锁"既有语义不回归 + 范围不膨胀"，与任何新能力的交付都不互相蕴含（新能力全对、既有面照样可能被改坏；也可能顺手加了 demand 之外的功能）。
- **未单立的项**：① §不做 9 条是边界而非交付物，落各卡边界与 G01 验收；② D-36（依据文档入库）是阶段 1 已完成的一次性动作，无独立验收面；③ 事实 F-3 / F-9 是根因旁证与动机，不构成功能点；④ HB-01 的三个备选（暴露 `timeout` / 可续做 / 剩余额度可见）与 HB-04 的可见性诉求**无 demand 条目**，按红线不立卡（见 §疑问 4）。
