# F14 · 自派发告警

**来源**：demand.md 做什么#3（"自派发告警"）；§大概怎么做（控制面："自派发**告警**（`warnings[]`）"）；决策 D-6（先告警放行，不硬拒）；效果#4；复盘 G-19（自派发互锁 24 分钟，全程无人知晓）

## 用户价值

**危险的派发当场看得见**——"把活派给自己的实例"这个已知会互锁的动作，在响应里立刻打上标记，不用等到半小时后才发现死锁。

## 验收标准

1. **当场可判定**：调用方对**其自身实例**派发一次调用 ⇒ 该次派发的响应中含告警集合（`warnings[]` 语义），且**调用照常派发**（不硬拒、不返回业务失败）[D-6 / 效果#4 的裸判定]。
2. **对照实验**：同一入参、仅把目标换成**非自身实例** ⇒ 该告警**不出现**（唯一变量 = 目标是否自身实例）[复盘 G-19 的对照设计]。
3. **告警内容可识别**：告警项能表达"这是自派发"这一含义（可与其它类型的告警区分）。
4. **批量派发可归属**：一次派发多项时，哪一项是自派发在响应中**可定位**（不是一整批一个笼统标记）。
5. **不改变任何执行语义**：除告警字段外，响应其余部分与无告警情形逐字相同；目标实例、队列、结果投递的行为不变。
6. **无告警时形态稳定**：不产生告警时，响应形态与既有形态保持兼容（不因新增告警字段而破坏既有消费方）[G01 验收 3]。

## 边界（不包含）

- **不做硬拒**：不阻断自派发、不要求调用方二次确认 [D-6]。
- 不做自派发的自动检测阻断 / 自动取消 / 自动改派。
- **不承诺"自派发不会死锁"**：本卡只提供"当场告警"这一个可判定信号——机制消除与可见性降低是两件事。
- 不做告警的持久化 / 告警历史 / 告警统计。
- 不做其它类型告警的定义（本卡只定义自派发这一类）。
- 不改变既有"派发失败"路径的既有行为（角色离线 / 不可寻址的既有结论不变）。

## 架构维度

**已回填 · A-11（完整契约见 `architecture.md` §4 A-11）**：判定口径 = `instanceIdForRole(body.agent) === normalize(该身份声明的 instance_id)`——"自身实例"由调用方**在身份上自述**（`POST /api/principals` 的 `instance_id`，注册一次即可），归一化复用 `role-binding` 的唯一映射（实例名或角色名都认）；**未声明 ⇒ 不推断、不告警**。告警承载 = `POST /api/calls` 响应**顶层** `warnings: [{index（请求项序）, call_id, kind:'self_dispatch', message}]` ⇒ 批量可逐项定位、类型可识别；**不进调用信封**（既有封闭键集不动）；**仅当请求携带 `requester` 时该键出现**（可为空数组），未携带 ⇒ 响应逐字与迭代前相同。放行不阻断（D-6）：除 `warnings` 外响应逐字相同。

## model_inferred

- **MI-8**（验收 1 的口径）：demand 只说"对执行者自身实例派发会当场出现告警"，未定义"自身实例"的判定口径。本卡按"**目标实例与调用方所归属 / 持有的实例为同一实例**"落卡（依据：G-19 的死锁成因正是"目标 = 调用者自己的那个单 daemon 实例"），技术判定留 A-11，等主 agent 确认。
