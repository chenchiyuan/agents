# F07 · 终态结果取件（离线 / 晚订阅也不丢结果）

**来源**：demand.md 做什么#1（"终态结果取件（离线/晚订阅也不丢结果）"）；§大概怎么做（结果取件）；决策 D-3 / D-4 / D-14；效果#1 / #5；事实 F-9（调用登记在内存）

## 用户价值

调用方**走开也能拿到结果**——不需要在等的时候一直挂着、不需要轮询、不需要写 watchdog；回来取一次就有。

## 验收标准

1. **离线也能拿到**：调用方派发一次调用后**断开**（不持有任何订阅）、该调用在其断开期间到达终态 ⇒ 调用方重新接入后，**通过取件面取到这次调用的终态结果**（无需在断开期间订阅，也无需回放）[D-11]。
2. **未取件不消失**：在保留窗内重复查询，未取件的终态结果**稳定地在**（多次查询结果一致），不因"当时没有订阅者"而丢失 [效果#5 / 事实 F-4：现状"无订阅者即丢、不缓存不排队不补发"]。
3. **取件后可确认且不重复**：对已取的条目做确认后，它不再出现在未取件集合中；**对同一条目重复确认不报错、不产生副作用** [口径见 MI-5]。
4. **只承载终态结果**：非终态调用**不出现**在未取件集合中（取件面不是过程流）[§大概怎么做"语义收窄"]。
5. **与权威源一致**：取件拿到的结果正文与该调用 `calls get` 的终态信封一致（取件面不是第二真源）；`calls get` 在调用登记存活期内始终可查 [D-14；口径差见报告疑问]。
6. **保留期 = 跟随状态寿命，重启即丢（明文）**：协议面写明"本面为内存实现，hub 重启即丢，不保证跨重启保留"；重启后按 D-14 以**产物与 DB**为准继续 [D-3 / D-4 / 不做什么#4]。

## 边界（不包含）

- **不做事件回放**：不承载过程事件；要看过程走既有转录面 [不做什么#1]。
- **不做持久化**：不为取件面新增存储，也不承诺跨重启保留未取件结果（明文不保证）。
- **不做推送**：取件是"取"，不是"送"；主动到达由订阅面（F03 / F04）承担。
- 不承诺"结果一定送达调用方"——本卡保证的是**可取**，不是**已收到**。
- 不改变 `calls get` 的既有语义与其既有"不存在"条件。
- 不做取件的批量清理策略 / 不做归档。

## 架构维度

**已回填 · A-06（完整契约见 `architecture.md` §4 A-06）**：取件 = **web 进程内存表**（新增 `oamp/src/pickup.js`，体例照 `src/inbox.js`；**只存指针，不存正文副本**），条目 = `{call_id, requester, agent, chat_id, terminal_at, acked}`。写入点 = 既有**唯一终态发布点** `publishCallResult`，且**仅当该调用携带 `requester`** 时写入。正文来源 = 读取时经既有 `router.task_get` + `composeCallEnvelope` **现算**（⇒ 取件面不是第二真源；Router 重启后任务不可得 ⇒ 以"已失效"结论呈现，不伪造正文）。未取件集合 = `GET /api/pickup?principal=&epoch=` 返回该身份 `acked=false` 的全部条目（逐条现算信封）；**不引入游标**（集合天然有界且小）。确认 = `POST /api/pickup/<call_id>/ack`，**幂等删除语义**（重复 / 不存在均 200、无副作用）。保留窗 = **跟随状态寿命**（进程内不淘汰、确认即移出、重启即丢，协议面明文；**不引入 TTL 淘汰**，否则"未取件不消失"失真）。
