# F05 · agent 实时状态投影（含队列可见）

**来源**：demand.md 做什么#1（"纳管 agent 的实时状态投影"）；做什么#3（"队列可见"）；§大概怎么做（实时 / 控制面：`agents` 增 `busy / current_call_id / queued / since`）；效果#3 / #6；决策 D-8；复盘 G-19（现状无队列可见面）

## 用户价值

一眼看穿**每个实例此刻在干什么、手上排了几个活**——不用猜、不用钻进实例日志，也不至于"派给自己的实例然后互锁 24 分钟还看不出来"。

## 验收标准

1. **四项投影齐备**：实例快照（`GET /api/agents` 的无参形态）每条实例在既有字段之外含四项：是否在跑（`busy`）、当前调用 id（`current_call_id`）、等待中的轮次数（`queued`）、当前轮次起始时刻（`since`）[语义口径见 MI-1]。
2. **空闲态可判定**：该实例当前无在跑轮次时 ⇒ `busy` 为否、`current_call_id` 为空、`queued` 为 0。
3. **在跑态可判定**：该实例正在执行一次调用时 ⇒ `busy` 为是，且 `current_call_id` 与 `calls get` 能查回的同一调用 id 一致（两处同源、不漂移）。
4. **队列深度可见**：对同一实例连续派发 N 次（N 的取值为该实例无法并行执行的次数，判据：在其仍在跑第一次时继续派发）⇒ 快照的 `queued` ≥ 1；随队列被消化，该值下降 [复盘 G-19：现状只有 `state`，无队列可见面]。
5. **变化可实时到达**：四项取值的变化通过实时订阅（F03 / F04）推送 —— 订阅者**不轮询**即可看到某实例"空闲 → 在跑 → 空闲"的跳变。
6. **既有字段语义不变**：既有 `state` / `last_heartbeat` / `role` / `session_id` 的既有取值与语义不被本卡改变 [G01 验收 3]。

## 边界（不包含）

- **不做队列调度策略**：顺序、优先级、并发上限是否合理不是本卡判据（本卡只要求"看得见"）。
- 不做历史队列统计、不做用量与开销类派生列（沿用既有裁剪边界）。
- 不做停滞判定与停滞告警（字段在 F06）。
- 不承担"重连中"三态可区分（F16）、不承担恢复判据（F15）。
- 不做实例的增删 / 注册 / 注销流程（层 B 既有租约机制不动）。

## 架构维度

**已回填 · A-04（完整契约见 `architecture.md` §4 A-04）**：四字段**服务端推导**（实例不回报），来源 = **两个既有 UDS 方法**（`router.status` + `router.task_list`）：`busy` = ∃ 该实例的在跑任务；`current_call_id` = **最近进入在跑**的那次调用（并行多项时取最近）；`queued` = 该实例 `submitted` 状态的任务数；`since` = 该在跑任务条目的**新增字段 `started_at`**（首次观察到 `working` 时写入；空闲 ⇒ `null`）。重算与推送**复用既有拓扑轮询 tick**（默认 2000ms，仅在有订阅者时运行）：四字段或 `connected` **有变化才发**一帧 `agent_state`，播种基线不发事件；`router.task_list` **仅在新面订有 `agent_state` 时**拉取（既有面零新增流量）。与既有 `state` 的关系：`state` 仍是租约状态、值域不变，四字段是追加的投影列、**不参与** `?state=` 过滤。

## model_inferred

- **MI-1**（验收 1 / 4 的口径）：demand 只列出四个字段名，未定义语义。本卡按"`since` = 当前在跑轮次的开始时刻（无在跑时为空）；`queued` = 已受理但尚未开始的等待轮次数（含被派发但还没轮上的）"落卡，等主 agent 确认。
