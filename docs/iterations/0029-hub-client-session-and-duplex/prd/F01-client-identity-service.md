# F01 · 客户端身份注册与查询（幂等、无租约）

**来源**：demand.md 做什么#1（"把'客户端会话'做成一等入口：身份（幂等、无租约）"）；§大概怎么做（身份）；决策 D-2 / D-12

## 用户价值

调用方（本机 CLI / 编排器 / 主 agent 自身）**注册一次就长期可寻址**——进程退出、断线、hub 重启之后身份还在，不需要每次交互重新协商、也不靠"必须一直在场"续命。

## 验收标准

1. **幂等 upsert**：同一个 `principal_id` 连续注册两次 ⇒ 两次都成功（不返回冲突错误），且两次返回的创建时刻一致 ⇒ 第二次没有生成第二个身份。
2. **无租约**：注册后调用方进程退出（不再发任何请求、不心跳）⇒ 该身份仍可被查询到，且**不因"未续租"被判失效或清除**（判据 = 隔一段足够长时间后查询仍返回该身份）。
3. **可查询且含最近一次交互时刻**：按 id 查询返回该身份，其中含"最近一次交互时刻"字段；同一身份再做一次交互后，该时刻前进 [口径见 MI-10]。
4. **重启后身份不变**：hub 重启后，调用方用同一 `principal_id` 再注册 ⇒ 得到同一身份（不产生第二个身份、不报错）⇒ 调用方**不改任何身份**即可继续派发与查询 [D-12 ①]。
5. **显式声明，不猜测**：身份只能由调用方显式声明产生；未声明身份的调用方不被推断出身份 [D-2 最小实现]。
6. 身份的存在**不改变**未使用身份的既有路径：不以身份接续的调用方行为与迭代前一致 [与 F02 验收 2 互为对照；G01]。

## 边界（不包含）

- **不做鉴权**：不做令牌 / 口令 / 签名，不校验声明者是否"真的是"该身份 [D-2 最小实现]。
- **不做租约 / 心跳 / 续期**：层 B 既有的 agent 租约语义不变，也不把租约机制引入客户端身份。
- 不做跨机 / 多 hub 联邦，不做身份的组织 / 层级 / 权限概念 [不做什么#2]。
- **不扩 harness**：不依赖 harness 导出会话 id，也不要求调用方提供会话 id [不做什么#5 / demand 事实 F-10]。
- 不承担"身份 ↔ 实例"的同一性判定（自派发判定见 F14，技术口径见 A-11）。
- 不做身份的注销 / 清理策略（保留期跟随状态寿命，见 F07 验收 5 的同一寿命口径）。

## 架构维度

**已回填 · A-01（完整契约见 `architecture.md` §4 A-01）**：身份 = **web 进程内存表**（新增 `oamp/src/principals.js`，体例逐条照既有 `src/inbox.js`：无 TTL、无定时器、不落库 ⇒ 与既有状态表同寿命），幂等键 = `principal_id`（调用方自述；形态校验复用 `registry.isValidInstanceId` 的规则）。字段最小集 = `{principal_id, kind, instance_id, created_at, last_seen_at}`——`kind` 为自述类别（不校验取值域）；`instance_id` 为**可选**的"所归属实例"声明，唯一消费者是 F14 的自派发判定（**本卡不判定、不校验、不据此拒绝**）；"最近一次交互时刻"在该身份**任一被受理的请求**上（注册 / 查询 / 订阅 / 派发 / 取件 / 确认）前移，创建时与 `created_at` 同值。**"身份来源可替换的一层"** = 单一接缝函数 `requesterOf(source) → {principal_id, kind, instance_id} | null`（今天只读显式声明；将来换 harness 导出会话 id / 令牌只替换它，调用面与身份面零改动）。

## model_inferred

- **MI-10**（验收 3 的口径）：demand 只给出 `{principal_id, kind}` 与"含最近一次交互时刻"，未定义 `kind` 的取值口径与"最近一次交互"的更新时机。本卡按"`kind` 为调用方自述的会话类别（最小实现不校验）；最近一次交互时刻 = 该身份最近一次参与交互的时刻，无交互时为空"落卡，等主 agent 确认。
