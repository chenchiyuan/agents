# F15 · 恢复判据（health 三问）

**来源**：demand.md 做什么#3（"恢复判据（`health`）"）；§大概怎么做（恢复："`GET /api/health`（router / web / agents 三项判据）"）；决策 D-12；效果#6；复盘 G-18（"exit 0 但事实没做"的静默不生效）

## 用户价值

**"系统到底恢复没有"有一句话的答案**——不用逐个试探、也不用凭"命令没报错"推断；判据说可以，就可以。

## 验收标准

1. **一次调用回答三问**：存在一个判据入口（既有的自检入口或新增判据入口），**一次调用**即可回答 ① router 起没起 ② web 起没起 ③ 有几个 agent 在线（含重连中）[效果#6 的裸判定]。
2. **第三问可拆分读**：在线实例数与重连中实例数**分别可读**，不是一个合成数 [效果#6 "含重连中"]。
3. **判据可判失败**：router 未起 / web 未起时，对应项给出**明确的不可用结论**与可核对的原始原因——**不出现"调用成功但事实没做"的静默结论** [复盘 G-18 家族；D-8]。
4. **重启后转绿 = 恢复达成**：hub 重启（软重启：仅重启 hub 保留 agent 进程 / 硬重启：整体重建）后，三问转绿，且此时调用方**不修改任何身份**即可继续派发与查询，并能**成功完成一次调用** [D-12 ③ / P-G 验收]。
5. **可被发现**：判据入口的存在与字段可通过 F17 在文档面被发现（无需读源码）。

## 边界（不包含）

- **不做自动恢复 / 自动重启 / 自愈**：判据只回答状态，不触发动作。
- 不做历史可用性统计 / 不做 SLA / 不做告警推送。
- 不做后台轮询式健康守护进程（判据按需调用）。
- 不承担 agent 重连本身（F16）与身份可续（F01）。
- 不改变既有自检入口的既有检查项语义（本卡为加法：新增三问或补全其可判定性）[G01]。

## 架构维度

**已回填 · A-12（完整契约见 `architecture.md` §4 A-12）**：判据源 = ① `router`：一次 `router.status` 是否成功（失败给原始原因，含 socket 路径）；② `web`：本进程在监听（由响应本身证明）+ **持久层一次轻查询可读**；③ `agents`：同一次 `router.status` 节点集合派生的 `online` / `reconnecting`（`state='online' && !connected`）/ `offline` **三个数分别可读**。入口 = **新增 `GET /api/health`**，与既有自检入口 `hub doctor` **并存不合并**（前者是状态判据、后者是契约自检，合并互相耦合；doctor 行为逐字不变）。**"可调用"的达成口径** = 响应顶层 `callable = router.ok && web.ok && agents.online ≥ 1`（派发通路可用且有可寻址在线实例）；**判据本身不发起真实调用**（只读、零副作用）。任一项失败 ⇒ `ok:false` + `detail` 原始原因（不出现"调用成功但事实没做"的静默结论）；Router 不可达仍 200（唯一特例，它的职责就是回答"router 起没起"）。
