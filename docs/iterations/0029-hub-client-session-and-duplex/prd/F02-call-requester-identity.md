# F02 · 调用的请求方身份（缺省行为不变）

**来源**：demand.md 做什么#1（"发起调用"与"终态结果取件"之间的归属）；§大概怎么做（结果取件：`POST /api/calls` 增 `requester`）；决策 D-2 / D-14；事实 F-1（`from` 由 Router 用投递连接代填，调用面调用的 `from` 恒为 `'web'`）

## 用户价值

调用方派发出去的任务，**结果认得回来的路**——不再是"结果只回到那个常驻身份（web）"，而是回到发起它的那个身份。

## 验收标准

1. **结果归属可判定**：调用方以已注册身份派发一次调用 ⇒ 该调用在调用面**归属于该调用方**：该调用终态后，该身份从其取件面（F07）取到这条结果；**另一身份取件时取不到它**（对照实验，唯一变量 = 取件身份）。
2. **不传请求方身份时行为与今天逐字一致**：以同一入参做两组对照（带身份 / 不带身份）——不带身份那一组的响应字段集与取值域和迭代前逐字相同，且既有调用面归属与既有对话侧行为不变 [demand 明文要求；G01 验收 3]。
3. **归属在终态前后都成立**：派发时声明身份即可，**取件时不需要再次声明目标调用**（调用方不必自己维护"我发过哪些 id"）[根因：结果投递缺"投递给一个可寻址的身份"这一方向]。
4. 携带未注册的 id 直接派发：**不阻断派发**（最小实现不做鉴权），其行为按 MI-3 的口径处理 [D-2]。
5. 归属信息**不改变调用信封**：既有 10 键封闭信封不因本卡增减（归属走调用面 / 取件面，不进信封）[不做什么#3；G01 验收 2]。

## 边界（不包含）

- 不做鉴权 / 不做身份与目标实例的同一性校验（唯一相关动作是 F14 的自派发告警）。
- 不改变既有 CLI 与既有对话入口的派发行为（显式声明身份才走本卡路径）。
- 不承担"结果不丢"本身——本卡只保证**归属**；"离线也能拿到"是 F07，"终态即退出"是 F09 / F10。
- 不做调用的重放 / 重派 / 幂等去重。

## 架构维度

**已回填 · A-02（完整契约见 `architecture.md` §4 A-02）**：`requester` = `POST /api/calls` 的**可选标量**（`principal_id` 字符串）；未注册的 id ⇒ 按需幂等 upsert（不阻断）。传递路径 = 请求 → `requesterOf()` → web 侧调用登记（`entry.call.requester`，与既有 `tasks` / `callSchemas` 同寿命）→ 终态写入未取件指针 → 取件面按 principal 过滤。**不进 UDS 信封**（Router 的 `from` 仍由投递连接代填 `'web'`，既有"禁止自报 from"约束不动）。**既有归属判定的落点逐字保留**：`GET /api/calls` 的 `from === 'web'` 范围收口回答"是不是本 hub 派的"，本次新增的归属回答"是谁派的"，落点在取件面的 principal 键——两者并存、语义不相交、互不改写。缺省（不传 `requester`）⇒ 既有路径与响应逐字不变。

## model_inferred

- **MI-3**（验收 4 的口径）：demand 只说身份是"显式声明、幂等 upsert、不鉴权"，未定义**携带一个从未注册过的 id** 派发时的行为。本卡按"不阻断派发（幂等 upsert 语义下按需建立，或按既有路径记录但不校验）"落卡，等主 agent 确认：是否允许未注册 id 直接参与归属。
