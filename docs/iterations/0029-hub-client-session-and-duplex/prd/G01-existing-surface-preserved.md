# G01 · 既有面语义保持（**保证项**）

**来源**：demand.md §不做什么 #1 / #3 / #5 / #6；§大概怎么做（"仅做加法与补线，避免控制台行为回归"）；决策 D-2 / D-5

> **本卡不引入任何新能力**：它把 demand 已确认的既有面约束变成一条可独立验收的载体（体例先例：0018 的 F14~F16、0028 的 F13）。

## 用户价值

这次是**加法**不是重写——既有控制台、既有订阅方、既有调用面的使用者不会因为这次改动而行为变了、也没人被迫升级。

## 验收标准

1. **4 条既有推送面的事件语义保持**：按对话订阅 / 全局订阅 / 对话作用域调用订阅 / 按调用订阅四条面，在一次典型会话（订阅 → 派发 → 增量 → 终态）中其上出现的事件**类别与语义与此前逐字一致**（不新增、不删减、不改含义）。**判定方式**：迭代前后各跑一次同形态会话，比对面上的事件类集合 [不做什么#6]。
2. **不新增终态、不动调用信封键集**：`state` 封闭词表仍为既有四值（取消复用 `failed` + `error`，见 F13）；既有调用信封的键集合**不增不减** —— 本次新增的信息走独立字段（如快照行）与独立端点，**不进信封** [不做什么#3；事实：既有信封是封闭键集]。
3. **既有窗口契约不变**：既有错误响应形态（`{error, code}`）与既有错误文案不变；既有端点的既有参数语义不变（含既有实例状态过滤参数、既有调用 roster 的既有列）。
4. **不扩 harness、不依赖外部改造**：本迭代的全部验收在**既有环境**（harness 未导出会话身份）下成立；"身份来源可替换的一层"是留出的扩展点，**不是**本迭代的前置依赖 [D-2 / 不做什么#5 / 事实 F-10]。
5. **控制台不回归**：既有控制台所用的四条推送面与既有 JSON 契约不因新增面而改变；新增面在"启用 / 未启用"两种使用情形下，既有面行为一致（加法而非替换）。
6. **不做被否决的事**：不引入鉴权体系、不做跨机 / 多 hub 联邦、不做持久事件日志与回放、不把"hub 记忆"当恢复依据 [不做什么#1 / #2 / #4]。

## 边界（不包含）

- **不把本卡当作"任何既有文件都不许改"的约束**：本迭代**正是要**改运行时（P-A~P-G 全部机制）；本卡只锁"既有**语义**不回归"。
- 不修复与本迭代无关的既有缺陷（例如既有已实现能力未被 skill 暴露 [事实 F-8] —— 只登记，见 F18）。
- 不做既有面的重构 / 重命名 / 迁目录（只做加法与补线）。
- 不新增测试框架 / CI / 第三方依赖——本迭代的验收由证据承担（体例沿用 0028/0025）。
- 不把既有未定项（如既有等待语义未统一，事实 F-6）当作"必须保持"的语义：那正是 F11 / F12 要统一的对象。

## 架构维度

无待填项（本卡是对既有事实的冻结，不涉及技术选型 / 数据模型 / 接口设计）。
