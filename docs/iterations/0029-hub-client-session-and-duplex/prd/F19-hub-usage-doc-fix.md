# F19 · hub 使用面文档修复（暴露现成等待原语）

**来源**：demand.md 决策 **D-17**（prd 阶段反馈驱动升格，2026-09-16 用户裁决）；澄清依据**事实 F-8**（"既有 skill 未教已存在的等待原语"）；**D-13**（"像使用 subagent 一样使用 hub"的体感目标）

> 先例：事实 **F-7** 已实测 `oamp task watch` 与 `--mode block` 都是现成原语，只是文档没教。

## 用户价值

**下次用 hub 时不用翻源码就知道等待原语早就存在**——文档面直接给出「派发 → 等待 → 取件」的现成路径，而不是让人自己拼轮询。

## 验收标准

1. **两条现成原语都在文档面**（裸判定）：使用面文档 `oamp/skill/hub.md` 中**同时**出现 `--mode block` 与 `cli task watch` 两条现成等待路径，且各自说明适用场景（何时用哪条）。
2. **默认路径不再是轮询**：文档中「派发后如何拿结果」的主推路径为上述现成原语；轮询（`calls get` + sleep）降为兜底说明。
3. **只改表述不改能力**：本卡不新增任何 CLI / API 能力；若文档所述与实际行为不符，**按实际行为修正文档**（权威归属见 D-14）。

## 边界

- 不改变 hub 任何接口行为、不改事件语义、不改既有 4 条推送面（不做什么#6）。
- 不新立文档体系：体例沿用既有 skill 文档结构。

## 架构维度

**无**（纯文档表述修复，不涉及技术选型）。若阶段 3 判定文档面需与 F17 的元数据面联动，由阶段 3 记录。
