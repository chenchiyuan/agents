# F11 · 一次调用即返回的等待入口

**来源**：demand.md 做什么#2（"提供一次调用即返回的等待入口"）；§大概怎么做（等待：`GET /api/calls/wait?ids=…&timeout_ms=…`，全部终态才返回）；效果#1；事实 F-6 / F-7（既有等待原语的语义未统一）

## 用户价值

**一次调用就等到底**——调用方不必自己拼订阅、拼轮询、拼超时，一个请求返回时就带着结论。

## 验收标准

1. **一次调用等一批**：调用方发起一个等待请求（可携带多个调用 id）⇒ 返回体含**每个**调用各自的终态信封。
2. **退出条件 = 全部终态**：若其中一个调用先终态、另一个仍在跑 ⇒ 等待**不提前返回**；两者都终态当刻返回（秒级，不依赖超时值）。
3. **结果可对应**：返回体中的结果可按 id 对应回请求的 id，且每条与该调用 `calls get` 的信封一致。
4. **已终态立即返回**：请求中包含已终态的调用 ⇒ 其结论**立即**可得，不因等待其它调用而推迟该条的可见性，也不等到超时才返回 [与 F10 同一幂等口径]。
5. **可带时间上限，且上限语义正确**：到达上限时的行为按 F12 —— **超时只表示放弃等待，不改变任何调用的状态**。
6. **两种返回可区分**：调用方能判定"全部终态返回"与"超时放弃返回"两种情形（不得只靠"没有结果"来推断）[口径见 MI-6]。

## 边界（不包含）

- **不引入新的等待语义**：本卡只是"以终态为退出条件"的一次调用形态，不新增失败判定。
- 不做过程流展示（要看中间过程走订阅面或既有转录面）。
- 不改变既有 `--mode block` 与既有 CLI 等待命令的语义（既有面归 G01）。
- 不做服务端替调用方重试 / 自动续等 / 自动改派。
- 不做等待的排队与配额。
- 不承担多 hub / 跨机调用的等待聚合。

## 架构维度

**已回填 · A-09（完整契约见 `architecture.md` §4 A-09）**：实现形态 = **服务端挂起**（`GET /api/calls/wait?ids=&timeout_ms=`），**不是**客户端多路订阅聚合：入口逐 id 读一次 `router.task_get`（不存在 ⇒ 立即记入 `unresolved` 的 `state:null`，不等待；已终态 ⇒ 立即得信封），未终态 ⇒ 登记等待句柄，**句柄由既有唯一终态发布点释放**（与既有 `mode:block` 的 `call.resolve` 同构），本进程无登记的 id 由**既有对账兜底**复查覆盖 ⇒ 退出判据恒为终态。返回形态 = `{timed_out, timeout_ms, results[], unresolved[]}`：`results` 每条含 `call_id`（可对应回请求、与 `calls get` 同形状）；`unresolved` 的 `state` = 当刻状态（`null` = 不存在）；**`timed_out`（布尔）为唯一退出原因字段** ⇒ "全部终态"与"超时放弃"可判定地区分（MI-6）。`timeout_ms` 可选正整数，**缺省 = 不设上限**（与 `mode:block` 的"不设人为上限"同口径）；客户端 `--wait` 预算是**放弃等待的预算**，不是语义上限。

## model_inferred

- **MI-6**（验收 6 的口径）：demand 只规定"超时只表示放弃等待、不改变任务状态、不产生失败结论"，未规定调用方如何**区分**这两种返回。本卡要求存在可判定的区分方式（例如返回形态 / 状态字段 / 退出码语义的区别），具体形态留 A-09，等主 agent 确认该判据要求成立。
