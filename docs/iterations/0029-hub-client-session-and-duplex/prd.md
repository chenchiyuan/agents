## 术语口径（均为本迭代内的读法，不构成本阶段的任何决策）

| 术语 | 本文件的读法 |
|---|---|
| **调用方（接入方）** | 接入 hub 的客户端：本机 CLI、编排器、控制台、主 agent 自身。本迭代的"用户" |
| **客户端会话** | 调用方在 hub 上的一等身份：可寻址、可续接，区别于"每次交互换一个进程"的既有一致性缺口（事实 F-1 / F-2） |
| **终态** | 既有封闭词表中的 `completed` / `failed`；`submitted` / `working` 为非终态（事实：既有信封与 roster 同真源） |
| **取件** | 调用方**主动取走**已终态的结论；与"被推送"是两件事（推送 = F03 / F04） |
| **续接** | **重建视图 + 继续调度**，不是事件回放（D-11） |
| **一轮快照** | 用最少次数的查询回答"当前进度与状态"的字段面（实例快照 + 调用快照） |
| **best-effort** | 明示的不保证：不保证不丢 / 不保证不重 / 不承诺回放（D-10） |
| **等待** | 以**终态为退出条件**的阻塞或订阅-退出；超时只表示放弃等待 |
| **自身实例** | 与调用方归属同一执行实例的 agent 实例（口径见 MI-8，技术判定留 A-11） |

## 本次迭代边界说明

### 包含

- **身份与归属**（F01、F02）：客户端身份的幂等注册与查询；派发侧携带请求方身份，且不携带时既有行为逐字不变。

## 拆分理由（原子粒度判断）

**总原则：按「可独立出现的失败」拆卡；横切判据与保证项按「独立可被破坏的约束」单列。**

- **F01 与 F02 拆（身份服务 / 请求方身份）**：① 身份可注册可查询 ≠ ② 派发把身份带上。前者失败（身份带租约、重连后变了）与后者失败（派发不带身份、结果仍回常驻身份）互不蕴含，载体也不同（一个在身份面，一个在调用面与取件面的归属）。
- **F03 与 F04 拆（两个订阅形态）**：**有 HTTP 订阅但长连接面没有订阅入口**是一个可独立出现、可独立交付的缺口（demand 事实 F-2 已核实层 B 现有 8 条方法中无订阅入口）。二者共享受约语义，但交付单元与失败面独立。
- **F05 与 F06 拆（实例投影 / 调用进展）**：**"看得见实例手上有几个活"与"分得清一次调用是卡死还是长跑"是两个不同对象的字段面**，失败互不蕴含（队列深度可见 ≠ 停滞可区分）。
- **F07 与 F08 拆（取件 / 续接）**：取件是"结果可取"，续接是"视图可重建 + 可继续调度"。二者的判据不同（一条结果 vs 一轮快照四问），失败互不蕴含。
- **断线拉起的"两查可回答四问"并入 F08 而非单立卡**：若单立，其失败面被 F05 / F06 完全蕴含（字段齐了则四问必能答），不构成独立可交付单元；而**"续接契约"本身**（代次校验 + 固定流程 + 断开不产生结论性错误）才是独立失败面。故合为 F08 一张卡，验收 2 是它的裸判定。
- **F09 / F10 / F11 / F12 拆四张（等待）**：四种独立失败 —— ① 先订阅后终态不退出（现状 7 个等待作业靠超时交付）② 先终态后订阅静默永久挂起 ③ 没有"一次调用式"的等待入口 ④ 语义未统一（超时被当成失败结论）。①②③ 的判定场景互不覆盖，④ 是**契约面**（条文可读 + 反向验证），与前三者的行为面不同类。
- **F13 与 F14 拆（取消 / 自派发告警）**：G-19 暴露的正是两个独立失败 —— 互锁发生了却**无法解除**（取消缺失），以及互锁正在发生却**无人知晓**（告警缺失）。前者是状态面动作，后者是派发响应面的信号。
- **F15 与 F16 拆（判据入口 / 三态可区分）**：① 没有判据入口 ⇒ 无法回答"恢复没有"；② 状态取值不足以区分"正在重连" ⇒ 客户端把重连误判为死亡。二者可分别失败（有判据但读数不区分；读数能区分但没有判据入口）。
- **F17 单立（可发现性）**：它是**横切判据**（"存在一条新增能力未被投影 ⇒ 失败"），与各卡行为正确性正交 —— 端点全都工作、但文档面上找不到，是独立且真实的失败。
- **F18 单立（过程契约卡）**：来源是 §执行方式约束（过程要求），承载"D-13 体感目标被度量、摩擦被留痕"这一独立可被破坏的约束，体例沿用 0028 的 F12。
- **G01 单立（保证项）**：来源是 §不做什么 #1/#3/#5/#6 与"仅做加法与补线"。它锁的是"既有语义不回归"，与任何新能力的交付都不互相蕴含（新能力全对、既有面照样可能被改坏）。
- **未单立的项**：① §不做什么 6 条是边界而非交付物，落各卡边界与 G01 验收；② D-9（完整闭环）是落地切分决策，不产生独立验收面；③ §执行方式约束 4 是流程要求，由 F18 与本文件落点承载；④ 各卡引用的既有事实（F-1~F-10）是现状依据，不是功能点。
