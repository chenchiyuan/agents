# F05 · 测试协议 · 阶段 5 零测试态验收判据

**来源**：demand.md 做什么 W-3 第 4 条前半；结论 Q13；§5 影响面表第 4 行；§3「大概怎么做」（阶段 5 降级为逐条裸判定 + 机械判据）

## 用户价值

测试资产清零之后，"该 PR 验收标准全部通过"这条推进条件仍然可判定——主 agent 不会因为"没有套件可跑"而把验收降级成主观感觉，也不会去等一个已经不存在的"套件全绿"信号。

## 验收标准

1. 协议中明确回答：零测试（无保留用例）状态下，阶段 5 推进条件「该 PR 验收标准全部通过」靠什么判定——给出可执行的判定动作（逐条对照该 PR 的验收标准，用裸判定 + 机械判据取证），并明确"套件全绿"不再作为判据。
2. 该判据在零测试的实际状态下可执行：不依赖任何测试文件存在，也不要求"临时补写测试"这类与零测试交付相冲突的动作。
3. 协议不改动阶段 5 推进条件的文字本身（文字改动归 F02 的范围），只补"怎么判"。
4. 该约束带 `判断方式：…`（形态见 [F08](F08-protocol-judgeable-constraints.md)）：拿一次实际派发的验收过程，能判定它是否按该口径判定。

## 边界（不包含）

- 不含阶段 6 的独立取证方式（→ F06）。
- 不改阶段 5 推进条件所列的三项内容（验收标准全部通过 / 无简报外改动 / 对应 PR 文件存在）。
- 不定义 PR 验收标准本身的写法（属阶段 4 的 PR 文件格式规范，已在 `roles/workflow-pb/data/formats.md` 定义）。
- 不定义协议承载形态（§7 `user_deferred`，见 F08 边界）。
