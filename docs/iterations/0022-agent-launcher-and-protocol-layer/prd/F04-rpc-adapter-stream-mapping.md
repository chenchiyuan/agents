## 用户价值

默认链路换成 rpc 之后，agent 的文本、思考、工具运行都能被 hub 拿到——不再是"只看得到最终结果"。

## 验收标准

1. **三类增量在管道面被承接，不被丢弃**（W3 / F3）：rpc 链路下，**hub 与 omp 进程之间流动的数据**里带上三类增量——**(1) 思考片段**、**(2) 工具调用参数（边生成边流出）**、**(3) 工具执行中的输出**；三类都数得到即通过。
   *判定*：默认链路跑一轮带思考与工具调用的对话 → **在能看见 hub 与 omp 进程之间流动数据的地方逐类数**（**验收时不看浏览器 / 控制台界面**）→ **三类齐即过**（对照 acp 今天思考被丢弃的基线）。 〔`[user_confirmed MI-01]`：本卡的判据面 = **管道面**（hub ↔ omp 之间流动的数据）；**本卡判据不得并进 F08**——"界面有没有把它画出来"由 F08 在界面面判〕
2. **轮次结束以终态事件为准**（W3 / F2）：一轮结束的判据是**终态事件**；"受理"回包仅表示已接收，**不得**被判为轮次结束。
   *判定*：起一轮 → 受理回包到达后轮次**并不**被判为结束；终态事件到达才判为结束。
3. **rpc 面上的审批门可被承接**（W3 / F6）：rpc 链路下的工具审批门请求被承接（进一步映射到既有确认面 → F05）。
   *判定*：触发一次受门禁调用 → 该请求到达内部会话语义面，不被丢弃、不被静默放行。
4. **证据形态：真实进程，非 fake 桩**（E6 / A3/P6）：F04 的验收证据必须来自**真实 omp rpc 链路端到端一条**。
   *判定*：核对验收证据的产出对象 → 是真实进程（非 fake 桩）；证据的产出与核查时机属阶段 5 / 6。

## 边界（不包含）

- 不含权限门到既有确认面的映射与呈现（→ F05）。
- 不含过程增量的控制台展示与不入库核查（→ F08）——`[user_confirmed MI-01]`：界面面的判据归 F08，与本卡管道面判据**不重叠**
- 不含 rpc 协议面本身的改造（N2：**不改 omp / harness 源码与协议**）——RPC 所需能力经实测已具备（F1~F6），本迭代只消费既有能力。
- 不含 RPC 会话模型 / 取消与超时语义 / argv 面完整性 / 宿主工具面的**实测**（→ 移交阶段 3 承接项 M-1~M-5，需求级前置 = M7）。

- 不含 `steer`（运行中插话）的产品功能（N6 → F09 验收 4）。
- 不含 acp 链路的思考 / 工具输出增量（N12 → F06）。
