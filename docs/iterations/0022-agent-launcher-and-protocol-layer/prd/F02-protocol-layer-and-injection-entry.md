## 用户价值

走哪个协议由一处配置说了算——默认是 rpc，想退回 acp 兜底就改那一处；不用翻遍代码找"协议写在哪"。

## 验收标准

1. **标准被写定 + 协议指定的入口唯一，且落在配置面**（W2 / M2 / A2）：**由统一服务定义的协议 / 标准**在这一层被写定——会话语义接口（开会话 / 提示 / 取消 / 关闭 + **三类增量** + **两类反向请求** + **能力位**）作为标准，**方法面按这份标准表达**、不散落在各调用点；协议指定的入口只有**一处**；解析链 = **角色级配置 > 全局默认 > 内置 `rpc`**。
   *判定*：查该层 → 能指出**这份被写定的标准本身**（会话动作面 + 三类增量 + 两类反向请求 + 能力位，四类内容都在其中）；再查配置面 → 协议指定只有一处入口；逐档改取值起会话 → 生效结果依次覆盖（角色级覆盖全局、全局覆盖内置）。 〔`[user_confirmed MI-02]`：用户原话口径「有统一的服务管理启动agent这件事情，定义协议/标准，抽象方法和工具使用」；标准的签名形态与入口落点见 T-04 / T-03〕
2. **默认走 rpc**（E1 / J2 / A2 / U-1）：**默认配置**（不做任何协议指定）下起一轮对话，被启动的 omp 进程走 **rpc 模式**。
   *判定*：观察进程 argv（或既有 argv 日志）→ 含 rpc 模式参数即真。
3. **选择域封闭**（M2 / 登记①）：该入口的可选取值域 = 常驻会话协议 **`rpc` / `acp` 二选一**；**`oneshot` 不在该选择域内**（它由「一次性」语义选中，与常驻协议并存，不是"三选一"）。
   *判定*：读该入口的可选值 → 恰为 {`rpc`, `acp`}，不含 `oneshot`。
4. **不做动态切换、不做按对话 / 按请求指定、不做控制台可切**（N3 / A2）：不做同对话内的协议切换、不做 per-chat / per-request 协议指定、控制台**无**协议切换入口。
   *判定*：查控制台与接口面 → 无协议切换入口；无按对话 / 按请求的协议指定参数。
5. **可切回 acp 兜底，且切换即新会话**（J2 / N9）：改注入配置为 acp 后，该轮确实走 acp；切换是**下一次会话**的配置改变，**在飞上下文不迁移**（沿用既有「上下文已重置」提示语义）。
   *判定*：改注入配置为 acp → 起一轮确认走 acp；已有会话不被续接为新协议，界面出现既有上下文重置提示。

## 边界（不包含）

- 不含协议实现本身（→ F04 rpc / F06 acp / F07 oneshot）。
- 不含「指定即生效」「消费层不自行构造 / 选择」「切换零 diff」的契约判据（→ F03）。
- 不含协议能力位的声明机制（→ F09）。
- 不含 per-chat / per-request 指定与控制台可切（N3）。
- 不含协议切换时的在飞上下文迁移（N9）。
- 不含协议指定入口的具体落点与配置载体形态（→ T-03）。
- 不含那份被写定的标准的**签名形态**（会话动作面与两类增量 / 反向请求回调的接口签名 → T-04；本卡只判"标准被写定、方法面按它表达"）。
- 不含 omp / harness 侧源码与协议改动（N2 → F11）。
