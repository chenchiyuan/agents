## 用户价值

真要退回老链路，之前能干的事一样能干——确认栏、通知、对话状态都不变；这次不指望它多出什么新能力。

## 验收标准

1. **既有行为不退化**（W5 / E5 / F19）：注入配置切回 acp 后，既有行为与 0021 之后**一致**——确认收件箱 **7 字段语义**、**三事件通知**（`chat_completed` / `chat_failed` / `confirmation_required`）、消息与状态流转均不变。
   *判定*：按 0021 既有验收**同法复核一遍** → 结果一致。
2. **不补思考 / 工具输出增量**（N12 / A4）：acp 链路**不新增**思考与工具输出增量；该差异以能力位**显式声明**（`thinking=false`）。
   *判定*：acp 链路跑一轮 → **无思考增量不算失败**（该能力位已声明 false）；同时不得出现"声明具备但实际缺失"。
3. **可切回**（J2 / W2）：注入配置可切回 acp 兜底，且被指定的实现确实生效（不回落默认）。
   *判定*：改注入配置为 acp → 该轮确实走 acp 实现（与 F03 验收 1 同法复核）。
4. **证据形态：既有链路回归一条**（E6 / A3/P6）：acp 兜底链路的验收证据 = **既有链路回归一条**（真实进程）。
   *判定*：核对验收证据的产出对象 → 真实进程的回归证据可查；证据的产出与核查时机属阶段 5 / 6。
