## 用户价值

已经实现好的协议，只要被指定就一定生效（不会"配了却没走"）；换协议只动一处注入配置，消费层的代码一个字不用改。

## 验收标准

1. **D-1 注入点决定实现（指定即生效，硬要求）**：协议实现的选取发生在且仅发生在**注入点**（注入配置 / 解析链）；通讯层**实际使用的实现 = 注入点给出的实现**，**不回落到内置默认**。
   *判定*：向注入点指定 `acp`（已实现）起一轮 → 该轮确实走 acp 实现；指定 `rpc` → 确实走 rpc。**指定后仍走内置默认即为不通过。**
2. **D-2 消费层不自行构造 / 选择**：`src/` 中协议层（协议实现与注入点）以外的**生产**源码中，**不存在**具体协议实现的构造、导入，也**不存在**按协议取值的分支选择（协议实现的知识不落在消费层）。
   *判定*：grep 生产消费层源码 → 无具体协议实现的符号导入 / 构造；无按协议值的分支。
3. **D-3 切换只改注入配置**：切换协议 = 改**一处注入配置**（解析链 = 角色级 > 全局默认 > 内置 `rpc`）；切换前后生产消费层源码 **diff 为零**。
   *判定*：切换前后 `git diff` 看生产消费层 → 为空即通过。
4. **适用范围 = 生产消费层**（A5）：上述判据只约束**生产**消费层；**测试面不纳入**本轮零侵入判据（测试面按 profile 期望值断言、做**最小更新**）。
   *判定*：核对判据的适用对象 → 不含测试文件（6 个含 argv 断言的测试文件属"最小更新"对象、不属判据对象）。
