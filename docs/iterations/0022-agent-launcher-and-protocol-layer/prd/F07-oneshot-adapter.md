## 用户价值

「一次性」那条路也走同一套接口，但它不会假装自己有会话——不会留下一个其实续不上的上下文。

## 验收标准

1. **无会话语义**（W6 / M5 / J4）：`omp -p` 一次性执行被建模为协议层的**无会话语义**适配器——**不假装有会话**（不建立会话、不续接上下文）。
   *判定*：**两条可观察信号都成立即通过**——**(i)** 该轮的执行记录 / 日志能看出这一轮走的是一次性启动方式；**(ii)** 前后两轮之间**无上下文续接**（第二轮问它"上一轮问了什么"答不上来，或查不到该对话的常驻会话对象）。 〔`[user_confirmed MI-04]`〕
2. **能力差异显式降级**（M5 / A3/P3）：一次性路径与常驻协议的能力差异（门 / 流式等）以**能力位声明**表达，**不静默缺失**。
   *判定*：读一次性适配器的能力位声明 → 不具备的能力**显式标为不支持**，而不是缺失且无声明。 〔降级的表现形态见 T-10；机制见 F09〕
3. **shell 路径保持独立、行为不变**（N7 / J4 / E5）：`!` shell 执行器**不纳入**协议层，行为与现状一致。
   *判定*：走 `!` shell 路径 → 行为与现状一致；协议层实现中不含 shell 执行器。

## 边界（不包含）

- **不含 shell 执行器纳入协议层**（N7）；shell 保持独立、行为不变。
- 不含一次性路径的会话语义（**本就不存在**，M5 / J4）。
- 不含 oneshot 能力降级的**具体表现形态**（→ T-10）。
- 不含 acp / rpc 常驻链路（→ F06 / F04）；不含协议指定的选择域（`oneshot` 不在其中 → F02 验收 3）。
- 不含一次性路径既有 argv 知识是否合并的**实现决策**（F8 是现状事实；合并形态属阶段 3）。
- 不含一次性路径的其它行为变更（本迭代只做"建模 + 接口适配"）。
