## 验收标准

1. **逐协议显式声明（含工具使用面按同一标准表态）**（M6 / A3/P3）：**每个**协议实现都**显式声明**自己的能力位；能明确声明"不具备"；**工具使用（工具开关 / 宿主工具面）**同样按这份标准表态，不散落在各调用点。
   *判定*：逐个协议读其能力位声明 → 均存在，且每一项都有取值（具备 / 不具备）；工具开关与宿主工具面的表态也在同一份声明内。 〔`[user_confirmed MI-02]`：用户原话口径「有统一的服务管理启动agent这件事情，定义协议/标准，抽象方法和工具使用」；`hostTools` 的形态与是否实现见 T-09〕
2. **缺能力必须显式降级，不静默缺失**（M6 / A3/P3）：缺能力时**显式降级**而不是静默缺失（例：acp 的 `thinking=false`，见 F06 验收 2；oneshot 的门 / 流式能力，见 F07 验收 2）。
   *判定*：取任一"某协议不具备某能力"的场景 → 该能力位被声明为不具备、消费面据此降级；**不出现"无声明且行为缺失"**。 〔降级的表现形态见 T-10 / T-11〕
3. **候选清单为可表态检查点，不是最终集合门槛**（M6 原文）：候选清单 = `streaming` / `thinking` / `approvalGate` / `hostTools` / `introspection` / `queueControl`；验收只要求**每一项候选能力位都可被协议显式表态：有 / 无 / 降级**。
   *判定*：对照候选清单逐项查协议能力位 → 每项都能取到三个表态之一（有 / 无 / 降级），**没有"未表态"项即通过**；**本卡不把候选清单当作最终集合门槛**。 〔`[user_confirmed MI-03]`：定位 = 可表态检查点；**最终集合与签名留阶段 3**（T-05），不在本卡设门槛〕
4. **`steer` 仅作能力位声明**（N6 / F4）：rpc 的运行中插话能力**只作能力位声明**，本迭代**不做**产品功能。
   *判定*：查控制台与接口面 → 无运行中插话的产品功能；能力位上有该项声明。
