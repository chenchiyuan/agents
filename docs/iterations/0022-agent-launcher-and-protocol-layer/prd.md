## 本次迭代边界说明

### 包含（本迭代要产出的产品行为）

- **启动服务层（L1）**（W1 → F01）：把「怎么起一个 agent 进程」**数据化**为 profile（宿主 / bin 解析 / argv 构造 / env / cwd / 模型 / 角色 / 工具 / 权限这一组**内容维度**，形态见 T-02）；对外提供**统一起会话入口**；**新增宿主 = 新增 profile 数据**；claude / codex 本迭代只留 profile 结构与能力位。
- **协议层（L2）与协议指定入口唯一**（W2 / M2 → F02）：注入点唯一（落在配置面）；解析链 = 角色级配置 > 全局默认 > 内置 `rpc`；**选择域 = 常驻会话协议 `rpc` / `acp` 二选一**（`oneshot` 不在其中）；默认走 rpc；不做 per-chat / per-request / 控制台可切；切换即下一次会话，不迁移在飞上下文。
- **零侵入契约**（W8 + D-1~D-3 → F03）：指定已实现的协议**即生效**（不回落到内置默认）；生产消费层不自行构造 / 不自行选择协议实现；切换只改一处注入配置、生产消费层 `git diff` 为零；适用范围 = 生产消费层（测试面不纳入）。
- **omp 的 rpc 适配器落地（默认链路）**（W3 → F04）：映射**文本 / 思考 / 工具（参数与输出）**三类增量，不被丢弃；「一轮结束」以**终态事件**为准（不取受理回包）。
- **权限门跨协议映射**（W4 / M4 / A3/P5 → F05）：rpc 的工具审批门进入**既有确认面**（7 字段信封 → 收件箱 → 既有裁决回路）；一次受门禁调用**一条确认项（不重不欠）**；**字段集合与语义等价、值域随协议能力声明**（RPC 恒二元 `Approve` / `Deny`），**不要求跨协议逐字等价**；`tool` 名复用既有提取原语。
- **acp 协议实现保留（兜底链路）**（W5 / A4 → F06）：既有行为**不退化**；注入配置可切回；**保持现状、不补思考 / 工具输出增量**，能力位声明 `thinking=false`。
- **oneshot 适配器**（W6 / M5 / J4 → F07）：`omp -p` 一次性执行建模为**无会话语义**适配器；能力差异以能力位声明显式降级；**shell 执行器保持独立、不纳入协议层**。
- **过程可视化**（W7 / M3 / A3/P4 → F08）：思考 / 文本 / 工具增量经**既有按对话的运行时通道**（等价 `task_update` 语义）**实时展示**、落在**既有对话详情**内、**不新增 UI 载体、不做透出开关 / 过滤 / 分级**、**不落 SQLite**。
- **能力位显式声明**（M6 / A3/P3 → F09）：逐协议显式声明能力位；缺能力必须**显式降级**而不是静默缺失；`steer` 仅作能力位声明。
- **既有边界保持**（N8 / N2 / N10 / N11 → F10 / F11 / F12 / F13）：服务仍仅本机监听、零鉴权、不做多用户；不改 omp / harness 侧源码与协议；不引入第三方依赖；不实现 `docs/multi-omp-agent-protocol.md` 的 OAMP Router / 实例间消息层。

## 疑问与越界

1. **N 项未设独立卡**：N8 / N2 / N10 / N11 → F10 / F11 / F12 / F13（**保证项**，不引入新能力）；其余 N 项 → 相关卡的验收与边界（N1 → F01 验收 4；N3 / N9 → F02 验收 4~5；N4 / N5 → F08 验收 3~4；N6 → F09 验收 4；N7 → F07 验收 3；N12 → F06 验收 2 与 F09 验收 2）。**未为 N 项新增任何功能点**。体例先例：0021 F10 / F11 / F12，0020 F17 / F19 / F20。
2. **W1 括注的 profile 内容维度清单来源张力（本阶段处置，不新增验收）**：该清单出现在 `demand.md` W1 括注内，但其来源是 kickoff §五 的「分层建议」——`demand.md` §1 起点材料清单明定该节按「**非结论**」处理；同时 A6 记录用户对 profile 字段集「都没有额外想法」。故本阶段**只把「统一服务 + 标准被写定 + 启动信息数据化 + 工具使用按同一标准表达」（第 2 轮按 `user_confirmed MI-02` 回收后的口径）作为验收面**（U-2/J1/A2 直接支撑），**不把九个维度当作验收阈值**，仅登记为**内容维度参考**、其形态留 **T-02**。**未据此新增任何验收条目**，也未删除 `demand.md` 的任何内容（`demand.md` 只读）。
3. **拆分粒度的非显然判断（供主 agent 复核）**：本阶段按**可独立失败的失败模式**拆卡，未按 W 编号机械一对一。五处非一对一：
   - **W2 → F02（入口与选择域）+ F03（注入语义契约）**：M2 定的是"指定入口唯一 / 解析链 / 选择域"（配置面的可观测行为），W8 定的是"消费层不自行构造 / 不选择、切换零 diff"（DI 语义契约）——前者可满足而后者可独立失败，故拆两张（F03 为**形态约束卡**，体例先例：0021 F09）；
   - **W3 → F04（增量映射 + 轮次终态）+ F05（门承接）**：W3 的行文把"映射增量"与"工具审批门"并列，但其验收面在 `demand.md` 里分属两处（E3 的可见性面 vs E4 的确认面条目数面、M4 的映射口径面），"链路能拿到增量"与"门接得对"可独立失败，故拆两张；
   - **W5 / W6 → F06 / F07（各自一张）**：M5（oneshot 无会话语义 + 降级表现）与 A4（acp 保持现状 + `thinking=false`）是两条不同协议的不同裁决，判据面不重叠（E5 的两半），拆开各自可独立判定；
   - **M6 → F09（一张，[形态约束]）**：能力位声明机制横跨 F04~F07（rpc 声明具备、acp 声明 `thinking=false`、oneshot 声明降级），拆进各卡会让同一机制失去单一承载点；单独成卡后 F04/F06/F07 只引用其结论；
   - **M1 / M7 → 无独立卡**：M1 是三层**形态**（形态细节留 T-01），其需求级分工由 F01 / F02 / F03 三张卡分别承载；M7 是**阶段 3 的前置要求**（非产品行为），登记在「移交阶段 3 的承接项」。
