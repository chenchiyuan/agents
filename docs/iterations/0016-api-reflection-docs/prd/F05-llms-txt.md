# F05：面向 AI 的索引文件（两份同源、仅接口面）

**功能 ID**: F05
**来源**: `demand.md` W4；决策 D-3 / D-9 / D-11；澄清 M-3；效果 E1（第三面）/ E7 / E10（响应类型部分）；边界 N8 / N11；约束 C-6；现状缺口 F-17（无该文件）
**迭代**: 0016-api-reflection-docs

## 用户价值

一个 AI 客户端读一份短索引就知道这套服务是什么、有哪些接口、从哪深入，然后直接调通一次——不用读源码、不用问人。

## 验收标准

1. **两份产物存在**：通过 HTTP 能取得该索引文件；仓库中同时存在一份**同名的入库快照文件**，即该 HTTP 响应的内容（D-3 / D-11）。
   *判定*：请求该地址成功返回内容；在仓库中确认该快照文件存在。
2. **响应类型正确**：通过 HTTP 取回时响应类型为 `text/plain; charset=utf-8`（D-11 / C-6 / E10）。
   *判定*：`curl -I` 查看响应头，类型与编码逐字一致。
3. **两份逐字节相等**：HTTP 响应内容与仓库中的快照文件**逐字节相等**（W4 / M-3 / W5②）。
   *判定*：把两者取回后做字节比对，差异为零。
4. **内容为索引式且仅覆盖 HTTP 接口面**：包含——项目一句话说明；**接入方式**；按接口分组的清单摘要（**方法 / 路径 / 一句话说明**）；指向 `API.md`、`README.md`、接口文档页的链接。不含——接口以外的语料（D-9 / M-3 / W4 / X-2）。`[model_inferred MI-05：「接入方式」至少含服务地址（含端口）与取得服务的方式，使读者能实际发出第一次请求]`
   *判定*：逐项检索要素齐全；检索非 HTTP 面内容（内部协议用法、命令行用法摘要、仓库结构说明）零命中。
5. **接口清单与登记一致**：清单中的接口集合与路由登记的接口集合**一致（不多不少）**；新增登记后重新生成快照即出现该接口的一行摘要（W4 / E1）。
   *判定*：集合双向求差均为空；加一条登记 → 重新生成快照 → 清单中出现该接口。
6. **可独立完成一次接入**：仅凭该文件（**不读源码、不问作者**），读者能定位接口清单与 `API.md`，并完成一次真实接口调用（E7）。
   *判定*：照该文件的指引走通一次调用，全程不读源码。
7. **不产生第三份需要同步的副本**：不新增 `llms-full.txt` 或任何其它 AI 语料文件；不把 `API.md` 的全量内容复制进来（N11 / N7 / M-3）。
   *判定*：仓库中检索其它同类语料文件，零命中；该文件内容为索引式而非全量文档。

## 边界（不包含）

- **不含 `llms-full.txt` 或其它 AI 语料文件**（N11）。
- **不含非 HTTP 接口面内容**——不含内部协议用法、命令行用法摘要、仓库结构说明（D-9）。
- 不含 `API.md` 的全量内容（叙述与示例归 `API.md`，N7）。
- 不含 `API.md` 的自动化重写或从登记处重新生成（N7）。
- 不含接口版本化 / 多版本（N8）。
- 不含鉴权 / 凭据说明（N1）。
- 不含搜索、多语言等富能力（N8 / N10）。
