## 用户价值

"文档会不会过时"这件事不再靠自觉——只要有人漏登记、漏更新索引快照，或者漏在对外契约文档里登记新接口的路径，当场报错并指出漏在哪。

## 验收标准

1. **元数据必填锁**：每条登记缺**任一必需元数据**（方法 / 路径 / 一句话说明 / 参数元数据 / 是否有请求体）即检查失败，且失败信息**点名**是哪条登记缺哪个字段（W5① / M-2 / E2 / C-1）。
   *判定*：手动删掉某条登记的一个必填字段 → 运行既有测试命令（`npm test`）→ 观察失败，且失败信息点出该登记与该字段。
2. **索引快照逐字节锁**：索引内容的生成结果与仓库中的快照文件不逐字节相等即失败，且失败信息能定位差异所在（行 / 字节）（W5② / M-3）。
   *判定*：手动改动快照文件的少量字符 → 运行既有测试命令 → 观察失败并能定位差异。
3. **契约文档路径级双向覆盖锁**：① 登记中每条路由的路径必须在 `API.md` 中出现；② `API.md` 中出现的每个接口路径必须在登记中；**只锁路径集合，不锁文案**；缺失即失败并**点名**缺失路径（W5③ / D-6 / M-7 / C-2）。
   *判定*：a) 从 `API.md` 删掉一个既有路径 → 运行测试 → 失败并点名；b) 在 `API.md` 中加一个不存在的接口路径 → 运行测试 → 失败并点名。
4. **三条各自独立失败且可区分**：三条检查各自独立报告，一条失败不掩盖另外两条的结论（W5 / M-7）。
   *判定*：分别只破坏三处，三次运行各自报出对应的缺项，互不吞没。

## 边界（不包含）

- 不含对 `API.md` **文案**的锁定（只锁路径集合，D-6）。
- 不含对 `API.md` 章节、参数或示例完整性的锁定（C-2 只要求补一行路径）。
- **不检查"不登记也能被发现"**——本卡锁的是"登记后不可遗漏"，不承诺自动发现未登记的接口（M-2 明确不保证）。
- 不含文档页 / 调试台 / 索引文件的**内容正确性**检查（那是 F03 / F04 / F05 的验收面；本卡只管漂移）。
- 不含既有接口的行为回归（→ F02）。
- 不含运行时的服务内校验——三条均为工程保障，其触发点是测试（M-2 / W5）。
