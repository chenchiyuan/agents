## 用户价值

打开控制台点一下"文档"，就能看到当前这套接口的完整字段说明——不用翻源码，也不用担心它和实际接口对不上；想要用法场景和能直接复制的例子，再点进 `API.md`。

## 验收标准

1. **可达（顶栏入口 + 独立地址）**：控制台顶栏有"文档"入口，点击进入接口文档页；该页同时有**独立地址**，直接输入地址也能打开（D-5 / D-10 / M-6 / E8）。
   *判定*：从控制台顶栏点一次 + 手动输入地址一次，两次都能打开该页。
2. **入口不越界**：本卡只新增"文档"这一个入口；不新增其它入口类型（不加分组入口、不加页面底部互链式入口以外的替代形态）；既有 3 个顶栏占位项**保持原样不动**（D-10 / M-6）。
   *判定*：对照顶栏现有项，只多出"文档"一个真实可点项，"既有 3 个占位项"逐项未变。
3. **逐接口字段级内容**：页面按接口逐个展示：**方法、路径、一句话说明、参数（名称 / 位置 / 类型 / 是否必填 / 说明）、请求体字段（按字段逐个列出）、响应形态、该接口可能出现的错误码**（W2 / D-8 / M-8）。`[model_inferred MI-01：「响应形态」= 不含示例报文的形态说明（成功响应的类别 + 关键字段名清单），而非示例报文]`
   *判定*：随机抽取若干接口，逐项检索上述要素齐全、无缺项。
4. **不含响应示例**：页面**不出现**可直接复制的响应示例报文（示例职责归 `API.md`）（D-8 / M-8）。
   *判定*：逐页检索，零命中响应示例报文。
5. **覆盖登记中全部接口**：页面列出的接口集合与路由登记的接口集合**一致（不多不少）**，包含两条订阅型接口（W2 / M-4）。
   *判定*：两个方向的集合求差均为空。
6. **内容随登记变化**：改动登记后刷新页面，页面内容随之变化，**无需改动页面实现**（E9 / `[model_inferred MI-06]`）。
   *判定*：改动一处登记、让服务加载新登记 → 刷新对照，变化出现，页面实现零改动。
7. **反射边界如实标注**：页面上明确标注"**参数语义说明为人工撰写，结构与分发来自路由表**"（E9 / M-1 / C-1）。
   *判定*：打开页面即可看到该标注。
8. **互链到契约文档（页面侧）**：页面中**每个接口**都提供指向 `API.md` 的链接（W7；链接粒度见 F08 验收 4）。
   *判定*：逐接口检索，链接存在且可点开。

## 边界（不包含）

- **不含响应示例、使用场景与叙述性说明**——归 `API.md`（M-8 / N7）。
- **不含搜索 / 全文索引 / 侧边目录折叠等富交互**（N10）。
- 不含接口的调试与请求发送能力（→ F04）。
- 不含面向 AI 的索引文件的内容与生成（→ F05）。
- 不含漂移锁（→ F06）。
- 不含鉴权 / 跨机访问说明（N1）。
- **不把新页面的脚本 / 样式资产并入既有控制台页面资产**（N12）。
- **不出现需要单独维护的接口清单**——页面上的接口与字段必须来自登记处（M-1 / C-2）。
- 不含 `API.md` 的自动化重写或从登记处重新生成（N7）。
