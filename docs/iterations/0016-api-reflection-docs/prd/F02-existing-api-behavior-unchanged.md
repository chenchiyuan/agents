## 用户价值

这次只加"看"和"试"的能力：已经在用这些接口的程序和人**一行都不用改**——请求怎么发、返回什么、出错说什么，全都和以前一模一样。

## 验收标准

1. **既有用例文本零改写且全绿**：既有 HTTP 面测试文件**一个字都不改**，其全部顶层用例通过（W1 / E3）。
   *判定*：对既有测试文件做版本对比（diff 应为空）+ 运行全部既有用例，全绿。
2. **既有 10 条接口响应字节等价**：对既有 10 条接口逐条实测，**状态码、响应体、错误文案、处理顺序**与本次改造前逐字一致（W1 / N3 / E3）。
   *判定*：改造前后对同一批请求做响应比对，差异为零（新增的索引文件路由不在比对范围内）。
3. **不引入 405**：对已知路径使用**错误的方法**时，仍然走既有的"找不到"兜底，不出现 405 一类的新状态码（N4 / C-5①）。
   *判定*：对每条既有路径用错误方法请求，观察状态码与响应体，与改造前一致。
4. **路径匹配优先级与处理顺序不变**：具有前缀 / 后缀形态的既有路径（对话详情前缀；关闭 / 激活 / 改名后缀；批量归档的精确串）的**匹配结果**与改造前逐项一致；请求体的读取与校验**顺序**（例如改名的"读体 → 存在性 → 只读 → 写入"）逐字保持（C-5②③）。
   *判定*：按既有用例覆盖的形态逐条实测，结果与改造前一致。
5. **长连接接口不被分发层接管或改写**：订阅型接口仍然**独占响应流**，其响应内容与事件到达顺序不变（C-5④）。
   *判定*：订阅两个既有订阅接口，事件按序到达且内容不变。
6. **错误兜底覆盖面不缩小**：既有"整段分发逻辑失败即回统一错误"的覆盖范围不变，错误响应体的形状与状态码不变（C-5⑤）。
   *判定*：触发既有错误路径（含上游不可用一类），错误体与状态码逐字一致。
7. **既有参数语义的既有不一致原样保留**：空值参数在两处的既有不同处理（一处视为**无参**、一处走**参数错误**）保持原样，不被"顺手统一"（C-5⑥）。
   *判定*：分别发送空值参数，行为与改造前一致。
8. **零第三方依赖**：依赖清单仍为空，既有卫生检查通过（N2 / C-5⑦ / E10）。
   *判定*：读取依赖清单 + 运行既有卫生用例。

## 边界（不包含）

- **本卡不新增任何能力**——只声明"既有行为保持不变"。
- 不含文档页 / 调试台 / 索引文件的功能（→ F03 / F04 / F05）。
- 不含"登记即出现"与分发由登记驱动（→ F01）。
- 不含漂移锁（→ F06）。
- 不含接口版本化与兼容层（N8）。
- 不含鉴权与跨机边界的新增或调整（N1）。
- **不做"顺手改进"**：不引入 405、不统一既有空值语义、不改既有错误文案、不调既有参数校验——即使看起来更"一致"也不做（C-5 的既有契约保持清单）。
