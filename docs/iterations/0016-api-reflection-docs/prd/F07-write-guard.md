# F07：调试台写操作防护（风险提示 + 危险标识 + 发送前一次确认）

**功能 ID**: F07
**来源**: `demand.md` W6；决策 D-7 / D-12；澄清 M-5；效果 E5；约束 C-3；边界 N1 / N6；**用户确认（2026-09-12）：MI-07**
**迭代**: 0016-api-reflection-docs

## 用户价值

调试台点一下就是真操作——所以要让人一眼看出**哪些接口会改东西**，并且在真的发出去之前先确认一次，避免手滑把对话归档了、关掉了或者误发一条消息。

## 验收标准

1. **页面级风险提示**：调试台显著位置标注"**该页面直接作用于本机正在运行的应用，请求真实生效**"（W6① / M-5）。
   *判定*：打开页面即可看到该提示。
2. **只读接口直接发送**：只读接口点击发送**不需要**额外确认，请求直接发出（W6② / D-7）。
   *判定*：发送一个只读接口，一次点击即发出。
3. **POST 类发送前一次显式确认**：任何 POST 接口在发送前出现**一次显式确认**；未确认则不发出请求；确认后按 F04 展示真实响应（W6② / D-7 / E5）。
   *判定*：逐个 POST 接口点发送，首次点击**不发出**（对照服务端无任何变化），出现确认；确认后才真实发出。
4. **写类接口的可见危险标识**：改变数据或状态的接口（发消息 / 归档 / 关闭 / 激活 / 改名）在**表单**与**接口列表**两处都有**可见的危险标识**（W6③ / E5）。
   *判定*：逐个写类接口在列表与表单两处都能看到标识；只读接口无标识。
5. **不新增鉴权、不做只读模式总开关**：沿用"仅本机可用、无鉴权"的既有边界；不提供只读模式总开关（W6④⑤ / D-7 / N1 / N6）。
   *判定*：无任何凭据即可使用调试台；页面检索只读模式开关，零命中。
6. **新增写接口自动获得防护**：新增一个写接口登记后，调试台**无需改动实现**即对其生效（发送前确认 + 危险标识）（W6 / M-2）。`[user_confirmed MI-07：防护随登记自动生效，不由每个接口各写一遍]`
   *判定*：加一条写接口登记 → 让服务加载 → 刷新调试台 → 该接口出现在列表且带危险标识，首次点发送不直接发出。

## 边界（不包含）

- **不含更严格的确认强度**：不要求所有请求（含只读）都确认、不要求输入确认词（D-7 已确认取"一次显式确认 + 危险标识"，其余备选已否决）。
- **不含只读模式总开关**（N6 / P-7 已确认不做）。
- **不含鉴权 / 多用户 / 凭据管理 / 跨机访问**（N1）——本卡防护定位是"防误操作"，不是"防未授权"（C-3）。
- 不含请求历史 / 收藏 / 批量与脚本化请求（N6）。
- 不含 POST 之外的发送确认（只读接口直接发送）。
- 不含表单生成与响应展示本身（→ F04）。
- 不含对"哪些接口算写操作"的逐接口枚举——写标记来自登记处，不逐个手写（见验收 6）。

## 架构落定（阶段 3；完整契约见 `architecture.md` §6.6）

- **AR-07-a 确认的交互形态与文案**：**一次原生确认对话框** —— `window.confirm('该请求会真实生效：\n<METHOD> <path>\n\n确定发送？')`；`danger === false` 的接口**直接发送**（验收 2）。选原生对话框的理由：零 UI 代码、零状态机、一次确认（D-7 已否决"全部确认"与"输入确认词"）。备选（仅在主 agent 要求"非阻塞确认"时切换）：页面内 `.confirm-bar` 内联二次确认，改动局限在 `debug.js` + `api-pages.css`。
- **AR-07-b 危险标识的呈现方式**：`.danger-badge`（背景/文字取既有 `--red` token）+ 固定短文案（如「会改变状态」），渲染在**接口列表项**与**选中接口的表单顶部**两处（验收 4）；只读接口无标识。
- **AR-07-c 写标记在登记处的承载方式**：**不新增字段** —— `danger = method !== 'GET'`，在 `projectRoutes` 投影时派生（表项的 `method` 就是写标记的真源）。⇒ 验收 6 / MI-07 的"新增写接口自动获得防护"是**结构事实**：加一个 `POST` 表项，危险标识与发送前确认自动生效；也避免了"布尔字段必须与 method 保持一致"的第二真源。
- **AR-07-d 防护的统一挂载点**：调试台**发送函数内唯一一处**判断 `if (route.danger && !window.confirm(...)) return;` —— 不逐接口手写、不按接口维护清单；页面级风险提示（验收 1）是 `debug.html` 里的**静态段落**（不依赖取数成功，永远可见）。

**边界**：不新增鉴权、不做只读模式总开关、不要求凭据（验收 5 / N1 / N6）；防护定位 = 防手滑，不是防未授权（C-3）。
