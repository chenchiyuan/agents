# F07：调试台写操作防护（风险提示 + 危险标识 + 发送前一次确认）

**功能 ID**: F07
**来源**: `demand.md` W6；决策 D-7 / D-12；澄清 M-5；效果 E5；约束 C-3；边界 N1 / N6
**迭代**: 0016-api-reflection-docs

## 用户价值

调试台点一下就是真操作——所以要让人一眼看出**哪些接口会改东西**，并且在真的发出去之前先确认一次，避免手滑把对话归档了、关掉了或者误发一条消息。

## 验收标准

1. **页面级风险提示**：调试台显著位置标注"**该页面直接作用于本机正在运行的应用，请求真实生效**"（W6① / M-5）。
   *判定*：打开页面即可看到该提示。
2. **只读接口直接发送**：只读接口点击发送**不需要**额外确认，请求直接发出（W6② / D-7）。
   *判定*：发送一个只读接口，一次点击即发出。
3. **POST 类发送前一次显式确认**：任何 POST 接口在发送前出现**一次显式确认**；未确认则不发出请求；确认后按 F04 展示真实响应（W6② / D-7 / E5）。
   *判定*：逐个 POST 接口点发送，首次点击**不发出**（对照服务端无任何变化），出现确认；确认后才真实发出。
4. **写类接口的可见危险标识**：改变数据或状态的接口（发消息 / 归档 / 关闭 / 激活 / 改名）在**表单**与**接口列表**两处都有**可见的危险标识**（W6③ / E5）。
   *判定*：逐个写类接口在列表与表单两处都能看到标识；只读接口无标识。
5. **不新增鉴权、不做只读模式总开关**：沿用"仅本机可用、无鉴权"的既有边界；不提供只读模式总开关（W6④⑤ / D-7 / N1 / N6）。
   *判定*：无任何凭据即可使用调试台；页面检索只读模式开关，零命中。
6. **新增写接口自动获得防护**：新增一个写接口登记后，调试台**无需改动实现**即对其生效（发送前确认 + 危险标识）（W6 / M-2）。`[model_inferred MI-07：防护随登记自动生效，不由每个接口各写一遍]`
   *判定*：加一条写接口登记 → 让服务加载 → 刷新调试台 → 该接口出现在列表且带危险标识，首次点发送不直接发出。

## 边界（不包含）

- **不含更严格的确认强度**：不要求所有请求（含只读）都确认、不要求输入确认词（D-7 已确认取"一次显式确认 + 危险标识"，其余备选已否决）。
- **不含只读模式总开关**（N6 / P-7 已确认不做）。
- **不含鉴权 / 多用户 / 凭据管理 / 跨机访问**（N1）——本卡防护定位是"防误操作"，不是"防未授权"（C-3）。
- 不含请求历史 / 收藏 / 批量与脚本化请求（N6）。
- 不含 POST 之外的发送确认（只读接口直接发送）。
- 不含表单生成与响应展示本身（→ F04）。
- 不含对"哪些接口算写操作"的逐接口枚举——写标记来自登记处，不逐个手写（见验收 6）。
