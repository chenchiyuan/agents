## 本次迭代边界说明

### 包含

- **唯一真源**（W1 → F01）：HTTP 面上每个接口的方法 / 路径 / 说明 / 参数信息只有一处登记位置；新增接口只在登记处加一项 → 文档页、调试台、面向 AI 的索引三处出现该接口，**全程不改这三处的任何实现**；改登记中的路径，文档页与调试台显示同步改变。
- **既有行为零变化**（W1 后半 / N3 / N4 / C-5 → F02）：既有 10 条接口的方法 / 路径 / 状态码 / 错误体形状 / 错误文案 / 处理顺序**逐字不变**；既有 HTTP 面测试文件**文本零改写**且全部用例通过；不引入 405；路径匹配优先级、请求体读取与校验顺序、长连接接口独占响应流、统一错误兜底覆盖面、既有参数空值语义的既有不一致，全部原样保留；依赖清单仍为空。
- **在线接口文档页**（W2 → F03）：独立地址 + 顶栏"文档"入口；逐接口展示方法 / 路径 / 一句话说明 / 参数（名称·位置·类型·必填·说明）/ 请求体字段 / 响应形态 / 可能出现的错误码；**不含响应示例**；接口集合与登记集合一致；页面明确标注"参数语义说明为人工撰写，结构与分发来自路由表"；逐接口提供指向 `API.md` 的链接。
- **可交互调试台**（W3 → F04）：独立地址 + 顶栏"调试"入口；接口集合与登记集合一致；按元数据生成输入控件（无参直接发 / 查询参数 / 路径参数 / 请求体按字段类型）；发送后展示**真实**状态码 / 响应体 / 耗时（毫秒）；两条订阅型接口可建立订阅并按序实时展示事件；不出现登记之外的接口或快捷操作；无请求历史等留存。
- **面向 AI 的索引文件**（W4 → F05）：HTTP 可取得 + 仓库中一份同名快照，两份**逐字节相等**；响应类型为 `text/plain; charset=utf-8`；内容为索引式且仅覆盖 HTTP 接口面（项目一句话说明 / 接入方式 / 接口清单摘要（方法·路径·一句话）/ 指向 `API.md`、`README.md`、文档页的链接）；接口集合与登记集合一致；仅凭该文件可完成一次真实调用。
- **漂移锁三条**（W5 → F06）：① 每条登记缺任一必需元数据 → 检查失败并**点名**缺项；② 索引快照与生成结果不逐字节相等 → 失败并可定位差异；③ 契约文档与登记的**路径集合双向包含**（只锁路径、不锁文案）→ 缺失即失败并点名；三条各自独立报告、互不掩盖。
- **写操作防护**（W6 → F07）：页面级"请求真实生效"提示；GET 直接发送；POST 类发送前一次显式确认；改数据 / 状态的接口在表单与接口列表上有可见危险标识；不新增鉴权、不做只读模式总开关；新增写接口自动获得防护。
- **互补共存与互链**（W7 → F08）：`API.md` 保留叙述 / 场景 / 可粘贴示例，不被自动化替换；新增路由在其**补一行路径**（不要求章节 / 参数 / 示例）；`API.md` 顶部指向文档页，文档页逐接口指向 `API.md`；文档页不复制 `API.md` 的叙述与示例；两边对同一接口的事实不冲突。

## 拆分理由（原子粒度判断）

**总原则：按"可独立出现的失败"拆卡。**

- **W1 拆两张（F01 / F02）**：W1 包含两个观察面——"改登记 → 派生产物跟着变"（F01）与"既有行为字节等价"（F02）。两者失败互不蕴含：**只把表做成装饰**（登记存在但分发仍按原样硬编码）→ F01 红、F02 绿；**表真正驱动但顺序 / 兜底 / 读体位置被改动** → F01 绿、F02 红。各自有独立的裸判定（E1/E9 对 E3），且 F02 是本次改动**新引入的回归风险**（C-5 七条），必须有独立可测的承载（否则该风险无人验收）。体例沿用 0015 F08（回归卡）。
- **文档页与调试台分两张（F03 / F04）**：两个独立页面、两个独立地址、两个独立裸判定面；失败模式不同——"字段说明看不到 / 与接口对不上"（E9）与"发不出请求 / 拿不到真实响应"（E4/E6）。合并会让"页面能打开但发不出请求"变成不可独立判定的部分完成。
- **订阅面板并入 F04 而不单立**：两条订阅型接口的逻辑**已存在**于登记中，本卡只是消费它，不存在新的接口缺口（对比 0015 F05 是新增全局事件流，故当时单立）；同一页面、同一交付物、同一地址判定面。
- **索引文件独立成卡（F05）**：交付物是仓库内的一份文件，可离线消费；其失败模式（内容缺失 / 与登记不一致 / 两份不一样 / 无法据以完成一次调用）与页面类正交，且有专属裸判定 E7。
- **漂移锁独立成卡（F06）而不拆成三张**：三条锁是同一工程保证的三个对象，共享同一失败语义（"漂移未被发现"）与同一交付面（检查项集合）；三条各自独立可测、独立报告（验收 1~3 + 验收 4），拆开会产出三张各只有一条断言的极小卡。
- **写操作防护独立成卡（F07）**：W6 是 demand 依据用户 why 新增的必要保障，其失败模式独立——"能发、看得见真实结果，但会误操作"（F04 验收 4 绿、F07 验收 3 红），E5 是专属裸判定；防护对象（写标记）与发送能力（表单与发送）是两件事。
- **与契约文档的关系独立成卡（F08）**：M-8 是专属澄清，失败模式是"两边都能用，但互相找不到 / 变成两份互相矛盾的副本"；无其它卡承载。
- **未单立"既有资产同步"卡**：`demand.md` §3 列出的已知受影响既有文件（分发实现、控制台页面、`API.md`、`README.md`、既有测试文件）属实现的已知成本，不构成独立功能能力，列为**全局架构维度 AR-09**，不另立卡片（另立会构成 demand 之外的新增功能点）。

## 疑问与越界

1. **W7 "对应章节"与 C-2 "只补一行路径"的交界未定义（本阶段不选边，标 MI-04）**：W7 要求文档页"每个接口指向 `API.md` 对应章节"，而 C-2 明确新增路由在 `API.md` 只增加"补一行路径"的登记义务、不要求写章节。当一个接口在 `API.md` 中仅有路径登记时，"对应章节"指向何处未定义。本阶段的落卡方式：F08 验收 4 只要求"每个接口有指向 `API.md` 的链接"，**链接粒度标 `[model_inferred MI-04]` 待确认**，不擅自规定锚点形态（锚点形态本身也属 AR-08）。**非硬矛盾**（"指向 `API.md`"两处一致，分歧只在粒度），故未按矛盾处理，仅报备。
2. **两个新页面自身的导航形态未定义**：`demand.md` 只锁定"顶栏 2 个平铺入口 + 两个独立地址"（D-5/D-10/M-6），未要求新页面内部再有导航或返回控制台的入口。本阶段**不新增该功能要求**，仅作为 AR-09 的实现选择留架构。
