## 本次迭代边界说明

### 包含

- **一键归档**（A-1 / A-8 / A-9 → F01）：过滤栏右侧「归档全部」入口；范围 = 所有未归档且非进行中的对话（已完成 / 失败 / 已关闭）；已归档跳过；一次轻确认；批量结果可见且不回滚已成功项。
- **归档语义**（A-2 / A-5 前半 → F02）：独立归档标记 + 本次归档时间；归档不改变对话原状态；归档对话只读（拒收新输入）、历史完整可读；归档状态持久化（重启不变）；归档释放常驻上下文。
- **归档分类视图**（A-3 / A-10 → F03）：过滤栏「归档」标签页；只列已归档、主列表不再显示；归档时间倒序（同时间按对话标识倒序稳定排序）；每项含标题 / agent / 归档时间 / 原状态标识 / 独立可点的「激活」按钮；空态文案。
- **归档列表容量**（A-7 → F04）：归档视图可访问全部已归档对话；较大首屏 + 底部继续加载；续页保持同一排序；末尾无死控件。
- **单个激活**（A-4 / A-5 后半 / A-6 → F05）：移除归档标记、立即恢复可继续对话、移出归档视图并置顶 All 列表；状态还原（已关闭 → 已完成并清除关闭时间）；不恢复上下文；给出"不再记得此前内容"的显式提示；非归档的已关闭对话仍不可重开。

## 拆分理由（原子粒度判断）

- **F01 独立成卡，且 A-9 / A-8 不单独成卡**：F01 的失败模式是"按钮不在 / 范围错（误伤进行中或漏掉已关闭）/ 没有确认 / 失败无声"，观察面是一次点击前后两个列表的差异。A-9（二次确认）是这次点击的前置步骤、A-8（结果可见性）是这次点击的收尾——两者都无法脱离这一次点击被独立交付与独立验收，拆开会得到两张没有自身触发入口的卡，故并入 F01 作为验收 5 与验收 6/7。
- **F02 与 F05 分拆（归档与激活）**：归档是"进入只读"、激活是"退出只读并恢复可续"，两者互为反面但独立可测、独立可交付——归档有效而激活无效（或反之）都是可独立出现的失败。A-5（状态还原规则）横跨两卡：其"归档不改变原状态"只能由归档动作后观察到（落 F02 验收 1），"激活后保持原状态 / 已关闭例外"只能由激活动作后观察到（落 F05 验收 4）；硬塞进一张卡会让另一半失去独立验收条件。
- **F03 与 F04 分拆（归档视图与容量）**：A-3 的失败模式是"内容 / 顺序 / 入口 / 项构成不对"，3 条数据即可测；A-7 的失败模式是"超过单页上限后归档项看不见"，必须 60+ 条数据才能测。两者测试前置条件与失败模式都不同，故按独立验收拆开。与此对照，A-10（空态）与 A-6（激活后提示）**未**单独成卡：空态是归档视图在"零条"时的展示分支、提示只在激活动作之后才有意义，两者都没有独立于所属功能的交付物，故分别落 F03 验收 6 与 F05 验收 6。
- **F03 与 F05 未合并**：F03 判"归档视图列什么、怎么排、怎么进入"，F05 判"点激活之后发生什么"。归档视图正确但激活无效、或激活有效但归档视图列错，都是可独立出现的失败。
- **F01 与 F02 分拆（批量动作与单条语义）**：F01 判"谁被归档、由什么触发、结果如何反馈"，F02 判"被归档后这条对话处于什么状态"。批量执行成功但单条语义错（例如归档后仍能发消息）是典型可独立出现的失败。
- **未单立"既有契约同步"卡**：`demand.md` §3 列出的已知受影响契约（测试断言、README 中"closed 不可重开"表述收窄）属实现的已知成本，不构成独立功能能力，列为本文件「架构待填」的全局项 AR-17，不另立卡片（另立会构成 demand 之外的新增功能点）。
