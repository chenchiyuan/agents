# F02：归档语义（独立标记、归档时间、只读、历史保留）

**功能 ID**: F02
**来源**: `demand.md` A-2（归档语义三条）、A-5 前半（归档不改变对话状态）；澄清 M-1；决策 D-2 / D-5（做法 A）；效果 E-2、E-3、E-6、E-8（前半）；边界 N-1 / N-4 / N-9
**迭代**: 0013-chat-archive

---

## 用户价值

归档后的对话"收起来但没丢"——历史随时能翻，又不会再被误发消息打断，而且它原本是完成还是失败，归档后仍然分得清。

## 验收标准

1. **归档是独立标记，不改变对话原状态**：归档后的对话带有一个"已归档"分类标记；该标记不改变对话自身的状态——**已完成 / 失败 / 已关闭**原样保留（D-5 / M-1 / A-5 前半）。判定：归档一条已完成的对话后，它在归档视图中的状态标识仍为已完成；归档一条失败的对话同理。
2. **归档时间被记录，且以本次为准**：每条被归档的对话记录一次归档时间（A-2 ②）。对同一对话再次归档（归档 → 激活 → 再归档）时，归档时间刷新为**当次**归档时间（C-5）；处于已归档状态因而被"归档全部"跳过的对话，归档时间保持不变（F01 验收 4）。
3. **归档对话只读**：归档后该对话拒绝新的用户输入——在其中发送消息不会产生新的对话记录，并给出拒绝提示（D-2 / E-3）。判定：在归档对话中发送一条消息，消息未被记录为新的输入。
4. **只读由归档标记承担，与既有已关闭只读并存不冲突**：一条原本处于**已关闭**状态的对话被归档后，其拒绝新输入的行为与归档前一致；一条原本为已完成 / 失败的对话被归档后，**也**开始拒绝新输入（D-2 / C-2）。判定：对已完成与已关闭两种来源各归档一条，两者归档后均拒收输入。
5. **历史完整可读**：归档对话仍可打开查看，历史消息序列与归档前逐条一致（E-2）；归档不删除、不截断、不修改任何历史消息（N-1）。
6. **归档状态持久化**：重启服务后，对话的归档标记与归档时间保持不变——归档视图内容与重启前一致（E-6）。
7. **归档释放常驻上下文**：归档使该对话此前的常驻 LLM 上下文被释放（A-2 ①）。其可观察后果是——归档后再激活并继续对话时，回复不再记得归档前的内容（E-8 前半）。该判定与 F05 验收 6 共用同一组用例。

## 边界（不包含）

- 不含"哪些对话被归档、由什么触发、结果如何反馈"——那是 F01。
- 不含归档视图的入口、内容、排序、项构成与容量（F03 / F04）。
- 不含激活动作本身（F05）——本卡只规定"归档后处于什么状态"，不规定"如何退出归档"。
- 不做**上下文还原**：归档释放的常驻上下文在激活后**不**恢复（N-4 / A-4 末句）。
- 不做**对话删除**（N-1）——历史消息一律保留。
- 不做**历史数据迁移**：本次迭代之前已存在的已关闭对话保持现状，不被视为已归档，也不补写归档时间（N-9）。
- 不含归档对话的标题编辑、复制、导出等能力（demand 未要求）。
- 不含"归档"标识在对话详情内的展示形态（demand 只要求归档列表项显示归档时间与原状态，见 F03）。
