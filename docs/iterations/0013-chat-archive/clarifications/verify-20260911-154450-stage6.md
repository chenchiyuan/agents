## 下一迭代候选

> 本轮发现的优化点、边界问题或遗留限制。不在当前验收标准范围内，供主 agent 与 planner 决定是否纳入下一迭代。

- **`context_released` 一位标志的语义窄化**：当前一位同时承载「归档已释放上下文」与「激活后待新回答」，全靠前端 `archived_at === null &&` 这一半把归档态排除在提示之外。若将来出现第二种「已释放但未提问」的来源（如 `context_reset` 淘汰），该判据会失效。

- **归档视图的索引与排序成本**：`ORDER BY (CASE …)` + 归档谓词必然全表扫描（§15 R-2）。chats 达万级时需拆第二组语句 + `idx_chats_archived`，但拆分会牺牲「`total` 与列表同源」这条不变式（§3.3 V-2），届时要一并设计计数同源方案。
- **`failed_ids` 分支不可端到端覆盖**：`archiveChat` 的异常分支在单进程同步 `DatabaseSync` 下几乎不可达，仓库测试只能覆盖「working 不可归档 / 已归档跳过」边界。需决策：接受防御性死分支，或提供可注入的失败缝。
