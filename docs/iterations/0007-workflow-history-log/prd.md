## 本次迭代边界说明

### 包含

- 新增 `history.md` 产物，纳入 workflow-pb 现有文档路径协议，逐条追加写入（F01）。
- 单迭代级 `history` 开关，默认开启，显式关闭时跳过记录（F02）。
- 三类事件的记录内容契约：派发摘要（角色名/阶段/任务）、报告摘要（沿用各角色报告契约字段）、调度决策（决策内容+触发依据）（F03）。
- 阶段 5 并发场景下，同一轮内的多个并发派发按发起顺序各自独立记录，不合并、不省略（F04）。
- `history.md` 由主 agent 自己直接维护，不派发给执行角色代写（F01 边界内的正向声明）。

### 不包含

- 不记录派发 brief 中角色定义的全文注入内容（角色文件本身已受 git 版本控制）。
- 不替代或重写 `status.md` 的既有格式与维护时机——两者并存、职责不同。
- 不建立其他角色（`verifier`、`progress-observer` 等）读取或校验 `history.md` 内容的自动化依赖。
- 不实现跨迭代持久生效的全局配置文件来控制默认开关——本次只做单迭代级字段。
- 不记录主 agent 与用户之间除决策结果之外的日常说明性对话。
