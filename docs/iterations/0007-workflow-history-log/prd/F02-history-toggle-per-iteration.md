# F02 — 单迭代级 history 开关

**功能 ID**: F02
**来源**: `demand.md` §2「做什么」第 2/3 条，§5「达到什么效果」第 4 条
**迭代**: 0007-workflow-history-log

---

## 用户价值

不是每次迭代都需要这份记录，用户可以按迭代选择开启或关闭，而不是被强制附加一份始终存在的额外产物。

---

## 验收标准

1. 迭代启动时，`history` 记录默认处于开启状态，无需用户额外操作即生效。
2. 该迭代的 `status.md` 中存在一个可读的字段，声明该迭代 `history` 选项的开启/关闭状态（具体字段名留给架构阶段，见架构待填 AR-02）。
3. 该字段被显式设为"关闭"后，该迭代目录下不产生 `history.md`；若 `history.md` 此前已存在（例如从开启状态切换为关闭），后续不再对其追加写入。
4. 开关状态是单迭代级的——只影响声明该字段的这一个迭代，不影响其他迭代的默认行为，也不存在跨迭代生效的全局配置文件。

---

## 边界（不包含）

- 不实现跨迭代持久生效的全局配置文件来控制默认开关——用户只提到"默认开启"，未提出"需要跨迭代统一配置"的诉求。
- 不包含开关字段的具体命名和取值格式（已在下方「架构维度」标注留白）。
- 不包含关闭后是否删除已存在的 `history.md` 文件——demand.md 只要求"不产生/不追加"，删除现有文件不在本次范围内，也未被要求。

---

## 架构维度

**字段位置与格式**：在 `status.md` 头部字段区（`**工作流**`/`**迭代**`/`**当前阶段**`/`**状态**` 所在的那组字段），紧跟 `**状态**` 字段之后新增一行：

```markdown
**history**: 开启
```

取值只有 `开启` / `关闭` 两种，默认 `开启`。放入头部字段区而非新建表格列，理由：`history` 是"整个迭代的开关状态"，语义上与"当前阶段""状态"同属迭代级元信息，与现有四个头部字段格式一致，不新增章节或表格结构。

**关闭时的行为**：启动时即关闭 → 不创建 `history.md`；运行中途改为关闭 → 已存在的 `history.md` 保留不删除，但主 agent 后续不再对其追加写入（对应本卡边界"不包含删除已存在文件"）。

详见 `architecture.md` §决策 D3。
