# F03 — 三类事件的记录内容与粒度

**功能 ID**: F03
**来源**: `demand.md` §2「做什么」第 5 条，§5「达到什么效果」第 2/3 条
**迭代**: 0007-workflow-history-log

---

## 用户价值

事后阅读 `history.md` 的人（复盘者/debug 者）不需要询问执行者，就能看懂"这次迭代派发了什么、收到了什么反馈、主 agent 基于什么做了什么调度决策"。

---

## 验收标准

1. 每次主 agent 向执行角色发起派发时，记录一条包含角色名、当前阶段、任务一句话摘要的条目；不包含该角色定义全文。
2. 每次主 agent 收到执行角色的报告时，记录一条报告摘要条目；摘要内容取自该角色"报告契约"中已定义的字段结构（不是自由复述整段报告原文，也不是逐字段全文转录）。
3. 主 agent 做出以下调度决策时，各记录一条决策条目，且每条至少包含"决策内容"和"触发依据"两个字段：
   - 阶段推进核查结果（通过/未通过及原因）
   - Gate 暂停触发与用户确认结果
   - 阶段 5 并发槛位释放/爬升触发
   - PR 失败或阻塞判定
4. 读取任一决策类条目，不需要询问执行者即可判断该决策为何在那个时间点发生——即"触发依据"字段必须包含足以还原判断依据的具体信息（例如触发的具体条件、依据的具体文件或状态），不是"因为需要"这类无信息量的占位描述。
5. 不记录主 agent 与用户之间除决策结果外的日常说明性对话——完整对话已由会话本身承载，本卡范围只覆盖上述三类事件。

---

## 边界（不包含）

- 不包含各类记录的具体字段结构、字段命名（已在下方「架构维度」标注留白）。
- 不包含报告摘要如何具体映射到各角色报告契约字段的转换规则细节（逐字段摘录 vs 自由摘要），留给架构阶段设计。
- 不包含派发/报告条目中的角色定义全文——见 F01 边界，静态文本不重复记录。
- 不包含对决策正确性的二次判断——本卡只要求"记录决策内容和触发依据"，不要求验证该决策本身是否正确，这属于阶段 6 独立验证的职责范围，不在本迭代内。

---

## 架构维度

**统一外层格式**：每条记录是一个三级标题 + 若干字段行：

```markdown
### {YYYY-MM-DD HH:MM:SS} · {事件类型} · {对象}

- {字段1}：{值1}
- {字段2}：{值2}
```

事件类型取值三选一：`派发` / `收到报告` / `调度决策`。

**派发类**：字段取自「Brief 构建规则」中已内联进 brief 的阶段/任务字段（阶段 5 额外加 PR 路径），不复制角色定义全文——角色定义全文已由「派发」这一事实类型隐含存在（brief 构建规则已强制全文注入），history.md 只记录"这次派发的是谁、什么阶段、什么任务"这几个可变字段。

**收到报告类**：逐条摘录该角色「报告契约」已定义的编号/字段项，每项压缩为一句话结论值，不复制报告原文的解释性长文。字段序号与角色报告契约的编号严格对应，不合并不跳过；报告契约不是编号列表格式的角色（如 `verifier` 用固定模板字段），改为摘录模板字段名+结论值，规则同源。这是"逐字段摘录"，不是"自由摘要"——每个角色摘几条由该角色报告契约本身定义的字段数决定，不由 history.md 自行决定摘几条。

**调度决策类**：至少两个字段，demand.md/F03 验收标准已锁定字段名：

```markdown
- 决策内容：{具体决策是什么}
- 触发依据：{具体触发条件、依据的文件路径或状态值，不是"因为需要"这类占位}
```

详见 `architecture.md` §决策 D4（含三类记录各自的完整示例）。
