# F06 — SCM 强制约束声明

**功能 ID**: F06  
**来源**: demand.md §最小边界 #6  
**迭代**: 0003-workflow-scm

---

## 用户价值

通过工作流文件中的强制约束，确保从 `tasks.md` 产出起，所有代码变更都在 worktree+PR 隔离下进行，使"直接在主分支提交"成为可被工作流检测的违规行为，而不只是建议。

---

## 验收标准

1. `roles/workflow-scm/workflow-scm.md`（F01 的产物）中，存在独立的"约束声明"或"不变量"章节，包含以下两条规则，每条措辞明确、可被客观判断是否违反：
   - **规则 A**：从 `tasks.md` 产出（即 Phase 4 完成）之后，任何代码变更必须在独立 worktree 分支上进行，不得直接在主分支（main/master）上提交。
   - **规则 B**：每个 worktree 变更必须对应一个 `prs/pr-{id}.md` 文件（按 F03 规范），merge 前该文件须存在。
2. 约束声明中明确说明约束的生效范围：仅从下一个使用 workflow-scm 的迭代起生效，不追溯已完成迭代。
3. workflow-pb（F04 的产物）中，Phase 5（提交规划）的推进条件包含对上述约束的引用或说明，使主 agent 可从 workflow-pb 单独读出此约束。
4. dev 角色文件和 verifier 角色文件不因此约束而被修改（约束通过工作流契约传递）。

---

## 边界（不包含）

- 不要求自动检测违规（无 CI hook，无 pre-commit 钩子——本迭代只做定义）。
- 不要求对历史提交做合规性审查（约束不追溯）。
- 不要求对"紧急修复"等例外情况建立豁免机制（本迭代最小边界不包含例外处理）。

---

## 架构维度

无。此功能卡为纯文档约束声明，无架构决策。
