# F03 — PR 上下文文件规范

**功能 ID**: F03  
**来源**: demand.md §最小边界 #3  
**迭代**: 0003-workflow-scm

---

## 用户价值

为每个 PR 提供标准化的上下文文件，让 dev 无需从其他来源拼接信息，直接从单一文件构建完整上下文。

---

## 验收标准

1. workflow-scm 文件（F01）或 commit-planner 角色文件（F02）中，明确定义 `prs/pr-{id}.md` 的格式规范。
2. 格式规范中每个 PR 文件必须包含以下字段，缺一不可：
   - **上下文摘要**：描述该 PR 解决什么问题，dev 读完后能独立工作，无需额外询问。
   - **涉及 tasks**：列出来自 `tasks.md` 的任务 ID 列表（至少一个）。
   - **文件范围**：列出该 PR 预计涉及的文件路径或目录（用于范围约束）。
   - **验收标准**：该 PR merge 前须满足的可判断条件（至少一条）。
   - **参考资料**：可为空列表，但字段必须存在（可附链接或文件路径）。
3. PR 文件命名规则为 `pr-{id}.md`，`{id}` 为数字或有序标识符，规范中需说明命名规则。
4. PR 文件存放路径为 `docs/iterations/{迭代ID}/prs/pr-{id}.md`，规范中需说明此路径规则。
5. commit-planner 产出的实际 PR 文件能通过 F03 格式规范的逐项检查（由 verifier 可验证）。

---

## 边界（不包含）

- 不要求 PR 文件包含 PR 的 GitHub/GitLab URL（本迭代只做定义，不做 API 对接）。
- 不要求 PR 文件追踪 merge 状态（状态管理不在本迭代范围内）。
- 不要求 PR 文件包含 code review 意见（review 流程不在本迭代范围内）。

## 架构维度

**AR-03 已填（2026-09-02）**

1:N 映射内嵌在每个 PR 文件的"涉及 tasks"字段中，格式为 Markdown 无序列表（每行一个任务 ID）。无独立映射文件。

示例：

```markdown
## 涉及 tasks

- T01
- T03
- T07
```

- 给定 PR → 找 tasks：直接读"涉及 tasks"字段
- 给定 task → 找 PR：遍历 `prs/` 目录（单次迭代 PR 数 < 20，成本可接受）

PR 文件是映射关系的唯一权威来源，不设独立映射文件以避免维护不一致。

见 `architecture.md §四 AR-03`。
