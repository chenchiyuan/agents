# F04 — workflow-pb 阶段扩展

**功能 ID**: F04  
**来源**: demand.md §最小边界 #4  
**迭代**: 0003-workflow-scm

---

## 用户价值

在任务拆解之后、后端实现之前，强制插入提交规划阶段，保证所有代码变更在进入实现阶段前已有明确的 PR 分组和 worktree 隔离方案。

---

## 验收标准

1. `roles/workflow-pb/workflow-pb.md` 的"阶段定义"表包含新 Phase 5（提交规划），该行出现在原 Phase 4（任务拆解）之后、原后端实现阶段之前。
2. 新 Phase 5 行包含所有列：阶段编号、职责描述、输入、输出、推进条件，且均非空。
   - **输入**：`tasks.md`
   - **输出**：`prs/` 目录（含 Issues 分组 + PR 独立文件）
   - **推进条件**：至少包含"每个 tasks.md 中的任务都已归入某个 PR"和"每个 PR 文件满足 F03 规范"两条可判断条件。
3. 原 Phase 5（后端实现）顺移为 Phase 6，原 Phase 6（独立验证）顺移为 Phase 7，编号连续无跳跃。
4. 工作流文件总阶段数从 6 变为 7，文件开头的"工作流包含 N 个阶段"描述与实际阶段表一致。
5. 原有各阶段的"输入"、"输出"、"推进条件"内容不因编号顺移而被改动（只有编号变，内容不变）。

---

## 边界（不包含）

- 不要求修改 dev 角色文件（其输入从 workflow-pb 的"输入"列获取，编号顺移后自动更新）。
- 不要求修改 verifier 角色文件（见 F05）。
- 不要求修改现有迭代中已产出的 tasks.md（新工作流从下一迭代生效）。
- 不要求在此文件中描述 commit-planner 的内部执行算法。

---

无。此功能卡纯文档修改，无架构决策。
