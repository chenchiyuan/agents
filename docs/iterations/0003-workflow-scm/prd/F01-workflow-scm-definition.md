# F01 — workflow-scm 工作流规范文件

**功能 ID**: F01  
**来源**: demand.md §最小边界 #1  
**迭代**: 0003-workflow-scm

---

## 用户价值

为所有代码提交提供统一的 git 层工作流宪法，使任何代码变更都可被追溯、审计和回滚。

---

## 验收标准

1. 存在文件 `roles/workflow-scm/workflow-scm.md`，且文件可独立读取（无需其他文件补全理解）。
2. 文件内包含以下所有部分，缺一不可：
   - **不变量声明**：列出 git 层不可违反的规则（如"从 tasks.md 产出起，任何代码变更必须经 worktree+PR"），每条规则可被客观判断是否违反。
   - **阶段定义**：至少包含提交规划阶段的职责描述、输入、输出、推进条件。
   - **文档路径协议**：明确 `prs/` 目录的所属迭代路径规则。
   - **角色读取指南**：commit-planner 等执行角色读此文件能找到输入路径、输出路径、交付标准。
3. 文件 frontmatter 中 `name: workflow-scm`，`description` 字段非空。
4. 文件版本字段 ≥ 0.1.0，创建日期字段存在。
5. 文件不包含执行细节（具体实现步骤属于执行角色文件范围，不在此文件内）。

---

## 边界（不包含）

- 不要求此文件描述 CI/CD 流水线配置（demand.md 明确排除）。
- 不要求包含 GitHub/GitLab API 调用规范（本迭代只做角色/工作流定义）。
- 不包含跨迭代迁移指南（新工作流只从下一迭代生效）。
- 不包含 commit-planner 的执行算法细节（那是角色文件的职责）。
