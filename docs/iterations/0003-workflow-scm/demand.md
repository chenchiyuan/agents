# demand.md — 0003-workflow-scm

## 澄清依据

本需求通过主 agent 与用户对话完成澄清（2026-09-02），以下为关键澄清结论：

**Q: Issue 与 prd 功能卡是否 1:1 映射？**
A: 不是。Issue 自由组合 tasks，可引用 prd 功能卡作为上下文背景，但不强制绑定。

**Q: PR 上下文摘要的载体形式？**
A: 每个 PR 独立文件（`prs/pr-{id}.md`），文件内可附参考资料链接，供 dev 快速构建上下文。

**Q: 提交规划执行方式？**
A: 全自动。commit-planner 自动分组、生成 PR 文件、创建 worktree/branch。

**Q: 是否需要专门角色管理 SCM 流程？**
A: 需要。新增 `workflow-scm` 作为 git 层的工作流宪法，由独立角色定义和维护。这是一个流程约束，所有代码变更必须经过此流程。

## 需求结论

### 背景与动因

研发 agent 已能自主完成中等复杂度任务，但产出仍是"一坨"大 diff，无法 review、无法回滚、无法并行。当前 `workflow-pb` 在 Phase 5 边界处退出了 git 世界，没有任何关于提交粒度、worktree 隔离、PR 管理的约定。

**直接动因**：dev 产出的变更粒度失控，评审流于形式。  
**深层动因**：agent 要成为可托付的产出方，必须接受与人类工程师同等的代码管理约束。  
**战略目的**：通过原子拆分 + 隔离并行，把吞吐从单会话串行提升为多任务并行，同时保持可审计性。

### 最小边界

1. **新增 `workflow-scm`**：独立工作流文件，定义 git 层的不变量和阶段规则，是所有代码提交的宪法约束。有专属角色负责定义和维护。

2. **新增 `commit-planner` 角色**：workflow-scm 的 Phase 5（提交规划）执行者。接收 `tasks.md`，全自动产出 `prs/` 目录（Issues/PR 分组、PR 独立文件、worktree 创建）。

3. **PR 文件规范**：每个 PR 对应 `prs/pr-{id}.md`，包含上下文摘要、涉及 tasks、文件范围、验收标准、参考资料。此文件是 dev 的唯一上下文来源。

4. **workflow-pb 扩展**：在 Phase 4（任务拆解）和 Phase 5（后端实现）之间插入新的 Phase 5（提交规划），原 Phase 5/6 顺移为 Phase 6/7。工作流握手点为 `tasks.md`。

5. **verifier 扩展**：新增针对 PR 粒度和文件范围的验证目标，verifier 角色文件本身不动，通过工作流契约扩展其验证范围。

6. **约束声明**：从 `tasks.md` 产出起，任何代码变更必须经过 worktree + PR，无例外。dev 和 verifier 无缝跟进新工作流，无需修改其角色定义。

### 不在范围内

- CI/CD 流水线配置（阶段 0）
- GitHub/GitLab API 对接实现（阶段 1+，本迭代只做角色/工作流定义）
- 现有迭代的迁移（新工作流从下一个迭代生效）
