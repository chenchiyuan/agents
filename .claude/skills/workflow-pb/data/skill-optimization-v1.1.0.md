# SKILL.md v1.1.0 优化记录

**日期**: 2026-09-03
**触发**: 用户反馈"遵循度不好"，怀疑是 skill 定义问题，要求分析并给优化方案

## 根因诊断

对照 `docs/skill-design-protocol.md` 逐项核查 SKILL.md（对应规范 workflow-pb v0.2.1）后，定位两个具体缺口，而非结构性超载（七层结构齐全，250 行未超载）：

1. **内联小节是 workflow-pb.md 的浓缩复制，不是纯指针**——「推进条件速查」复制了 workflow-pb.md「阶段定义」表；「Brief 模板」复制了「角色读取指南」+「文档路径协议」。这违反 workflow-pb.md 自己的「原则4：约束和调度契约只存在于本文件一处」——两份内容中的任意一处将来单独修改都不会同步，产生协议 Ch.6 要求避免的"单一定义源"漂移。
2. **阶段 1~4 完全没有阶段→角色的映射**——SKILL.md 全文只在 Step 5 提过一次"planner → dev"，主 agent 每次都要自己猜阶段该派哪个角色。workflow-pb.md「原则：不指定执行角色名」把这个映射职责留给了调度层（SKILL.md），但 SKILL.md 之前没做，这正是 Goal 2（协调 role 交付）遵循度差的直接原因。

## 决策（用户确认）

- 处理路线：不做 Ch.7 编排器+子 skill 分解（不满足分解触发条件），在现有两文件架构内定向修复
- 角色映射粒度：简单阶段→角色映射表（不做逐角色差异化 brief 指引，现有通用 Brief 模板已覆盖）
- 内联速查表处理：改为纯指针+加载时机说明，不保留内容副本

## 改动

- 删除「§ 推进条件速查」「§ Brief 模板」两个内联复制小节
- Step 1~4 改为显式指向 `workflow-pb.md §阶段定义表`；Brief 模板改名「§ Brief 构建规则」，字段值改为"读自 workflow-pb.md 对应列"而非硬编码内容
- 新增「§ 阶段→角色映射」表，阶段 1~6 + progress-observer 全覆盖
- 新增 Resources 章节（协议 4.3.8 要求，此前缺失），列出 workflow-pb.md/角色文件/本记录文件三类资源及加载时机
- Tools and capability boundaries「做什么」补回"读取 workflow-pb.md"这条（此前隐含在已删除的内联小节里，独立成条更清晰）
