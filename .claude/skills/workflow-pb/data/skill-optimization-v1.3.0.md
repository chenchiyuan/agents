# SKILL.md v1.3.0 优化记录

**日期**: 2026-09-03
**触发**: 用户明确要求"需求实现全过程都是明确的实施与还原，变更都需要发起新迭代来完成"——本迭代一旦通过阶段1产出 `demand.md`，执行过程中不应再被"发现需求问题"打断去回退修正，而是记录下来留给用户决定是否开新迭代；且强调"执行者直接写，主 agent 的作用就是分发、调度、验证，主 agent 不干活"。

## 根因

对应规范文件 `roles/workflow-pb/workflow-pb.md` 的「阶段回退」章节这次改动是本次改动的主体——原来是逐行硬编码的"发现问题→回退上游阶段修正"模式，与用户想要的"确定性还原"执行模型冲突：回退意味着本迭代中途被需求变更打断。本文件（SKILL.md）是主 agent 调度协议的精简版，必须同步规范文件的这条变更，否则主 agent 会按旧协议在执行角色报告问题时代为回退或暂停等待，而不是让执行角色自己直接搭置记录继续。

## 决策过程

- 最初提案是新增强制回退规则（demand.md 只能由 demand 角色修改，任意阶段发现问题都回退阶段1）——用户否决："这样改太重了，我不需要这么强制"
- 用户提出替代方案：不回退纠正，只"搭置记录"，本迭代按既定需求执行完，问题留给 verifier 交付报告，需要时再开新迭代处理
- 判断标准确立：用户明确"发现更好的实现方式、发现问题都应该直接解决"，只有"更改需求"才需要开新迭代——判断标准从"哪个阶段发现的"改成"解决这个问题是否要改变 demand.md 的结论"
- 记录归属确立：用户明确"执行者直接写，主 agent 不干活"——搭置记录由发现问题的执行角色直接写入，不经过主 agent 转达或代写

## 改动

- description 和 Purpose 补充说明阶段1硬性前置 + 需求问题搭置不回退的新协议
- 新增两条 CRITICAL：阶段1不可跳过；执行角色发现的需求变更/错误主 agent 不代为处理
- Important facts 新增第6条：需求问题不回退不暂停，只搭置；唯一硬停例外是依赖图有环
- Step 1~4 新增"阶段1硬性前置"声明 + "不是用户决策点"说明（需求问题不触发暂停）
- Step 6 新增：主 agent 若发现 `deferred-demand-changes.md` 存在，必须把路径显式塞进委托给 verifier 摘录透传（verifier 自身边界是只读委托指定路径，不会自己扫目录找这个文件）
- § 用户决策点与暂停格式表新增"不在此列"说明
- Tools and capability boundaries「不做什么」新增一条：不代替执行角色判断需求/技术问题、不代写搭置记录
- Safety 新增两条：阶段1不可跳过；需求变更/错误不是用户决策点

## 未变

- 阶段→角色映射、角色文件路径解析机制（v1.2.0 引入）不受本次改动影响，两者是独立维度
- `deferred-demand-changes.md` 的具体格式定义在规范文件 `roles/workflow-pb/workflow-pb.md`（文档路径协议一节），本文件只引用不重复定义
