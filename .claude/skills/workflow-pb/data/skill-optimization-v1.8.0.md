# SKILL.md v1.8.0 优化记录

**日期**: 2026-09-06
**触发**: 用户提出优化方向（planner 拆分 PR 后必须显式落盘 depends_on；派发执行者必须显式要求多子 agent 执行；每个 agent 独立完成一个 PR）。研究确认三条在 `workflow-pb.md` v0.4.0 中均已是显式要求，真实问题是 `docs/iterations/0005-pr-concurrent-execution/verification-report-stage6.md` 独立验证发现的 4 处文字歧义 + 协议从未在真实多 PR 场景验证过执行结果。用户采用方案 B，`workflow-pb.md` 完成 v0.4.0 → v0.5.0 的文字修复和阶段 6 强制检查项新增后，本次同步更新 SKILL.md 精简版协议。

## 根因

`workflow-pb.md` v0.4.0 阶段 5 的首批派发步骤和补位派发步骤用了两套不字面绑定的封顶规则；没有正面陈述"槛位空置不放宽解锁条件""不得清理失败/阻塞 PR 现场"这两条负面约束；`累计成功解锁次数` 字段名暗示只在成功时累加，与实际累加规则（成功和失败/阻塞都累加）不符。SKILL.md 作为该规范的精简版协议，逐字复制了同样的歧义表述。

## 决策过程

- `workflow-pb.md` 已完成 v0.5.0 的全部文字修复（阶段 5 封顶规则统一、两条负面约束、字段改名）和阶段 6 新增强制检查子章节
- SKILL.md 沿用既有惯例：只在对应章节补充要点式描述，不逐字复制正式规范全文，保证与正式规范不矛盾
- 沿用项目既有惯例：每次 `workflow-pb.md` 协议实质变更都同步更新 SKILL.md 和对应的 `data/skill-optimization-v{版本}.md` 记录文件

## 改动

- 文件头版本号 1.7.0 → 1.8.0，"对应规范"号同步为 workflow-pb v0.5.0；`description` 字段版本号同步
- 「### Step 5: 依赖解锁式并发 PR 派发」步骤 2 补上封顶规则和槛位空置负面约束；步骤 4（`progress-observer` 报告闲置 PR）补上失败/阻塞 PR 禁止清理的约束；「并发槛位算法要点」段落 `累计成功解锁次数` 改名为 `累计槛位释放次数`
- 「## Important facts and constraints」第 7 条补充"主 agent 不得执行 `git worktree remove`/`git branch -d`"的正面陈述；新增第 8 条槛位空置负面约束
- 「### Step 6: 独立验证」补充一句：≥2 个 PR 且依赖图有真实并发分支的迭代，阶段 6 委托须额外要求核查真实执行证据，指向 `workflow-pb.md` 新增子章节
- 新增两条 CRITICAL：失败/阻塞 PR 清理禁令
- 「## Safety」补充两条：槛位空置不放宽解锁条件；失败/阻塞 PR 清理禁令
- `## Resources` 的历史记录文件列表追加 `data/skill-optimization-v1.8.0.md`
