# SKILL.md v1.6.0 优化记录

**日期**: 2026-09-04
**触发**: 用户要求把「§ 阶段→角色映射」从简单表格扩展为逐阶段详细执行卡片，同时指出 `{角色根}` 双场景（agents 自身开发 vs 业务项目部署）的动态解析没有必要——两种场景可以统一走同一套安装路径。

## 根因

`{角色根}` 变量的存在本身就是一处不必要的间接层：v1.2.0 引入它是为了兼容"agents 项目自身开发时角色根是 `roles/`，业务项目部署后角色根是 `.pb-agents/roles/`"两种场景，但这个区分从未真正必要——agents 项目自身开发 workflow-pb 时，同样应该走"先安装、再从 `.pb-agents/roles/` 读取"的路径，而不是特殊化直接读源码目录。保留这个变量和双场景表格，只是把一个可以消除的分支持续留在协议里，增加了每次引用角色路径时的心智负担。

## 决策过程

- 用户先确认方向：把「§ 阶段→角色映射」扩展为详细执行卡片，在一处同时呈现角色名、角色文件路径、执行流程
- 用户随后提出更根本的简化：`{角色根}` 不需要动态判断，因为安装方法已经确定——统一安装到当前项目的 `.pb-agents/` 下即可，给出固定相对路径
- 确认 agents 项目自身开发场景也不例外：workflow-pb 在 agents 仓库里跑，也要先装到 `.pb-agents/`，不能读 `roles/` 源码目录
- 讨论真实 copy vs symlink 两个安装方案后，用户选择方案 1（真实 copy）：统一安装脚本，所有项目一视同仁，代价是修改 `roles/` 源码后需要重新执行安装脚本才能同步——用户明确确认接受此代价

## 改动

- 新增 `tools/install-pb-agents.sh`：幂等安装脚本，把 `roles/<role>/<role>.md`（排除 `_template`）和 `principles/` 真实 copy 到目标项目 `.pb-agents/` 下；不 copy 各角色的 `data/`、`memory.md`（按 `docs/memory-system.md` §六约定，这两者是运行时产物，不随框架部署）
- 消除 `{角色根}` 变量：全文所有引用替换为固定路径 `.pb-agents/roles/`，不再区分"agents 自身开发"与"业务项目部署"两种场景
- 「§ 角色文件路径解析」重写为「§ 角色文件路径与安装」：说明固定路径、安装方法（`tools/install-pb-agents.sh`）、检测时机（Step 0 一次性检测）、已知代价（改源码后需重新安装才能同步）、只读约束
- 「§ 阶段→角色映射」重写为「§ 阶段执行卡片」：每个阶段（1~6 + 内部三段式阶段 5 + progress-observer）单独一张卡片，同时列出角色名、角色文件路径、该阶段执行流程，替代原来只有角色名的简表
- Step 0、CRITICAL 声明块、Tools and capability boundaries、§ Brief 构建规则、Resources、Safety 中所有 `{角色根}` 引用同步替换为固定路径，并更新指向新章节名的引用
- 版本号 1.5.0 → 1.6.0

## 未变

- 需求问题搭置不回退协议（v1.3.0）、对外协议三组契约（v1.4.0）、角色名+路径三元绑定呈现约束（v1.5.0）不受本次改动影响，本次只处理路径解析机制本身的简化
- 角色文件内容（`demand.md` 等）未修改，问题定位在路径解析和呈现结构，不涉及角色定义层
- `.pb-agents/` 已在 `.gitignore` 中，安装产物不会被提交进版本控制
