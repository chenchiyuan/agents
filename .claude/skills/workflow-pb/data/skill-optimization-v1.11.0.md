# SKILL.md v1.11.0 优化记录（对应规范 workflow-pb v0.8.0）

**触发**：迭代 `0008-iteration-branch-workflow`——main 应始终只包含已完成、已验证的迭代产出；此前 PR 直接合并 main 意味着单个迭代未完成时其中间产出已落地 main，一旦迭代中途终止或需求有变，main 已被污染，难以整体回退。

**根因**：当前工作流 `main ← PR worktree 分支` 的单层结构，将"迭代内 PR 集成点"与"已验证迭代产出落地点"混为一谈，缺少中间隔离层。

**方案**：新增独立于 main 的中间分支层"迭代分支"（`iteration/{迭代ID}`），形成 `main ← 迭代分支 ← PR worktree 分支` 两层结构。阶段 1（需求收敛）完成后立即创建迭代分支，阶段 2~5 期间所有 PR 的 base 和合并目标改为迭代分支，阶段 5 解锁判据同步改为"合并进迭代分支"，迭代分支在阶段 6（独立验证）pass 后由主 agent 自动合并进 main。

**具体改动**：
- 版本号 v1.10.0 → v1.11.0，对应规范引用同步为 workflow-pb v0.8.0
- 11 处"主分支"术语替换为"当前迭代的迭代分支"或"迭代分支"（具体行号和替换内容见下表），确保所有合并目标、解锁判据、worktree base 引用均指向迭代分支而非 main

**一致性核对**：`SKILL.md` 与 `workflow-pb.md` v0.8.0 在以下关键点描述一致：

- 迭代分支合并进 main 的时机均为"阶段 6 独立验证 pass 后"
- 未在 `SKILL.md` 中发现任何遗留的"合并进主分支"作为 PR 合并目标或解锁条件的用法
